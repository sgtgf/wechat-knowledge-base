# 游戏中被击杀，矩阵行列式居然是幕后凶手


> 原文地址: [https://mp.weixin.qq.com/s/-CKO6AnCurAtALSkncLBYQ](https://mp.weixin.qq.com/s/-CKO6AnCurAtALSkncLBYQ)

# 1. 问题背景

玩游戏时，你可能也经历过这种 “摔键盘”的瞬间：在《王者荣耀》里，你操纵残血英雄极限走位，明明看到百里守约的子弹擦着衣角飞过，视觉上还隔着一段距离，但下一秒就直接黑屏阵亡；或者在《英雄联盟》里，你躲在兵线后自以为绝对安全，结果韦鲁斯的穿刺箭矢却穿过缝隙命中了你。玩家们通常管这类视觉和判定不符的现象叫 “吸铁石判定”。

遇到这种情况，大家的第一反应往往是：服务器卡顿？还是英雄碰撞判定框存在程序漏洞？其实都不是。如果复盘游戏后台的数据，你会发现这既不是网络延迟，也不是玄学外挂。在你被视觉画面 “欺骗” 的那一瞬间，游戏引擎的后台已经完成了无数次冰冷的数学计算。而那个判定你必死无疑的幕后黑手，其实是线性代数课本里一个经常被我们忽略的重要工具。

# 2. 游戏中的碰撞检测

要理解行列式在其中扮演的角色，我们需要先揭开游戏引擎的核心底层机制——碰撞检测。通俗来说，这便是判定技能有没有击中目标，或者目标有没有被击中。

我们在屏幕上看到的峡谷战场，充斥着精美的皮肤、复杂的衣服褶皱和华丽的技能特效。但在游戏服务器后台，如果逐帧计算模型全部精细面片与特效，运算量会急剧飙升，带来巨大的额外计算负担。为了让全场玩家在十几毫秒的延迟下流畅运行，游戏底层采用了一种极其务实的做法：剥离所有画面特效，把英雄和技能都简化成隐形的几何图形。

简单来说，你操纵的英雄在计算伤害时，后台会将其简化为一个多边形区域；而百里守约的子弹、韦鲁斯的箭矢，在飞行的那一瞬间，本质上只是坐标系里一个不断移动的坐标点。

这样一来，屏幕上的极限走位与擦边击杀，在游戏底层就被彻底转化成了一个纯粹的数学题：如何快速判断子弹或箭矢的那个坐标点，在当前这一帧到底有没有落入英雄的几何区域内部。

为了在转瞬之间给出准确的判定结果，游戏引擎在处理这类击中判定时，使用的重要工具，正是我们在线性代数中所学的矩阵行列式。

# 3\. 行列式的空间定向原理

在大多数人的常规认知里，线性代数课本中的行列式往往只是一堆通过交叉相乘算出来的密密麻麻的数字。然而从几何角度来看，行列式本质上是用来衡量空间中平行多面体体积大小的度量工具。比如在二维平面上，两个向量组成的二阶行列式，其绝对值就代表它们张成的平行四边形面积。

不过在许多应用场景中，体积和面积的大小反而是次要的。行列式还有一个经常被初学者忽略、却极其重要的底层特性——它本身还可以用来进行空间定向。

# 4\. 任意多边形受击框的判定

当这种纯粹的数学定向原理被引入到游戏引擎中时，它便成了解决碰撞检测的底层利器。

在真实的《王者荣耀》、《英雄联盟》等游戏开发中，英雄的受击框往往是由矩形、五边形甚至更复杂的任意凸多边形围成的区域。面对这么多条边界，游戏引擎在工程落地时，首先要解决一个标准问题：每条线段的起点和终点到底该怎么定？如果方向弄反了，行列式的正负号判定就会全盘崩溃。

工程上的解决办法非常简单，那就是统一顶点的旋转方向。在游戏加载角色模型时，引擎就会把受击框的所有顶点按照逆时针的顺序固定下来。比如一个五边形受击框，它的五个顶点依次是![](https://mmbiz.qpic.cn/mmbiz_png/iagCqyDH0KsmicNu0Z95a4eDVXdYoEaFbEYGibNQK4tKvCafDYMo4bWz5NoBawMGrtXMf5DlDjUBkSoNra8I9mGW2ujib0O9nl1vZpFjpB5wy9k/640?wx_fmt=png&from=appmsg)（图2）。这样一来，所有边界向量的方向就自动确定了：第一条线段是![](https://mmbiz.qpic.cn/mmbiz_png/iagCqyDH0KslRYIBSASOZEDGfwunfvKmgiaKAliakDicnniblUnEqQAb3r8bOJr0wjsQRWJTszMXHBY8o6Ujbv2r5cznKC4LcmeUkxgJZG0nGTqg/640?wx_fmt=png&from=appmsg)，第二条是![](https://mmbiz.qpic.cn/sz_mmbiz_png/iagCqyDH0Ksm7hluOVkaC2lj9n3P5O2xludkCib3oCGlPVNyQnu41v4SljsEtiaByAEfENlc0pp8djWrDzYYueKTNc4r6YkwKwhEccbZjhkias4/640?wx_fmt=png&from=appmsg)，以此类推，最后一条是![](https://mmbiz.qpic.cn/mmbiz_png/iagCqyDH0Ksmu5xlLHz5GiaKEg8Cy1YPhLLpTGWVlHMLrzqtY3dMgPWuXeD9dFhkRYoyO0FqNANbfBsktMsaZvMMhic3dDzmxLrtKzY7pySZ7s/640?wx_fmt=png&from=appmsg)。

规范了边界的方向后，前文提到的那个在坐标系里移动的子弹中心点，就可以正式开始参与计算了。

当百里守约的子弹或者韦鲁斯的箭矢飞向目标时，在每一帧的运算中，游戏引擎就会顺着逆时针方向，直接将子弹中心点P的当前坐标代入公式（1），对这个五边形的所有边界依次执行行列式定向计算。它先算点P相对![](https://mmbiz.qpic.cn/mmbiz_png/iagCqyDH0KslRYIBSASOZEDGfwunfvKmgiaKAliakDicnniblUnEqQAb3r8bOJr0wjsQRWJTszMXHBY8o6Ujbv2r5cznKC4LcmeUkxgJZG0nGTqg/640?wx_fmt=png&from=appmsg)的位置，再算相对![](https://mmbiz.qpic.cn/sz_mmbiz_png/iagCqyDH0Ksm7hluOVkaC2lj9n3P5O2xludkCib3oCGlPVNyQnu41v4SljsEtiaByAEfENlc0pp8djWrDzYYueKTNc4r6YkwKwhEccbZjhkias4/640?wx_fmt=png&from=appmsg)的位置，接着是![](https://mmbiz.qpic.cn/mmbiz_png/iagCqyDH0KsnBOjXIcfEpaoVRIWujIib8erwtPoYXyBwq58I87TjaTGh2CQHQJoa1z3357IgicWsmWym3IXDEV06kvB2NoPaMK99UiaQWiboJvKY/640?wx_fmt=png&from=appmsg) 、和![](https://mmbiz.qpic.cn/mmbiz_png/iagCqyDH0Ksmu5xlLHz5GiaKEg8Cy1YPhLLpTGWVlHMLrzqtY3dMgPWuXeD9dFhkRYoyO0FqNANbfBsktMsaZvMMhic3dDzmxLrtKzY7pySZ7s/640?wx_fmt=png&from=appmsg)。

因为所有的边界都是按逆时针首尾相连的，这就形成了一个数学上的绝对规律：如果点P代入这五次计算后，算出来的五个行列式结果全部大于0（全为正数），说明从每条边界看过去，子弹都在它们的左侧。根据几何拓扑学，这意味着点P已经彻底陷入了凸多边形的内部，被所有边界死死包围。反之，只要有任意一个行列式算出来小于0，就说明子弹还在某条边界的外侧，判定为没有打中。

需要说明的是，在真正的游戏引擎底层代码中，程序员们通常会使用一个叫“二维向量叉积”的函数来执行这种方向判定。但它的展开式与我们公式（1）给出的二阶行列式完全是一回事。游戏引擎通过这套“顶点逆时针排序 + 符号流水线计算”的组合拳，将复杂的空间碰撞完美解构成了一组纯粹的正负号筛选，在极短时间内就能给出准确判决结果。

# 5\. 总结

在游戏中那些看起来不可思议的走位击杀，底层其实都是在每一帧的运算里，子弹的坐标点完全落入了英雄的多边形受击框内部。

行列式能支撑海量密集技能判定的根本原因，就在于整个运算过程没有引入任何复杂的数学分支，只用到了基础的乘法和加减法。当子弹的坐标和多边形的每条边界被代入公式后，引擎不需要做任何图形的复杂处理，它只需要顺着逆时针方向，去观察那几个算出来的行列式数字到底是正还是负。

这套判别方式有一个严格的数学前提，那就是它只能处理没有凹陷的凸多边形。在真实的开发中，面对各种形状怪异的非凸受击框，游戏引擎会提前在后台做三角剖分处理，把不规则的复杂多边形拆解成几个紧密拼接的凸图形，从而继续套用矩阵行列式进行流水线式的正负号比对。

依靠符号判别方位的方案大幅提升了引擎高频刷新的运行效率，在几毫秒内就能输出准确的命中数据。说到底，并不是游戏画面在操控一切，真正决定玩家生死的，是后台高频运转的线性代数算式。
