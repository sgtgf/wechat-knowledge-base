[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486922&idx=1&sn=570a767e64e79f60ffaaffc02d5b3864&scene=21#wechat_redirect)我们讲了 I/f 启动的基本逻辑：控制器强制旋转一个电流矢量，转子在后面跟着走。但很多人调试时会发现，失步总是来得特别突然——前一秒电流、转速看着都正常，下一秒电机就像被人踩了一脚刹车，转速开始往下掉，电流也跟着往上冲，最后保护跳闸。

遇到这种情况，第一反应往往是“电流是不是给小了”，于是不断加大电流幅值。但结果往往是发热去了，失步的问题并没有减少。

真正的问题不在电流够不够大，而在电流矢量和永磁体磁链之间的夹角  是否越过了 。这篇文章就来推导这个边界的来历，并说清楚它和调试时的几个常见误区到底有什么区别。

## 一、为什么这个问题值得关心

开环 I/f 启动不依赖转子位置，靠的是一个“我设定好电流矢量怎么转，转子爱跟不跟”的逻辑。设定合适，转子会被电流拖着同步加速；设定不合适，转子跟不上，电流矢量就“甩”到转子前面去了。

在代码里，这件事通常被简化成两个参数：电流幅值和电流矢量旋转速度。以 VESC 为例，它的开环电流入口 `mcpwm_foc_set_openloop_current()` 只做这几件事（节选自 VESC bldc `motor/mcpwm_foc.c`，Git HEAD `c59445545fa8f1a6093e882807b2ca46d1870f24`，约第 876–892 行）：

`void mcpwm_foc_set_openloop_current(float current, float rpm) {       utils_truncate_number(&current,           -get_motor_now()->m_conf->l_current_max * get_motor_now()->m_conf->l_current_max_scale,           get_motor_now()->m_conf->l_current_max * get_motor_now()->m_conf->l_current_max_scale);          get_motor_now()->m_control_mode = CONTROL_MODE_OPENLOOP;       get_motor_now()->m_iq_set = current;       get_motor_now()->m_openloop_speed = RPM2RADPS_f(rpm);    // ...   }`

它把电流直接赋给 q 轴电流给定 `m_iq_set`，并把 `rpm` 转成电角速度存入 `m_openloop_speed`。后续 FOC 线程会按这个速度去积分强制相位。

代码里既不显式知道转子在哪里，也不显式检查“电流矢量与转子夹角  是多少”。 的约束完全藏在电机物理里。你要是不理解这个约束，调试时就像在黑盒里拧旋钮，永远不知道哪一下会触发失步。

## 二、旋转磁场中的指南针：一个能映射结构的直觉

你可以把 I/f 启动想象成把一个指南针放进旋转磁场里。

磁场方向（电流矢量）以固定速度旋转，指南针（转子永磁磁链）想跟着它转。但因为负载和惯量，指南针会落后磁场一个角度 。磁场对指南针的力矩与  成正比： 越大，力矩越大，但这个力矩只有在正确方向上才能帮指南针跟上。

当  时，指南针落后或超前不到 ，磁场力矩总有一个分量把它往磁场方向拉。这时候，如果指南针受到一点扰动，力矩会把它推回原来的跟随位置，系统稳定。

但如果磁场突然加速，指南针因为惯性和负载跟不上，落后角度就会增大。一旦  超过 ，磁场力矩在指南针运动方向上的分量变号——不再是帮它加速，而是开始把它往反方向推，指南针就“脱开”了。电机也一样：电流矢量一旦超前转子磁链太多（），电磁转矩在转子运动方向上的分量变号，不但不拉转子同步，还会让它越来越跟不上，最终失步。

## 四、 到底是哪条边界

很多工程师误以为  是“转矩反向”的边界。其实不是。

从式 (1) 看， 时  最大， 越过  后  才反向。 的真正含义是“同步刚度”变号。

什么叫同步刚度？就是在稳态工作点  附近， 受到一个小扰动时，电磁转矩会产生多大的恢复力矩。对式 (1) 在  处线性化：

这就是文献 \[1\] 中的式 (12)。当  时，， 增大一点，转矩就增大，经过机械动态会把  拉回； 减小一点，转矩就减小， 会被推回去。系统有正的同步刚度。

当  时，，同步刚度为零。此时你加再大的小扰动，转矩都不会有恢复分量，系统处于临界状态。

当  时，，同步刚度为负。 再增大，转矩反而减小；转子越来越跟不上，最终失步。这就是为什么一旦越过 ，电流再大也拉不回来——不是转矩不够，而是恢复力矩的方向反了。

## 六、代码里为什么不直接检查 

既然  这么关键，为什么开源代码里很少看到类似 `if (theta > 90°)` 这样的判断？因为  在开环模式下根本不可测——你不知道转子真实位置，只能知道“我设定的电流矢量在哪里”。

所以代码里的约束是通过设计参数间接保证的。phobia 的开环强制模式里，有几个典型参数（节选自 phobia `src/phobia/pm.c`，Mercurial id `4058e68de0cd`，约第 197–204 行）：

`pm->forced_maximal = 280.f;      /* 最大强制转速，rad/s */   pm->forced_accel   = 400.f;      /* 强制加速率，rad/s² */   pm->forced_hold_D  = 20.f;       /* 预定位/保持电流，A */   pm->forced_stop_DC = 0.7f;       /* 占空比阈值；源码中用于限制 forced_wS 更新，具体保护语义待核实 */`

这些参数本质上都在间接影响  的动态裕量：电流给转矩余量，加速率决定负载能不能跟上，速度上限和占空比阈值则限制强制拖拽过程的风险。 的  边界在代码里不会显式出现，但设计这些参数时必须考虑它。

VESC 的代码里也能看到类似的间接约束：开环电流、开环转速阈值、切入转速等配置项（如 `foc_openloop_rpm`、`foc_sl_openloop_time`、`foc_sl_openloop_boost_q` 等，配置序列化逻辑见 VESC bldc `confgenerator.c` 约第 85–92 行），本质上都是在围绕“别让  越界”这件事做工程折中。

## 七、常见误解澄清

**误解 1： 是电流矢量与 d 轴的夹角，所以  最稳。**

在 SPMSM 中，d 轴确实对齐永磁磁链，所以这种说法等价。但  时 ，没有电磁转矩，带载时根本不能作为稳态工作点。在本文约定的正向电动带载工况下，只要有正向负载转矩， 就会被推到大于 0 的位置。

**误解 2：电流越大越不会失步。**

电流大能增大最大转矩、减小稳态 ，确实能提高稳定裕量。但  一旦越过 ，同步刚度已经变负，电流再大也拉不回来。此时你的“拉力”方向反了，只会把转子推得更远。

**误解 3： 是转矩反向的临界点。**

 越过  后转矩才反向。 是同步刚度为零、转矩最大的点； 时转矩回到零，再过去才变负。失步的机理是“刚度变号”，不是“转矩反向”。

## 八、工程代价、适用边界与调试后果

不理解  的代价，会直接反映在调试现场：

-   • **电流设太小**：稳态  已经接近 ，稍有扰动就越界，电机失步、转速开始跌落。常见表现是反电动势的“反向”作用开始下降、电流跟着上冲，随后进入限流或保护；具体波形取决于驱动器控制和保护策略。
    
-   • **加速斜率设太陡**：动态过程中  的峰值越过 ，转子还没跟上就被甩开。参考文献\[2\]的分析给出了加速率的上限设计思路。
    
-   • **负载突变**：比如压缩机负载转矩随活塞位置剧烈变化， 会瞬时漂移。如果稳态  离  太近，就会越过边界。
    
-   • **盲目加大电流**：不仅效率低、发热大，而且不能从根本上解决  越界问题。
    

因此，设计 I/f 启动时，真正要关心的是“稳态工作点离  有多远”，而不是“电流峰值有多大”。

## 九、可迁移的工程判断

 不是经验阈值，而是同步刚度由正变负的临界点。判断一个 I/f 启动设计是否靠谱，你应该问三个问题：

1.  1\. 在当前负载下，稳态  是多少？离  有多远？
    
2.  2\. 加速过程中  的动态峰值会不会越过 ？
    
3.  3\. 负载突变时， 的瞬态偏移量有没有裕量？
    

如果这三个问题回答不上来，就不要急着调电流，先把电流—转速曲线和负载特性对齐。理解了  的边界，调试 I/f 启动时就不会再盯着电流峰值发愣，而是会先问： 是不是跑到  以外去了？
