做电机控制的工程师，大多是从有感控制起步的。

电机后端装个编码器，每转一圈吐几千个脉冲。你数脉冲，就知道转子在哪。电流环、速度环、位置环，一环套一环，闭环稳得很。

直到有一天，客户把电机往桌上一放，说了一句话，你可能当场就愣住。

"这个不要编码器。"

转速八万转，体积比拳头小，成本卡得死。你打开手里的工具链——ST MC SDK 以编码器模式为常见配置，ODrive 的 `axis.cpp` 里全是 `ENCODER` 的字眼，VESC 的 `datatypes.h` 里倒是能看到 `FOC_SENSOR_MODE_SENSORLESS`，但你从来没点进去过。

问题来了：没有编码器，FOC 怎么闭环？

编码器是电机的"肉眼"。它盯着转子，告诉控制器"我现在朝哪"。但这只"肉眼"有时候太贵，有时候太大，有时候太娇气。

这时候就得靠另一只"眼"——观测器。

观测器不是传感器。它不直接看，而是靠**算**。测电流，测电压，反推转子的位置和速度。这个"算"的过程，就叫状态估计。

说白了，编码器是"直接看"，观测器是"算出来"。没有编码器，FOC 必须靠观测器算出角度，不然就是瞎子。

## 黑屋子里的电风扇

想象你在一个黑屋子里，里面有台电风扇在转。你想知道叶片朝哪，但灯坏了，手也不能伸进去——转速太高，伸进去就废了。

你有两个办法。

**办法一**：在风扇轴上装一个**带狭缝的圆盘**（码盘）。圆盘两侧，一侧装 LED 发光，另一侧装光敏传感器接收。风扇每转过一个狭缝，光线被切断一次，传感器就输出一个**方波脉冲**。

为了判断转向，码盘上实际有两组传感器（A、B 两相），彼此错开 1/4 周期。正转时 A 相脉冲超前 B 相，反转时 B 相超前 A 相。控制器不用眼睛看，而是用**高速计数器**数脉冲、判方向。转速再高，只要码盘不碎、电路跟得上，转子的角度就是**离散且确定**的。这就是**编码器**——直接，准确，不废话。

**办法二**：不在风扇上装任何机械装置。你在屋子外接一个**麦克风**听风声，再外接一个**功率表**测风扇电机的电流和电压。你手里有一张"风扇物理参数表"：叶片几片、电机电阻电感多少、转速与电气信号应该满足什么关系。根据这些，你**推算出**叶片现在的朝向和转速。这就是**观测器**——不直接看，靠物理模型的逆运算推断。

编码器是"切光计数"，观测器是"听风辨位"。

电机上的编码器，通常是个光电或磁电装置，装在轴后端。转一圈，输出几千个脉冲。控制器数脉冲，就知道转子转了多少度。简单粗暴。

但这只**机电装置**毛病不少。

贵。高精度光电编码器，有时候比电机本体还贵。大。有厚度，有直径，微型电机根本塞不进去。娇气。光电的怕油怕灰怕震动，磁电的怕强磁场干扰。线多。六到十根线拉到驱动板，走线麻烦，EMC 难搞。

所以客户说"不要编码器"，往往不是刁难你。是真的装不上。

### FOC 为什么非要那个角度？

各位同仁知道，磁场定向控制（FOC, Field-Oriented Control）的核心，是把三相交流电变换到旋转的 d-q 坐标系，让 d 轴管磁链，q 轴管转矩。

这个变换叫 Park 变换。本文采用幅值不变的 Clarke 变换，d 轴对齐转子永磁磁链， 为电角度——这些都是后续公式的默认约定。

说白了，Park 变换就是你拿着一张地图给电机"指路"。但电机内部的三相电流是在"旋转坐标系"里流动的，你的地图必须跟着转子磁场一起转，才能指对方向。不知道转子朝哪，地图就是歪的，指的路也是歪的。

没有 ，Park 变换就废了。d 轴和 q 轴电流混在一起，转矩控制变成一锅粥。

所以，**不管用编码器还是观测器，核心目的都是拿到这个** 。编码器直接测，观测器算。殊途同归。

换句话讲，FOC 就像导航。编码器是 GPS 直接定位，观测器是根据车速和方向盘角度推算位置。没有定位信息，导航就瞎了。

## 编码器的麻烦，远不止"贵"

咱们花点时间，把编码器的工作原理彻底搞懂。只有知道它怎么工作的，才能理解"不要编码器"为什么那么难。

最常见的增量式光电编码器，结构简单到可笑：一个码盘装在电机轴上，盘上有很细的光栅。一边是 LED 发光，另一边是光电二极管接收。

电机一转，光栅交替挡住和透过光线。光电二极管收到一连串脉冲。转一圈，固定数量的脉冲——1024 个、4096 个、甚至 10000 个。

控制器数脉冲，就知道转子转了多少度。4096 线的编码器，一圈 4096 个脉冲，每个脉冲对应  度。

原理听着简单，工程上全是坑。

**安装是个大问题。**

编码器要装在电机后端，和轴严格同轴。高速电机一转几万转，编码器轴承的同心度稍有偏差，就会产生振动，甚至损坏。牙科手机电机那种 30 万转的，常规编码器很难覆盖这类转速和体积约束。

**环境耐受更头疼。**

工业现场的电机，高温、高湿、多油、多尘。光电编码器最怕灰尘和油污——码盘上一粒灰尘，光电二极管就可能误判一个脉冲。磁编码器好一些，但强磁场干扰又是个噩梦。

**成本卡脖子。**

低端和高规格编码器价格差距很大。普通光电编码器批量价不高，但一旦要求高线数、抗干扰、耐高温或超薄封装，成本会急剧上升。家电、电动工具这些成本敏感的产品，往往难以接受。

**布线也麻烦。**

编码器通常引 6~10 根线到驱动板：A 相、B 相、Z 相、电源、地、屏蔽。电机和驱动板之间线越长，干扰越大。无人机、水下推进器这些场景，编码器线就是一根长长的"干扰天线"。

所以，**"不要编码器"不是工程师任性，是应用场景逼的。**

### 没了编码器，FOC 真就瞎了？

回到核心问题：编码器没了，FOC 还能不能跑？

能。但必须有一只"电子眼"来代替它。

这只"电子眼"就是观测器。

观测器的核心思想朴素到近乎粗暴：电机的电压方程和磁链方程，描述了电流、电压、转速、角度之间的关系。测了电流和电压，就能利用这些关系，**反推出**转速和角度。

像个老司机。不听发动机声音、不感受车身震动、不看仪表盘，就能大概知道车速多少。观测器就是这个"老司机"——通过电机对外表现出的"电信号"，推断内部状态。

今天只需要记住一个结论：

**观测器不是魔法，是物理定律的反向运用。**

### 盲人按摩师怎么知道客人哪疼？

刚才说了，观测器是"算"出来的。但这个"算"具体怎么算？

再打个比方。

你是位盲人按摩师，客人躺在按摩床上。你看不见他的脸，但能通过触摸判断他的身体状况。

肌肉僵硬 → 最近很累。体温偏高 → 有点发烧。呼吸急促 → 精神紧张。

观测器干的就是这个。它"摸"的是电机的电流和电压，"猜"的是角度和速度。

观测器内部有个**数学模型**。这个模型描述的是："如果电机现在的角度是 、速度是 ，那电流和电压应该长什么样"。

观测器把模型算出来的"理论电流"和实际测的"真实电流"对比。不一样，就说明模型里的  和  猜错了。然后调整  和 ，直到模型输出和实际测量对上。

这个过程叫**状态估计的闭环校正**。

编码器是直接测量——不需要估计算法反复校正，测量值本身就是反馈。观测器是先估计、再用误差校正——猜错了就调，调对了再输出。

所以观测器比编码器"慢半拍"。编码器实时测量，观测器要先猜、再验证、再调整，天然有动态响应过程。

但这个"慢半拍"不是坏事。带宽设计得当，绝大多数应用完全够用。ODrive、VESC 在GitHub上的开源源码中，默认无感方案用的都是观测器。工业和消费品领域已有大量无感电机在稳定运行。

### 有感 vs 无感：不是谁干掉谁

聊到这儿，有同仁可能会误解：观测器这么香，以后是不是所有电机都不需要编码器了？

不是。

有感和无感，不是替代关系，是不同场景下的**权衡**。

对低速性能要求极高的场景——伺服定位、机器人关节——编码器仍然不可替代。

对成本和体积敏感、不需要零速定位的——风机、水泵、电动工具——无感控制更优。

转速极高的——涡轮压缩机、牙科手机——常规编码器很难覆盖这类转速和体积约束，无感方案往往更现实。

**学观测器，不是为了消灭编码器，是为了在"装不上编码器"的场景下，依然能做出稳定的 FOC 控制。**

### 观测器早就不是"便宜货"的专利了

观测器最初的目的，确实是省掉编码器的成本和体积。但发展到现在，它在越来越多**高端场景**中成了刚需。

**超高速电机。**

转速超过 10 万转/分钟，高速场景对编码器的机械强度、带宽和安装提出很高要求。光电编码器的码盘高速下产生巨大离心力和振动，磁编码器的信号带宽也跟不上。编码器很难作为常规选择，无感方案通常成为主流选择。

已有高速无感研究覆盖 5~9 万 rpm。VESC 的 FOC observer（`foc_observer_update()`）设计之初就考虑了无感运行场景。

**恶劣环境。**

航天、深海、核工业。温度太高、辐射太强、压力太大，编码器要么失效，要么精度暴跌。观测器是纯软件算法，只要 MCU、采样链路和功率级状态正常，就不依赖额外的机械位置传感器。

**冗余备份。**

电动汽车主驱这种高可靠性场景，部分系统会同时运行观测器用于诊断或冗余备份。编码器信号异常时，理论上可以切换到观测器模式维持运行，但具体实现因厂商而异。

观测器技术在过去二十年发展迅猛。它早已不是"省钱的替代品"，而是**现代电机控制的核心技术**。

## 代码不会撒谎

聊了这么多概念，看看代码层面，有感和无感是怎么切换的。

ODrive 的 `axis.cpp` 里，控制器决定用编码器反馈还是观测器反馈：

`// 来源: ODrive@3a2e4dd1 Firmware/MotorControl/axis.cpp:258-314   // 有感/无感模式的切换逻辑（节选相位与速度来源）      bool sensorless_mode = config_.enable_sensorless_mode;      // 判断是否为异步感应电机（ACIM）   bool is_acim = motor_.config_.motor_type == Motor::MOTOR_TYPE_ACIM;      // 根据配置选择角度来源：观测器 or 编码器   OutputPort<float>* phase_src = sensorless_mode       ? &sensorless_estimator_.phase_       : &encoder_.phase_;      // 根据配置选择速度来源：观测器 or 编码器   OutputPort<float>* phase_vel_src = sensorless_mode       ? &sensorless_estimator_.phase_vel_       : &encoder_.phase_vel_;      // 真实源码中还会经过 ACIM 分支处理   OutputPort<float>* stator_phase_src = is_acim       ? &acim_estimator_.stator_phase_       : phase_src;      // 将选定的角度和速度来源连接到电流控制器   motor_.current_control_.phase_src_.connect_to(stator_phase_src);   motor_.current_control_.phase_vel_src_.connect_to(phase_vel_src);`

很直观。不管有感还是无感，**最终给 FOC 控制器的输入都是 `phase_` 和 `phase_vel_`**。控制器不关心角度从哪来，只关心准不准、延迟大不大。

再看 VESC 的 `datatypes.h`，传感器模式的枚举：

`// 来源: bldc@c5944554 datatypes.h:58-69   // 传感器/观测器模式枚举（节选）      typedef enum {       FOC_SENSOR_MODE_SENSORLESS = 0,  // 纯无感，观测器       FOC_SENSOR_MODE_ENCODER,         // 编码器       FOC_SENSOR_MODE_HALL,            // 霍尔传感器       FOC_SENSOR_MODE_HFI,             // 高频注入（低速用）    // ... 其他模式   } mc_foc_sensor_mode;`

## 上手之前，先摸清这三个坑

### 示波器看哪里

这篇文章不讲具体观测器算法，但评估"要不要上无感"时，可以先做个摸底：

\[ \] **Check 1**：电机开到目标最高转速，看相电流波形。波形干净、正弦度好，说明电气特性适合无感。  
\[ \] **Check 2**：精确测量电机参数 、、、。参数越准，观测器越好调。偏差大时会明显恶化估计，具体阈值需结合电机和算法验证。  
\[ \] **Check 3**：确认应用是否有"零速定位"需求。如果有，必须额外加 HFI 或 I/F 启动策略，纯观测器零速不工作。

### 常见坑

**坑 1：以为去掉编码器就省钱了，结果调试花了一个月**

> **症状**：为省编码器成本选了无感，调试周期远超预期，最终成本反而更高。
> 
> **根因**：无感调试难度远高于有感。观测器增益、PLL 参数、电流环带宽、逆变器补偿……每个环节都要整定。
> 
> **解法**：立项阶段评估好调试投入。量产数量大、成本极度敏感，无感方案的长期回报才够高。小批量项目，编码器可能更划算。

**坑 2：电机参数不准，观测器怎么调都抖**

> **症状**：观测器输出的角度估计值抖动严重，电机嗡嗡响，低速甚至反转。
> 
> **根因**：观测器数学模型依赖电机参数 、、。参数偏差大，模型和实际电机对不上，观测器就"猜错"。
> 
> **解法**：用 LCR 表或专用仪器精确测量电机参数。批次间参数分散度大，考虑在线参数辨识。

**坑 3：零速时强行用观测器启动，电机乱转**

> **症状**：电机静止时直接切入无感 FOC，电机抖动、反转，甚至过流保护。
> 
> **根因**：零速时反电动势为零，观测器没有输入信号，无法估计角度。
> 
> **解法**：零速启动必须用 HFI（高频注入）或 I/F（强拖启动）。纯观测器只能在一定转速以上工作。

## 🔧 调试 Checklist

\[ \] 确认应用是否允许零速时无知角度（如不允许，需规划 HFI/I-F 启动方案）  
\[ \] 精确测量电机参数：（绕组电阻）、（电感）、（磁链）  
\[ \] 确认最高转速：低速应用无感难度大，需评估可行性  
\[ \] 确认环境是否适合装编码器（空间、温度、振动、成本）  
\[ \] 准备好示波器和电流探头，调试时对比实测电流与模型预测电流
