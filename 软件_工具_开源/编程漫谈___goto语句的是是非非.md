在编程的世界里，goto语句一直是一个颇具争议的存在。有人视其为高效代码的法宝，有人则认为它是代码质量的噩梦。今天，我们就来聊聊goto语句。从编程语言发展的视角，结合Fortran和C语言，探讨一下goto语句的利与弊，以及在何种情况下可以使用它。

## 什么是goto语句？

goto语句通常在程序中执行非结构化的跳转，它最初的来源可能是汇编代码中的跳转指令。  

在20世纪60年代和70年代结构化编程尚未出现的时候，goto语句的使用非常流行。最早使用它的可能是Fortran，随后是Cobol。Fortran在20世纪70年代纳入了结构化编程，从那之后对goto语句的依赖性就开始下降了。虽然随后出现的语言大多都抛弃了goto语句，如Java和Python，但goto语句仍然被纳入了部分语言中，比如Ada和C。

实际上，许多现代编程语言中使用的控制结构都是从早期的goto语句演变而来的。例如，用于条件跳转的goto语句演变成了带有复合体的if语句；使用goto语句和标签来构建的循环变成了循环结构：for、while、do-while、repeat-until等；用于跳出循环的条件goto语句演变成了break语句。

### goto语句真的有害吗？

在1968年，Edsger Dijkstra发表了一篇题为《Go-to statement considered harmful》（goto语句是有害的）的文章，刊登在《Communications of the ACM》上。这篇文章在随后的年份中经常被引用，这可能也为非结构化编程的消亡奠定了基础。具有讽刺意味的是，Dijkstra在《What led to ‘Notes on Structured Programming’》（《结构化编程笔记》背后的故事）中承认，最初的论文标题其实是《A case against the goto statement》(一个反对goto语句的案例)，但被编辑Niklaus Wirth给更改了。

我们知道，一个完全由赋值语句组成的程序很容易追踪，因为它的流程是顺序的，没有非结构化的分支。加上条件语句也不会改变太多，尽管可以经过不同的代码路径，但过程仍然保持着线性顺序。增加重复语句会使代码变得更复杂，但并不会使其非结构化——我们总是可以轻松地追踪代码。而添加非结构化的跳转则会使得跟踪程序变得更加困难。用Dijkstra的话来说，goto语句“太原始了”，这种结构使得证明程序的正确性变得更加具有挑战性。

那么，为什么goto语句被认为是有害的呢？首要原因可能是使用goto语句的方式可能会使程序的结构变得模糊到无法解读的程度。William Wulf在他的论文《A Case Against the GOTO》中给出了一种更形象的表述：**goto语句的使用可能会制造出贯穿控制流程的“老鼠洞”**。话虽如此，但我们也不要忘记，早期的语言在结构方面几乎什么也没有——几乎所有东西都是通过使用goto语句来实现的。在早期的Fortran中，if语句被限制为单个语句，复合语句需要使用goto语句。例如，如果要在变量X的值小于100时执行一段代码，需要写成如下形式：

          IF (X .GE. 100) GO TO 50  
          ... X<100时执行的代码  
 50

同样，因为也没有else语句，所以需要类似地构造如下语句：

          IF (X .GE. 100) GO TO 50  
          ... X<100时执行的代码  
          GO TO 100  
 50  
          ... X>=100时执行的代码  
 100

而循环则是以下面的方式创建的：

          I \= 0  
 10     I \= I + 1  
          ... 循环中执行的代码  
          IF (I .NE. N) GO TO 10

以上这些代码表达使用起来显然不够方便，这应该是Fortran语言向结构化编程转变的重要原因。

也可能有这样一种观点：“goto语句本身不会产生糟糕的代码，糟糕的程序员才会”。而事实上是，在结构化编程出现之前就存在的goto语句，经常会产生所谓的“意大利面条式代码”（Spaghetti Code）。如果没有亲自阅读和重构过Cobol或Fortran等语言的一些历史遗留代码的话，也许你永远也不会真正理解这句话的含义。这些代码之中真的包含了大量以各种形式伪装的goto语句。

例如，在Fortran中，有：

-   计算跳转：
    

 GO TO (210,220,230,240,250), i

-   无条件分支
    

 GO TO 400

-   赋值跳转
    

 GO TO N, (10,20,30,40)

-   算术if（执行相同类型的非结构化分支）
    

 IF (N) 10,20,30

### 何时可以使用goto语句？

话说回来，在特定情况下，经验丰富的程序员偶尔使用一下goto语句其实还是可以的。例如，使用单个goto语句和单个标签来退出多个作用域级别，或者在复杂结构中间使用goto语句来快速跳转到循环的顶部。在没有提供异常语句（Exception）的情况下，它也可以用于错误处理。我想，这应该也是在C语言中一直保留着goto语句的重要原因。下面结合C语言，给出几个特定场景下的使用goto语句作为高效工具的例子。

1.  **错误处理**：在C语言中，goto常用于错误处理。当一个函数中出现多个需要返回错误信息的点时，使用goto可以避免多层嵌套的`if-else`语句，使得代码更加清晰。
    
     int divide(int a, int b) {  
         if (b \== 0) {  
             fprintf(stderr, "Error: Division by zero\\n");  
             goto cleanup;  
         }  
         int result \= a / b;  
     cleanup:  
         return result;  
     }
    
    在这个例子中，如果除数为0，我们使用goto跳转到`cleanup`标签，统一处理错误并返回结果。
    
2.  **复杂的条件判断**：在复杂的条件判断中，使用goto可以简化代码结构，尤其是在多个条件分支需要执行相同的代码时。
    
     int value \= 0;  
       
     if (condition1) {  
         value \= 1;  
         goto assignValue; // 跳转到赋值标签  
     }  
       
     if (condition2) {  
         value \= 2;  
         goto assignValue; // 跳转到赋值标签  
     }  
       
     assignValue:  
         // 使用value的代码...
    
    在这个例子中，无论哪个条件满足，都会执行`assignValue`标签下的代码，避免了代码的重复。
    
3.  **清理资源**：在需要释放多个资源的情况下，goto可以帮助我们在出错时跳转到统一的资源释放代码块，避免资源泄露。
    
     FILE \*fp \= fopen("data.txt", "r");  
     if (fp \== NULL) {  
         perror("Error opening file");  
         goto cleanup; // 跳转到清理标签  
     }  
       
     // 处理文件内容...  
       
     cleanup:  
         // 清理资源，例如关闭文件  
             fclose(fp); // 关闭文件  
    
    在这个例子中，如果`fopen`失败，我们使用goto跳转到`cleanup`标签，统一关闭文件。
    

### 结语

goto语句就像是一位拥有瞬间移动能力的超级英雄，它既有可能帮助我们解决一些棘手的问题，也可能给代码带来混乱和破坏。关键在于我们如何使用它。通过谨慎地使用goto，并且在适当的场景下发挥其优势，我们可以编写出既高效又易于维护的代码。但同时，我们也应该努力寻找替代方案，比如使用函数调用、异常处理等机制，来减少对goto的依赖，从而提高代码的整体质量。
