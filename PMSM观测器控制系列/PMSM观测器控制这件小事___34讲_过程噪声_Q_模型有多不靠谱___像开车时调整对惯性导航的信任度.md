你正在调一台 PMSM 无感 EKF，参数面板里躺着四个看起来毫不相关的数字：

`kalman_gain_Q[0] = 0.5;      // 电流？   kalman_gain_Q[1] = 2.0;      // 角度？   kalman_gain_Q[2] = 2e6;      // 速度？——这数写错了吧？   kalman_gain_Q[3] = 0.2;      // bias？`

你盯着 `2e6` 看了半分钟。一个过程噪声参数，比别的分量大了整整四百万倍。你把它改成 2000，编译下载，电机跑起来。P\[9\]（速度方差）果然不再飙高了，转速估计稳得像粘住了一样。你松了口气。

直到你给电机发一个转速阶跃。

ω 的估计像被按了慢放键——实际转速都爬到 800 rpm 了，你的 EKF 还在 200 rpm 附近磨叽，整整拖了两百多毫秒才跟上去。你赶紧把 Q\[2\] 改回 2e6，响应倒是立刻回来了，可负载一加重，P\[9\] 又开始膨胀，电机低频啸叫，电流波形毛糙得像砂纸。

你在调试笔记上写：

> "Q\[2\] 太小 → 速度迟钝；Q\[2\] 太大 → 噪声透过来。但为什么非得是 2e6 这个量级？其他三个 Q 又是管什么的？"

写到一半你停住了。你发现自己虽然会拧这四个旋钮，却**说不清楚每个旋钮在拧什么**。

教科书告诉你 Q 是"过程噪声协方差矩阵"，公式 `P = F·P·F' + Q` 也背得滚瓜烂熟。但"过程噪声"四个字给不了你任何工程直觉——它既不告诉你噪声从哪来，也不告诉你该拧多大。

本文要做的核心动作就是：**把 Q 的四个分量，还原成电机模型里"哪部分最不靠谱"的物理判断。**

## 像开车一样理解 Q：惯性导航的信任度

想象你开着一辆车，车上有两套定位系统。

一套是**纯速度积分的航位推算**。它不依赖外界信号，只靠当前速度 × dt 推算位移，叠加上一时刻的位置，就能一直算下去。问题是这个推算有个致命假设——**默认你在做匀速直线运动**。一旦路面有颠簸、进弯道、上坡下坡，速度在变，这个假设就崩了，误差会随时间累积。

（这里为了类比简洁，我们把模型预测简化为"只用速度积分"的形式。真实的 IMU 还会测量加速度，但在协方差预测层面，速度近似按 ω 不变处理。）

另一套是**GPS**。它直接告诉你当前坐标，不积分、不累积，但受遮挡和噪声影响，读数会抖。

你的导航软件内部，其实一直在做一件事：**判断这段路我的"匀速直线"假设有多不靠谱，然后决定该多信 IMU 还是多信 GPS。**

这就是 EKF 里 Q 的本质。

EKF 的"惯性导航"就是电机电压方程。[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486783&idx=1&sn=3da8ae74c88861a06c2991aa7bbadf8b&scene=21#wechat_redirect)我们讲过，phobia 的 5 维状态向量是 `[iX, iY, θ, ω, bias_Q]`，前两个分量描述电流，第三、四个描述角度和速度。预测模型靠这些方程推进：

`diX/dt = (uX - Rs·iX + λ·ω·sinθ) / Lq + 未建模项   diY/dt = (uY - Rs·iY - λ·ω·cosθ) / Lq + 未建模项   dθ/dt  = ω + 积分误差   dω/dt  = ？？？ + 负载突变   d(bias_Q)/dt = 慢漂`

前两个方程描述电流怎么变，第三、四个描述角度怎么积分——它们构成了 EKF 的**预测模型**。Q 就是你对"这个模型有多不靠谱"的量化打分。

**Q 小，相当于路面平坦。** 你的匀速假设很靠谱，IMU 积分误差小，导航软件选择多信模型预测，GPS 只做微调。反映在 EKF 上：Q 每周期只往 P 里加一点点不确定性，P 被 F·P·F' 的传播和更新的压缩维持在一个低位，Kalman 增益 K 小，滤波器平滑得像低通滤波器——但前提是模型真的准。

**Q 大，相当于路面颠簸、连续弯道。** 你的匀速假设在胡猜，IMU 误差快速累积，导航软件赶紧切到"多信 GPS"模式。反映在 EKF 上：Q 每周期往 P 里注入一大团不确定性，P 膨胀，K 变大，滤波器更积极地用电流测量来修正状态估计——代价是测量噪声也会更多地透过去。

这里有一个**和 PID 调参相反的直觉**，很多工程师一开始会搞混：

> **Q 增大 = 更信测量，响应变快但噪声变大；Q 减小 = 更信模型，响应变慢但噪声更小。**

这不是"加大增益"，这是**调整"模型 vs 测量"的信任天平**。

理解了这一点，再看 phobia 里 Q 的四个分量，就不会觉得它们是四个孤立的数字了。它们分别对应模型里四个"最容易翻车"的环节。

这里有个边界差异要说明：GPS 直接给出位置坐标，而电流传感器给出的是电流，它需要经过观测矩阵 H 的映射，才能间接修正角度和速度。但"信测量还是信模型"的权衡逻辑，和导航软件里的 IMU/GPS 融合是一样的。

## Q\[0\]：电流模型，参数不准是原罪

`kalman_gain_Q[0] = 0.5`，加到电流方差 `P[0]` 和 `P[2]` 上，缩放系数是 `lazy_TiLq = dt / Lq`。

电流的预测模型来自电压方程：

这个模型看起来挺严谨，但工程上至少有三处"不靠谱"：

**第一，定子电阻 Rs 随温度漂移。** 系列标准取冷态（25°C）约 0.35 Ω，电机跑到 80°C 时，铜的电阻温度系数约 0.00386/°C，Rs 升到约 0.42 Ω。模型里如果还按冷态值算，电流预测就会系统性地偏。

**第二，交直轴电感 Ld、Lq 不是常数。** 电流大了，铁芯饱和，Lq 会下降。模型里用的是标称值 `const_im_Lq`，实际可能低 10%~20%。这意味着模型以为电流变化率该是多少，实际不是那么回事。

**第三，交叉耦合项的近似。** phobia 的模型里已经考虑了部分交叉耦合（F 矩阵里的 F\[2\]、F\[7\] 等），但高阶效应（如磁链谐波、涡流）没有建模。这些没进方程的东西，就是模型失配。

Q\[0\] 就是你对"电流模型有这么多隐藏误差"的诚实承认。0.5 这个默认值不算大，说明作者认为电流模型相对靠谱——电压方程毕竟是电机学里被验证过无数次的基石。但如果你的电机温升特别狠、或者铁芯材料非线性很强，这个数就得往上调。

**调错会怎样？** Q\[0\] 太小，电流估计过度自信，参数漂移后实际电流和预测电流对不上，残差持续非零，滤波器会把这种偏差错误地归因到 θ 或 ω 上，导致角度估计跑偏。Q\[0\] 太大，电流方差被吹胀，K 的电流分量变大，测量噪声更多地透进状态估计，电流波形毛糙——但角度估计反倒不容易被电流偏差带歪。

就这一行，没有别的了。这个模型假设在一个控制周期内（20 kHz PWM → dt = 50 μs），转速是恒定的。

50 μs 确实很短，但如果电机正在加速——比如从 0 加到 3000 rpm，加速度很大——那么这 50 μs 内的平均速度并不等于 `ω_k`。这个差异就是积分误差。

Q\[1\] = 2.0 就是给这个积分过程买一个"误差保险"——主要补偿的是 dt 内速度变化带来的离散化误差，以及更高阶的未建模动态。数值不大，因为 dt 本身很小，典型工况下积分离散化的误差可控。但如果你的 PWM 频率很低（比如 4 kHz → dt = 250 μs），或者电机经常处于急加减速工况，这个数就该往上走。

**调错会怎样？** Q\[1\] 太小，角度方差 P\[5\] 被压缩得过低，滤波器对角度过度自信。转速突变时，角度积分跟不上实际转子位置，角度估计滞后，最终表现为电流相位对不上，力矩输出下降。Q\[1\] 太大，P\[5\] 持续膨胀，角度修正过于敏感，静止或低速时角度抖动加剧，严重时会触发堵转。

没有然后。在协方差预测的 F 矩阵里，ω 行基本按恒速处理——F\[3\] 和 F\[8\] 虽然是非零值，但那是电流通过 back-EMF 对速度的耦合敏感度，不是对加速度的显式建模。状态估计路径中确实有一路 `pm_lu_accel()` 的加速度前馈（`flux_gain_IF = 0.1f`，Kalman 路径见 `pm.c:1363-1367`；Ortega 路径也有同类前馈在 `pm.c:992-996`），用电磁转矩减负载转矩除以惯量来推算加速度，但它不是完整的机械方程建模，也没有进入 P 矩阵的雅可比传播。所以在协方差层面，速度的模型失配仍然是最剧烈的。

可实际电机呢？负载转矩一突变——比如机械臂碰到障碍物、压缩机进入高压区、风扇阵风——转速在几十个毫秒内就会变。协方差预测模型对这种突变没有足够表达。如果 Q\[2\] 不够大，P\[9\] 会被更新步的压缩迅速压小，Kalman 增益 K 的 ω 分量趋近于零，滤波器拒绝用电流测量来修正速度估计。结果就是：负载一变，速度估计像粘住了，拖几百毫秒才反应过来——这正是你把 Q\[2\] 改成 2000 时看到的症状。

Q\[2\] = 2e6 这个看起来离谱的数，从源码结构和 EKF 原理来看，是一个**有意为之的大 Q 设计**——它持续给 P\[9\] 注入足够大的不确定性，迫使 Kalman 增益维持在一个非零的水平，让速度估计始终对电流测量保持响应。代价是 P\[9\] 永远很大，速度估计的噪声基底比别的状态高——这是"速度模型太不靠谱"在 phobia 实现中付出的工程代价。

这里有个常见的误解要澄清：**Q\[2\] 大不是因为"速度本身噪声大"，而是因为"速度的预测模型几乎没有信息量"。** 如果速度真的能被精确建模（比如你有编码器做速度闭环，或者你显式加入了加速度项），Q\[2\] 完全可以小很多。但在无感 FOC 里，速度是隐式估计量，没有独立的测量通道，模型又简陋，所以只能退而求其次：用一个大 Q 来维持滤波器的"开放性"。

**调错会怎样？** Q\[2\] 太小是灾难性的——我们已经看到了，转速阶跃时估计滞后两百毫秒，这在需要快速响应的伺服应用里不可接受。Q\[2\] 太大则会让速度估计的噪声一直透过去，低速时转速读数抖动，电流环给定也跟着抖，电机啸叫。但相比之下，"太大"只是噪声问题，"太小"是跟踪失效问题。从这个默认值看，工程取向更偏向保持跟踪能力，而不是把速度噪声压到最低。

## Q\[3\]：bias\_Q 的慢漂移，一把小锤子敲钉子

`kalman_gain_Q[3] = 0.2`，加到 bias\_Q 方差 `P[14]` 上，缩放系数是 `dt`。

bias\_Q 是什么？在无感 EKF 里，它是一个**扩展状态**，用来补偿模型里的系统性偏差。具体来说，phobia 在电压方程的 q 轴分量里注入了一个 `kalman_bias_Q`：

`uQ += pm->kalman_bias_Q;  // pm.c:1020`

这个 bias 用来吸收投影到 q 轴电压方程的慢变等效偏差——比如电阻温漂在 q 轴的残余分量、电感饱和的未补偿部分、ADC 采样偏置等。这些东西变化很慢（秒级到分钟级），但如果不补偿，会持续地往电流方程里灌偏差。

不过要注意，phobia 里 bias\_Q 的更新是有条件的。在 `PM_ZONE_HIGH` 运行区间（高速区），bias\_Q 才通过 Kalman 增益持续更新；在低速或启动阶段，它会被清零（`pm.c:1334`）。另一分支还有符号钳制——当 bias 与速度同号时会被强制归零（`pm.c:1347-1353`）。所以 bias\_Q 不是万能的"系统误差吃掉器"，它只在特定运行区间内起作用。

把 bias\_Q 放进状态向量里一起估计，是 EKF 处理模型系统误差的经典手段。但 bias 自己也有演化：它不会凭空跳变，但会缓慢漂移。

Q\[3\] 就是这个漂移速率的"方差预算"。0.2 是个很小的数，说明作者假设 bias 的漂移非常慢。每周期注入 `0.2 × 50μs = 1e-5` 到 P\[14\] 上，这个量级的注入几乎不会引起波动，但足以让滤波器在长期运行中慢慢"咀嚼"掉累积的系统性偏差。

**调错会怎样？** Q\[3\] 太小，bias 估计长期锁死在一个值上，电阻温漂等慢变误差中投影到 q 轴等效电压偏置的部分无法被这一路 bias 继续追踪，电流估计出现持续性偏差，角度估计跟着跑偏。Q\[3\] 太大，bias 估计变得过于敏感，高频噪声被误当成漂移来追，bias 本身开始抖动，反而引入新的扰动。

因为 bias 是间接估计的（没有独立的测量，只能通过电流残差反推），它的收敛速度天然比 iX/iY 慢。Q\[3\] 的调参原则是：**够小，让它慢慢追；但不能为零，否则追不动。**

## 源码印证：Q 在预测步里是怎么注入 P 的

说完了物理直觉，我们回到代码，看看 Q 是怎么在 `pm_kalman_forecast()` 里变成 P 的增量的。

[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486783&idx=1&sn=3da8ae74c88861a06c2991aa7bbadf8b&scene=21#wechat_redirect)我们详细拆解了 `P = F·P·F' + Q` 的完整计算流程，F 矩阵的 10 个元素在线算出，`M = F·P 和 P_new = M·F` 做了两轮矩阵乘法。这些做完之后，只剩最后四行：

`/* pm_kalman_forecast() 末尾，pm.c:1169-1173 */      P[0]  += Q[0] * pm->lazy_TiLq;   // iX 方差 += 电流过程噪声   P[2]  += Q[0] * pm->lazy_TiLq;   // iY 方差 += 电流过程噪声（同量）   P[5]  += Q[1] * pm->m_dT;        // θ 方差 += 角度过程噪声   P[9]  += Q[2] * pm->m_dT;        // ω 方差 += 速度过程噪声   P[14] += Q[3] * pm->m_dT;        // bias_Q 方差 += bias 过程噪声`

注意这里的**缩放差异**：

-   • `Q[0]` 乘的是 `lazy_TiLq = dt / Lq`，这是离散电压方程中**电压到电流增量的转换增益**（单位 A/V）。`dt/Lq` 的物理意义是：每伏特电压在一个控制周期内能产生多少安培的电流变化。
    
-   • `Q[1..3]` 乘的是纯 `dt`，和积分方程 `dθ/dt = ω`、`dω/dt = 0`、`d(bias)/dt = 0` 的时间口径一致。
    

这意味着 **Q\[0\] 和 Q\[1..3\] 不能直接横向比较数值大小**。Q\[0\] = 0.5 看起来比 Q\[1\] = 2.0 小，但经过 `dt/Lq` 缩放后的实际注入量取决于 Lq。以典型值 Lq ≈ 100 μH 为例，`lazy_TiLq = 50μs / 100μH = 0.5`（A/V），所以 Q\[0\] 的实际注入是 `0.5 × 0.5 = 0.25`，和 Q\[1\] 的 `2.0 × 50μs = 1e-4` 完全不在一个量级。

需要强调的是，phobia 源码在这里采用的 `dt/Lq` 缩放是一种**工程归一化设计**，不是标准连续时间过程噪声协方差的严格离散化推导。`kalman_gain_Q[0..3]` 的本质是**调参旋钮**，不是可以直接按方差量纲解释的物理量。这也解释了为什么 Q\[0\] = 0.5 和 Q\[1\] = 2.0 的数值看起来接近，实际注入量却差了几个数量级——它们经过的物理缩放完全不同。Q\[1..3\] 没有 `dt/Lq` 这种增益缩放，因为它们对应的状态方程是简单的积分关系（增量只与 dt 有关）。

以下源码引用基于 phobia 2026年5月的版本，行号可能随版本变化（`pm.c:219-222`）：

`pm->kalman_gain_Q[0] = 5.e-1f;   // 0.5   pm->kalman_gain_Q[1] = 2.e+0f;   // 2.0   pm->kalman_gain_Q[2] = 2.e+6f;   // 2,000,000   pm->kalman_gain_Q[3] = 2.e-1f;   // 0.2`

这组默认值的排列本身就在讲故事：电流模型相对靠谱（Q\[0\] 中等），角度积分有小误差（Q\[1\] 不大），速度模型几乎不靠谱（Q\[2\] 极大），bias 漂移极慢（Q\[3\] 极小）。这不是作者随手填的，而是对"模型可信度"的工程判断。

## 核心判断：Q 不是水，是诚实的承认

读完本文，你应该带走三个工程判断。

**第二，在 phobia 的无感 FOC 实现中，Q\[2\] 远大于其他三个，因为速度是模型失配最剧烈的状态。** 2e6 不是 bug，从源码行为看更像一个有意为之的大 Q 设计。它保证速度估计始终对电流测量保持开放，代价是速度噪声基底偏高。在无感 FOC 里，"跟踪不失"通常比"噪声更低"优先级更高。

**第三，调 Q 不是调"灵敏度"，而是调"模型 vs 测量的信任天平"。** Q 增大 → 更信测量，响应快但噪声大；Q 减小 → 更信模型，响应慢但噪声小。这和 PID 的"加大增益"直觉相反。拧旋钮之前，先问自己：**这段工况下，我的电机模型有多不靠谱？**
