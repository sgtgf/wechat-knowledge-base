各位同仁有没有注意过手机里的天气预报？

今天显示"明天晴，23°C"，你大概会信。但如果它说"下周五晴，23°C"，你心里多半要打鼓——五天后的预报，准头能剩几成？

这不是气象局偷懒。而是任何预测都有一个天然规律：**你离当前时刻越远，模型跑出来的结果就越"虚"**。气象模型再复杂，也挡不住蝴蝶扇翅膀。

电机控制器里每天都在发生同样的事。

每个控制周期——可能是 50 微秒，也可能是 100 微秒——处理器都要回答一个问题：**下一刻电机的电流、转速、转子位置会是多少？**

它没有水晶球。它手里只有两样东西：上一刻算出来的"最佳估计"，和描述电机物理规律的微分方程。然后它把这两者丢进模型，让方程向前跑一步。

这一步，在卡尔曼滤波（Kalman Filter）的术语里，叫做**预测步（Forecast Step）**\[E-001\]。

如果你读过 [第26讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486699&idx=1&sn=8cbb67d09da66566a4ade84b77fa46f7&scene=21#wechat_redirect) ，应该还记得 EKF 的"猜-看-修正"九字循环。预测步就是"猜"——在没有任何新测量的情况下，全凭模型和旧估计，推一手里会出什么牌。

说白了，预测步就是控制器在说："根据我掌握的物理规律和当前状态，我**猜**下一刻长这样。但这个猜是有成本的——每多猜一步，我心里就没底一分。"

这像极了天气预报员每天凌晨面对的屏幕。

## 气象台怎么工作，控制器就怎么工作

各位同仁，咱们先不碰公式，来打个比方。

假设你是一位气象预报员。你的工作是预测北京明天的温度。你手里有：

-   • **当前数据**：今天 14:00 的温度 28°C、湿度 65%、气压 1012 hPa、风速 3 m/s
    
-   • **数值模型**：一套描述大气运动的微分方程组，告诉你温度、气压、风速之间怎么互相影响
    

你的工作流程很简单：把今天的数据塞进模型，让模型跑 24 小时，出来的结果就是你明天的预报。

电机控制器的预测步，流程一模一样。

-   • **当前数据** = 上一时刻的状态估计 x̂ₖ₋₁：XY 轴电流 iα、iβ，转子角度 θ，转速 ω，可能还有个电压偏置
    
-   • **数值模型** = 永磁同步电机（PMSM）的电压方程和机械方程
    
-   • **预报结果** = 下一时刻的预测状态 x̂ₖ⁻
    

说白了，电机模型就是一套"电磁气象方程"。它告诉你：给定当前电流和电压，电流下一刻会怎么变；给定当前转速和转矩，转速下一刻会怎么变。

控制器每个周期都干一次这事。只是它预报的不是"明天晴不晴"，而是"50 微秒后电流会不会超调"。

## 预测步干两件事：猜状态 + 猜自己有多不确定

气象预报员在播报的时候，通常不会只说"明天 25°C"。

细心的同仁可能注意过，有些预报后面会跟一句"预报准确率 85%"，或者画一个温度区间。这意味着预报员在告诉你：**我的模型跑出来的数是 25°C，但我心里也不是百分百有底**。

这个"有没有底"，在卡尔曼滤波里叫做**协方差（Covariance）**，用大写字母 **P** 表示。

P 小，说明系统很自信："我算出来的数，误差范围就这么大，你放心用。"

P 大，说明系统心里发虚："我就这么一猜，偏差可能挺大，你悠着点。"

**预测步的核心，就是同时更新两个东西：**

1.  1. **状态预测** x̂ₖ⁻：根据模型推算下一刻的状态
    
2.  2. **协方差预测** Pₖ⁻：推算下一刻的不确定性有多大
    

这像极了气象预报的两个输出：温度预测值 + 置信区间。

## 第一件事：状态预测，让模型跑一步

咱们先来看状态预测。

电机的数学模型本质上是一组**常微分方程**。用大白话说，它描述的是"某个量此刻的变化率是多少"。

这两个方程的左边是电压，右边是电阻压降、电感压降和反电动势。

**最关键的部分是 di/dt。** 它告诉你电流此刻的变化率。知道变化率，再加上当前电流值，就能推算一小段时间后的电流。

比如，你开车时速 60 公里，加速度是 5 km/h/s。那 1 秒后你的速度大概是 65 公里/小时。这不是精确值，但方向是对的。

这就是最简单的 **前向欧拉（Forward Euler）** 积分。

不过，电机方程不是线性的——里面藏着 ω·i 的乘积项，还有随角度变化的 sin/cos。变化率本身也在变。用简单的前向欧拉，一步跨大了容易"跑偏"。

但电机控制器的工况可不是"速度慢慢变"。电流可能在几百微秒内从 0 冲到额定值，转速可能在负载突变时瞬间下跌。变化率 di/dt 本身就在剧烈变化。

这时候前向欧拉的误差会迅速累积。想象一下：你开车上山，坡度越来越陡。你按出发时的坡度估算 1 小时后海拔，肯定会低估——因为你没考虑后面坡更陡。

所以工程上常用精度更高的数值积分方法。phobia 项目里用的是**二阶 Runge-Kutta / 改进欧拉法（Heun 法）**。

思路不复杂：先按当前斜率跨完整一步，算出预测终点；再在预测终点重新算斜率；最后用起点斜率和终点斜率的平均来修正。相当于"先莽一步探探路，再回头修正"。

这和"中点法"不一样。中点法是跨半步看中场，Heun 法是先跨完整步再看终点。

误差上，前向欧拉的局部截断误差是 O(Δt²)，二阶 RK 是 O(Δt³)。控制周期减半，前向欧拉精度提 4 倍，RK 提 8 倍。对于 50~100 μs 的电流环周期，RK 的精度足够，计算量又比四阶 RK 小得多——毕竟控制器里每微秒都是钱。

## phobia 里怎么跑的？看 pm\_kalman\_solve()

咱们来看 phobia 项目里的真实代码。

`// 来源: phobia/src/phobia/pm.c:pm_kalman_solve() (commit 4058e68de0cd)   // 二阶 Runge-Kutta / 改进欧拉法（Heun 法）求解电流微分方程      static void   pm_kalman_solve(pmc_t *pm)   {    float  D0[2], D1[2];    /* 第一步：用当前状态算斜率 D0 */       pm_kalman_equation(pm, D0);    /* 先按 D0 跨完整一步，得到预测终点 */       pm->flux_X[0] += D0[0] * pm->m_dT;   // i_d 先走一步       pm->flux_X[1] += D0[1] * pm->m_dT;   // i_q 先走一步       m_rotatef(pm->flux_F, pm->flux_wS * pm->m_dT);       m_normalizef(pm->flux_F);    /* 第二步：用预测终点状态重新算斜率 D1 */       pm_kalman_equation(pm, D1);    /* 用起点和终点斜率的平均修正 */       pm->flux_X[0] += (D1[0] - D0[0]) * pm->m_dT * 0.5f;       pm->flux_X[1] += (D1[1] - D0[1]) * pm->m_dT * 0.5f;   }`

这段代码的核心逻辑就三步：

1.  1. **算初斜率 D0**：用当前电流、电压、转速，代入电压方程，算出 di/dt
    
2.  2. **全步预测**：按 D0 跨完整一步，得到预测终点状态
    
3.  3. **算终点斜率 D1**：用预测终点状态重新算 di/dt
    
4.  4. **修正最终值**：实际增量 = (D0 + D1) / 2 × Δt，精度比前向欧拉高一阶
    

`flux_X[0]` 和 `flux_X[1]` 是 d-q 轴电流（在随转子旋转的坐标系下积分，因为电压方程在这里最简洁）。`flux_F` 是转子磁链方向向量（cosθ, sinθ），每步按转速旋转一次。`m_dT` 是控制周期。

这里有个细节：phobia 的 EKF 状态向量是在 XY 静止坐标系下维护的（状态顺序为 `[iX, iY, θ, ω, bias]`），但电流积分选择了在 d-q 坐标系下进行。原因是 d-q 坐标系把旋转的坐标变换项整理成了固定的速度耦合项（ω·L·i 形式），数值积分更稳定。积分完再转回 XY 坐标系。这是工程上的常用技巧。

另外，`kalman_A[0]` 和 `kalman_A[1]` 是 XY 坐标系下的电流缓存，它们不是 EKF 的"最终状态向量"，而是供下一周期 `pm_kalman_forecast()` 使用的辅助变量。真正的状态分散在 `flux_X`（dq 电流）、`flux_F`（磁链方向）、`flux_wS`（转速）、`kalman_bias_Q`（偏置）等多个变量中。

这段代码说明一个事实：**状态预测没有什么魔法，就是数值积分**。模型告诉你变化率，积分器帮你向前推一步。

## 第二件事：协方差预测，不确定性通常变大

状态预测讲完了。但预测步还有另一半——协方差预测。

这半件事，很多初学者容易忽略。但它恰恰是卡尔曼滤波比纯模型预测更聪明的地方。

咱们回到天气预报的类比。

假设你今天的预报很准，误差范围 ±1°C。那你明天的预报误差是多少？

**通常不会比 ±1°C 更小。** 因为明天是基于今天推导的，今天的误差会传递到明天，再加上模型本身的不完美，误差大概率会累积。

五天后的预报误差可能是 ±5°C。这就是不确定性膨胀。

### 第一层：F·P·Fᵀ —— 旧的不确定性怎么传播

**F** 叫**状态转移雅可比矩阵（State Transition Jacobian）**。名字吓人，意思很简单：

> "如果当前状态估偏了一点点，下一时刻会偏多少？"

打个比方。你预测一辆车 1 秒后的位置。如果初始位置估偏了 1 米，1 秒后可能偏 1.1 米（因为速度也有误差）。F 描述的就是这个"误差放大倍数"。

在数学上，F = ∂f/∂x，即**状态方程对状态的偏导数**。它告诉你：状态向量里的每一个分量变化一点点，会对下一时刻的每个分量产生多大影响。

F·P·Fᵀ 这个操作，就是**把上一时刻的不确定性，按系统的传播规律，映射到下一时刻**。

如果系统很"稳定"（F 的元素很小），旧的不确定性不会被放大太多。如果系统很"敏感"（比如高速旋转的电机，电流对角度误差极其敏感），F 会把旧误差放大好几倍。

### 第二层：+ Q —— 模型不完美，得给自己留余地

就算上一时刻的估计完美无缺（P = 0），预测步也不能让 P 保持为零。

因为**模型本身就不完美**。

电机模型做了多少简化？定子电阻随温度变化，电感随电流饱和，磁链可能退磁，负载转矩可能突变——这些都没被模型精确描述。模型就像一张简化地图，大方向对，但小路没标。

**Q** 叫**过程噪声协方差（Process Noise Covariance）**，它量化的就是"我的模型漏掉了多少东西"。

Q 大，说明模型不太靠谱，每次预测都要给不确定性多添一把火。Q 小，说明模型很精确，不确定性主要来自旧误差的传播。

气象预报里也有对应的量：数值模型的物理近似误差、网格分辨率限制、边界条件不准确——这些统称"模式误差"。模式误差大的模型，预报置信区间就得画宽一点。

### 第三层：没有新信息，P 不会系统性地缩小

注意一个关键事实：预测步的公式里，Pₖ⁻ = F·P·Fᵀ + Q。

F·P·Fᵀ 这一项描述的是旧不确定性的"传播和变形"。F 会把某些方向的不确定性拉伸，也可能把另一些方向压缩。然后 + Q 叠加模型噪声，再给不确定性添一把火。

**没有测量带来的信息增益，P 会被 F 拉伸/压缩，并叠加 Q。工程直觉上常表现为预测后更不确定，但数学上并不保证每个元素、每条对角线或 trace 都单调增大。**

用一个标量例子来帮你建立直觉：假设你只有一个状态，F = 0.9（系统本身有衰减），Pₖ₋₁ = 4，Q = 1。那 Pₖ⁻ = 0.9² × 4 + 1 = 3.24 + 1 = 4.24。旧不确定性从 4 被压缩到 3.24，但模型噪声 Q 又把它抬到了 4.24。这个例子里总体涨了，但换一组参数完全可能不同。

如果 Q = 0（模型完美），那 Pₖ⁻ = 3.24，确实比原来小。但现实中 Q = 0 是不可能发生的——你的电机参数总会漂移，负载总会变化，ADC 总会抖。

所以这符合直觉：你没看任何新测量，只是让模型跑了一步。没有新信息进来，P 不可能因为"获得了确定性"而缩小。它只会因为模型的固有噪声和误差传播规律而变化。

## phobia 里的协方差传播：pm\_kalman\_forecast()

咱们来看 phobia 项目里协方差传播的实现。

`// 来源: phobia/src/phobia/pm.c:pm_kalman_forecast() (commit 4058e68de0cd)   // 协方差预测: P = F * P * F' + Q      static void   pm_kalman_forecast(pmc_t *pm)   {    float  *P = pm->kalman_P;        // 协方差矩阵（对称，15个独立元素）    const float  *A = pm->kalman_A;  // 辅助变量缓存    const float  *Q = pm->kalman_gain_Q;  // 过程噪声增益    // ... 省略 F 矩阵元素计算 ...    /* F * P 的中间结果缓存到 u[] */       u[0] = F[0]*P[0] + F[1]*P[1] + F[2]*P[3] + F[3]*P[6] + F[4]*P[10];       u[1] = F[0]*P[1] + F[1]*P[2] + F[2]*P[4] + F[3]*P[7] + F[4]*P[11];    // ... 共 15 个中间量 ...    /* (F*P) * F'，结果写回 P */       P[0]  = u[0]*F[0] + u[1]*F[1] + u[2]*F[2] + u[3]*F[3] + u[4]*F[4];       P[1]  = u[5]*F[0] + u[6]*F[1] + u[7]*F[2] + u[8]*F[3] + u[9]*F[4];    // ... 对称矩阵更新 ...    /* 加上过程噪声 Q */       P[0]  += Q[0] * pm->lazy_TiLq;   // iX 不确定度       P[2]  += Q[0] * pm->lazy_TiLq;   // iY 不确定度       P[5]  += Q[1] * pm->m_dT;        // θ 不确定度       P[9]  += Q[2] * pm->m_dT;        // ω 不确定度       P[14] += Q[3] * pm->m_dT;        // bias 不确定度   }`

代码里的 P 是 5×5 对称协方差矩阵，只存 15 个独立元素（下三角）。F 矩阵的物理结构在注释里写得很清楚：

    `[ F(0) F(1) F(2) F(3) F(4) ]   <- iX 对各状态的灵敏度       [ F(5) F(6) F(7) F(8) F(9) ]   <- iY 对各状态的灵敏度   F = [ 0    0    1    dT   0    ]   <- θ 的传递（角度积分转速）       [ 0    0    0    1    0    ]   <- ω 的传递（转速基本不变）       [ 0    0    0    0    1    ]   <- bias 的传递（假设慢变）`

底部三行几乎固定：角度 θ 是转速的积分（θ\_new = θ + dT·ω），转速 ω 在单个控制周期内假设基本不变，电压偏置 bias 假设变化很慢。真正复杂的是前两行——电流对角度、转速、电压偏置的耦合关系。

Q 的添加很简洁，只在对角线相关的 5 个位置加噪声。Q\[0\] 对应电流噪声，Q\[1\] 对应角度噪声，Q\[2\] 对应转速噪声，Q\[3\] 对应偏置噪声。

### F 矩阵前两行的物理意义

协方差传播代码里，最烧脑的是 F 矩阵的 10 个元素怎么算出来的。这里不展开完整推导（后续有文章详细拆解），但咱们可以挑几个关键元素看看物理意义。

**F\[0\] = ∂iX⁺/∂iX**：当前 X 轴电流变化一点点，下一时刻 X 轴电流会怎么变？

从代码里可以看到：

`F[0] = 1.f - R1 * (pm->lazy_TiLd - u[1] * pm->lazy_TiLu[0]);`

`R1` 是定子电阻 Rs，`lazy_TiLd` 是 `m_dT/Ld`（时间步长除以 d 轴电感）。如果 `Ld = Lq`（无凸极效应），`lazy_TiLu[0] = 0`，该式简化为 `F[0] = 1 - Rs·m_dT/Ld`。其中 `Rs·m_dT/Ld` 是无量纲阻尼因子；在常见采样周期下通常远小于 1，但具体量级取决于定子电阻、电感和控制周期。只要阻尼因子为正，F\[0\] 就略小于 1。物理意义是：电流变化会被电阻阻尼掉一部分，不会无限放大。

**F\[2\] = ∂iX⁺/∂θ**：当前角度估偏了一点点，对下一时刻 X 轴电流有多大影响？

`F[2] = u[6] * u[4] - u[5] * u[3] + u[7] * fC;`

这一项包含坐标旋转和反电动势的耦合。角度误差会导致 dq→XY 的坐标变换出错，进而让电流预测跑偏。源码后面还有 `+= wS * u[8] * pm->lazy_TiLu[1]` 的修正项，转速越高，这一项的整体影响越严重——这也是高速时 EKF 更难调的原因之一。

**F\[3\] = ∂iX⁺/∂ω**：转速估偏了，对电流预测有多大影响？

`F[3] = E1 * fS * pm->lazy_TiLq;`

`E1` 是永磁磁链 λ，`fS` 是 sinθ。这一项直接来自反电动势：转速误差会导致反电动势算错，进而影响电流预测。注意 F\[3\] 的主项不含 `wS`，它主要由磁链、角度和电感决定；高速下角度误差相关项（F\[2\]/F\[7\]）通常更敏感。

（以上只列了关键主项，源码后面还有凸极效应和坐标旋转的 `+=` 修正项。）

看完这几个元素，你应该有个感觉：**F 矩阵不是从天上掉下来的，每一个元素都对应着电机物理规律里的一条因果关系。**

## 雅可比矩阵 F：非线性系统的"局部地图"

状态预测和协方差预测都说完了。但有一个问题还没讲透：

> 为什么协方差传播需要 F 矩阵？为什么不能直接写 P = P + Q？

答案是：**电机模型是非线性的。**

线性系统的状态方程长这样：

A 是一个固定矩阵，不管你在什么状态，它都不变。所以误差的传播规律也固定：P = A·P·Aᵀ + Q。

但电机模型里藏着一堆非线性项：

-   • 电流和转速相乘：ω·i
    
-   • 反电动势随角度变化：λ·ω·sinθ
    
-   • 坐标旋转变换：iα = i\_d·cosθ − i\_q·sinθ
    

这些项让状态方程变成了：

f 是一个非线性函数。非线性函数没有统一的"斜率"。你在低速时的斜率和高速时完全不同。

线性系统是一条直路，坡度固定。你知道走偏 1 米会滑下去多少，这个规律到处都一样。

非线性系统是盘山公路。有的路段平缓，有的路段陡峭。你必须知道"当前在哪一段"，才能判断走偏 1 米的后果。

**雅可比矩阵 F 就是你在当前位置拍的一张"局部坡度照片"。**

它取的是 f 对 x 的偏导数，并且只在当前估计点 x̂ₖ₋₁ 处取值。这意味着 F 是**局部**的、**瞬时**的。你换了一个工作点，F 就得重新算。

这就是为什么 phobia 的 `pm_kalman_forecast()` 每周期都要重新计算 F 的 10 个元素——因为电机的电流、转速、角度每秒都在变，局部斜率也跟着变。

以上这些内容会在后续的文章里拆开细讲。在本讲中只需要记住一件事：**非线性系统的误差传播不能套用固定矩阵，必须用当前工作点的局部雅可比。**

## Q 不是越大越好：模型自信 vs 模型谦虚

预测步公式里有一个参数值得单独拿出来说：**Q**。

Q 的取值直接决定了你的滤波器性格。

Q 很大，相当于你在说："我的电机模型糙得很，温度变了、负载变了、参数漂移了，我统统没考虑。所以我每次预测都不怎么信自己，宁愿多靠测量来修正。"

如果 Q\[0\]（电流噪声）设得很大，而 `lazy_TiLq = m_dT/Lq` 这个缩放因子又不小，那预测步会把电流不确定度抬得很高。滤波器几乎完全依赖电流传感器的测量，模型预测沦为摆设。

这种滤波器**响应快**，测量一变化就跟上。但副作用是**噪声敏感**，测量里的毛刺也会被放大。

Q 很小，相当于你在说："我的模型很准，电阻电感我标定过，负载基本恒定。预测结果我很自信。"

这种滤波器**平滑**，抗测量噪声能力强。但遇到模型没考虑到的情况——比如突然加载、参数温漂——就会**反应迟钝**，甚至彻底发散。

Q 大就像是一个频繁看导航的司机，路稍有不对立刻修正，但容易被导航误导。Q 小则像是一个熟记路线的老司机，自信满满，但一旦封路就懵了。

**工程上没有绝对的好坏，只有对工况的匹配。**

## 预测步的边界：什么情况下会翻车？

预测步再聪明，也有翻车的时候。下面是几个典型场景。

### 场景一：模型和实物对不上

你用的电机模型假设 Ld = Lq（隐极电机），但实物是凸极电机（Ld ≠ Lq）。模型里的方程和实际物理规律不一致，预测步每周期都在往错误的方向推。

这时候 Q 必须给大点，让滤波器多信测量、少信模型。否则 P 会越来越小（因为模型太自信），滤波器彻底跑偏。

### 场景二：状态跳变

电机突然从空载切换到满载，转速瞬间下跌。但你的机械模型里负载转矩是慢变的，预测步没料到这一出。

这时候预测的状态和实际状态差距巨大，残差（下一篇要详细讲）会爆表。如果 Q 太小，滤波器要花好几个周期才能缓过来。

### 场景三：数值积分发散

控制周期太长（比如 500 μs 以上，具体阈值依赖电机 L/R 时间常数和最高转速），而电流变化很快。改进欧拉法虽然比前向欧拉稳，但也架不住步长太大。

症状是电流预测值越界，F 矩阵元素算出奇奇怪怪的数，P 跟着发散。

### 场景四：协方差矩阵"冻住"

有一种隐蔽的 bug：Q 设成了 0，而且 F 的特征值恰好都小于 1。这时候 P = F·P·Fᵀ，每周期都在缩小。几毫秒后 P 缩到接近零，滤波器彻底"冻住"——它认为自己已经 100% 确定，再也不接受任何测量修正。

症状是状态估计停在某个值不动，哪怕电机实际在转。检查方法是看 P 的对角线元素，如果持续单调下降且不回升，大概率是 Q 过小或 F 算错了。

## 🔧 调试 Checklist

\[ \] 状态预测后的电流值是否在合理范围（不超过母线电压能提供的极限电流）  
\[ \] 协方差矩阵 P 至少对角线元素不能为负（出现负数说明数值溢出或 bug；更严格还需检查对称性和正定性）  
\[ \] F 矩阵元素的数量级是否合理（电流自耦合、角度→电流、转速→电流、bias→电流等元素，具体量级依赖电机参数和控制周期）  
\[ \] Q 的取值是否让 P 在预测步变化、在更新步收缩（通过调试器或日志跟踪 P 的时域变化，正常应像呼吸一样涨落）  
\[ \] 控制周期是否够短（电流环通常在 50~100 μs；若周期过长，需结合电机 L/R 时间常数和最高电角速度重新评估数值积分精度 \[待核实\]）

## 调试现场：变量跟踪看哪里

P、F、`flux_X` 都是内存内部变量，普通示波器不能直接看。你需要通过**调试器断点**、**SWO/RTT 实时跟踪**、**串口日志**或**DAC 映射**来观察。下面是几个关键检查点。

### 看状态预测值

在 `pm_kalman_solve()` 返回后打断点，看 `flux_X[0]` 和 `flux_X[1]`。如果电机稳态运行，这两个值应该和上一周期接近，变化幅度通常不大（具体范围取决于电机额定电流和工况）。如果出现明显跳变，说明数值积分步长太大或电压采样有问题。

### 看协方差对角线

在 `pm_kalman_forecast()` 末尾打断点，看 `P[0]`（电流不确定度）和 `P[9]`（转速不确定度）。正常工况下，P 应该在预测步变化、在更新步收缩，像呼吸一样周期性涨落。如果 P 单调递增从不收缩，说明更新步没起作用（可能是残差计算错误或 K 为 0）。如果 P 单调递减，参考"场景四：协方差冻住"。

### 看 F 矩阵元素数量级

在 F 计算完后打断点。F\[0\] 和 F\[6\]（电流自耦合）通常在 0.9~1.0 附近（但依赖控制周期和电感参数）；F\[2\] 和 F\[7\]（角度→电流耦合）在高速时可能较大；F\[3\] 和 F\[8\]（转速→电流耦合）通常较小（具体量级取决于电机参数和转速）。如果某个元素突然跳到几十或几百，说明电流或转速采样出现了异常值。
