你刚把 sign 换成 sat，抖振小了，电机安静了不少。

但你盯着代码里的 `sat()` 函数看了三秒——两个 `if`，一个除法，中间那个硬折点怎么看怎么不顺眼。

你心想：边界层的思路是对的，但这个实现方式太糙了。要是换成 `tanh`，一条语句就搞定，处处平滑，没有折点，数学上还更漂亮。

问题来了：**`tanh` 和 `sat`，都是把硬开关变软，但它们在电机里真的一样吗？**

## 线性调光器 vs 曲线调光器

假如你去家具城买灯，发现两款调光器。

一款是线性的。旋钮从 0 拧到 100，亮度均匀变化：拧到 50 就是 50% 亮度。简单、直观、可控。

另一款是曲线的。开头拧半天，亮度几乎不变；到了中间某个位置，亮度突然跳变；最后阶段又变得迟钝。整个响应不是均匀的，而是 S 形的。

sat 函数就是线性调光器。在边界层内，输出和误差严格成正比：s = 0.3Φ 时输出 0.3，s = 0.7Φ 时输出 0.7。斜率固定，一清二楚。

Sigmoid（以 `tanh` 为代表）就是曲线调光器。它的输出是一条 S 形曲线：s = 0.3Φ 时输出约 0.29，s = 0.7Φ 时输出约 0.60，s = Φ 时输出约 0.76。同样的旋钮位置，亮度完全不同。

看出来了吗？在边界层边缘（s = Φ），sat 已经输出满格的 1.0，而 tanh 只输出 0.762——差了整整 24%。

这意味着：当误差刚好达到边界层厚度时，sat 已经恢复 sign 的满推力，而 tanh 还在"温柔"地慢慢加码。

## 导数才是区别所在

各位同仁注意一个细节：对比两个函数不能只看输出值，要看**导数**——也就是斜率，它决定了系统对误差变化的敏感度。

sat 的导数是分段常数：

-   • |s| < Φ 时：导数 = 1/Φ（固定）
    
-   • |s| ≥ Φ 时：导数 = 0（严格饱和）

关键点：**在 s = 0 处，两者的导数完全相同**——都是 1/Φ。这意味着在极小的误差范围内，sat 和 tanh 的行为几乎一样。区别只在中等误差和大误差区域才显现出来。

更反直觉的是：**tanh 的导数在自身曲线的零点附近最大**——恰恰就是抖振发生的区域。这意味着 tanh 对自身零点附近的微小噪声最敏感（注意：在 s=0 处 tanh 和 sat 的导数相同，都是 1/Φ，所以与 sat 相比并没有额外优势）。而 sat 在边界层内的导数固定为 1/Φ，行为更可预测。

## 大误差时，一个不退，一个退不干净

[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486604&idx=1&sn=f221f7e9a9ba7e4a05ca6e2daf3f474c&scene=21#wechat_redirect)咱们说过，边界层法保留了 sign 的"兜底"能力——大误差时退回 sign，满格推力。

这个"兜底"在 sat 身上是**严格的**。当 |s| ≥ Φ，sat 的输出就是 ±1，和 sign 没有区别。观测器方程里的校正项还是满格的 ±K\_slide/L\_s。

tanh 呢？它永远不会真正达到 ±1，只是无限接近。

咱们算几个具体数值：

-   • s = Φ 时，tanh(1) ≈ 0.762。校正项 = 0.762·K\_slide/L\_s，比 sat 少了 **23.8%**。
    
-   • s = 2Φ 时，tanh(2) ≈ 0.964。校正项 = 0.964·K\_slide/L\_s，比 sat 少了 **3.6%**。
    
-   • s = 3Φ 时，tanh(3) ≈ 0.995。校正项 = 0.995·K\_slide/L\_s，比 sat 少了 **0.5%**。
    

23.8% 不是小数字。当误差刚好达到边界层边缘（s = Φ）——这是系统从线性区进入"饱和区"的临界点——tanh 的推力直接打了七六折。如果你的 K\_slide 已经设到了鲁棒性下限，这 24% 的衰减意味着系统可能根本到不了滑模面。

s = 2Φ 时损失降到 3.6%，s = 3Φ 时只剩 0.5%。这说明 tanh 的推力损失集中在**边界层边缘附近**，大误差时损失反而很小。

这个过程，就好比你雇了一个保镖。sat 模式的保镖说："敌人距离我三米，我立刻全力出击。"tanh 模式的保镖说："敌人距离我三米，我出 96% 的力——还有 4% 留着以防万一。"问题是，你请保镖就是为了以防万一，那 4% 的保留在关键时刻可能就是致命的。

这就是 tanh "渐进饱和"的本质：**它永远给自己留有余地，但工程上有时候你需要的是全力以赴**。

## 零点附近的微妙差异

抖振发生在滑模面附近，也就是 s 在零点附近来回翻的时候。既然 sat 和 tanh 在 s = 0 处的导数相同，那它们在零点附近的行为应该一样吧？

近似一样，但不完全一样。

举个例子：s = 0.5Φ 时，tanh 输出 0.462，sat 输出 0.500。差值 0.038 主要来自三次项的贡献（，与 0.038 接近，再加上更高阶小量）。

这个差异的工程意义是：**在边界层内，tanh 的"有效边界层"比 sat 更厚**。因为 tanh 在 s = Φ 时只输出 0.762，要到 s ≈ 1.5Φ 才输出 0.905——相当于 sat 在 Φ 处的"饱和度"，tanh 要到 1.5Φ 才达到。

换句话说，如果你把 sat 的 Φ 和 tanh 的 Φ 设为相同的数值，tanh 的实际"等效边界层厚度"大约是 sat 的 1.5 倍。

## 频谱上谁更干净

有人选 tanh 的理由是：sat 的硬折点会在频域产生高频谐波，tanh 处处平滑，频谱更干净。

这个说法在**连续时间理论**中是对的。sat 的函数值本身连续，但在 ±Φ 处一阶导数发生跳变，会在频域引入高频分量。tanh 的 S 形曲线导数处处连续，高频谐波理论上更少。

但在**数字实现**中，情况复杂得多。

首先，tanh 的计算本身需要指数运算（），这在嵌入式 MCU 上通常用查表法或多项式近似。近似误差本身就会引入高频成分。

其次，无论是 sat 还是 tanh，控制输出都是每隔 T\_s 才更新一次的离散序列。ZOH 效应会在频域产生 sinc 包络衰减，这个衰减对所有信号都一样，tanh 理论上更干净的频谱优势可能被 ZOH 和离散采样掩盖。

最后，真正决定抖振基本量级的，不是切换函数的形状，而是控制周期 T\_s 和系统惯性 L\_s。[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486604&idx=1&sn=f221f7e9a9ba7e4a05ca6e2daf3f474c&scene=21#wechat_redirect)咱们算过，|Δs| ≈ (K/L)·T\_s。这个公式更接近硬 sign 在采样周期内的跳变量级；sat 和 tanh 进入边界层后，小信号动态更接近指数收敛。两者零点导数相同，只能说明在 s≈0 的局部区域内线性动态接近，不能推出抖振的波形和振幅完全一样。

所以频谱差异确实存在，但在实际工程中，**它的影响远小于 T\_s 和 L\_s 的影响**。如果你为了频谱纯净度换 tanh，却忽视了更根本的采样周期优化，那是舍本逐末。

## 代码里差多少

咱们把两种实现放在一起看：

`// 示意用代码，非产品级别代码：饱和函数   float sat(float s, float phi) {    if (s > phi)       return 1.0f;    if (s < -phi)      return -1.0f;    return s / phi;   }      // 示意用代码，非产品级别代码：双曲正切（Sigmoid）   // 方法 A：直接调用 math 库（需链接 libm）   float sigmoid_tanh(float s, float phi) {    return tanhf(s / phi);   }      // 方法 B：查表法（资源受限 MCU）   float sigmoid_lut(float s, float phi) {    float x = s / phi;    int idx = (int)((x + SIGMOID_MAX) * SIGMOID_SCALE);    if (idx < 0) return -1.0f;    if (idx >= SIGMOID_TABLE_SIZE) return 1.0f;    return tanh_lut[idx];   }`

`sat()` 只需要两次比较、一次除法。现代 MCU 上有硬件除法器的话，这个开销在 FOC 周期预算里几乎可以忽略。

`tanhf()` 来自 math 库，内部通常用多项式近似或 CORDIC 算法。经验上运算量可能是 `sat()` 的数倍到数十倍，具体取决于 MCU 是否有 FPU、math 库实现和编译器优化。在 20 kHz 控制频率下，如果你的 MCU 已经跑得比较满，这个额外开销可能影响 ISR 的实时性。

查表法可以省掉计算，但需要占用 Flash 存储一张查找表。以 256 点、float32 格式为例，需要 1 KB Flash。对于资源紧张的小容量 MCU，这也是一笔账。

各位同仁注意一个细节：如果为了省除法，你预计算了 `K_slide / phi`，那 `sat()` 可以进一步优化为乘法：

`float k_recip = 1.0f / phi;     // 初始化时预计算   float sat_val = s * k_recip;    // 边界层内直接用乘法`

tanh 查表法也可以预计算 `s / phi` 然后查表，但查表本身有索引计算和内存访问开销。

从代码复杂度和运算开销的角度，**sat 完胜 tanh**。这不是偏见，是算术事实。

## 三个容易掉进去的坑

**坑 1：把 tanh 的 Φ 和 sat 的 Φ 设为同一个值**

因为 tanh 在 s = Φ 时只输出 0.762，它的实际"软化范围"比 sat 更宽。如果你直接把 sat 的 Φ 值套用到 tanh 上，相当于在 s = Φ 处推力直接打了七六折，鲁棒性下降比预期严重得多。

修正方法：若想使 tanh 在 s = Φ 处达到与 sat 相近的输出水平（约 0.9+），可尝试把 Φ 调小约 30%~40% 作为起点，再按负载突变效果微调。或者换个思路，不比较 Φ，而是比较"达到 95% 饱和度的误差值"——tanh 在 s ≈ 2Φ 时达到 0.964，sat 在 s = Φ 时就达到 1.0。

**坑 2：以为 tanh 能消除抖振**

[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486604&idx=1&sn=f221f7e9a9ba7e4a05ca6e2daf3f474c&scene=21#wechat_redirect)咱们算过，|Δs| ≈ (K/L)·T\_s 是 sign 情况下的抖振估算。进入边界层后，sat 和 tanh 的小信号动态更接近指数收敛 ds/dt ≈ -(K/(Φ·L\_s))·s + d\_v/L\_s。两者零点导数相同，只能说明在 s≈0 的局部区域内线性动态接近，不能推出抖振的波形和振幅完全一样。

tanh 改变的只是抖振的**高阶形状**——方波的棱角变圆滑了，但振幅和频率的基本量级不变。如果你的目的是大幅降低抖振，换 tanh 不如降 K\_slide 或加厚边界层。

**坑 3：为了"数学优雅"牺牲调试直观性**

sat 有一个巨大的工程优势：它的行为是**分段明确的**。你可以精确知道状态在哪个区域、输出是多少、导数是多少。调试时看到 z\_a = 0.7·K\_slide，你就知道 s = 0.7Φ。

tanh 的 S 形曲线是连续的，没有明确的分界线。状态在"某个模糊的区域"里慢慢过渡。调试时你很难一眼看出当前的等效边界层厚度是多少。

在调试现场，**可预测性比优雅性重要得多**。

## 什么时候真的该考虑 tanh

说了这么多 sat 的好处，那 tanh 是不是一无是处？不是。它在特定场景下有明确的价值。

**场景 1：配合自适应律**

如果你的 SMO 同时运行了自适应律（在线调整参数），自适应律的推导可能需要 Lyapunov 函数处处可导。sat 的折点是不可导的，tanh 处处平滑，更适合这类理论框架。

**场景 2：对频谱纯度有硬性要求**

某些精密伺服应用（如半导体设备、光学平台）对电流谐波有严格的频谱约束。如果 sat 的折点谐波刚好落在禁止频段，tanh 的平滑过渡可能是必要的妥协。\[P-003\]

**场景 3：控制周期极短**

当 T\_s 极短（比如 FPGA 或高速 DSP 实现，T\_s < 10 μs）时，sat 折点的离散效应可能需要重新评估——状态穿越边界层时，系统可能来不及在一个周期内响应折点突变。此时 tanh 的连续过渡可能更自然，但需要具体验证。

但请注意：以上三个场景都是**小众需求**。对于绝大多数电机控制应用——风机、水泵、家电、一般工业伺服——sat 是更务实、更可控、更省资源的选择。

各位同仁注意第一行：**零点导数相同**。这意味着在抖振的核心区域（s ≈ 0），两者的行为几乎一样。你换 tanh，换来换去，最核心的问题——抖振——并没有质的改善。

差异主要在中等误差和大误差区域。而恰恰在这些区域，sat 的严格饱和是它的优势，不是劣势。

最终判断：**不要被"平滑"的外表迷惑。SMO 的核心价值是鲁棒性，sat 的硬折点不是缺陷，是它保留 sign 兜底能力的"保险丝"。Sigmoid 的优雅是以牺牲明确边界为代价的。**

除非你有明确的理论或频谱需求，否则**用 sat，别折腾 tanh**。

🔧 **调试 Checklist**

\[ \] 比较 sat 和 tanh 时，确认两者的 Φ 不是等价概念（tanh 的等效边界层更厚）
