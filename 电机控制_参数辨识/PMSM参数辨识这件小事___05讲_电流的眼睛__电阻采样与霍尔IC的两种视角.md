## 一、“幽灵电流”与失控的力矩

一个低压大电流的电机控制器项目（比如18V/36V平台的电动工具或电摩），用的是**两相相电流采样**（采样U相和W相，V相由`Iv = -Iu - Iw`计算得出）。在小电流下，电机运行平稳。但只要负载一上来，电流超过额定的一半，问题就来了：

1.  **莫名其妙的过流保护**：明明指令转矩没给那么大，电流环输出也正常，但硬件过流保护却频繁触发。
    
2.  **转矩脉动和噪音**：电机开始发出“嗡嗡”的异响，用扭矩传感器一看，有明显的6次谐波转矩脉动。
    
3.  **“幽灵电流”**：算法工程师在看示波器时发现，虽然Iu和Iw看起来还算平稳，但算出来的三相电流之和 `Iu+Iv+Iw` 居然不等于零，而是有一个不大不小的交流分量。
    

团队排查了很久：算法查了PI参数，硬件查了驱动芯片和MOSFET。最后发现，问题出在**电流采样**上：U相和W相的两个采样电阻，虽然标称值一样，但实际存在2%的误差。而且，它们各自运放电路的零点漂移和增益也略有不同。

正是这点“微不足道”的差异，导致计算出的V相电流完全失真，进而污染了整个dq变换。控制器以为自己给的是一个平滑的直流`Id/Iq`，实际上注入电机的是一个**带有严重谐波的畸变电流**。

**问题的答案在哪儿？**

就在我们硬件工程师的图纸上，和算法工程师的代码里。标准`IEEE Std 1812-2023`在**1.5 Instrumentation**中强调要分析“**级联仪器误差**”，而电流采样就是我们控制器里最重要、也最容易出问题的“仪器”。

今天，我们就来深入剖析各位同仁项目里遇到的两种主流的电流采样拓扑：**基于采样电阻的（分流）**和**基于霍尔传感器**的，看看它们各自给参数辨识带来了什么样的“先天优势”和“天生缺陷”。

## 二、电流采样的“两种世界观”：电阻采样 vs. 霍尔IC

### 1\. 电阻采样（分流采样）：“经济适用，但细节是魔鬼”

**工作原理**: 在母线或三相逆变器下桥臂串联一个小阻值的精密电阻，通过测量它两端的电压降 `V = I * R` 来反算电流。

**常用的拓扑**:

-   **两相相电流采样**: 测量Iu, Iw，计算Iv。
    
-   **单相直流母线电流采样**: 在直流母线负端放一个电阻，通过在PWM周期的特定时刻采样，来重建三相电流。
    

-   **优点**:
    

1.  成本低，方案成熟。
    

-   **缺点（辨识算法的噩梦之源）**:
    

1.  **共模电压干扰**: 采样电阻是浮动在高频开关的PWM电压上的，对运放的共模抑制比（CMRR）要求极高。一点点抑制不好，PWM的开关噪声就直接灌进电流信号里。
    
2.  **增益与零点不一致**: 就像开头的故事，不同相的电阻、运放、布线都存在微小差异，导致“10A”在U相和W相的ADC读数可能不一样。`Iu+Iv+Iw ≠ 0` 的“幽灵电流”大多因此而生。
    
3.  **采样窗口的“生死劫”**: 这是电阻采样（分流）方案最致命的约束。
    

-   **下桥臂电阻采样**: 只有当对应相的桥臂下管导通时，电流才流过采样电阻，你才能测。如果某相的PWM占空比太小或太大，下管导通时间会短到无法稳定采样，这个PWM周期内你的MCU就“瞎了”。
    
-   **母线电阻采样**: 虽然任何时候都能测，但电流信号上叠加了剧烈的PWM开关纹波。你必须仔细配置ADC的采样点，比如，在PWM高占空比时在PWM周期的中间点进行采样，在PWM低占空比时在PWM的OFF瞬间进行采样（麻烦不？硬件工程师省下的BOM成本，转嫁到软件工程师这里来了）。
    

### 2\. 霍尔采样（隔离式线性霍尔）：“精准昂贵，但也有自己的脾气”

**工作原理**: 电流流过导体，产生磁场，（线性）霍尔元件依据感应到的磁场强度输出一个与电流成正比的隔离电压信号。

-   **优点**:
    

1.  **电气隔离**: 安全，抗共模干扰能力强。
    
2.  **（基本上）全周期可测**: 不像下桥臂分流那样受PWM占空比限制。
    
3.  **三相独立测量**: 直接测得Iu, Iv, Iw，避免了“两相算一相”带来的误差传播。`Iu+Iv+Iw` 更接近于零。
    

-   **缺点**:
    

1.  **成本高，体积大**。
    
2.  **温漂**: 霍尔元件的零点和增益会随温度变化，虽然现代传感器都有温补，但在宽温域应用下仍不可忽视。
    
3.  **带宽与相位延迟**: 霍尔传感器本身有响应带宽，在高频注入辨识（比如代码A的HF注入法）时，它引入的**相位延迟**可能会成为一个不可忽略的误差源。如果三相的延迟不一致，同样会引入谐波。
    
4.  **磁滞和非线性**: 在大电流范围内，可能存在轻微的非线性和磁滞效应。
    

**总结一下:**

-   **电阻（分流）采样**，你看重的是它的“经济”，就必须为它的“挑剔”（时序、噪声、不一致性）付出算法补偿的代价。
    
-   **霍尔IC采样**，你看重的是它的“精准”，就必须考虑它在“温度”和“速度”（带宽/延迟）上的物理极限。
    

## 三、代码A如何与“不完美的采样”共存

现在我们看代码A中的`pm.c`和`pm_fsm.c`文件，代码A的作者显然对电阻（分流）采样的“坑”有深刻理解，并设计了一套非常精巧的应对机制。

### 核心思想：先承认“数据不可信”，再筛选“可信数据”

代码A没有天真地认为ADC上来的数据随时都能用。它引入了一个关键机制：**Clearance Zone (安全窗口)**和**Validity Flags (有效性标志)**。

代码证据就在pm.c文件中的`**pm_clearance**`**函数**

```
void pm_clearance(pmc_t *pm, int xA, int xB, int xC)
```

**代码片段解读**:

1.  `ts_clearance` 这个参数，就是定义了PWM周期末尾的一段“**禁区**”。如果PWM的脉冲边沿落在这个禁区里，就认为电流采样受到了开关振铃的干扰，不可信。
    
2.  `vsi_AF`, `vsi_BF`, `vsi_CF`这三个标志位，就是每相电流的“**健康码**”。`0`代表可信（健康），`1`代表不可信（受污染）。
    
3.  `vsi_IF` 是总的“**采样健康码**”。代码里 `vsi_AF + vsi_BF + vsi_CF < 2` 这个判断，意味着**只要有两相或更多相的电流是可信的时候，这次的总体采样才算有效**。对于两相采样的系统，这意味着两相都必须可信。
    

**这个机制的应用**: 在辨识过程中，比如 pm\_fsm.c文件中的`**pm_fsm_state_zero_drift**`**函数：**

```
v[1] = (pm->vsi_AF == 0) ? pm->fb_iA : 0.f;
```

它只在 `vsi_AF` 为0（可信）时，才使用 `fb_iA` 的值，否则就用0。这就在软件层面，把硬件带来的“坏数据”给过滤掉了。

### 校准流程：把“不一致”变成“一致”

除了过滤坏数据，代码A还试图**校准测量链本身的不一致性。**

-   **代码证据 (**`**pm_fsm.c**`**文件)**:
    

-   `PM_STATE_ZERO_DRIFT`: 测量零电流时的**零点偏置**，并修正 `scale_iA[0]`, `scale_iB[0]`, `scale_iC[0]`。
    
-   `PM_STATE_ADJUST_ON_PCB_CURRENT`: 通过给不同两相通电（例如AB通，C断），理论上`Ia`应等于`-Ib`。利用这个物理约束，去反解三相电流采样的**增益比例**，并修正 `scale_iA[1]`, `scale_iB[1]`, `scale_iC[1]`。
    

-   **它在做什么？** 它在用软件的方法，给硬件上那“2%误差的采样电阻”和“不一致的运放”，做一次“**软件拉齐**”。
    

## 四、代码B如何应对采样问题

代码B片段，对采样细节的处理没有代码A那么“外露”，但我们依然能从它的实现中看到对工程现实的考虑。

-   **中断驱动的时序保证**: `RsIdentify_ADC_Over_isr()`、`ADCEndIsrTune_POLSE_POS()` 这些函数在ADC中断中执行，本身就是一种**硬性的时序同步**，确保了采样和PWM状态的关联性。
    
-   **低通滤波与平均**: 代码中大量使用了 `FilterX` 这样的宏或函数，以及对多次采样结果进行累加平均（如`TotalI`, `TotalIL`）。
    
-   **证据 (**代码B中的`**MotorPmsmParEst.c**`**,** `**BeforeRunRsIdentify**`函数**)**:
    

```
if(gUVCoff.Number > m_Data) {
```

-   **它在做什么？** 它没有像代码A那样去“筛选”每一笔数据，而是相信通过**大量的平均**，可以把随机噪声和高频纹波的影响给“磨平”。这是一种在算力有限或时序控制不那么精细时的经典工程方法。
    
-   **对电流重建的隐含假设**: 对于单电阻母线电流采样，它必须在PWM矢量切换的间隙，精确地抓取能代表相电流的时刻。虽然代码里没直接展示，但这种拓扑的成功，本身就意味着其底层的PWM和采样时序配合得很好。
    

## 五、给工程师的行动指南

今天我们剖析了电流采样的“两种世界观”和代码中的应对之道。这对各位同仁意味着什么？

### 1\. 对硬件工程师

-   **可测试性设计**: 以后设计PCB时，多留几个测试点，能方便地用示波器同时看到PWM门极信号和电流采样运放的输出。这能帮算法同事快速定位“采样窗口”问题。
    
-   **器件选型**: 在评估运放时，除了看带宽和精度，**共模抑制比(CMRR)** 对电阻采样（分流）方案至关重要。评估霍尔IC采样时，多关注一下**相位延迟**和**温漂**数据。
    

### 2\. 对算法工程师

-   **别信裸数据**: 拿到ADC值，先别急着往FOC模块里送。先问问自己，这个数据是在PWM的哪个时刻采的？有没有经过滤波？有没有可能被污染？
    
-   **建立“数据质量”概念**: 学习代码A的 `vsi_IF` 思想。在你自己的代码里，也应该有一个变量来标记“当前这组dq电流的可信度”。在辨识时，只用“高可信度”的数据。
    
-   **母线电流采样的局限**: 如果有同仁的平台用了单电阻母线电流采样，要特别注意，在某些PWM占空比区域（比如低速或过调制），相电流是无法准确重建的。在这些区域，参数辨识算法可能需要“降级”或者暂停。
    

### 3\. 对测试工程师

-   **建立“测量链”测试用例**: 除了测电机，我们也要测“控制器自己”。设计一个用例，用高精度源给控制器注入一个已知的直流电流，看看软件报出的三相电流值是多少，`Iu+Iv+Iw`是否为零。这就是在**标定我们的“尺子”**。
    
-   **问题复现**: 当遇到类似“幽灵电流”的问题时，测试手段不应仅限于看转矩和效率。用示波器抓取**相电流波形**，并做FFT分析，看看谐波成分，往往能更快地定位问题。
    

## 六、本文小结：

各位同仁，今天我们深入了控制器的“眼睛”——电流采样系统。我们发现，这双眼睛看到的，可能是一个经过了硬件“美颜”或“扭曲”的世界。

但光看清电流还不够，控制器做出决策，依据的是**电压，**因为我们的控制器是基于**VSI（Voltage Source Inverter）**拓扑结构构建的。我们用PWM斩波母线电压，以为给电机施加了我们想要的电压，但这同样是一个美丽的“谎言”。

下一篇文章要解决的问题就是：

**“我们指令的PWM占空比，和真正作用在电机绕组端的电压，中间到底隔了多少‘坑’？死区、MOSFET的导通压降、二极管的续流压降，这些‘看不见’的电压损失，是如何神不知鬼不觉地‘偷走’我们的转矩，并让我们的参数辨识结果产生系统性偏差的？我们的代码A和代码B，又是如何尝试去戳穿这些‘电压的谎言’的？”**

下一讲，我们将聚焦于**电压模型与死区补偿**，这是从“能转”到“精控”必须跨过的一道坎。
