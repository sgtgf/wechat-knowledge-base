你刚把 sign 函数接进观测器，电流环跑起来。你把内部变量通过 DAC 或调试上位机导出来，在示波器上抓了一条波形。

通道一接的是 `z_a`——α 轴 sign 切换项的输出。屏幕上的波形在 `+K_slide` 和 `-K_slide` 之间疯狂翻折，最严重几乎每个控制周期都翻转，满屏碎屑。你换到通道二，接的是 `e_alpha_est`——LPF 之后的反电动势估计——居然是一条光滑的正弦波，幅值跟理论 BEMF 只差几个百分点。

你盯着这两条波形看了半分钟，脑子里只有一个问题：

**那条方波，是怎么变成这条正弦波的？**

这就是等效控制要回答的事。sign 的粗暴切换不是缺陷，它是一个编码器。咱们这一篇，专门聊聊这串方波里的"密文"是怎么写进去的，以及低通滤波器怎么把它破译出来。

## PWM 调光：人眼是怎么从闪烁里看出亮度的

咱们先离开电机，聊一个你天天见的东西。

你手机上的屏幕背光，本质上是一堆 LED 在快速开关。假设开关频率是 240 Hz，人眼根本分辨不出单次闪烁。但你调亮度的时候，屏幕确实在变暗——因为人眼不是看"每一次亮灭"，而是看**一段时间内的平均亮度**。

这个平均值怎么来的？

LED 亮的时长占总周期的比例，叫**占空比**。占空比 80%，平均亮度就是最大亮度的 80%；占空比 20%，平均亮度就是 20%。PWM 控制器通过改变占空比，把连续变化的亮度指令"编码"成了一串高频方波。人眼的视觉暂留效应相当于一个低通滤波器，把高频方波滤掉，只留下缓慢变化的平均亮度。

回到咱们的观测器。

sign 函数的输出 `z = K_slide * sign(s)`，本质上也是一串高频方波。只不过这串方波的**等效占空比（正半周时间占比）不是人为设定的**，而是由系统本身的动态决定的——具体来说，是由反电动势的大小和方向决定的。

当系统进入滑模面（`s ≈ 0`）之后，sign 在 `+K_slide` 和 `-K_slide` 之间高频翻转。翻转的时间比例刚好使得：

> **正半周的面积减去负半周的面积， 平均化输出之后，恰好等于反电动势。**

这就是等效控制的核心直觉。sign 不是缺陷，它是一个**编码器**——把连续的反电动势信号，编码成了高频方波的等效占空比。咱们的任务，只是把这串方波解码回来。

**注意**：上面这段话描述的是**数字实现中的工程直觉**。在连续滑模理论里，等效控制有更严格的数学定义，咱们马上聊。

### 一个关键前提：增益必须够大

等效控制 `z_eq = e` 成立的前提是 **`|e| < K_slide`**。

如果反电动势的幅值超过了切换增益（比如电机高速运行，BEMF 达到 40 V，但 `K_slide` 只设了 30 V），sign 根本无法在平均意义上"抵消"这么大的反电动势。系统要么到达不了滑模面，要么在滑模面附近剧烈震荡但始终收敛不了。

所以工程上的经验起点是：`K_slide` 可取额定转速下最大反电动势的 **1.5~2 倍** 作为初始值，但最终需按实机噪声、采样、参数误差和边界层调试验证。裕量不足是等效控制提取失败的最常见根因之一。

这里有个工程前提必须满足：`α << 1`。一般取 `α = 0.05 ~ 0.2`，对应 `f_c / f_s ≈ 1/126 ~ 1/31`（由 `α = 2π·f_c·T_s = 2π·f_c/f_s` 推算）。

`α = 0.05 ~ 0.2` 是小带宽近似和强平滑的经验区。`α` 增大时，平滑能力下降、纹波漏过更多；`α` 接近或超过 1 时，前向 Euler 近似明显变粗；`α > 2` 时系统不稳定。这就像你追着目标跑，步幅越来越大，跟踪精度越来越差。

### 截止频率该设多少

这是设计 LPF 时最让人头疼的权衡过程。

**滤得太轻**（`f_c` 太高）：

-   • 高频抖振漏过去，反电动势估计带毛刺
    
-   • 位置估计噪声大，低速抖动
    

**滤得太狠**（`f_c` 太低）：

-   • 反电动势的动态变化跟不上，相位滞后严重
    
-   • 高速时角度估计拖后腿，电流解耦出错
    

经验起点是把截止频率设在**最高电频率的 2~5 倍**。但这个范围内部还有讲究：

-   • **若后续直接用 `atan2` 提取角度**：建议取 **5 倍以上**，把相位滞后控制在 `arctan(1/5) ≈ 11.3°` 以内。atan2 对相位误差极其敏感，11° 的偏差在 FOC 里已经算大了。
    
-   • **若后续用 PLL 跟踪角度**：2~3 倍也可以作为起点。PLL 是闭环跟踪器，可平滑跟踪输入相位并配合相位补偿/标定减小稳态误差，但 LPF 的滞后仍需在设计阶段显式约束。
    

假设电机最高转速 6000 rpm，极对数 4，最高电频率就是 `6000/60 × 4 = 400 Hz`。那么：

-   • atan2 方案：`f_c ≥ 2000 Hz`
    
-   • PLL 方案：`f_c = 800 ~ 1200 Hz`
    

实际调试时，你要把 `e_est` 通过 DAC 或日志导出来观察：

-   • 如果波形"毛刺多"但形状大致正确 → `f_c` 可以往下调
    
-   • 如果波形"太圆"，峰值比实际 BEMF 明显偏低 → `f_c` 太低了，相位滞后严重，需要往上调

### 延迟能补吗

能，但各有代价。

**方案一：相位超前补偿**  
在 LPF 后面串一个一阶超前环节，抵消部分滞后。但超前环节会放大高频噪声，补偿深度有限。工程上很少单独用，通常跟 PLL 配合。

**方案二：PLL 代替反正切**  
按坐标约定用 `atan2` 从 `e_α/e_β` 提取角度，并做必要相位补偿，对 LPF 的相位误差极其敏感。PLL 是一个闭环跟踪器，可平滑跟踪输入相位并配合相位补偿/标定减小误差，但 LPF 的滞后仍需在设计阶段显式约束。咱们后期会专门开系列文章聊 PLL。

**方案三：不用 LPF，改用 sigmoid**  
参考文献 S-002 里的 Kim 等人直接用 sigmoid 函数替代 signum，从根本上消除了高频抖振，省掉了 LPF，也就省掉了相位延迟。但 sigmoid 的响应速度比 sign 慢，低速跟踪精度会下降。这是咱们后续要详聊的话题，这里先埋个伏笔。

## 数字实现里的采样效应

### 一个周期内 sign 可能不翻转

在数字控制器里，sign 的评估是离散的——每个控制周期采样一次，输出要么 `+K_slide`，要么 `-K_slide`。如果在一个 `T_s` 内电流误差 `s` 没有变号，那这一个周期里 sign 就不翻转。

这意味着：单个周期的输出**不等于**等效控制。等效控制是**多个周期加权平均**之后的结果。所以 LPF 的截止频率不能设得太高——至少得让截止频率对应的周期覆盖几十个控制周期，否则平均效应还没累积起来，滤波器就已经"跟"上了噪声。

经验上，LPF 的截止频率应该远低于控制频率。例如控制频率 20 kHz，`α = 0.1` 对应 `f_c ≈ 318 Hz`，截止频率对应的周期 `1/f_c` 约包含 63 个控制周期，足够让 sign 的翻转统计特性稳定下来。若电机电频率较高，需要把 `f_c` 提得更高（如 1~2 kHz），此时 `α` 会增大，平滑能力下降、纹波漏过更多。

### 高频纹波抑制

sign 的翻转频率最高可以达到控制频率的一半（Nyquist 极限）。如果 `f_c` 设得太高，LPF 没有把高频分量滤干净，这些高频纹波会残留到 `e_est` 中，造成反电动势估计的伪噪声。

所以 LPF 在等效控制提取中的角色，不只是"平滑"，它还**抑制接近 Nyquist 的离散高频纹波**。`f_c` 的选择要在"跟踪动态"和"抑制纹波"之间找平衡——这就是为什么工程上通常把 `f_c` 设在控制频率的 `1/100 ~ 1/30` 附近（对应 `α = 0.05 ~ 0.2`），同时需满足 `f_c` 高于最高电频率的 2~5 倍。若两者冲突（如高速电机），优先保证 `f_c > 2f_e`，接受 `α` 增大带来的纹波抑制变弱和离散近似误差增大。

### alpha 和 T\_s 的耦合

`α = ω_c · T_s = 2πf_c · T_s`。这个公式里有三个变量，但通常 `f_c` 是由电机参数决定的，真正在代码里写的是 `alpha`。

你把代码从 10 kHz 平台移植到 20 kHz 平台，`T_s` 从 100 μs 变成 50 μs。如果 `alpha` 还是原来的 `0.1`，实际 `f_c = alpha / (2π·T_s)` 就从 `159 Hz` 变成了 `318 Hz`，LPF 带宽翻倍，抖振全漏进来了。

**正确做法**：`alpha` 必须根据新的 `T_s` 重新计算。或者干脆在代码里写成 `alpha = (2.0f * PI * fc) * T_s`，让编译器在初始化时帮你算。更稳的做法是把 `f_c` 和 `T_s` 都做成可配置参数，用脚本或宏自动推导 `alpha`。

以下代码为示意用的伪代码，展示了等效控制提取的核心逻辑，不对应特定开源项目源码：

`// 观测器主循环（每 T_s 执行一次）   // alpha = wc * T_s = 2*pi*fc * T_s，需满足 alpha << 1      // 1. 电流误差（滑模面）   float s_a = i_alpha_est - i_alpha_meas;  // α轴误差，单位 A   float s_b = i_beta_est  - i_beta_meas;   // β轴误差，单位 A      // 2. sign 切换项（高频方波，±K_slide）   float z_a = K_slide * (s_a >= 0.0f ? 1.0f : -1.0f);  // 单位 V   float z_b = K_slide * (s_b >= 0.0f ? 1.0f : -1.0f);  // 单位 V      // 3. LPF 提取等效控制（反电动势估计）   // 一阶 IIR（指数平滑），alpha << 1 时等价于前向 Euler   // y[k] = y[k-1] + alpha * (u[k] - y[k-1])   e_alpha_est += alpha * (z_a - e_alpha_est);  // 单位 V   e_beta_est  += alpha * (z_b - e_beta_est);   // 单位 V      // 4. 等效控制提取完成，e_alpha_est/e_beta_est 即为反电动势估计`

注意第 3 步的累加形式：`e += alpha * (z - e)`。这是递推式 LPF 的等价写法，避免了临时变量，也更直观——每次把输出往输入方向拉一步，步长由 `alpha` 控制。

### AN1078 中的等效控制提取

Microchip AN1078 的 SMO 实现中，等效控制提取采用了边界层内的线性化近似。以下为根据 AN1078 逻辑改写的示意用伪代码，非逐行源码摘录：

`// 来源: Microchip AN1078, Sensorless FOC of PMSM   // 以下代码为示意用伪代码，非逐行源码摘录   // 边界层内：z = (K_slide / MaxSMCError) * Error   // 边界层外：z = K_slide * sign(Error)      if (fabsf(Error) <= MaxSMCError) {       Z = (K_slide / MaxSMCError) * Error;  // 线性区，连续输出   } else {       Z = K_slide * ((Error >= 0.0f) ? 1.0f : -1.0f);  // 饱和区，硬切换   }      // 修正电流估计（量纲转换：G = T_s / L，单位 s/H = A/V）   i_est = i_est - G * Z;      // AN1078 中对 Z 做两级一阶 LPF 后得到反电动势估计   // 边界层降低了硬切换抖振，但 Z 仍需经 LPF 滤波和相位补偿后才作为 BEMF 估计`

在 AN1078 的框架里，边界层降低了硬切换抖振，但 `Z` 仍需经后续 LPF 滤波和相位补偿后才作为 BEMF 估计。经典 SMO 的工程实现通常保留独立的 sign 和 LPF，因为分开调参更灵活——`K_slide` 管到达速度，`f_c` 管平滑度，两个旋钮互不干扰。

## 调试技巧与常见坑

### 示波器看哪里

以下变量为 MCU 内部量，需通过 DAC、PWM+RC、调试上位机、RTT/SWO 或导出日志后在示波器/上位机上观察。

**第一步：确认系统进了滑模面**

看 `s_a`（电流误差）。正常应该在零附近高频震荡，峰峰值不超过额定电流的 5~10%。如果 `s_a` 长期偏离零（比如稳定在 +2 A），说明 `K_slide` 太小，系统根本没到滑模面，等效控制无从谈起。

**第二步：看 `z_a` 的翻转模式**

正常应该在 `±K_slide` 之间高频翻转。如果长时间停留在单侧，优先检查 `K_slide` 是否不够、模型参数（`R̂_s`、`L̂_s`）是否偏差过大、电流采样是否有零漂、电压重构是否有误差、死区/管压降补偿是否到位。`f_c` 太低主要表现是 `e_est` 滞后，不会直接导致 `z_a` 单侧停留。

**第三步：看 `e_alpha_est` 的波形质量**

正常应该是光滑的正弦波，幅值接近理论 BEMF（`λ_f · ω`）。把两个通道叠在一起对比：

-   • **波形"毛刺多"**：`f_c` 太高，高频抖振没滤干净。往下调 `f_c`，或减小 `K_slide`。
    
-   • **波形"太圆"、峰值明显偏低**：`f_c` 太低，相位滞后 + 幅值衰减严重。往上调 `f_c`。
    
-   • **波形形状对但相位偏**：LPF 相位延迟。如果偏差小于 10°，可配合 PLL 的相位补偿/标定处理；如果大于 20°，先调 `f_c`。
    

**第四步：对比幅值**

`z_a` 的峰峰值是 `2*K_slide`，而 `e_alpha_est` 的峰峰值应该接近 `λ_f · ω`。如果 `e_alpha_est` 的幅值远小于理论值，检查：

-   • `f_c` 是否过低（幅值被 LPF 衰减了）
    
-   • 观测器模型中的电阻/电感参数是否偏差过大
    
-   • `K_slide` 是否小于实际 BEMF（等效控制根本不成立）
    

### 常见坑

**坑一：alpha 忘记跟着控制频率变**

你把代码从 10 kHz 平台移植到 20 kHz 平台，`T_s` 从 100 μs 变成 50 μs。如果 `alpha` 还是原来的 `0.1`，实际 `ω_c = alpha / T_s` 就从 `1000 rad/s`（`f_c ≈ 159 Hz`）变成了 `2000 rad/s`（`f_c ≈ 318 Hz`），LPF 带宽翻倍，抖振全漏进来了。

**正确做法**：`alpha` 必须根据新的 `T_s` 重新计算。推荐在代码里显式写成 `alpha = (2.0f * PI * fc) * T_s`。

**坑二：把 LPF 当万能药，盲目压低 f\_c**

看到 `e_est` 有噪声，第一反应是"把 `f_c` 再调低一半"。但如果根本原因是 `K_slide` 选得太大，sign 的翻转幅度本来就超标，你再怎么滤也只是把大抖振变成小抖振，跟踪延迟反而更大了。

**正确做法**：先确认 `s` 是否在零附近震荡。如果 `s` 偏零很远，说明还没进滑模面，先调 `K_slide`；如果 `s` 在零附近但 `z` 的翻转幅度太大，再考虑降低 `K_slide` 或加边界层。

**坑三：忘了等效控制本身就是反电动势**

有些同仁在代码里写完 LPF 之后，又乘了一个莫名其妙的增益系数，以为"等效控制只是反电动势的一部分"。不是的。在理想滑模理论下，**等效控制等于反电动势**；实际代码里的 LPF 输出是带滤波动态的 BEMF 估计，不应随意再乘增益。如果你发现 `e_est` 的幅值跟理论 BEMF 不符，应先检查参数（`R_s`, `L_s`）、滤波器设计和相位/幅值补偿，而不是等效控制本身。

## 等效控制提取的替代方案

一阶 LPF + sign 是经典组合，但不是唯一选择。工程上还有几条路：

**边界层法（AN1078）**  
边界层把 sign 在零附近线性化，降低了硬切换抖振，但 `Z` 仍需经 LPF 滤波和相位补偿后才作为 BEMF 估计。边界层厚度 `MaxSMCError` 跟 LPF 截止频率不是一回事——它管的是"什么时候开始硬切换"，而不是"切换后怎么平滑"。调 `MaxSMCError` 和调 `f_c` 是两把不同的螺丝刀。

**Sigmoid 替代 signum（S-002）**  
Kim 等人用 sigmoid 函数 `H(x) = 2/(1+exp(-a·x)) - 1` 替代 sign，从根本上消除了抖振，无需 LPF。但 sigmoid 的斜率 `a` 决定了响应速度：斜率太大近似于 sign，抖振就又回来了；斜率太小响应慢，动态跟踪差。而且 sigmoid 的计算量比 sign 大（指数函数），在资源紧张的 MCU 上要考虑周期预算。

**二阶 LPF / Butterworth**  
理论上二阶 LPF 的滚降更陡，可以更好地分离信号和噪声。但二阶 LPF 的相位非线性更严重，在截止频率附近相位变化剧烈，对反电动势的相位一致性破坏更大。工程上 SMO 很少用二阶 LPF，一阶 IIR 已经够用。

## 到目前为止的完整链路

咱们把 [第12讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486565&idx=1&sn=8c8f378e0a60412da1a4661b7c1ad3a1&scene=21#wechat_redirect)、[第13讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486570&idx=1&sn=07b447f52042781a94d452b8c9503132&scene=21#wechat_redirect)、本讲串起来，看看 SMO 是怎么一步一步把反电动势"算"出来的：

1.  1. **滑模面**（[第12讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486565&idx=1&sn=8c8f378e0a60412da1a4661b7c1ad3a1&scene=21#wechat_redirect)）定义了"往哪推"——`s = i_est - i_meas`，误差空间里的那条沟槽；
    
2.  2. **sign 函数**（[第13讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486570&idx=1&sn=07b447f52042781a94d452b8c9503132&scene=21#wechat_redirect)）提供了"无限增益的推力"——要么全力往左推，要么全力往右推，没有中间态；
    
3.  3. **等效控制**（本讲）从推力中提取出了反电动势——高频方波的平均值恰好等于 BEMF，LPF 负责解码。
    

三个环节缺一不可。没有滑模面，sign 是无头苍蝇；没有 sign，等效控制没有高频载体可以编码；在经典 sign + LPF 的工程路径里，没有滤波/平均环节，就无法从高频切换项中得到可用的 BEMF 估计。

说白了，观测器不是魔法，它只是把电机方程倒过来用，再用 sign 的开关逻辑强行收敛而已。等效控制 `z_eq` 就是那个收敛之后自然浮现出来的副产品——它刚好等于反电动势，因为系统方程要求它必须等于反电动势。

## 🔧 调试 Checklist

\[ \] `s_a` 是否在零附近高频震荡？长期偏离零说明 K\_slide 太小，系统未进入滑模面  
\[ \] `K_slide` 是否取额定转速下最大反电动势幅值的 1.5~2 倍作为初始值？裕量不足会导致等效控制无法成立，最终需按实机调试  
\[ \] LPF 截止频率是否高于目标最高电频率的 2 倍以上？若用 atan2 直接提取角度，建议 5 倍以上  
\[ \] `α = ω_c · T_s` 是否在合适范围？`α` 过小→跟踪慢；`α` 过大→纹波漏过多、Euler 近似变粗；`α > 2` 不稳定  
\[ \] 移植代码时是否根据新的控制周期 `T_s` 重新计算了 `alpha`？  
\[ \] `e_alpha_est` 的幅值是否接近理论 BEMF（`λ_f · ω`）？幅值偏低说明 LPF 太狠或参数有误  
\[ \] 如果用了 AN1078 边界层，`Z` 是否经 LPF 滤波和相位补偿后才作为反电势估计？
