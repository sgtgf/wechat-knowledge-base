## 一、“那笔算不清的账”

硬件工程师老王设计了一块新的驱动板，为了散热和成本，他用了一种新的MOSFET。算法工程师小陈拿来做Rs辨识，用的是我们第13讲里讲过的“[两点法](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247485081&idx=1&sn=4c4bd5c41a80b43a62f93caa99bff375&scene=21#wechat_redirect)”：

1.  给个小电压U1，测得电流I1。
    
2.  给个大电压U2，测得电流I2。
    
3.  Rs = (U2 - U1) / (I2 - I1)
    

结果小陈他发现，每次辨识出的Rs值都不稳定，而且总感觉偏大。更奇怪的是，当他把辨识出的Rs、Ld、Lq、ψm都用到能量守恒模型里去估算电机损耗时，发现**“账总是对不上”**：控制器报告的输入电功率，减去所有已知的电磁损耗（铜耗、铁耗）后，剩下的机械功率，和测功机上测到的实际输出机械功率，总有一个不大不小的差额。

**这笔“算不清的账”是哪里来的？**

经过一番艰苦的排查后发现，老王新换的MOSFET，虽然导通电阻很低，但它的**开关时间（上升/下降沿）和体二极管的反向恢复特性**，与之前用的型号有细微差别。这导致了**死区（Dead-time）**期间的电压损失变得和以前不一样了。

小陈的`Rs=(U2 - U1)/(I2 - I1)`公式，虽然通过两点法消除了**固定**的电压偏置，但它没能处理好这个**随工况变化的、更复杂的非线性电压损失**。这笔“糊涂账”，最终都“摊派”到了Rs的头上，让Rs的辨识结果背了锅。

**问题的解决方案在哪儿？**

就在我们今天要深入剖析的**代码B**的Rs辨识流程里：`BeforeRunRsIdentify()`。

代码B的作者，作为一个“实用主义工程师”，他没有像代码A那样去建立复杂的[电压补偿模型](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247485081&idx=1&sn=4c4bd5c41a80b43a62f93caa99bff375&scene=21#wechat_redirect)。他用了一种更直接、更“接地气”的方法：**我不管中间过程多复杂，我只关心结果。我直接用一个简单的PI控制器，把PWM的占空比“拧”到一个能让电流稳定在我想要的目标值的状态，然后我再来算总账。**

今天，我们就来逐行拆解这套“拧水龙头”式的辨识方法，看看它是如何用一个简单的闭环，来巧妙地绕开复杂的[非线性电压建模](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247485081&idx=1&sn=4c4bd5c41a80b43a62f93caa99bff375&scene=21#wechat_redirect)，并最终得到一个相对可用的Rs值的。

## 二、代码B的Rs辨识哲学：不建模，只“凑”结果

在深入代码之前，我们先理解一下代码B的核心思想。

面对“[电压的谎言](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247485015&idx=1&sn=89ace6f66ffe529b7454c3aff075e026&scene=21#wechat_redirect)”（死区、压降等），代码A的思路是“**[建模补偿](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247485081&idx=1&sn=4c4bd5c41a80b43a62f93caa99bff375&scene=21#wechat_redirect)”**：我先想办法把这个谎言的模型建出来（`dcu_deadband`），然后在每次计算电压时都做补偿。

而代码B的思路是**“闭环修正”**：我不知道这个谎言具体是什么样，但我有一个目标（比如，我想要10A的直流电流）。于是我用一个PI控制器，不断地调整我的指令（PWM占空比），直到我实际测到的电流稳定在10A为止。

**PI控制器就像一个自动“拧水龙头”的机器人：**

-   水流小了（电流<目标），它就多拧开一点（增大占空比）。
    
-   水流大了（电流>目标），它就关小一点（减小占空比）。
    

**最终的结果是：**当电流稳定在10A时，此时的那个**稳定下来的占空比**，就已经**自动地、隐含地**把所有的非线性电压损失都“补偿”进去了。它就是那个能让电机在所有“中间商”盘剥之后，还能“实收”10A电流的“出厂价”。

有了这个“包含了补偿的占空比”，再结合母线电压，我们就能算出一个更接近真实的、作用在电机等效电阻上的电压。

## 三、BeforeRunRsIdentify() / RsIdentify\_ADC\_Over\_isr() / BeforeRunRsIdentifyICal() 逐行走读

`**1. BeforeRunRsIdentify()**`**: “导演”喊“开拍”**

```
void BeforeRunRsIdentify(void)
```

不知道各位同仁发现没有，这个函数，但它居然不直接读ADC的值！

它就像是一位**导演**（状态机），负责发号施令：

-   Step 1: 准备！
    
-   Step 2: 低电流，给我稳住！
    
-   Step 3: 高电流，给我冲！
    
-   Step 4: 算账！
    

真正的脏活累活（采样、累加、闭环调节），都扔给了那个被调用的中断函数 RsIdentify\_ADC\_Over\_isr 去做。

这就是**控制平面与数据平面**分离的设计哲学。主循环只管流程控制（低频），中断只管数据执行（高频）。这样设计，代码逻辑清晰，实时性极强。代码里至少藏着三个硬核知识点，还有一个只有被坑过的工程师才懂的“彩蛋”。

-   **硬核知识点一：如何消灭“过路费”？（两点法辨识）**
    

同仁们看代码里最核心的这一句：

```
m_ULong3 = m_ULong2 - m_ULong1; // 电压差
```

这就奇怪了，为什么不算一次 **U/I** 就完事，非要算两个点（`TotalI` 和 `TotalIL`），然后求**斜率**_△U/△I_ 呢？

因为变频器里的开关管（IGBT或MOSFET）不是理想开关。电流流过它，它要收“过路费”，也就是**管压降**（_Vdrop_），通常是0.7V到2V左右。

如果你只测一点：

算出来的 _Rs_ 会比真值大很多，尤其是在低压电机上，误差能到20%！

但是，如果我们测两个点：

![](https://mmbiz.qpic.cn/mmbiz_png/Z8Iha3NiaCRFQibPP80ZIiak0uHBFCwrT25gaxlxBvkJMrZrlgbdaceAOtia0Y0icjJagziaCGHlyJWEhBMt9Bpoq9eg/640?wx_fmt=png&from=appmsg)

两式相减，_Vdrop_ 这个“过路费”就被减掉了！

![](https://mmbiz.qpic.cn/mmbiz_png/Z8Iha3NiaCRFQibPP80ZIiak0uHBFCwrT25jY9Llf539nZbRDtiawrQVmFOZwiaaDbo2vmvTJnfSKDhiazxibthO0JXgA/640?wx_fmt=png&from=appmsg)

**这就是代码里**`Case 4`**拼命在做减法的物理本质。**代码B的作者非常清楚，硬件是不完美的，软件必须通过数学手段来“提纯”物理参数。

-   **硬核知识点二：消失的时间去哪了？（死区补偿）**
    

再看这行不起眼的代码：

```
m_UData1 = gUVCoff.TotalComperL - m_UData7; // m_UData7 是死区时间
```

这里有个大坑。DSP发出的PWM波形，假设占空比是50%，到了电机端，实际得到的电压并没有50%。为什么？因为为了防止上下桥臂直通炸机，我们必须插入**死区时间（Dead Time）**。

这就好比你雇个人干活，说好干8小时，但他中间必须要休息半小时吃饭。你发出的指令是“导通T时间”，实际导通只有 _T_ - _Tdead_。

如果不把这个死区时间减掉，你算出来的电压就会偏大，算出来的电阻就会偏大。这段代码在 `Case 4` 里，极其精准地把 `gDeadBand`（死区）从累计时间里扣除了。这说明什么？说明写代码B的作者**对功率器件的物理特性了如指掌**。

-   **硬核知识点三：定点数的“移位魔法”**
    

代码里满屏的 `>>7`, `<<11`, `*10`，看起来是不是很晕？

```
m_ULong1 = ((Ullong)m_UData1 * m_UData2)>>7;
```

这是嵌入式高手的基本功——**定点运算（Q格式）**。

在代码B构建的这套电机控制系统里，电压单位是0.1V，电流是0.01A，时间是计数器值。要把它们凑在一起算出“欧姆”，量纲必须对齐。

-   那个 `*10` 不是随便乘的，是为了补齐电压（1位小数）和电流（2位小数）之间的数量级差异。
    
-   那些左移右移，是在保证精度不丢失（不被截断）的前提下，防止数据溢出（Overflow）。
    

这就像是在钢丝上跳舞，多移一位精度没了，少移一位数据爆了。这段代码的移位逻辑非常老练，显然是经过无数次调试验证过的“黄金比例”。

最后，要讲一个代码里只有老鸟才懂的“**彩蛋**”，也是一个很有意思的细节：

```
if(gInvInfo.InvTypeApply > 18) // 37Kw以上增加定子电阻辨识时间
```

为什么要区分 37kW？

因为大电机和小电机，脾气是不一样的！

-   **小电机**（几kW），电阻大，电感小，电流响应快，“嗖”的一下就稳了。
    
-   **大电机**（几百kW），电感巨大，给它通个电，电流爬升非常慢（ _L/R_ 时间常数大）。
    

如果你用小电机的等待时间去测大电机，电流还没走稳你就采样了，算出来的电阻绝对是错的。

所以，代码里专门加了这个判断：**大电机，多等一倍的时间（1024 vs 512）**。

这行代码背后，不是数学公式，而是**现场调试的血泪经验。**

上一部分内容，我们共同学习了只会发号施令的“总导演” `BeforeRunRsIdentify`。这一部分我们来扒一扒真正干脏活、累活的两个“特技演员”：`RsIdentify_ADC_Over_isr`（中断处理）和 `BeforeRunRsIdentifyICal`（闭环计算）。

各位同仁别看这两个函数代码不长，但注释可以写得很长，因为它们展示了嵌入式控制中最核心的两个素质：**对时间的极致掌控**和**对物理世界的妥协**。

如果说上一个函数是在**运筹帷幄**，那这两个函数就是在**贴身肉搏**。

-   **硬核知识点一：为什么要在中断里“偷懒”？**
    

看 `RsIdentify_ADC_Over_isr` 的第一句：

```
if(EPwm1Regs.TBSTS.bit.CTRDIR == 1)  // 上升沿
```

这行代码直接决定了控制系统的**采样率**。

DSP 的 PWM 计数器通常被设置成“增减计数模式”（三角波），一个周期内，计数器会先向上数到顶（CTRDIR=1），再向下数到底（CTRDIR=0）。

这意味着，如果不加这行代码，一个 PWM 周期会进两次中断。

但是，对于“定子电阻辨识”这种直流实验，我们需要那么高的频率吗？不需要！

加上这句 `return`，就像是告诉 CPU：“兄弟，上坡的时候你歇着，下坡到底了再干活。”

这把控制频率**减半**了。这么做有两个极大的好处：

1.  **避开开关噪声：**PWM 的开关动作通常发生在计数的顶点或底点附近，只在单边采样可以避开 IGBT 或 MOSFET 开关瞬间的振铃干扰。
    
2.  **节省算力：**电阻辨识是热学和电化学级别的慢过程，不需要微秒级的响应，省下来的 CPU 算力可以去干点别的。
    

-   **硬核知识点二：不是 PID 的“PID” （砰砰控制与迟滞比较）**
    

各位同仁看 `BeforeRunRsIdentifyICal` 函数，它是如何调节电流的？

很多同仁以为会自动套用 PID 公式。错！这里用的是更原始、但更鲁棒的**砰砰控制（Bang-Bang Control）**变种。

看这段逻辑：

```
gRsIdentifyPID.Deta = Target - Actual; // 误差
```

**这就是设计哲学：** 在参数辨识这种静态场景下，PID 的积分项（I）容易饱和，微分项（D）容易引入噪声。工程师选择了一种**“步进逼近”**的策略：

-   你小了？我就直接给你加一档。
    
-   你大了？我就直接给你减一档。
    

而且这里有一个非常骚的操作：**迟滞区间（Hysteresis）**。

注意看 `else if` 里的条件 `误差 < -m_Data`（也就是 -500）。这意味着，如果电流只比目标大一点点（比如大 100），程序是**不动作**的！只有大得离谱了（超过 500），才开始回调。这避免了 PWM 占空比在目标值附近疯狂抖动（Chattering），保证了系统的稳定性。

-   **硬核知识点三：稳态判据——“只有不动，才算有效”**
    

这段代码设计简直是教科书级别的。请看：

```
if(gUVCoff.Number == 0) 
```

而 `gUVCoff.Number` 什么时候会被清零呢？

**只要 PWM 占空比（Comper）发生了变化，**`**Number**`**就立马清零！**

这说明了什么？说明代码B的作者只**要稳态数据，不要动态数据**。

-   只要我在调节 PWM，说明电流还不稳，这时候采样的电压电流数据统统作废（Reset）。
    
-   只有当误差足够小，PWM 占空比不再调整了，电路进入稳态了，我才开始累加数据（Accumulate）。
    

这就是为什么上层函数算出来的电阻那么准。因为它过滤掉了所有调整过程中的波动，只取了最纯净的“静止画面”。

-   **只有被现场坑过的工程师才懂的“彩蛋”**
    

**彩蛋一：大车小车的区别对待**

```
if(gInvInfo.InvTypeApply > 16) // 大机型
```

为什么要分机型？

-   **小功率变频器**带的小电机，电阻大，给一点电压电流就上来了，所以步长可以大一点（+2），为了快。
    
-   **大功率变频器**（>16型），对应的电机是巨无霸，电感极大，电流惯性大，如果你步子迈大了（+2），电流会直接冲过头，导致震荡。所以必须小心翼翼地加（+1）。 这行代码背后，是无数次大电机调试震荡换来的教训。
    

**彩蛋二：用电阻辨识来查“断路”**

函数最后有一段：

```
if(gUVCoff.Comper >= gUVCoff.Rs_PRD) // 占空比都拉满了
```

这是一个极其巧妙的逻辑复用！

本来我在测电阻，结果发现：**我都把电压加到最大了（占空比100%），电流怎么还上不来？**

根据欧姆定律 _I_ = _U/R_，如果 _U_ 很大，_I_ 还是很小，说明什么？说明 _R_ 无穷大！**_R_ 无穷大意味着什么？意味着线断了！**

所以，这个函数不仅是在测电阻，还在顺便做硬件链路完整性检测。这就是嵌入式软件的“一鱼多吃”。

代码B的作者使用的这个电阻辨识方法，非常接近文末的 **IEEE Std 118-2023** 中提到的**伏安法（Voltmeter-Ammeter Method）**，但它是在驱动器内部，用PWM占空比和母线电压来等效一个“可调直流源”，用ADC来等效“电压表和电流表”。并且，它还创造性地在计算中**显式地减去了死区时间的影响**，比简单的伏安法更进了一步。

## 四、本讲落地：给三类工程师的行动指南

1.  **对算法工程师**
    

-   **闭环辨识的优势:** 学习代码B的思路，当模型不确定时，用一个简单的闭环控制器（比如PI）去“凑”到目标工况，是一种非常实用和鲁棒的工程技巧。
    
-   **死区补偿的重要性:** 代码B明确告诉我们，在计算等效电压时，必须把死区时间减掉。这个思想可以应用到你所有的电压估算环节。
    
-   **定点数计算的“坑”:** 代码B里大量的移位和长整型运算，是为了在没有浮点单元的DSP上保证计算精度。各位同仁在使用时，要特别注意每个变量的Q格式和单位，否则一个移位错误，结果就谬以千里。
    

**2\. 对硬件工程师**

-   **死区参数的来源:** 算法同事会问你要`gDeadBand.DeadBand`这个参数。这个值应该来自你们对驱动芯片、MOSFET开关特性的规格书研究和实际测试（比如用示波器测量上下管开关的实际延迟），而不是一个经验值。
    
-   **母线电压的稳定性:** 这个辨识方法强依赖于母线电压的准确测量。如果母线电压本身波动很大，或者采样噪声很大，`TotalVolt`的累加值就会不准，直接影响Rs结果。
    

**3\. 对测试工程师**

-   **验证Rs辨识的线性度:** 在台架上，可以手动设置不同的`gUVCoff.CurComperCoff`（目标电流），比如额定电流的20%, 40%, 60%, 80%，分别跑一次`BeforeRunRsIdentify`。记录下每次辨识出的Rs。理想情况下，这些Rs值应该非常接近。如果随电流增大，Rs系统性地变大或变小，那说明死区补偿或压降模型还有问题。
    
-   **对比四线法:** 同样，在电机冷态和热稳态下，分别用高精度微欧计测量一次基准Rs，再用驱动器辨识一次。记录两者的差异，这个差异就是你们控制器“测量系统”的系统误差，可以作为后续软件补偿的依据。
