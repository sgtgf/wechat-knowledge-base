# CAE 软件发展方向 —— 通用和专用之争


> 原文地址: [https://mp.weixin.qq.com/s/6h1POU2feANzM0YXBIXm7g](https://mp.weixin.qq.com/s/6h1POU2feANzM0YXBIXm7g)

目前国内外的许多有限元软件，包括那些通用有限元程序系统，一般只适用于某些特定领域和特定类型的有限元问题，而且大多数是根据结构力学的需要而设计的，对其它领域的工作者，尤其对从事科研和教学的人来说，远远不能满足需要。为了吸引更多的用户，求解更多的有限元问题，不少有限元软件公司拼命增大他们的有限元程序系统，扩大求解领域，但其结果往往都是事倍而功半。其主要原因在于：

1.  一个有限元程序，不管它多么庞大，通用性多强，也只能解决很少的一部分问题。因此，用户往往需要修改或加进一部分功能才能达到自己的目的。而这些工作，如果没有得到源程序开发者的参与，通常是十分困难甚至是无法实现的。
    
      
    
2.  有限元程序并没有统一的文本格式。不同的有限元程序要求用户填写的数据文件完全不同。用户要理解、信任和习惯任何一个有限元程序，都需要花费许多的金钱和精力，付出很大的代价。这就是为什么大多数用户更愿意采用旧的（落后的）但自己熟悉的有限元程序系统，而不愿意接受新的（先进的）但不熟悉的有限元程序系统的一个重要原因。
    
      
    
3.  通用性越强的程序，按理说越容易满足用户的需要，然而另一方面，对于这样的程序，用户需要填写的数据也会越多。用户越难理解和掌握，当然也就越难修改和扩展功能。这是限制有限元程序的通用性不能无限扩大的一个重要因素。
    
      
    
4.  开发一个通用软件需要几百甚至几千人年，投资大，时间长，维护费用很高。随着高性能计算的兴起，软件的并行化在所难免。基于 OpenMP 和 MPI 的并行软件结构要比串行软件复杂得多。船大调头难。通用软件由于其自身结构的庞大与复杂，升级改造必将面临巨大的挑战。
    
      
    
5.  通用性程序的一个普遍趋势是，程序体积越来越臃肿，对计算机硬件的需求也越来越高，占用的系统资源更是节节攀升。程序系统看似每次升级只是修复一些 bug、增加了一些功能，实际上往往是增加一个很小的功能，代码量也会成倍地增长，因为程序每增加一个节点就必须保持和其他节点的联通。这样一件事情其实很早就形成了一个定律，大名鼎鼎的安迪·比尔定律（Andy gives, Bill takes away）—— 硬件厂商每时每刻都在致力于提升硬件的性能，而新开发出来的系统和软件会迅速地消耗这些硬件提升。必须看到，硬件的提升是存在瓶颈的，摩尔定律越来越难维持即是最好的证明。显然，通用程序中好多功能对特定用户来说是冗余的。**删繁就简，回归数值计算的根本**，也许这才应该是未来有限元软件发展的大方向。
    
      
    

由此推断，相对短小与简单，易理解、易使用、易修改的专用有限元软件，仍有弯道超车通用软件的机会。采用统一的文本格式、统一的程序框架，灵活地搭配专属算法，具体问题具体分析，实现成体系的批量化生产，专用软件同样会受到大量用户的欢迎，占有 CAE 广阔市场的一席之地。
