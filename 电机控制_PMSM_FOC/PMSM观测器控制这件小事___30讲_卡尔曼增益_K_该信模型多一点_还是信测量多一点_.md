有天下午，我正对着示波器发愁。

phobia 的代码里 `kalman_gain_Q` 四个值和 `kalman_gain_R` 一个值，被我调了十几个组合。电机低速时抖得像筛糠，高速时倒是稳了，可一换负载又飘。我盯着那串数字——`5.e-1`、`2.e+0`、`2.e+6`、`2.e-1`、`5.e-1`——心里只有一个念头：

这 K，到底该怎么给？

我试过把 Q\[2\] 从 2e6 改成 2e5，结果低速不抖了，但负载突变时估计器直接掉线。改回 2e6，负载扛住了，低速又抖。来来回回折腾了两小时，电机还是那个电机，参数还是那五个 float，但我对它们的理解完全变了。

后来我把 K 的值打出来看——`K[0]` 在 0.6 左右晃，`K[6]` 忽上忽下能差一个量级——这才意识到：**我卡的不是参数值，而是我对 K 的理解。**

我把 K 当成一个"系数"在调，实际上它是一杆**天平**。天平两边分别坐着你的**模型预测**和**实际测量**，K 的每一个元素，都在回答同一个问题：

> "这一刻，我该信谁多一点？"

这个问题搞懂了，调参才有了方向。否则就是闭着眼睛转旋钮，转对算运气，转错算常态。

## 天平的两端：模型 vs 测量

各位同仁，假设你去菜市场买肉。

摊主把肉往秤上一放，指针停在了 500 克。但你心里犯嘀咕——这秤准吗？你同时掂了掂手里的肉，凭经验觉得大概 480 克。现在你有两个信息：秤的读数（测量）和你的手估（模型）。

你该信谁？

如果这杆秤是市监管定期校准过的，你当然信秤。如果秤是从隔壁借来的，螺丝都松了，那你宁可信自己的手。反过来，如果你是第一次买菜，手估完全没谱，那就算秤再破，你也得硬着头皮信它。

**卡尔曼增益 K，就是你心里这杆秤的刻度。**

但这里有个关键区别。在菜市场，你只需要决定"信秤还是信手"——一个比例就够了。但在**扩展卡尔曼滤波器（EKF, Extended Kalman Filter）**里，你有**五个状态量**（iX、iY、θ、ω、bias\_Q），每个状态都要回答"信谁"，而且**两个测量通道**（X 电流、Y 电流）各自独立给出修正意见。

所以 K 不是一个数，而是 5×2 = 10 个数。`kalman_K[10]` 这个数组的每一个元素，都是一杆独立的小天平。

**K\[0\]/K\[3\]（电流自增益）可以用"信任比例"来理解**：它们是无量纲的，接近 1 说明更信测量，接近 0 说明更信模型。但"接近 1"不是目标——如果自增益全是 1，预测步就完全没用了，滤波器退化成纯测量平均；如果全是 0，测量完全没进估计，滤波器退化成开环模型。

**但其他 K 元素不能简单套用这个直觉。** K\[1\]/K\[2\]（交叉增益）也是无量纲的，但可正可负，反映的是状态间的耦合关系，不是"信谁多一点"。K\[4\]/K\[5\]（角度修正）的量纲是 rad/A，K\[6\]/K\[7\]（转速修正）的量纲是 (rad/s)/A，K\[8\]/K\[9\]（bias\_Q 修正）的量纲是 V/A（等价于 Ω）——它们不是比例，而是**残差到状态修正量的映射系数**。

所以"天平"这个类比，更适合用来理解自增益 K\[0\]/K\[3\] 的直觉。对于带量纲的状态，你要换个角度：K 的值越大，说明该状态对测量残差越敏感，修正动作越猛。

-   • **P**：状态估计的不确定性（协方差矩阵）。P 越大，说明你对模型的预测越没把握。
    
-   • **R**：测量噪声的协方差。R 越大，说明传感器越不靠谱。
    
-   • **H**：观测矩阵，告诉你"测量值对应的是哪些状态"。

**对于自增益 K\[0\]/K\[3\]，这个关系可以写成 `P/(P+R)` 的形式，结果落在 0 和 1 之间。** P 大 → K 大（更信测量），R 大 → K 小（更信模型）。但交叉增益和带量纲增益不受这个 0~1 范围的约束。

但这个公式在工程代码里几乎不会直接出现。在 phobia 里，`pm_kalman_update()` 用了一套**标量顺序更新**的技巧，把 2×2 矩阵求逆变成了两次标量除法。原理是一样的，只是写法让单片机少算了很多浮点指令。

我们先记住直觉，等下再看代码怎么玩的花活。

## K 不是常量，是活的

很多初学者有个误解：K 是设计阶段算好、然后固定不变的常数。

不是的。**K 每一个控制周期都在变。**

为什么？因为 P 在变。预测步里 `P = F*P*F' + Q`，P 每一拍都在膨胀或收缩。P 变了，K 就跟着变。哪怕 Q 和 R 完全不动，K 也会随着电机运行状态的变化而上下波动。

打个比方。你开车时用导航，K 就像你对导航的信任度。刚出小区，路况简单，你对路线的记忆很清晰（P 小），这时候导航说左转，你可能只信 30%（K 小）。但进了陌生的老城区，路窄车多，你对路况完全没概念了（P 大），导航再说左转，你可能信 80%（K 大）。

电机运行也一样。低速稳速运行时，电流变化慢，模型预测很准（P 小），K 自然偏小。负载突变时，转速剧烈变化，模型完全摸不着头脑（P 大），K 就会瞬间飙高，让测量来救命。

**所以 K 不是参数，是状态。** 它反映了滤波器在当前时刻的"心态"——我有多慌？我该信谁？

phobia 里 `kalman_K[10]` 每一拍都被重新计算，就是这个原因。如果你在某个工况下把 K 打出来，会发现 K\[0\] 可能在 0.4~0.7 之间摆动，K\[6\] 可能从 0.01 跳到 0.3 再跳回来。这不是 bug，是 EKF 在正常工作的证据。

## P 大还是 R 大？这才是调参的命门

回到那杆天平。

**P 很大** = 模型预测很飘。你不知道电机下一秒电流会跳多少，转速会漂移多少。这时候测量来了，哪怕传感器有点噪声，你也赶紧抓过来修正——所以 K 会变大，更信测量。

**R 很大** = 测量很脏。电流传感器有零漂，ADC 有量化噪声，采样时刻还有抖动。这时候测量来了，你不敢全信——所以 K 会变小，更信模型。

注意这里的因果关系。很多工程师第一次调 EKF 时，会下意识觉得："K 是直接调的。"不是的。phobia 里没有直接调 K 的接口，你调的是 **Q** 和 **R**：

-   • `kalman_gain_Q[4]`：过程噪声协方差，影响 P 的增长速度
    
-   • `kalman_gain_R`：测量噪声协方差，直接影响 K 的分母
    

K 是 Q 和 R 的"孩子"。你养的是 Q 和 R，K 自己长出来。

这个过程有点像养植物。Q 是浇水量，R 是光照强度，K 是长出来的叶子大小。你不能直接伸手把叶子拉长，但你可以多浇水、多晒太阳，让叶子自然长大。

但这里有个反直觉的点：**Q 不直接出现在 K 的公式里。** K = P_H'/(H_P\*H'+R)，分子里没有 Q。Q 是通过影响 P 来间接影响 K 的。预测步里 `P = F*P*F' + Q`，Q 越大，P 膨胀越快，下一轮的 K 就越大。

所以调 Q 和调 R 的"手感"完全不同：

-   • **调 R 是立竿见影。** R 直接进 K 的分母，改一个数，下一秒 K 就变。
    
-   • **调 Q 是慢热型。** Q 先影响 P，P 再影响 K。改一个数，要过几个控制周期才能看到 K 的变化。
    

这就解释了为什么很多工程师调参时觉得"Q 怎么调都没反应"——不是没反应，是反应有延迟。你要等 P 矩阵"长起来"，K 才会跟着变。

## phobia 里的 K 长什么样？

打开 `phobia/src/phobia/pm.c`，`pm_kalman_update()` 从第 1177 行开始。

`// 来源: phobia/src/phobia/pm.c:pm_kalman_update() (commit 4058e68de0cd)      float *P = pm->kalman_P;   float *K = pm->kalman_K;   float iR = pm->kalman_gain_R;      float HP[5], u;      /*    * S = H * P * H' + R.    * K = P * H' / S.    * P = P - K * H * P.    */      HP[0] = P[0];   HP[1] = P[1];   HP[2] = P[3];   HP[3] = P[6];   HP[4] = P[10];      u = 1.f / (HP[0] + iR);      K[0] = HP[0] * u;   // iX 对 X 残差的增益   K[2] = HP[1] * u;   // iY 对 X 残差的增益   K[4] = HP[2] * u;   // dA 对 X 残差的增益   K[6] = HP[3] * u;   // wS 对 X 残差的增益   K[8] = HP[4] * u;   // bias_Q 对 X 残差的增益`

这段代码干了什么？

第一，`HP = H * P`。H 是观测矩阵，只挑前两行（X 和 Y 电流），所以 `HP[0..4]` 就是 P 的前两列元素。具体来说：

-   • HP\[0\] = P\[0\] = Cov(iX, iX) → iX 对 X 残差的相关性
    
-   • HP\[1\] = P\[1\] = Cov(iX, iY) → iY 对 X 残差的相关性（交叉项）
    
-   • HP\[2\] = P\[3\] = Cov(iX, θ) → 角度对 X 残差的相关性
    
-   • HP\[3\] = P\[6\] = Cov(iX, ω) → 转速对 X 残差的相关性
    
-   • HP\[4\] = P\[10\] = Cov(iX, bias\_Q) → 电阻偏置对 X 残差的相关性
    

第二，`u = 1 / (HP[0] + iR)`。分母 `HP[0] + iR` 就是 `H*P*H' + R` 的标量形式——注意 phobia 里 R 用的是标量 `iR`，不是矩阵。这意味着 X 和 Y 两个测量通道的噪声被假设为**同方差、不相关**。

这是 phobia 的工程简化假设。源码里用标量 `iR` 等价于假设 `R = iR·I`（X/Y 通道噪声同方差、不相关）。这个假设是否近似成立，取决于实际采样拓扑、Clarke 变换方式和电流传感器标定。

第三，`K = HP * u`。这就是 `K = P*H' / (H*P*H' + R)` 的标量实现。每个 `K[偶数]` 代表某个状态对 **X 测量残差**的修正系数；其中 K\[0\]（iX 自增益）可近似理解为信任比例，K\[2\]（iY 交叉增益）是无量纲但可正可负的耦合系数，K\[4\]/K\[6\]/K\[8\] 分别是残差到角度、转速、bias\_Q 的带量纲映射系数。

接着代码把 P 更新一轮，再对 Y 通道重复一遍：

`HP[0] = P[1];   HP[1] = P[2];   HP[2] = P[4];   HP[3] = P[7];   HP[4] = P[11];      u = 1.f / (HP[1] + iR);      K[1] = HP[0] * u;   // iX 对 Y 残差的增益   K[3] = HP[1] * u;   // iY 对 Y 残差的增益   K[5] = HP[2] * u;   // dA 对 Y 残差的增益   K[7] = HP[3] * u;   // wS 对 Y 残差的增益   K[9] = HP[4] * u;   // bias_Q 对 Y 残差的增益`

Y 通道的分母用的是 `HP[1] + iR`（即 P\[2\] + R），不是 `HP[0] + iR`。这是因为顺序更新时，第一次更新已经把 P 改了，第二次用的是更新后的 P。这也是为什么顺序更新在数学上等价于联合更新，但计算路径更轻、更适合 MCU 实现。

最后还有一个骚操作：

`u = -K[2];      K[0] += K[1] * u;   K[2] += K[3] * u;   K[4] += K[5] * u;   K[6] += K[7] * u;   K[8] += K[9] * u;`

这是把两次顺序更新的结果，转换成**联合残差形式**。说人话就是：后面的状态更新可以直接用原始残差 `E[0]` 和 `E[1]` 乘一个统一的 K，不需要分两次乘。`pm_flux_kalman()` 里就是这样用的：

`// 来源: phobia/src/phobia/pm.c:pm_flux_kalman() (commit 4058e68de0cd)      A[0] += K[0] * E[0] + K[1] * E[1];   A[1] += K[2] * E[0] + K[3] * E[1];      dA = K[4] * E[0] + K[5] * E[1];   dA = clamp(dA, -1.f, 1.f);   m_rotatef(pm->flux_F, dA);      pm->flux_wS += K[6] * E[0] + K[7] * E[1];   pm->kalman_bias_Q += K[8] * E[0] + K[9] * E[1];`

一行 `K[0]*E[0] + K[1]*E[1]`，就是"用 X 残差修正 iX，同时用 Y 残差也修正 iX"。**K\[0\] 和 K\[1\] 不是多余的，它们各自负责一个测量通道。**

## 标量顺序更新：为什么要分两次算？

刚才提到"顺序更新在数学上等价于联合更新，但计算路径更轻"。这值得展开说一下，因为这个技巧直接省掉了显式的 2×2 矩阵求逆，是 phobia 代码能在单片机上跑 5 维 EKF 的关键。

标准的联合更新做法是：先算 2×2 的 S 矩阵（`S = H*P*H' + R`），再求它的逆，然后用 `K = P*H'*S^-1` 算出完整的 5×2 增益矩阵。

问题是：2×2 矩阵求逆虽然公式简单（`det = a*d - b*c`，然后 swap + negate），但在浮点运算里还是要算一次除法、两次乘法、两次加减法。而且这还只是 S 的逆，后面还要跟 P\*H' 做矩阵乘法——5×2 乘 2×2，又是 20 次乘法、10 次加法。

phobia 的做法是**把两个测量通道拆开，一次只处理一个标量**。第一次处理 X 通道：

`S_X = P[0] + R  （标量！）   K_X = [P[0]; P[1]; P[3]; P[6]; P[10]] / S_X   P = P - K_X * [P[0], P[1], P[3], P[6], P[10]]`

然后第二次处理 Y 通道，但这时候用的 P 已经是第一次更新后的结果了：

`S_Y = P[2] + R  （注意 P[2] 已经被更新了！）   K_Y = [P[1]; P[2]; P[4]; P[7]; P[11]] / S_Y   P = P - K_Y * [P[1], P[2], P[4], P[7], P[11]]`

两次标量除法替代了一次 2×2 矩阵求逆，两次向量外积替代了一次完整的矩阵乘法。**避免了显式的 2×2 矩阵求逆和完整的矩阵乘法，便于在资源受限的 MCU 上实现。**

最后那步 `u = -K[2]` 的修正，是为了把顺序更新得到的 K 转换成"联合残差形式"。顺序更新时，第一次的 K\[偶数\] 已经"消化"了 X 通道对 P 的影响，第二次的 K\[奇数\] 是在更新后的 P 上算的。如果直接把这两组 K 拿去乘原始残差 E\[0\] 和 E\[1\]，数学上是不对的——因为第二次的 K\[奇数\] 是在第一次更新后的**条件协方差**上算的，其物理意义是"在已经吸收了 X 通道信息后的增益"，不能直接作用于原始残差。

那步修正的物理意义是：**把顺序更新的结果，重新投影回原始残差坐标系**。代码里用的是 `u = -K[2]` 这个耦合系数——K\[2\] 是 iY 对 X 残差的交叉增益，它编码了两次顺序更新之间的相关性。用 `-K[2]` 做修正，相当于把第二次更新的结果"去相关"后再叠加到第一次更新上，最终得到的 K 可以直接作用于原始残差 E\[0\] 和 E\[1\]。

工程上你不需要理解每一步的数学证明，只需要记住：**`pm_kalman_update()` 出来的 K，可以直接给 `pm_flux_kalman()` 用，数学上是等价的。**

## 交叉增益：为什么 K\[2\] 不为零？

仔细看上面的表，有个反直觉的地方：

**iY 对 X 残差有增益（K\[2\]），iX 对 Y 残差也有增益（K\[1\]）。**

这不是 bug，是 EKF 的精髓。

在 XY 坐标系下，X 和 Y 轴电流不是独立的。电机旋转时，DQ 轴电流投影到 XY 平面，两个轴之间有很强的耦合。P 矩阵的非对角元素（协方差）反映的就是这种耦合——"我知道 iX 估计偏了，那 iY 估计很可能也偏了"。

所以当你看到 X 电流的测量残差时，不仅要修正 iX（K\[0\]），还要**连带修正 iY（K\[2\]）**。这就是协方差矩阵非对角元素的作用：它把不同状态之间的相关性，传递到了增益上。

说白了，**交叉增益是 EKF 比纯独立滤波强的地方**。如果 K 只有对角元素（K\[0\] 和 K\[3\]），那就退化成五个独立的标量卡尔曼滤波器，失去了多状态联合估计的优势。

就好像你在健身房举哑铃，左手酸了（测量告诉你左臂状态不对），你不仅会调整左手的姿势，右手也会下意识跟着调整——因为左右手臂是联动的，一个偏了另一个很难独善其身。

交叉增益就是这个"联动调整"的数学表达。

再具体一点。假设 P\[1\] = Cov(iX, iY) = 0.3，P\[0\] = 0.8，R = 0.5，那么：

`K[0] = P[0] / (P[0] + R) = 0.8 / 1.3 ≈ 0.615   K[2] = P[1] / (P[0] + R) = 0.3 / 1.3 ≈ 0.231`

X 残差来了，iX 修正 61.5%，iY 连带修正 23.1%。这就是交叉增益的数值含义。

如果 iX 和 iY 完全不相关（P\[1\] = 0），那 K\[2\] 就是 0，X 残差不会影响 iY。但在电机里，DQ→XY 的旋转变换让两个电流分量天然耦合，P\[1\] 几乎不可能为零。

## Q 和 R 的默认值：为啥 Q\[2\] 是 2e6？

phobia 里默认参数长这样（Q\[0\] 经 `lazy_TiLq` 缩放后同时加到 iX 和 iY 的方差上）：

`// 来源: phobia/src/phobia/pm.c:pm_auto_config_default() (commit 4058e68de0cd)      pm->kalman_gain_Q[0] = 5.e-1f;   // iX/iY 共享的过程噪声   pm->kalman_gain_Q[1] = 2.e+0f;   // 角度 θ 的过程噪声   pm->kalman_gain_Q[2] = 2.e+6f;   // 转速 ω 的过程噪声 ← 这啥？   pm->kalman_gain_Q[3] = 2.e-1f;   // bias_Q 的过程噪声   pm->kalman_gain_R = 5.e-1f;      // 测量噪声`

Q\[0\]、Q\[1\]、Q\[3\] 都在 0.1~2 的量级，很合理。但 `Q[2] = 2.e+6` 让人瞳孔地震——两百万？

别慌，这有原因。

Q\[2\] 对应的是**转速 ω** 的过程噪声。在 phobia 的 EKF 中，速度预测模型非常保守——F 矩阵中速度的自转移项为 1，预测步里 `ω_next ≈ ω`，没有明确的转矩驱动项。速度主要依赖残差修正来更新，另有可选的加速度前馈 `pm_lu_accel()` 参与 `flux_wS`。高速运行时，负载转矩突变会导致实际转速剧烈变化，但模型预测完全跟不上，只能靠 Q\[2\] 注入大量过程噪声来"承认"这种不确定性。

**Q\[2\] 给得极大，是在告诉滤波器："我对转速模型的预测极度不信任。"**

不信任到什么程度？我们算一下。假设 dt = 50μs（20kHz 控制频率），Q\[2\] = 2e6，那么预测步里转速方差 P\[9\] 的增量就是 `Q[2] * dt = 2e6 * 50e-6 = 100`。这个值会让 P\[9\] 迅速膨胀，通过预测步 F 矩阵中转速→电流的耦合项（F\[3\]、F\[8\]）间接推高 P\[6\]/P\[7\]（电流-转速协方差），最终导致 K\[6\] 和 K\[7\] 变大。

结果是什么？滤波器会**极度依赖电流测量来修正转速估计**，而不是靠模型外推。

这很合理。电机转速受负载影响太大了，模型根本预测不了负载突变。与其让模型瞎猜，不如让测量说话。两百万不是 bug，是**工程上的刻意放大**。

反观 Q\[0\]（iX/iY 共享的过程噪声）只有 0.5，Q\[1\]（角度过程噪声）只有 2.0，Q\[3\]（bias\_Q 过程噪声）只有 0.2，说明电流、角度和偏置模型相对可信。电流变化主要由电感和电阻决定，角度变化主要由转速积分决定，这些在短时间内是稳定的。

R = 0.5 则是一个中等偏小的值，说明电流传感器还算靠谱。如果 ADC 噪声大、采样电路设计差，这个值需要调大。

再深入一步，为什么转速增益在负载突变时会飙高？因为负载突变瞬间，实际转速剧烈变化，但 phobia 的速度预测模型几乎没有外推能力（`ω_next ≈ ω`），预测值和实际值差距巨大。同时 Q\[2\] 注入了极大的过程噪声，P\[9\] 瞬间膨胀，通过 F 矩阵耦合推高 P\[6\]/P\[7\]，K\[6\]/K\[7\] 跟着变大。滤波器"慌"了，赶紧抓电流测量来修正转速。

这个"慌"的过程只持续几个控制周期。一旦转速估计重新收敛，P 收缩，K 也就回落了。如果你在示波器上把 K\[6\] 打出来，会看到一个个尖峰——每个尖峰对应一次负载突变。

## 调参不是玄学：Q 和 R 的物理意义

很多工程师调 EKF 时，把 Q 和 R 当成"魔法数字"。其实它们每个都有明确的物理对应。

**kalman\_gain\_Q\[0\] ~ iX/iY 共享的过程噪声**

对应电机电流在 XY 坐标系下的模型不确定性。Q\[0\] 同时加到 P\[0\]（iX 方差）和 P\[2\]（iY 方差），说明两个电流分量共享同一个过程噪声参数。如果电机电感参数标定不准，或者 PWM 非线性严重，这个值要调大。调大的后果：K\[0\]~K\[3\] 都会变大，滤波器更听测量的话。

**kalman\_gain\_Q\[1\] ~ 角度 θ 的过程噪声**

对应角度估计的模型不确定性。角度 θ 的演化是 `θ += ω * dt`，如果转速估计不准，角度预测就会偏差。Q\[1\] 加到 P\[5\]（角度方差）。通常这个值不需要太大，因为角度变化主要由转速积分决定，而转速本身有独立的 Q\[2\]。

**kalman\_gain\_Q\[2\] ~ 转速 ω 的过程噪声**

这个参数直接决定你的电机能不能扛住负载突变。Q\[2\] 加到 P\[9\]（转速方差），电机转速变化越快（加减速猛、负载突变多），这个值越大。如果电机长期稳速运行，可以适度减小。但别减太小——一旦负载突变，模型预测完全跑偏，K 太小就拉不回来。

**kalman\_gain\_Q\[3\] ~ bias\_Q（Q 轴电压偏置）的过程噪声**

对应 `kalman_bias_Q` 估计的模型不确定性。在 phobia 中，`kalman_bias_Q` 直接作为补偿项加到 Q 轴电压 `uQ` 上（见 `pm_kalman_equation()`），单位为 V。Q\[3\] 加到 P\[14\]（bias\_Q 方差）。这个偏置通常变化很慢（如由温度漂移或参数失配引起），所以过程噪声给得很小（0.2）。如果电机工作环境温差大，可以适当调大，让 bias\_Q 的估计更灵活。

**kalman\_gain\_R ~ 测量噪声**

直接对应电流残差坐标下的测量噪声方差，单位与 P\[0\]/P\[2\] 一致，近似是 A² 量级。phobia 的默认值 R = 0.5 表示测量噪声方差约 0.5 A²。如果你用电流传感器的噪声来估算，R 的量级应该和电流采样波动幅度的平方相当。例如，若电流采样有 ±0.3A 的随机噪声，R 大概在 0.1 A² 左右。

## 常见调参错误：别踩这些坑

**错误 1：Q\[2\] 设得太小，负载突变时估计滞后**

有位同仁把 Q\[2\] 从 2e6 改成 2e3，觉得"转速模型挺准的，不用给那么大噪声"。结果电机空载启动没问题，一加负载，转速估计慢了整整 50ms 才跟上。为什么？Q\[2\] 小了 → P\[9\] 涨得慢 → K\[6\]/K\[7\] 变小 → 滤波器太信模型了，测量修正不够力。负载突变时，模型预测完全跑偏，但 K 太小，拉不回来。

**错误 2：R 设得太小，高速时电流估计抖动**

另一位同仁把 R 从 0.5 改成 0.05，觉得"传感器很准，R 应该小"。结果高速运行时电流估计抖得像正弦波——因为 R 太小，K 太大，滤波器对每一个测量噪声都过度反应。电流测量的微小抖动被放大成了状态估计的剧烈振荡。

**错误 3：直接改 K 的数组值**

最危险的错误。有人在 `pm_kalman_update()` 返回后，直接把 `K[6]` 手动改成 0.1，觉得"转速增益太大了，压一压"。这会让协方差更新方程失衡——P 矩阵的更新是按标准卡尔曼方程算的，但状态更新用了人工修改的 K。下一轮 P 和 K 的对应关系就被打破了，滤波器要么发散，要么收敛到错误值。

**错误 4：四个 Q 值量级差太远，P 矩阵失去正定性**

Q\[2\] = 2e6 和其他 Q 值差六个数量级，这在数学上是允许的，因为 P 矩阵的更新是局部耦合的。但如果你自己把 Q\[0\] 也改成 1e6，同时 Q\[2\] 保持 2e6，那 P 矩阵的电流块和转速块都会急剧膨胀，不同状态之间的相对尺度完全失控。在更极端的参数差异下（如十个数量级），浮点舍入误差可能让 P 失去正定性，滤波器发散。

## ODrive 和 VESC 为啥不用 EKF？

前面我们一直在讲 phobia 的 EKF 实现，但有个问题可能在你脑子里打转：ODrive 和 VESC（bldc）这两大开源项目，为啥都不用 EKF？

答案是：**它们用了更简单、更鲁棒的非线性观测器。**

ODrive 的 `SensorlessEstimator` 实现的是 Ortega 非线性磁链观测器，核心就是一个微分方程加一个标量反馈增益 `observer_gain`：

`// ODrive/Firmware/MotorControl/sensorless_estimator.cpp (示意)   float bandwidth_factor = 1.0f / pm_flux_sqr;   float eta_factor = 0.5f * (config_.observer_gain * bandwidth_factor) * (pm_flux_sqr - est_pm_flux_sqr);`

VESC 的 `foc_observer_update` 也是类似思路，支持 Ortega 原始版和若干变体，但都没有协方差矩阵、没有卡尔曼增益、没有预测-更新框架。

这不是因为 EKF 不好，而是因为：

1.  1. **EKF 的调参门槛高。** Q 和 R 五个参数，相互耦合，调错一个全盘皆输。Ortega 观测器只有一个 `observer_gain`，"拧大拧小"就能出效果。
    
2.  2. **EKF 的计算开销大。** 5×5 协方差矩阵的预测和更新，每一步都要做大量浮点运算。Ortega 观测器只需要几次乘法和一次积分，对低端单片机友好得多。
    
3.  3. **EKF 对模型精度敏感。** PMSM 的电感、电阻、磁链参数会随温度和饱和度变化，EKF 的线性化假设（雅可比矩阵）在这些变化面前会引入误差。Ortega 观测器本质上是李雅普诺夫稳定的，对参数不确定性的容忍度更高。
    

那 phobia 为什么敢用 EKF？因为 phobia 的作者 Roman 做了大量工程优化（标量顺序更新、联合残差形式、区域切换策略），把 EKF 的计算开销压到了和 Ortega 观测器相近的水平。同时，EKF 在多状态联合估计（电流+角度+转速+bias\_Q）上的精度优势，在高速高性能场景下确实能体现出来。

说白了，**ODrive 和 VESC 选择"简单够用"，phobia 选择"复杂但精"。** 没有绝对的好坏，只有场景适配。

但这里有个很实际的问题：如果你现在的项目用的是 ODrive 或 VESC，有没有必要自己移植一套 EKF 过来？

我的建议是：**先把手里的观测器调透，再考虑升级。** Ortega 观测器调参简单、鲁棒性强，在大多数常规场景下都能工作。EKF 的优势可能体现在需要多状态联合估计（如同时跟踪电流、角度、转速和 bias\_Q）、或需要更精细的协方差管理的场景。如果你的电机负载变化不大、精度要求不高，强行上 EKF 反而增加了维护成本。

**技术选型不是选最贵的，是选最合适的。**

不过话说回来，理解 EKF 的原理对你调任何观测器都有帮助。Ortega 观测器里的 `observer_gain` 和 EKF 里的 K 都影响"观测器纠偏强度"，但数学对象完全不同：`observer_gain` 缩放的是非线性磁链范数校正项，不含协方差含义；K 则是基于 P 和 R 统计计算出的最优增益。两者的直觉可以借鉴（增益大 = 修正更猛），但底层机理不一样。

## 调试 Checklist

上了这么多理论，最后给一个可直接抄作业的调试流程：

1.  1. **先固定 R，只调 Q。** R 由硬件决定，换传感器之前不用动。先用默认值跑起来，看行为。
    
2.  2. **低速抖 → 看 Q\[1\] 和 Q\[2\]。** 如果低速时角度估计来回跳，说明角度或转速的过程噪声给得不对。Q\[1\] 控制角度方差 P\[5\] 的增长，Q\[2\] 控制转速方差 P\[9\] 的增长。低速时转速低，Q\[2\] 过大可能导致转速估计过度敏感；Q\[1\] 过大则直接导致角度估计抖动。试试分别调整，观察变化。
    
3.  3. **高速漂 → 看 Q\[0\]/Q\[1\]。** 如果高速运行时电流估计偏离实际，说明电流模型不准。调大 Q\[0\] 和 Q\[1\]，让滤波器更依赖测量。
    
4.  4. **长时间运行后偏 → 看 Q\[3\]。** 如果电机跑半小时后位置估计逐渐漂移，可能是电阻温度漂移没被跟踪到。调大 Q\[3\]，让 bias\_Q 估计更活跃。
    
5.  5. **用示波器抓 K 的值。** phobia 没有直接输出 K 的接口，但你可以在 `pm_kalman_update()` 返回后，把 `K[0]` 到 `K[9]` 打出来。正常稳态低速工况下，K\[0\] 和 K\[3\]（自增益）通常在 0.3~0.8 之间，K\[1\] 和 K\[2\]（交叉增益）通常在 ±0.2 量级。如果 K\[1\]/K\[2\] 持续超过 0.5，建议结合当前工况排查：高速运行时 Park 变换耦合增强、电流模型参数（Ld/Lq）标定不准、或负载突变导致协方差未收敛，都可能让交叉增益升高，不一定是坐标变换错误。
    
6.  6. **角度估计发散 → 检查 P 矩阵和残差。** 如果 P\[5\]（角度方差）持续增大但角度估计不收敛，首先检查 `pm->vsi_IF` 是否为 0（非 0 时 update 被跳过而 forecast 仍在执行，P 只涨不缩）。其次检查 `kalman_POSTPONED` 是否正常触发（未触发时整个 kalman 块被跳过，P 不涨也不缩）。然后检查 update 是否真的在执行——只要 `pm_kalman_update()` 被调用，P 就会按协方差方程收缩，与残差 E\[0\]/E\[1\] 的大小无关（残差只影响状态修正，不影响协方差更新）。若 update 正常执行但 P 仍发散，可能是 P 矩阵失去正定性，需检查 Q 值是否过大或 R 是否过小。
    
7.  7. **记住：K 不是直接调的，是 Q 和 R 的"孩子"。** 不要试图直接改 K 的数组值，那会让协方差更新方程失衡，P 矩阵失去正定性，滤波器发散只是时间问题。
