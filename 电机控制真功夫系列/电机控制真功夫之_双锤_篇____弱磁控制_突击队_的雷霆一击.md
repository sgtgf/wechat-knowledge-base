我们再次回到主战场——`pm_loop_current()`函数。目光锁定“突击队”执行任务的核心区域。

```
static void pm_loop_current(pmc_t *pm)
```

看到这个结构了吗？在`if`语句块内部，作者先挥舞了“守护之锤”（限制`iq`），再挥舞了“破壁之锤”（叠加`id`）。这个顺序非常有讲究，我们后面会分析。现在，我们一锤一锤地看！

#### 第一锤：破壁之锤 —— `track_D += pm->weak_track_D;``   `

这把锤，用起来最简单，但效果最直接！

-   **`track_D`**
    
    这是我们d轴的总目标电流。在进入弱磁区之前，它可能等于0（对于SPM电机），也可能是一个根据MTPA算出来的负值（对于IPM电机）。
    
-   **`pm->weak_track_D`**
    
    这是我们[上一讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247484576&idx=1&sn=fc2337bd88f0be62dc3977573ff3d365&scene=21#wechat_redirect)，“指挥部”根据电压裕量算出来的那个负的弱磁电流指令。
    
-   **`+=`**
    
    **核心动作：叠加！** 这一下，就把“削弱磁场”的使命，注入到了d轴的最终目标里。
    

假设这是一台IPM电机，正在MTPA区域运行。

-   `Iq` = 50A
    
-   MTPA算出来的 `Id` = -10A。此时 `track_D` 等于-10A。
    
-   现在转速升高，进入弱磁区，“指挥部”算出来需要-15A的弱磁电流，即`pm->weak_track_D` = -15A。
    

那么，最终的d轴目标电流是多少？`track_D` = `(MTPA的-10A)` + `(弱磁的-15A)` = **\-25A**！

看到了吗？“破壁之锤”的作用，就是在原有的d轴电流基础上，再狠狠地砸上一个负值！它的目的只有一个：**产生一个更强的逆向磁场，把那个该死的反电动势给我压下去！**

这一锤，砸开了“电压墙”的突破口！简单、粗暴、有效！

#### 第二锤：【守护之锤】—— 动态限制 `track_Q``   `

如果说“破壁之锤”是“勇”，那么“守护之锤”就是“谋”！光有勇无谋，只会让部队陷入险境，全军覆没（电机失步）！

弱磁控制本质上是在**电压极限椭圆**的边界上跳舞。我们给了很大的负`id`，如果`iq`还维持原来的大小，那么合成的电流矢量 `Is` 就会很长，同时需要的电压矢量 `Us` 也会很大，很可能就超出了电压椭圆的范围，导致电流环饱和，控制失效。

所以，我们必须**牺牲`iq`（转矩），来换取`id`（转速）的生存空间**。

“守护之锤”的任务，就是计算出在当前这个“九死一生”的弱磁边界上，`iq`最大还能给多少。

我们来看它的核心计算公式（源代码中line3034-line3039的合并简化）：

```
iMAX = (pm->k_EMAX * pm->const_fb_U) * m_fast_recipf(m_fabsf(pm->lu_wS * pm->const_im_Lq));
```

这个公式，可不是拍脑袋想出来的，它是从PMSM的**稳态电压方程**简化而来的！

PMSM的Q轴电压方程是：

Uq = Rs\*Iq + ωe\*Ld\*Id + ωe\*Ψm

在高速弱磁区（ωe 非常大），我们可以做几个合理的**近似和忽略**：

1.  忽略电阻压降: `Rs*Iq` 相比于后面的电感和反电势项，是小巫见大巫，可以忽略。
    
2.  忽略凸极效应(或简化模型)： 在很多弱磁策略中，为了简化计算，会暂时忽略`ωe*Ld*Id`这一项，或者认为`Ld ≈ Lq`。这份代码里的简化程度更高，它只保留了和`Iq`相关的项，我们来看它是如何思考的。
    

让我们看一个更根本的约束：**电压极限圆**。

Ud² + Uq² ≤ Umax²

其中`U_max`是SWPWM能输出的最大相电压幅值，约等于`Udc/ √3`，在代码里就是`pm->k_EMAX * pm->const_fb_U`。

当我们处于深度弱磁状态时，`Id`是很大的负值，`Ud`（`Rs*Id - ωe*Lq*Iq`）的主要矛盾是 `-ωe*Lq*Iq`。而 `Uq` 的主要矛盾是 `ωe*Ψm`。 作者在这里做了一个非常大胆的工程简化：他认为，**决定`Iq`上限的，主要是`Ud`这一项不能太大**。

即： `` (`-` ``ωe \* Lq \* Iq)2 ≈ Ud2≤ Umax2 (这里忽略了Ud中的Rs\*Id项)

所以，`Iq`的上限约等于：

Iqmax ≈ Umax / (ωe \* Lq)

我们再来对比代码：

-   eDC = pm->k\_EMAX \* pm->const\_fb\_U \-> 这就是 `Umax`！
    
-   wLS = pm->lu\_wS \* pm->const\_im\_Lq -> `lu_wS`是电角速度`ωe`，`const_im_Lq`是`Lq`。这不就是 `ωe * Lq` 吗！
    
-   m\_fast\_recipf(...) -> 这是求倒数。
    

所以，代码里的 `iMAX` 计算，完全就是我们推导出来的

 `Iqmax ≈ Umax/(ωe * Lq)`

算出了这个 `iMAX` 之后，代码毫不留情地执行（源代码line3041）：

```
track_Q = (track_Q > iMAX) ? iMAX : (track_Q < - iMAX) ? - iMAX : track_Q;
```

这一锤下去，不管你之前（比如速度环）想要多大的`iq`（转矩），都必须给我在这个`iMAX`的框框里待着！超了就给你砍掉！

这就好比指挥官下令：“弟兄们，城墙砸开了，但我们弹药有限，现在所有人不准用重机枪扫射（大Iq），只准用手枪点射（小Iq），把所有资源都留给爆破手（负Id）继续炸墙！”

这一锤，守护了系统的稳定性，确保了我们的“突击队”始终在可控的范围内作战，不会因为贪图转矩而导致全盘崩溃！
