你刚把逆变器死区补偿调好，电机低速的吱吱声小了，电流波形也顺了。

把转速拉到额定值的一半，观测器输出的角度估计值接上示波器一看——低速区像心电图，每隔几十毫秒来一个尖刺。高速区更离谱，锯齿密得像把电锯。

你怀疑观测器增益不对，从 500 调到 5000，再调回 1500。尖刺还在。

**问题可能不在观测器本身，而在观测器后端——你怎么从观测器输出的 αβ 量里，把转子角度"抠"出来。**

VESC 的源码里，`foc_math.c` 有两行代码并肩站着。一行是 `utils_fast_atan2(state->x2 - L_ib, state->x1 - L_ia)`，从磁链估计值里直接算角度。另一行是 `foc_pll_run(...)`，把角度喂给一个锁相环（PLL, Phase-Locked Loop），让它"跟上去"。

你愣了一下。既然反正切函数（atan2）一步就能算出角度，为什么还要多此一举搞个 PLL？

这是很多工程师第一次看无感控制代码时的共同困惑。今天咱们就把它拆碎了分析一下。

## 单次对焦的人，和连续追焦的人

各位同仁不妨先放下示波器，想一个生活中的场景。

你拿单反相机拍一只飞鸟。

**方式一：单次对焦（AF-S）。** 你半按快门，相机"嘀"一声对上了。焦点清晰、读数精准。但鸟一拍翅膀飞出去半米，焦点就落在空处了。你得重新半按快门再对一次——每次对焦都是独立的，上一次的对焦信息不会帮到你下一次。

**方式二：连续自动对焦（AF-C）。** 你把对焦模式切到 AF-C，镜头里的马达嗡嗡响，焦点死死咬住飞鸟。鸟往左飞，焦点往左跟；鸟往右飞，焦点往右追。相机会持续追踪目标，自动过滤手抖造成的轻微晃动，还能顺便告诉你目标移动的速度。

**atan2 就是单次对焦。** 它一步算出"转子此刻在哪"——给一个精确的角度值。但观测器输出里的噪声一来，就像你手抖了一下，焦点瞬间跳到错误位置。而且每次计算都是独立的，上一拍的角度不会帮下一拍做预测。

**PLL 就是连续追焦。** 它不直接"读取"角度，而是持续追踪观测器输出相位的变化，通过闭环控制"跟上"转子的旋转。它有天然的低通特性，能抑制开关纹波和测量噪声，同时还能输出平滑的速度估计。

说白了，两种方式都能算出角度，但一个在噪声面前步步惊心，一个在干扰面前稳如老狗。

但工程上有三个致命缺陷。

**第一个缺陷：噪声放大。**

atan2 的数学本质里有除法。当这个 αβ 向量的幅值很小，噪声相对于信号占比变大时，微小的噪声就会被放大——角度误差约随  增长。

打个比方：你测得 （含噪声），。真实角度约 63.4°，向量幅值只有约 0.011。但如果噪声让  从 0.005 变成 0.000（噪声与信号分量同量级），atan2 的输出会从 63.4° 跳到 90°——26.6° 的跳变完全来自噪声，不是转子真的动了。

低速时这个问题尤其严重。对 BEMF 后端来说，BEMF 幅值随速度降低而变小，信噪比差；对磁链观测器来说，磁链幅值本身不随转速变小，但电压模型中的电阻压降、偏置、积分漂移和电压重构误差更容易污染磁链估计。

**第二个缺陷：象限跳变。**

atan2 的输出范围是 。当转子角度从 179° 增加到 181° 时，atan2 会从 179° 跳到 -179°。

这个 358° 的跳变不是真实的——转子只转了 2°，但 wrapped 输出"绕了大半圈"。对 Park 变换本身来说，如果后面直接算 sin/cos，三角函数是周期连续的，不会因为 179° 到 -179° 而瞬间错乱。**真正危险的是下游处理**：直接对 wrapped angle 做差分求速度、做滤波、做比较判断或日志显示时，这个 2° 的微小变化会被误判为 358° 的巨大跳转。

处理它需要额外的 unwrap 逻辑：记录上一拍角度，如果当前和上一拍差值超过 180° 就加减 360°，还原真实的连续角度。这个逻辑本身不难，但在高速或噪声大的场景下，可能误判跳变方向。

**第三个缺陷：速度需要微分。**

atan2 只给角度，不给速度。要得到速度，你必须对角度做差分：

差分是噪声的放大器。角度上的微小抖动，经过差分后变成速度上的大幅波动。低速时角度变化本来就慢，差分结果几乎被噪声淹没。

说白了，单次对焦拍出来的照片张张清晰，但连起来看——鸟飞了，焦点没跟上。

## PLL：不直接看，而是"跟上去"

锁相环（PLL, Phase-Locked Loop）的思路和 atan2 完全不同。

它不把观测器输出当成一个"角度源"去直接读取，而是把它当成一个"参考信号"去跟踪。PLL 内部有一个"本地振荡器"，产生一个跟踪相位 。它不断比较跟踪相位和输入相位之间的误差 ，然后用一个反馈控制器调整跟踪相位，直到误差趋近于零。

说白了，PLL 不是在拍一张照片找位置，而是在追一辆车——它不断判断"我离前车还有多远"，然后加速或减速，直到两车速度一致、距离恒定。

电机控制中最常用的 PLL 是**二阶 PLL**，结构非常简单：

**第一步，算误差。**

角度是周期性的，所以  需要做模  归一化到 。

**第二步，更新相位。**

这里  是 PLL 当前估计的速度， 是比例校正项。先"预测"下一时刻的相位（），然后根据相位误差做"校正"（）。

**第三步，更新速度。**

上式中的  是积分增益。速度估计值会根据误差累积不断调整，直到稳态时  趋近于零。

这个过程有三个关键特性：

**第一，天然低通。** PLL 闭环从输入相位到输出相位呈低通特性。观测器输出里的开关纹波和测量噪声（比如 20kHz PWM 引入的高频分量）经过 PLL 后会被大幅压制，只有低频的"真实角度变化"才能驱动跟踪相位。

**第二，同时输出角度和速度。** 就是角度估计， 就是速度估计。不需要额外的差分运算，速度天然平滑。

**第三，不会被象限跳变误导。** PLL 内部用归一化相位误差闭环（如 `utils_norm_angle_rad` 把误差限制在 ），输入相位从 179° 翻到 -179° 时，PLL 知道"只差 2°"，不会被 ±π 分支切换误导。但注意：工程代码里的相位输出通常仍会归一化到 ，若要画连续曲线，仍需额外的 unwrap 处理。

## 代码里找答案

聊了这么多直觉，看看真实代码里 PLL 是怎么写的。

### VESC：最简标准 PLL

VESC 的 `foc_math.c` 里，`foc_pll_run()` 就五行核心代码：

`// 来源: bldc/motor/foc_math.c:foc_pll_run()   // 节选自 VESC 标准二阶 PLL（省略了 NaN 保护宏 UTILS_NAN_ZERO）   // bldc@c5944554      void foc_pll_run(float phase, float dt, float *phase_var,                 float *speed_var, mc_configuration *conf) {    float delta_theta = phase - *phase_var;       utils_norm_angle_rad(&delta_theta);  // 归一化到 [-pi, pi]    // 相位更新：预测（速度积分）+ 校正（比例项）       *phase_var += (*speed_var + conf->foc_pll_kp * delta_theta) * dt;       utils_norm_angle_rad((float*)phase_var);    // 速度更新：积分项累积误差       *speed_var += conf->foc_pll_ki * delta_theta * dt;   }`

三步：算误差 → 更新相位（预测+校正）→ 更新速度（积分）。

`phase` 是输入相位（可以来自 atan2、观测器或其他的相位源）。`phase_var` 是 PLL 跟踪的相位。`speed_var` 是 PLL 估计的速度。`dt` 是采样周期。

VESC 把这个 PLL 用在观测器输出的相位跟踪上，从选定的相位源估计速度。

### ODrive：带宽法设计的 PLL

## PLL 带宽到底怎么选？

这是工程师调 PLL 时最头疼的问题。带宽设多少合适？

**带宽的物理意义**：PLL 的带宽就是它的"跟踪灵敏度"。带宽越高，对输入相位变化的反应越快；带宽越低，噪声滤得越干净，但动态跟踪越慢。

**两条经验初值：**

**第一条：PLL 带宽 < 电流环带宽 / 10。**

如果电流环带宽是 1 kHz，PLL 带宽通常不超过 100 Hz（注意 ODrive 源码中 `pll_bandwidth` 的单位是 rad/s，若按 Hz 理解需先换算 ）。因为 PLL 的跟踪结果（角度或速度，取决于你的方案如何实现）直接参与 FOC 运算，如果 PLL 跟踪太快（带宽接近电流环），抖动会直接耦合到电流环里，引起振荡。

**第二条：PLL 带宽 > 速度环带宽 × 2。**

速度环的带宽决定了速度给定的变化速率。PLL 必须能跟上速度环的动态，否则速度环要加速，PLL 的角度还没跟上，转矩控制就乱了。

这两条是经验初值，不是铁律。真正合适的带宽还要结合噪声水平、加速度、采样周期和离散化稳定性检查（如 ODrive 的 `current_meas_period * pll_kp < 1.0`）共同决定。如果按这两条算出来上限比下限还低，说明你的电流环和速度环带宽比太接近了，需要重新设计环带宽分配。

调参的时候记住这个直觉：**对焦灵敏度太高，镜头抖；灵敏度太低，鸟飞走了还对不上。**

## 什么时候用 atan2，什么时候用 PLL？

直接给结论：

**单独用 atan2 直接做速度差分风险很高。** 工程上常见的做法是把 atan2 作为"相位测量"（给出一个原始角度），再配合 PLL（或低通滤波+补偿）获得平滑的速度或相位。VESC 和 ODrive 的代码里，atan2 和 PLL 同时存在，正是因为 atan2 的输出作为 PLL 的**输入相位**——这是一个前后级关系，不是并列关系。

有些论文为了"剥离"观测器本身的误差和角度提取的误差，会同时输出 atan2 和 PLL 的结果做对照。但这种用法不要照搬到工程代码里——论文是为了分析，而你是为了跑稳定。

## 两个坑，坑坑都要避开

**坑 1：PLL 带宽设太高，系统振荡**

> **症状**：电机一转起来就嗡嗡响，相电流波形出现低频振荡，PLL 速度估计剧烈抖动。
> 
> **根因**：PLL 带宽太高，超过了电流环带宽的 1/10，角度抖动直接耦合到电流环。
> 
> **解法**：按"PLL 带宽 = 电流环带宽 / 10"的经验法则重新整定。ODrive 的稳定性检查 `current_meas_period * pll_kp < 1.0` 是一个很好的硬性约束。

**坑 2：混用不同延迟/滤波特性的相位源**

> **症状**：电机运行中突然出现角度抖动或转矩脉动，排查后发现代码里存在两个独立的相位来源（如一个来自 atan2，一个来自 PLL）。
> 
> **根因**：不要在同一控制链路里混用两个彼此独立、延迟不同、滤波特性不同、且没有时序补偿的相位源。如果 PLL 只是用来估速度，而 Park 变换仍使用 atan2/观测器相位，这是可以成立的——ODrive 和 VESC 都是这么做的——但必须确认二者来自同一观测链路，并且延迟、滤波和补偿关系清楚。
> 
> **解法**：工程上必须统一相位基准。某些方案用 PLL 相位给 Park 变换，某些方案用 atan2/观测器相位给 Park、PLL 只用于速度估计——两种架构都可以工作，但不要在同一控制链路中混用不同延迟、不同滤波特性的相位源。

## 示波器看哪里

**症状 1：角度估计周期性跳变（±180°）**

-   • **看哪里**：观测器输出的角度估计值
    
-   • **正常**：若已做 unwrap 或显示连续相位，波形是没有周期性锯齿的
    
-   • **异常**：用 atan2 时，角度在 ±180° 处跳变，波形呈锯齿状
    
-   • **根因**：atan2 的象限跳变，或 PLL 的 angle wrap 处理不当
    

**症状 2：速度估计高频抖动**

-   • **看哪里**：速度环反馈（即 PLL 输出的速度估计）
    
-   • **正常**：PLL 速度平滑，抖动幅度小
    
-   • **异常**：速度波形叠加高频毛刺，在低速区尤其严重
    
-   • **根因**：PLL 带宽太高，没有充分滤除观测器输出中的开关纹波噪声
    

## 🔧 调试 Checklist

\[ \] 确认相位基准统一：不要在同一控制链路中混用不同延迟/滤波特性的相位源和速度源  
\[ \] 检查 PLL 带宽是否在合理范围：通常速度环带宽 × 2 < PLL 带宽 < 电流环带宽 / 10（经验初值，最终以噪声、加速度和稳定性检查为准）  
\[ \] 验证离散化稳定性条件（如 ODrive 的 `current_meas_period * pll_kp < 1.0`）  
\[ \] 低速区（<10% 额定转速）观察速度估计波形，确认无高频抖动；有则降低 PLL 带宽  
\[ \] 加减速测试，对比编码器实测角度和控制实际使用的估计角度，确认滞后角度在合理范围（视应用精度要求而定）  
\[ \] 如果用 atan2 做调试对比，确认只用于显示或日志，不给控制环用
