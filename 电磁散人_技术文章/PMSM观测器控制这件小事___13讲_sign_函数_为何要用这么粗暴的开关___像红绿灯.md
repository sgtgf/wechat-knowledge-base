# 《PMSM观测器控制这件小事》| 13讲：sign 函数：为何要用这么粗暴的开关？——像红绿灯

你正在调试 SMO。示波器探头接在通过MCU的DAC管脚发出的电流误差 `s` 上，波形像一条发疯的蚯蚓——在零线上下疯狂翻转，每个控制周期都在正极限和负极限之间跳。

你盯着屏幕看了五分钟，心里冒出一个特别自然的念头：

这 sign 函数也太粗暴了吧？要么全力推，要么完全不推。误差小的时候也推得那么猛，不浪费吗？为什么不能温柔一点？比如 `u = K * s`，误差大的时候用力推，误差小的时候轻轻推，不是更合理吗？

这个念头非常合理。我头几次看 SMO 代码的时候，也是这么想的。

但后来滑模控制理论告诉我：**在 SMO 这个特定场景里，sign 的粗暴不是缺陷，是 feature。**

就像， sign 函数和线性反馈之间，差了一个红绿灯。

## 没有黄灯的红绿灯

各位同仁都等过红绿灯。红灯停，绿灯行，规则简单到不需要智商。

注意，标准的 sign 函数式就像红绿灯，但**没有黄灯**。没有"可以走但最好不要走"的过渡态，没有"看情况"的选择空间，没有"我再想想"的犹豫时间。只有两种状态：停，或者行。

sign 函数就是这样一个没有黄灯的红绿灯：

          `{ +1,   s > 0   sign(s) = {  0,   s = 0             { -1,   s < 0`

误差 `s` 只要还大于零，不管大还是小，sign 都输出 +1。满额输出，绝不手软。误差一旦过零变成负的，sign 立刻翻转为 -1，同样是满额输出，绝不犹豫。

代码里就一行：

`#define SIGN(x) ((x) >= 0.0f ? 1.0f : -1.0f)`

没有 `if-else if-else`，没有分段函数，没有查表。就一个判断，两种结果。

线性反馈呢？`u = K * s`，它就像一个有黄灯的信号系统：

-   • `s = 0.001` 时，`u = 0.001K`，绿灯刚刚亮起，几乎看不见；
    
-   • `s = 0.1` 时，`u = 0.1K`，黄灯亮了，推一点但不多；
    
-   • `s = 1` 时，`u = K`，绿灯全亮，全力推。
    

看起来线性反馈更聪明、更节能、更符合直觉。但在 SMO 这个特定场景里，这个"聪明"成了弱点。

因为电机现场有扰动。反电动势在变，负载在变，温度在变，参数在漂。线性反馈的增益 K 不能无限增大——太大了系统会不稳定。所以当一个大扰动突然袭来，误差 `s` 被拉得很远，线性反馈那点有限的推力可能就压不住扰动了。

sign 函数不管这些。误差再小，sign 也给出满额输出 ±K。就像红灯一亮，所有车都必须停，不管那辆车是自行车还是重型卡车。这个"不分对象、不分大小、一律满额"的粗暴，正是 sign 的鲁棒性来源。

说白了，在 SMO 的场景里，**线性反馈像手术刀，精准但遇到硬骨头切不动；sign 像斧头，一刀下去不分层，但保证斩断。**

## 为什么线性反馈推不动？

咱们把这个问题拆开，看看数学怎么说。

### 线性反馈的困境

假设咱们不用 sign，改用线性反馈来设计观测器。估计电流的更新方程变成：

`di_est/dt = (v - R * i_est - z_linear) / L   z_linear = K_linear * s`

其中 `s = i_est - i_meas` 是电流误差，`z_linear` 是线性反馈项，`K_linear` 是线性反馈系数，单位 **V/A**（和电阻同量纲）。

误差动力学方程是：

`ds/dt = -(R/L) * s - (K_linear/L) * s + e / L          = -(R + K_linear)/L * s + e / L`

这个方程的解是一个一阶指数收敛：

`s(t) = s(0) * exp(-(R + K_linear)/L * t) + 稳态项`

看起来挺美好的。增大 `K_linear`，收敛更快。但问题来了：

**K\_linear 不能无限增大。** 在离散实现中，`K_linear` 太大会让系统不稳定——电流估计开始震荡，甚至发散。这是因为线性反馈本质上是在观测器里增加了一个等效电阻项 `(R + K_linear)`，太大了会让系统过阻尼甚至失稳。

这就是经典控制理论里的限制：线性反馈的校正力直接依赖误差大小，而误差又受扰动影响。当外部扰动（反电动势、负载突变、参数漂移）的综合幅值很大时，线性反馈那点与误差成正比的推力可能就压不住了。

### sign 的核心优势：对微小误差的满额响应

现在把线性反馈换成 sign：

`di_est/dt = (v - R * i_est - K_slide * sign(s)) / L`

误差动力学：

`ds/dt = -(R/L) * s - (K_slide/L) * sign(s) + e / L`

这个方程里，sign 项的"等效增益"是多少？

在描述函数法（Describing Function Analysis）框架下，sign 函数对正弦输入的等效增益是 `4K_slide / (πA)`，其中 `A` 是输入幅值。关键在这里：当误差幅值 `A` 趋近于零时，等效增益趋近于**无穷大**。

这意味着什么？意味着当系统接近滑模面（`s` 很小）时，sign 提供的校正力相对于误差大小是无限大的。哪怕误差只有 0.0001A，sign 仍然输出满额的 ±K\_slide。线性反馈在 `s = 0.0001` 时只输出 `0.0001 * K_linear`，几乎没有任何推力。

**这就是 sign 相比线性反馈的核心优势。** 不是说不稳定的问题不存在了，而是说 sign 对任意小的偏离都能提供足够大的校正力，使得系统不可能因为"推力不足"而偏离滑模面。

## 鲁棒性从哪来？

[上一节](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486565&idx=1&sn=8c8f378e0a60412da1a4661b7c1ad3a1&scene=21#wechat_redirect)讲的是数学。这一节咱们聊聊工程直觉：为什么 sign 不怕现场的那些乱七八糟？

### 方向不变性

sign 的鲁棒性，核心不是来自"K 很大"，而是来自**方向不变性**。

想象一个场景：电机在额定转速下运行，反电动势是 50V。突然负载突变，反电势的等效扰动变成了 80V。你的观测器增益 K\_slide 设的是 100V。

用线性反馈：`u = K_linear * s`。如果 `K_linear` 设得不够大，大扰动会把误差 `s` 拉得很远，控制输出 `u` 也跟着变大。但如果 `u` 已经碰到了执行器饱和（比如逆变器最大输出电压），控制就"封顶"了，再多的误差也只能产生固定的最大输出。这时候等效增益急剧下降，系统失去校正能力。

用 sign：`z = K_slide * sign(s) = ±100V`。在滑模条件满足的情况下（K\_slide 足够大），扰动不会让误差 `s` 长期偏离零点。即使瞬时有扰动，`s` 的符号仍然反映了估计电流偏大的事实，sign 输出 -1，控制仍然往正确的方向推。

**只要 K\_slide 足够大，sign 的输出方向就由误差符号决定，而这个方向不会被扰动轻易颠倒。** 这就是鲁棒性的精确来源。

线性反馈的输出大小依赖误差，误差依赖扰动，扰动大了误差就大，误差大了可能饱和，饱和了等效增益减小。这是一个脆弱的链条。

sign 的输出大小不依赖误差（永远是 ±K），只依赖误差的符号。链条少了一环，自然就 robust。

### 参数漂移？无所谓

Li 和 Elbuluk 在 2001 年的经典论文里做了一个仿真：把定子电阻偏调到 200%，定子电感偏调到 100%，观测器照样稳定，位置估计无稳态误差 \[S-002b\]。

为什么？因为 sign 不在乎你的电阻到底是 0.035Ω 还是 0.07Ω。sign 只看误差的符号。参数漂移改变了系统的具体动态，但只要误差的符号没有因为漂移而翻转，sign 就继续往对的方向推。

线性反馈呢？参数漂移改变了系统的极点位置，原来的 `K_linear` 可能就从"刚好稳定"变成"震荡发散"。你需要重新整定增益，而现场往往没条件给你慢慢调。

说白了，**线性反馈对模型精确度有要求，sign 对模型精确度没要求——它只要求你知道误差在哪边。**

## 粗暴的代价：频谱

sign 给了你这么强的鲁棒性，代价是什么？

频谱。

sign 函数在 `s = 0` 处有一个**跳变**。从数学上说，不连续函数的傅里叶变换包含无限高频分量。理想 sign 在滑模面上会以无限频率切换，产生覆盖整个频谱的高频噪声。

这就是**抖振**的数学根源。

咱们用一个直觉类比来理解这件事。想象你用刀切蛋糕：

-   • 线性反馈像一把锋利的刀，切口平滑，蛋糕切面很干净。但如果你要切的是冻硬的黄油，刀可能切不动。
    
-   • sign 像一把斧头，冻黄油也劈得开。但斧头的切口不是平滑的，而是崩裂的，碎屑四溅。
    

那些"碎屑"就是高频分量。sign 为了在零点处实现无限陡峭的切换，不得不产生无限多的谐波。

在实际数字控制器里，这个理想模型被两个因素修正：

**第一，采样频率。** 你的控制周期是 50µs（20kHz），sign 的切换频率不可能超过这个上限。高频分量被采样过程**混叠**（aliasing）到了低频，表现为电流纹波和位置估计噪声。

**第二，实现方式。** 工程代码里的 sign 通常不是数学意义上的理想 sign。浮点比较的精度限制、ADC 噪声导致的零点抖动、滞环（hysteresis）的引入，都会让实际切换比理论模型"软"一些。

但这些修正只是缓解，不是消除。只要你在用 sign，高频分量就是结构性代价。下一篇咱们聊怎么用 LPF 从这些高频碎屑中提取出真正的信号——等效控制。

## 代码里的 sign 长什么样

### VESC 的纯 sign 实现

VESC 的代码里，sign 就是一个宏定义，粗暴到极点：

`// 来源: VESC/Firmware/motor/foc_math.c 及相关头文件   #define SIGN(x) ((x) >= 0.0f ? 1.0f : -1.0f)      // 在 SMO 中的使用   float s_a = i_alpha_est - i_alpha;   float z_a = K_slide * SIGN(s_a);   // ±K_slide，没有中间值`

没有边界层，没有饱和，没有过渡。误差大于等于零就是 +1，小于零就是 -1。在浮点实现中，`s_a` 恰好等于零的概率极低，所以零点定义取 +1 还是 -1 几乎不影响。

### AN1078 的工程折中

AN1078 的实现则"温柔"一些：

`// 来源: AN1078, Sensorless FOC of a PMSM      Error = i_est - i_meas;   // 滑模面 s      if (fabs(Error) <= MaxSMCError)       Z = K_slide * Error;                    // 边界层内：线性过渡   else       Z = K_slide * MaxSMCError * sign(Error);  // 边界层外：饱和到 ±K_slide`

AN1078 在边界层内用了线性反馈，边界层外才用 sign。这不是因为 sign 不好，而是因为纯 sign 的抖振在低成本家电电机上太吵、损耗太大。工程师在"理论严格性"和"现场可接受性"之间做了折中。

这个折中是合法的、成熟的、值得尊重的。不要觉得 AN1078 "不正宗"——它卖了十几年，装在几千万台空调压缩机里，比任何论文都更有资格谈"工程"。

### 滞环实现：给红绿灯加一点"犹豫时间"

有些实现会给 sign 加一层滞环（hysteresis）：

`float sign_with_hysteresis(float x, float eps) {    if (x > eps)  return 1.0f;    if (x < -eps) return -1.0f;    return sign_prev;   // 在 [-eps, eps] 内保持上一个状态   }`

滞环的作用是防止噪声导致 sign 在零点附近频繁翻转。就像红绿灯加了"全红间隔"——所有方向都红两秒，清理路口。滞环的 `eps` 通常设为电流采样噪声的 2~3 倍。

## 调试技巧与常见坑

### 示波器看哪里

**第一，看 sign 输出 `z` 的波形。**

正常状态下，`z` 应该在 `+K_slide` 和 `-K_slide` 之间高频翻转。如果你看到 `z` 长期停留在某一侧（比如连续几十个周期都是 +K），说明要么系统根本没进滑模面（K\_slide 太小），要么误差一直没有过零（可能是 LPF 相位滞后导致）。

**第二，看 `s` 的符号切换频率 vs 控制频率。**

理想情况下，切换频率应该远低于控制频率。如果每个控制周期都 flip，说明要么噪声太大，要么 K\_slide 太大、系统在过阻尼震荡。试试加大滞环宽度 `eps` 或引入边界层。

**第三，比较 `z` 和 LPF 输出 `e_est` 的幅值。**

`z` 的幅值约等于 `K_slide`，而 `e_est`（反电动势估计）的幅值应该和转速成正比。如果你发现 `e_est` 的幅值远小于 `z` 的幅值，说明 LPF 截止频率太低，把有用的等效控制也滤掉了。

### 常见坑

**坑一：把 sign 当成放大器**

有些同仁误以为 `K_slide * sign(s)` 的幅值会随误差大小变化。不会。sign(s) 永远是 ±1，`z` 的幅值永远是 K\_slide。如果你想根据误差大小调整推力，那你想要的是线性反馈或边界层，不是纯 sign。

**坑二：浮点零判断**

在浮点实现中，`s == 0.0f` 几乎永远不会发生。所以 sign 的零点定义（+1 还是 -1 还是 0）不重要。但如果你把 sign 用在整数实现里，零点处理就要小心——建议统一按 +1 处理，避免死区。

**坑三：K\_slide 越大越好**

K\_slide 大确实增强鲁棒性，但代价是抖振。太大的 K\_slide 会让 sign 输出过强的切换力，电流估计在滑模面附近剧烈震荡，LPF 滤完之后仍然有噪声。K\_slide 的整定要在"压得住扰动"和"抖振可接受"之间找平衡，不是无脑往大调。

* * *

sign 函数是 SMO 的灵魂。

滑模面是骨架，告诉你往哪推；sign 是肌肉，负责用力。但没有 sign 的不连续性，这个肌肉就是虚的——线性反馈那点有限的推力，根本压不住现场的扰动。

sign 的粗暴正是它的力量来源。没有黄灯，就没有犹豫；没有犹豫，就没有被扰动钻空子的机会。代价是高频碎屑（抖振），而工程上的各种折中——边界层、饱和函数、滞环、Super-Twisting——都是在"保留 sign 的鲁棒性"和"降低抖振的代价"之间找平衡。

下一篇，咱们聊聊怎么从这些高频碎屑里，把真正的信号挖出来。

## 🔧 调试 Checklist

\[ \] sign 输出 `z` 是否在 `±K_slide` 之间高频翻转？长期单侧停留说明 K\_slide 太小或 LPF 滞后  
\[ \] K\_slide 是否大于额定转速下最大反电动势的 1.5~2 倍？裕量不足会导致扰动下方向翻转  
\[ \] 如果用了边界层，MaxSMCError 是否平衡了抖振和跟踪精度？  
\[ \] 浮点 sign 实现是否避免了零点死区？建议 `>= 0` 取 +1，`< 0` 取 -1  
\[ \] 比较 `z` 和 `e_est` 的幅值，确认 LPF 没有把等效控制过度滤除
