在高性能计算领域，程序优化是一项至关重要的任务。其中，循环作为程序中最常见的结构之一，其优化对于提升程序性能尤为关键。本文将聚焦于 Fortran 语言，探讨几种常见的循环优化策略，包括循环交换、循环合并、循环分解、循环分块以及循环展开，以期帮助开发者们提炼出更高效、更优雅的代码。

基本原理

  

通常，程序访问内存的时间消耗绝大多数集中在对少数区域的访问。大量实践表明：在程序执行过程中，90% 的内存访问实际上集中于 10% 的内存区域，这就是程序的**局部性原理**（Local Principle）。

![](https://mmbiz.qpic.cn/sz_mmbiz_png/icVUVTFlBCVV2sGibKf4Tib0rjU99oiaiap03tdw90Lg92ibRP245LmETutax2iaWVxiaQFsFo2d3rbhA1dbvpyRyRzHhg/640?wx_fmt=png&from=appmsg)

  

程序的局部性可分为如下两种情况：

-   **时间的局部性**（Temporal Locality）：如果一个区域被访问，那么它将被再次访问的概率也较大，这主要是指那些需要频繁访问的热点数据。
    

![](https://mmbiz.qpic.cn/sz_mmbiz_png/icVUVTFlBCVV2sGibKf4Tib0rjU99oiaiap03LR5WakPM2D4eWlsIoY97a0QvbWEoQdqHd9TT4PljHJ3AyuwkGXAEDA/640?wx_fmt=png&from=appmsg)

  

-   **空间的局部性**（Spatial Locality）：如果一个区域被访问，那么与它相邻的区域被访问的概率也较大。这是因为 CPU 对内存的访问通常是将一个连续区域内的所有数据均读取到缓存中。
    

![](https://mmbiz.qpic.cn/sz_mmbiz_png/icVUVTFlBCVV2sGibKf4Tib0rjU99oiaiap03fUc34SZYfoBbLHhUHCTPZU6hckXkbZib2KdCE3deX1N9u7rl2gkRn2A/640?wx_fmt=png&from=appmsg)

  

提高缓存命中率的一个简单原则是**尽量改善数据访问的局部性**，使 CPU 需要访问的数据尽可能连续地存放在同一个内存区域，或者长时间地驻留缓存。这样，编程人员可以通过**循环变换**来改变指令执行顺序，从而提高缓存命中率。

循环变换的**优点**在于：实施循环变换后的程序可以在不同平台上运行，具有很好的通用性。这是因为循环变换是通过改变程序自身的局部性来提高缓存性能，与平台无关，也不需要特定硬件的支持。

循环变换的**难点**在于：在进行循环变换的过程中，既要保证变换前后程序代码的正确性，还要保证变换前后程序可执行语义的等价。

循环交换：改善空间局部性

  

循环交换是改变嵌套循环的次序，以提高数组访问的空间局部性，增强CPU缓存的命中率。在 Fortran 语言中，数组是按列优先顺序存储的。因此，访问三维数组 `a(i, j, k)` 时，推荐将循环指标变量 `i` 作为内层循环的指标变量，采用 `kji` 顺序的循环嵌套能确保数据访问的连续性，进而提高缓存性能。例如：

`do k = 1, n     do j = 1, m       do i = 1, l         a(i, j, k) = b(i, j, k) + 3       end do     end do   end do   `

这种循环次序可以使得数据访问更加连续，从而提高缓存的命中率。

循环合并：减少循环开销

  

循环合并是将多个小循环合并为一个大循环，以改善数据的时间局部性。这种方法可以减少循环的开销，并增加循环的粒度，有利于多线程的并行执行。例如，原本独立的两个循环：

`do i = 1, m     b(i) = a(i) + 3   end do      do i = 1, m     c(i) = b(i) * 3   end do   `

可以合并为：

`do i = 1, m     b(i) = a(i) + 3     c(i) = b(i) * 3   end do   `

这样，既保证了数据依赖关系，又减少了循环的开销。

循环分解：消除循环依赖

  

与循环合并相反，循环分解是将一个大循环拆分为多个小循环。如果一个大循环中的数据之间存在依赖关系，那么可以通过循环分解方法将这些数据分配到不同的循环中，以消除或减弱这些循环依赖关系，改善数据的空间局部性。

例如，下述循环存在着复杂的循环依赖关系：

`do i = 1, m     b(i) = a(i-1) + b(i)     a(i) = c(i-1) * x + y     c(i) = 1. / a(i)     d(i) = c(i)**3 + b(i)   end do   `

分解后的循环如下：

`do i = 1, m     a(i) = c(i-1) * x + y   end do   do i = 1, m     c(i) = 1. / a(i)     b(i) = a(i-1) + b(i)     end do     do i = 1, m     d(i) = c(i)**3 + b(i)   end do   `

## 

这样，对于存在循环依赖的小循环，后续可以采用串行方式执行；对于不存在循环依赖的小循环，可以采用并行方式执行，从而提高程序的性能。

循环分块：优化大型数组访问

  

循环分块策略根据缓存大小将循环分割，确保每次只处理可以完全装入缓存的数据块，以此提高时间局部性。在分块的过程中，一定要关注“尾巴”的处理。例如，对于双层循环：

`do i = 1, m     do j = 1, n       x(i) = x(i) * y(j)     end do   end do   `

通过分块，可以优化为：

`do j = 1, n, dn     do i = 1, m       do jj = j, min(j+dn-1, n)         x(i) = x(i) * y(jj)       end do     end do   end do   `

这里的 `dn` 是分块的大小，其值需要根据缓存的大小来确定，以确保 `y(j:j+dn-1)` 能够被容纳在缓存中。

循环分块是一项比较复杂的优化技术，其分块方式和分块参数通常需要根据实际代码和缓存结构，经过细致的分析和大量的数值实验来确定。这种优化方式一般仅用于需要深度优化的场合。

循环展开：减少分支开销

  

循环展开是通过多次复制循环体代码，来减少循环分支指令的开销，从而加快程序的执行速度。这种方法通过增加指令调度的空间，减少循环开销，有助于充分发挥 CPU 性能。例如，对数组求和：

`do i = 1, m     sum = sum + x(i)end do   `

展开后：

`do i = 1, mod(m, 4)     sum = sum + x(i)end do   do i = mod(m, 4) + 1, m, 4     sum = sum + x(i) + x(i+1) + x(i+2) + x(i+3)   end do   `

可以看出，对循环进行手工展开是十分麻烦的。为此，在实际应用中，通常使用编译器的相关编译开关进行循环的自动展开。例如，GFortran 提供了 -funroll-loops 开关，用于指定对代码中的循环进行展开。

结语

  

循环变换是串行程序优化中的一项重要技术。通过上述几种策略，我们可以有效提高程序的缓存命中率和执行效率。在实际应用中，选择合适的循环变换策略需要根据具体的程序特点和硬件环境进行细致的分析和实验。通过这些优化，我们可以使程序运行得更快，更高效。
