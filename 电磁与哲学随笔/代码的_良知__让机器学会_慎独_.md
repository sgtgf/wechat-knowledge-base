# 代码的“良知”：让机器学会“慎独”

原创 傅存敬 电磁散人 2026-01-11 07:06 广东

> 原文地址: [https://mp.weixin.qq.com/s/myIL-QYb2TaGiAQQ6s6mFA](https://mp.weixin.qq.com/s/myIL-QYb2TaGiAQQ6s6mFA)

我最近一直在思考一个问题：在今天这个硬件性能日益趋同的时代，是什么在定义一个“好”的工业产品和一个“伟大”的工业产品之间的区别？

是更多的功能吗？是更快的响应速度吗？

这些都很重要。但在我看来，真正拉开差距的，是一种看不见、摸不着，却能被用户在漫长使用周期里清晰感知到的东西——**产品的“品格”**。

一个有品格的产品，是可靠的，是诚实的，是值得托付的。而这种品格，在嵌入式世界里，源自于代码深处的一种设计哲学。我称之为：**让机器学会“慎独”**。

“慎独”，是中国儒家思想里的一个极高境界。它指的是在无人监督之时，一个人的言行举止依然合乎道义，不欺暗室。

那么，一台冰冷的机器，一个电机控制器，如何“慎独”？

答案就在它上电之后、真正开始旋转输出力矩之前那关键的几百毫秒里。在这短暂的、无人监督的“独处”时间里，它在做什么，决定了它未来全部工作时间的可靠性。

我见过太多平庸的控制器。它们的逻辑是：上电，初始化参数，等待指令，执行。简单直接。

但卓越的控制器，它的灵魂里被工程师注入了一种“三省吾身”的机制。它会利用这段时间，完成三件大事，这三件事，就是机器“慎独”的具体体现。

**第一省：履职前的“忠诚”——我，准备好了吗？**

“为人谋而不忠乎？” 这是曾子对自己的第一个拷问。翻译成机器的语言就是：**“我即将为整个系统服务，我的自身状态是否对得起这份托付？”**

一个卓越的电机控制器，在上电后做的第一件事，不是等待，而是**全面的自我体检。**

它会检查电流传感器的零点漂移。如果传感器告诉它，在没有任何电流流过的情况下，读数是0.1安培，它不会默默接受。它知道，这是一个“幻觉”。带着幻觉去闭环控制，就像一个飞行员戴着一块走时不准的手表去导航，后果是灾难性的。

所以，它会通过算法（比如最小二乘法）精确地测量出这个“幻觉”——也就是零点偏置——是多少，然后在后续的所有计算中减去它。如果它发现这个偏置大到离谱，超出了预设的容忍范围，它会勇敢地“罢工”，上报一个 `PM_ERROR_ZERO_DRIFT_FAULT` 错误。

这看似是一次“罢工”，但这恰恰是机器最高级别的**“忠诚”**。它忠于它的核心使命——精确、安全地控制电机。为了这个使命，它宁可不出工，也绝不带病上岗。

这种设计，就是把产品的可靠性，从“期望可靠”提升到了“必须可靠”的哲学高度。

**第二省：数据上的“诚信”——我，看到的是真相吗？**

“与朋友交而不信乎？” 这是第二个拷问。对于机器而言，它的“朋友”就是它的传感器。传感器就是它感知物理世界的眼睛。控制器和它的主控MCU之间，必须建立在绝对**“诚信”**的数据基础上。

平庸的设计，对于传感器数据，可能就是一个简单的滤波，去去毛刺。但我们都清楚，传感器的误差不仅有随机的噪声，还有系统性的增益误差。也就是说，它的眼睛不仅可能“眼花”，还可能戴着一副“哈哈镜”。

一个学会“慎独”的控制器，它对数据的态度是**“实事求是”**。

它会利用电机绕组自身的物理约束——比如基尔霍夫电流定律（流入节点的电流和永远为零）——来创造一个**“对质”**的场景。它会主动在AB两相间注入一个测试电流，这时，物理定律告诉它，A相电流应该精确地等于B相电流的负值。

如果传感器A告诉它电流是1.0A，而传感器B告诉它是-1.1A，它就知道，这里面一定有谁“不诚实”。它不会偏信任何一方，而是通过复杂的矩阵运算，解算出每一路传感器的增益误差，然后进行补偿。

更进一步，它还会计算数据的“标准差”。如果数据抖动得太厉害，说明信噪比太低，它会认为这个结果“不足为信”（`PM_ERROR_UNCERTAIN_RESULT`），并拒绝使用。

这种对数据源的极致较真，就是机器的“诚信”。它保证了控制器输出的每一份力，都是基于对物理世界最真实的认知。而这份真实，最终会转化为电机极其平顺的旋转、极低的噪音和极高的效率。

**第三省：认知后的“验证”——我，真的理解了吗？**

“传不习乎？” 这是第三个拷问。意思是，学到的知识，有没有去反复温习、实践验证？对机器来说，就是：**“我校准出的参数，在真实的闭环场景下，管用吗？”**

在校准电流增益时，它不是简单地给一个开环电压，然后去读电流。因为这样做，结果很不稳定。

卓越的设计，会临时在内部构建一个**小小的、专用于“温习”的PI控制器**。它给自己设定一个目标（比如，让电流从0线性爬升到1A），然后像一个学生做练习题一样，不断地根据误差（`eA = target - feedback`）来调整自己的输出电压，直到电流精确地跟随目标。

这个过程，就是一次**“演习”**。

它在演习中，不仅得到了在动态响应下的真实数据，还顺便验证了整个控制回路的健康度。如果它发现自己使出了九牛二虎之力（积分器饱和），电流还是纹丝不动，它就知道，回路可能断了（`PM_ERROR_CURRENT_LOOP_FAULT`）。

这种“学”与“习”的结合，让校准过程从一个静态的测量，变成了一个动态的、有反馈的验证。这是一种深刻的工程智慧。

**最后，我想说**

对于一线工程师来说，我们的工作，远不止是实现一个个功能。我们是在用代码，为一个产品注入“品格”。下一次，当你设计一个自检程序时，不妨问问自己，我是在让它走个过场，还是在教它学会“慎独”？

对于行业里的操盘手们，我想说，一个懂得“慎独”的机器，背后是一个懂得“慎独”的团队和一种追求卓越的企业文化。这种由内而外的可靠性，是任何市场宣传都换不来的。

在一个万物互联的时代，机器将被前所未有地委以重任。我们托付给它们的，是生产效率，是驾驶安全，甚至是生命。

**而我们能给予它们最宝贵的，不是更快的CPU，而是注入代码的“良知”。**

这，才是我们这个行业，最深的护城河。
