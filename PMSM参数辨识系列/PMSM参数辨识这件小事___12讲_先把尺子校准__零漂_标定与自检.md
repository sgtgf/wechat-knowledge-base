### 3.1 核心思想：利用“两点法”标定线性系统

我们知道，电压采样电路（分压电阻 + 运放/ADC）通常是一个线性系统：

Vadc = k·Vactual + b

或者反过来，我们要算出真实电压：

Vactual = Scale · Vadc + Offset

要解出这个方程里 Scale（增益）和Offset（偏置），我们需要**两个点**：

1.  **点 A（零点）**：把输出电压设为 0V（GND）。
    
2.  **点 B（满量程）**：把输出电压设为母线电压（VBUS）。
    

只要测出这两点下 ADC 的读数，我们就能画出这条直线，算出校准参数。

#### case 4: 求解与增量更新（最精彩的部分）

这里用到了一个非常高级的**增量校准算法。**

我们原本的计算公式是：

Vout = Sold · Vadc + Oold

这个公式描述的是：**在校准之前，控制器是怎么根据 ADC 的读数算出电压值的。**

-   **Vadc (ADC Reading)**：
    

-   这就是单片机 ADC 寄存器里读出来的那个原始整数（比如 0 到 4095）。
    
-   在代码里对应 `fb->voltage_A` 等原始值。
    

-   **Sold (Old Scale / Gain)**：
    

-   这是**当前的增益系数**。
    
-   它的物理意义是：ADC 每增加 1 个字，代表电压增加了多少伏。
    
-   在代码里对应 `pm->scale_uA[1]`（注意是下标 1）。
    

-   **Oold (Old Offset / Bias)**：
    

-   这是**当前的偏置系数**。
    
-   它的物理意义是：当 ADC 读数为 0 时，对应的物理电压是多少伏（通常用来修正运放的零点漂移）。
    
-   在代码里对应 `pm->scale_uA[0]`（注意是下标 0）。
    

-   **Vout (Output Voltage)**：
    

-   这是控制器**目前认为**的电压值。
    
-   注意！这个值**可能是不准的**（因为 Sold 和 Oold 可能已经过时了或者有误差），所以我们才需要校准。
    

LSE（最小二乘法）通过对比“目前算出来的电压Vout”和“真实目标电压Vtarget”，拟合出了它们之间的关系：

Vout = k1 · Vtarget + k0

-   k1 (`ls->sol.m[1]`)：目前的增益误差比例（如果准的话应该是 1）。
    
-   k0 (`ls->sol.m[0]`)：目前的零点误差（如果准的话应该是 0）。

#### 安全检查（Safety Check）

通过以上的增量校准算法算出结果后，代码没有马上用，而是先做了一堆检查：

1.  **结果有效性**：`m_isfinitef`，防止算出无穷大或 NaN。
    
2.  **合理性检查**：
    

-   `m_fabsf(ls->sol.m[0]) > pm->fault_voltage_tol`：如果算出来的零点偏置太大（比如偏了 10V），说明硬件可能有断路或短路，**报错！**
    
-   `m_fabsf(ls->sol.m[1] - 1.f) > pm->fault_accuracy_tol`：如果算出来的增益变化太大（比如增益变成了 1.5 倍），说明分压电阻可能烧了或者变质了，**报错！**
    

### 3.3 本段代码小结

这段 `pm_fsm_state_adjust_on_pcb_voltage` 的精彩之处在于：

1.  **自举自纠**：它不需要外部高精度的电压源，而是利用**母线电压采样电路**（通常精度较高且不需要高速采样，比较稳定）作为基准，来校准**三相端电压采样电路**（通常需要高速采样，容易受干扰）。这是一种“以稳准快”的策略。
    
2.  **两点法线性拟合**：利用 0V 和 VBUS 两个极端点，精准锁定了线性方程的斜率和截距。
    
3.  **硬件保护细节**：在输出 VBUS 进行校准时，还贴心地考虑了自举电容的充电限制，防止为了校准把驱动电路搞挂了。
    
4.  **增量迭代与安全边界**：不仅能自动修正参数，还能识别出“修正量过大”的异常情况，守住了安全的底线。
    

这就像是一个狙击手，在开枪（闭环控制）之前，先打两枪靶子（0V 和 VBUS），根据弹着点自动修正瞄准镜的刻度。有了这个功能，各位的电机控制器即使在大批量生产中电阻有公差，或者长期使用后器件老化，也能通过一次“自检”自动恢复高精度！

### 4.1 魔术的道具：三相全桥电路

我们要校准的是 A、B、C 三个电流传感器，也就是`scale_iA[1]`、`scale_iB[1]`、`scale_iC[1]`这三个增益系数。

代码作者的思路是：虽然我不知道绝对电流是多少，但我可以让**同一股电流**流过不同的传感器！

-   **场景一**：打开 B 相上管，打开 C 相下管。电流路径是：电源 → B相桥臂 → 电机线圈 → C相桥臂 → 地。
    

-   根据串联电路原理：Ib = -Ic（绝对值相等）。
    
-   如果我们测出来的 Ib 和 Ic 绝对值不相等，那就说明这两个传感器的比例不对！
    

-   场景二：A → B。
    
-   场景三：A → C。
    

只要把这三种组合都测一遍，我们就能建立起三个传感器之间的**比例关系**。

#### case 6: 正则化约束

这里有一个很容易被忽略的细节：

我们有三个未知数Ka, Kb, Kc，但只有两个独立的比例方程（A/B 和 B/C，第三个 A/C 是相关的）。

这意味着方程有**无穷多解！**（比如 1, 1, 1 是解；2, 2, 2 也是解）。

我们需要引入一个**约束条件**，才能求出唯一解。通常我们会假设：**“三个系数的乘积为 1”**或者**“三个系数尽量接近 1”**。

代码里用了一个很隐晦的方法：

```
                REF = 1.E-2f;    /* regularization constant */
```

**以上这段代码翻译成大白话就是**： 这是告诉求解器：“嘿，虽然我不知道绝对值是多少，但你尽量让 Ka, Kb, Kc 都接近 1.0，别给我算出个 100, 100, 100 来。”这叫**正则化（Regularization）**，是解决病态方程组的标准手段。

#### case 7: 求解与更新

最后解出`lb`，得到的就是三个**修正系数**。

```
                pm->scale_iA[1] /= lb->sol.m[0];
```

**代码小结：这段电流校准的代码厉害在哪儿？**

1.  **无源校准**：不需要昂贵的外部电流源，仅仅利用电机自身的绕组作为导线，就把三个传感器的**一致性**校准得非常完美。
    
2.  **意义重大**：在 FOC 控制中，三相电流的**平衡**比**绝对精度**更重要！如果 A 相偏大 5%，B 相偏小 5%，算出来的磁场角度就会有巨大的脉动，导致电机转矩波动、噪音大。
    
3.  **相对精度 vs 绝对精度**：这个函数保证了 Ka : Kb : Kc = 1 : 1 : 1 。虽然绝对值可能整体偏大或偏小 1%，但这对 FOC 的影响很小（只是力气大点或小点），而**不平衡**的影响是致命的。
    

**这就是高手的思维：**在资源受限（没有标准源）的情况下，抓住主要矛盾（三相平衡性），利用数学工具（LSE 和正则化），四两拨千斤地解决了问题。

这段代码值得我们（尤其是我个人）好好膜拜一下。

## 五、本讲落地：给三类工程师的行动指南

今天我们看到了代码A这位“老师傅”是如何打磨尺子的。这对我们团队意味着什么？

### 1\. 对硬件工程师

-   **PCB设计的“可标定性”**: 代码A的电压标定依赖于“全上管导通”和“全下管导通”能产生稳定的Vdc和GND。如果你的硬件设计里，母线电压采样点和逆变器桥臂之间有很大的压降（比如走线太细），或者地平面干扰严重，这个标定就会失效。
    
-   **电流采样的一致性**: 代码A虽然能软件校准增益，但它校不准**非线性**。如果你的采样电阻温漂太大，或者运放在不同电流下的增益不线性，软件是救不回来的。
    

### 2\. 对算法工程师

-   **把标定流程作为“开机仪式”**: 不要把这些标定代码仅仅当成一段“只跑一次”的初始化代码。建议在每次电机**Enable**之前，或者在系统**空闲**时，周期性地去跑一下`ZERO_DRIFT`。因为温度变了，零漂就会变。
    
-   **理解 LSE 的威力**: 代码A展示了 LSE 不仅能做拟合，还能做统计平均。在各位同仁写其他数据处理逻辑时，也可以借鉴这种“收集数据 → 统一求解”的模式，比单纯的滑窗滤波更灵活。
    

### 3\. 对测试工程师

-   **验证标定的效果**: 怎么知道标定准不准？
    
    **零漂验证**: 标定完后，给个零电流指令，用示波器抓ADC原始值，看是否在0附近跳动，且均值为0。
    
    **增益验证**: 用源表给三相注入同样的直流电流（比如5A），通过调试口读`fb_iA, fb_iB, fb_iC`。标定前可能参差不齐，标定后应该非常一致。
    
    **电压验证**: 用万用表测母线电压，对比软件读到的`const_fb_U`，误差应在1%以内。
    

## 六、本文小结：

各位同仁，今天我们把“尺子”校准了。现在的控制器，看电压、看电流，都是精准且一致的。

但是，这把尺子去量“静止的东西”很准，量“动的东西”还准吗？

特别是我们要测的第一个电机参数——**定子电阻 Rs**。

你可能会说：“测电阻有什么难的？欧姆定律`R = U/I`，给个电压，测个电流，一除不就完了？”

**事情没那么简单。**

我们在第6讲里说过，“[电压的谎言](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247485015&idx=1&sn=89ace6f66ffe529b7454c3aff075e026&scene=21#wechat_redirect)”——死区和压降会偷走电压。如果你直接用 `U_cmd / I_fb` 来算电阻，算出来的结果肯定偏大，因为`U_cmd`里包含了一部分根本没加到电阻上的“过路费”。

**我们下一讲的要解决的问题是：**

**“代码A是如何在辨识电阻的同时，把‘死区’这个讨厌的‘过路费’也一起算出来的？**

**它用到了一个非常巧妙的数学技巧：‘直线拟合’。它不是测一个点，而是测两个点、三个点，画出一条直线。这条直线的斜率是电阻，那它的截距是什么呢？**

**没错，截距就是死区！”**

下一讲，我们将进入**Rs与deadband辨识**的精讲，看看代码A是如何用一次测量，同时抓住两个参数的。
