## 量角器怎么量两个正弦波的角度？

各位同仁，咱们先来打个比方。

想象你手里有一个透明的量角器，中心点钉在坐标原点。e\_alpha 是量角器水平方向的读数（邻边），e\_beta 是垂直方向的读数（对边）。这两个数合起来，就是一个二维向量。

atan2 的作用就是：**告诉这个向量指向哪个方向**。

数学上很简单：

通俗来讲，`arctan2(y, x)` 和普通的 `arctan(y/x)` 有什么区别？

普通的 arctan 只能回答"斜率是多少"，它不知道你在第一象限还是第三象限。因为 `arctan(1/1)` 和 `arctan(-1/-1)` 算出来都是 45°，但这两个向量的方向差了整整 180°。

**atan2 的关键就在这：它接收两个独立参数 y 和 x，根据它们的符号判断象限。**

标准的 atan2 算法流程是这样的：

先算 `abs_y = |y|`，然后比较 `x` 和 `0` 的大小。如果 `x >= 0`，向量在第一或第四象限，用 `(x - abs_y) / (x + abs_y)` 算一个中间变量 r，再代入多项式得到 0-π/2 之间的基准角。如果 `x < 0`，向量在第二或第三象限，用 `(x + abs_y) / (abs_y - x)` 算 r，得到 π/2-π 之间的基准角。最后检查 y 的符号：y 为负说明在第三或第四象限，把基准角取负。

换句话说，atan2 是个带象限判断的量角器。没有它，你的角度估计会在第二、第三象限莫名其妙地翻转到对面去。

这对应到物理直觉上：e\_alpha 和 e\_beta 是反电动势在静止坐标系（α-β 轴）上的投影。转子每转一圈，这两个投影画出一个圆。但 atan2 读出的**是这个圆上某一点的方位角**，未必直接等于转子磁链角——取决于你代入的是什么向量。

如果你不小心写成了 `atan2(e_beta, e_alpha)`，读出来的就不是转子角，而是 BEMF 向量本身的方位角——和转子角差了 90°。

**这是最常见的坐标陷阱之一。** 不同教材和代码库对 e\_alpha/e\_beta 的符号定义并不统一。有些定义把负号包在 e\_alpha 里，有些定义把负号包在观测器方程里，有些代码直接从磁链取角。如果你把一种约定下的公式套到另一种约定的代码上，角度估计和真实角度之间就会差一个固定偏移——通常是 90° 或 180°。

这个偏移在高速时不容易暴露，因为固定小偏移带来的 dq 混叠可能被外环或电流裕量掩盖，但效率会下降、带载能力会变差。一旦偏移达到 90° 或 180°，那就是严重的坐标错误，电流环再强也救不回来。如果偏移不是固定值，而是随转速漂移，那电流环就会一直在"追"一个错误的基准。

很多工程师在这里栽过跟头：SMO 跑通了，atan2 算出来了，电机就是转不顺，带载时电流环饱和，效率比有感模式低一截。调了三天参数，最后发现是坐标系定义差了一个负号。

说白了，atan2 只管"向量指向哪"，不管"这个向量是不是你想量的那个向量"。符号约定不一致，量角器再准也白搭。

## 象限跳变：180° 和 -180° 其实是同一个方向

atan2 输出范围是 \[-π, π\]。这带来一个经典问题：**圆周不连续**。

想象一个时钟。11:59 分针指向 354°，12:01 分针指向 6°。这两根针几乎贴在一起，但数字上差了 348°。

atan2 也是一样。当转子角度从 179° 慢慢转到 181°，atan2 的输出会从 3.12 rad 突然跳到 -3.12 rad。物理上转子只转了 2°，数字上却像转了 358°。

**这就是象限跳变。**

如果你拿它做差分求速度，`Δθ = θ[n] - θ[n-1]` 会在跳变点算出一个荒谬的值——比如 -6.26 rad/100μs，对应的速度可能是几十万 rpm。如果你把它送进 LPF 或 PLL 做误差计算，未做 wrap 保护的相位差同样会被误判为一个巨大的阶跃。

不过有一个细节值得注意：**直接把跳变后的角度拿去做 Park 变换，sin/cos 本身不会崩**。因为三角函数是周期连续的，179° 和 -179° 的 sin/cos 值几乎一样。真正受害的是后续处理——差分、滤波、PLL 误差计算，以及任何依赖角度单调性的逻辑。

这个 bug 在代码里特别阴险，因为它**只在角度 wrap 边界附近触发**。你高速测试几百次都不一定能碰到，但偏偏在客户现场、负载突变、转速波动的场景下，它就跳那么一下。就一下，足够让后续依赖角度单调性的逻辑（差分、滤波、PLL 误差）全部错乱。

工程上怎么防？我总结了三个思路。

**思路一，角度归一化。**

每次拿到新的 θ，先把它拽到 \[-π, π\] 区间：

`// 将角度归一化到 [-pi, pi]   while (theta > M_PI) theta -= 2.0f * M_PI;   while (theta < -M_PI) theta += 2.0f * M_PI;`

VESC 里的 `utils_norm_angle_rad()` 干的就是这个。ODrive 的 `wrap_pm_pi()` 也是同一逻辑。

**思路二，差分时的跳变保护。**

做差分之前，先检查 Δθ 是不是离谱地大。如果 |Δθ| > π，说明发生了跳变，给它补一个 2π：

`float delta = theta_now - theta_prev;   if (delta > M_PI) delta -= 2.0f * M_PI;   if (delta < -M_PI) delta += 2.0f * M_PI;   float omega = delta / Ts;  // 这才是合理的速度`

VESC 的 `utils_angle_difference_rad()` 封装了这个逻辑。它的作用不是消除跳变，而是**让差分不受跳变影响**。跳变还在，但至少不会把速度算成天文数字。

**思路三，干脆不要用差分求速度。**

这是最狠的一招，也是后面 PLL 要解决的问题。atan2 输出本身已经带噪声，再差分一次等于把噪声放大了一遍。这就是为什么工业界主流方案不在 atan2 后面直接做差分，而是接 PLL。

说白了，atan2 只管"现在指向哪"，不管"刚才指向哪"。前后两帧之间如果没有做跳变保护，它就是一颗定时炸弹——你不知道它什么时候炸，但你知道它一定会炸。

## 盲区一：低速下的"失明"

这是 atan2 最致命的盲区。

反电动势的幅值和转速成正比：

高速时 ω\_e 大，|e| 几十伏，e\_alpha/e\_beta 波形顶天立地，atan2 随便算都准。但低速时——比如 5% 额定转速——|e| 可能只有几伏甚至更低（具体值取决于永磁体磁链 λ\_f）。

这时候问题就来了。**e\_alpha/e\_beta 不再是一对干净的正弦波，而是被噪声、死区效应、采样量化误差淹没的微弱信号。**

打个比方：高速时像在晴天看太阳，方向清晰无疑。低速时像在浓雾中用手电筒找路——光源本身就很弱，雾里的颗粒物（噪声）把光散射得乱七八糟，你根本判断不出光从哪来。

更糟的是，atan2 在原点附近**极度不稳定**。当 e\_alpha 和 e\_beta 都接近零时，向量长度趋近于零，方向变得毫无意义。一点点噪声就能让向量从第一象限跳到第三象限，atan2 输出在 ±π 之间疯狂摇摆。

VESC 的代码里有一段**磁链状态保护**：

`// bldc/motor/foc_math.c:foc_observer_update()   // x1/x2 是 alpha/beta 轴磁链估计值 [Wb]，不是直接的反电动势   float mag = NORM2_f(state->x1, state->x2);   if (mag < (lambda * 0.5)) {       state->x1 *= 1.1;       state->x2 *= 1.1;   }`

这段代码的目的不是"改善 atan2 的角度精度"——等比例放大磁链向量的 x1、x2，atan2 算出来的角度**理论上不变**。它的真实作用是**防止观测器状态塌陷到原点附近**。

当反电动势极弱（低速或启动阶段），观测器的校正项几乎为零，积分器可能因数值漂移导致磁链估计值逐渐收缩。一旦 x1/x2 缩到接近零，下一周期 atan2 就会进入数值不稳定区，输出乱跳。VESC 的做法是：当磁链幅值低于阈值时，人为把它"撑"大 10%，防止状态进入危险区。

这有点像你在雾中眯着眼睛，努力不让视线完全失焦。不是解决了雾的问题，而是不让眼睛因为完全看不清而乱转。但这个保护的副作用是：**低速时磁链估计被人为放大了，而后续控制可能依赖这个估计值做其他计算**。

Microchip 的 AN1078 用了另一种策略：**干脆不在低速用 atan2** \[AN1078\]。

电机静止到启动阶段，反电动势为零，观测器没有任何有效输入。AN1078 的做法是——**强制开环**。控制器按一个预设的斜坡角度驱动电机，电流环正常工作，但角度不是算出来的，是"编"出来的。

`// 示意用代码：开环 I-F 启动   angle_openloop += omega_cmd * Ts;   omega_cmd += acceleration * Ts;  // 平方率升速`

这个角度按平方率递增（I-F 启动），电机被"拖着"转起来。等转速足够高（通常 10%~15% 额定转速，具体取决于电机参数和负载），反电动势幅值够大了，再平滑切换到闭环 atan2 模式。

切换的瞬间是危险期。如果开环角度和闭环 atan2 算出来的角度差得远，电流环会在一个控制周期内收到巨大的角度误差，导致电流冲击、转矩脉动，甚至触发过流保护。

工程上的解法是**软切换**：不要瞬间从开环切到闭环，而是让闭环角度通过一个一阶 LPF 慢慢"追"上开环角度，或者反过来让开环角度按闭环角度修正。过渡时间通常设 50~200 ms，足够电流环平稳过渡。

说白了，低速时 atan2 不是"算不准"，是"算不了"。要么你保护它（VESC 放大法），要么你绕过它（AN1078 开环启动），要么你干脆不用它（切到 HFI 或 I-F）。

## 盲区二：噪声的放大镜

假设你的 e\_alpha/e\_beta 已经够大了，波形也挺干净。你直接把 atan2 输出做差分求速度：

**这就是在拿放大镜看报纸上的灰尘。**

e\_alpha/e\_beta 上的每一丝噪声，经过 atan2 的非线性映射，都会变成角度上的抖动。再经过差分，这些抖动被除以 100μs——一个极小的数——瞬间放大成百上千倍的"速度噪声"。

P-001 的原文指出，反正切法的输入信号"具有周期性零穿越特性且位于分母中，这会大幅降低角度精度并引入噪声" \[P-001\]。这里说的"分母"问题，主要针对的是早期用普通 `arctan(e_beta/e_alpha)` 比值法实现的方案——e\_alpha 接近零时，除法会产生数值爆炸。现代工程里大家基本都用 `atan2(y,x)` 了，象限歧义已经解决。

但 `atan2` 并没有解决**向量幅值小**时的问题。

从数学上看，小扰动下 atan2 的角度误差近似为：

分子是噪声在垂直方向上的投影，量级约 ；分母是 。合起来看，整体约为 ，角度误差的灵敏度大约随  增大——**向量幅值越小，同样的噪声引起的角度抖动越大**。

举个例子：假设噪声峰峰值 0.05 V。高速时向量幅值  V， rad ≈ 0.29°，几乎感觉不到。低速时  V， rad ≈ 5.7°——**误差放大了约 20 倍**。

这意味着**atan2 的角度误差不是均匀分布的**。向量越接近原点，噪声灵敏度越高。如果你的应用对角度精度要求高（比如伺服定位），低速段的噪声尖峰会直接体现在位置环的跟随误差上。

D-003 综述更直接：**"arctan+微分（简单但噪声敏感），PLL（主流，低通滤波特性）"** \[D-003\]。

工程上的主流做法是：atan2 输出作为角度控制的直接来源，但**主速度反馈通常不用未处理的 atan2 差分**。速度要么走 PLL（推荐），要么走 wrap 保护后的差分+强 LPF（如 VESC 的 `m_speed_est_fast` 路径）。 untreated 的 atan2 差分噪声太大，不适合直接闭环。

AN1078 的做法是**两级一阶 LPF** \[AN1078\]。SMO 输出的高频切换信号先经过第一级 LPF 得到粗糙的 e\_alpha/e\_beta，再经过第二级 LPF 进一步平滑，最后才送进 atan2。两级滤波把噪声压到了足够低的水平，但代价是**相位延迟**——角度估计滞后于真实角度，滞后量与转速成正比。

这个延迟不是固定的。如果 LPF 截止频率固定，电频率 ω 越高，相位滞后角越大：。高速时滞后角可能达到 60° 甚至更大；低速时滞后角小，但滤波效果也相对变弱。**固定截止频率的 LPF 在全速域内表现不一致。**

AN1078 的对策是**自适应截止频率**：让 LPF 的截止频率实时跟踪电频率，这样在不同转速下保持固定的 90° 相位延迟，便于补偿 \[AN1078\]。这是个巧妙的工程技巧，但实现起来需要 Q15 定点运算，对 16 位 MCU 比较友好，32 位浮点 MCU 反而可以直接用更灵活的方案。

LPF 截止频率设多少合适？这是个权衡的问题。

设高了（比如 2 kHz），相位延迟小，但滤波效果差，噪声压不住。设低了（比如 200 Hz），噪声被滤得干干净净，但相位延迟大，动态响应慢——负载突变时角度估计要拖好几个周期才能跟上。

一个粗糙的经验法则是：**LPF 截止频率建议不低于 5 倍最高电频率**（仅为理解量级的经验起点，非硬性阈值）。如果你的电机最高转速 6000 rpm，4 极对，电频率是 400 Hz（6000/60 × 4），那 LPF 截止频率至少设 2 kHz。但这只是底线，实际还要根据噪声水平和 MCU 算力调整。

说白了，atan2 本身不产噪声，但它**对输入噪声极度敏感**。就像量角器本身很精密，但如果尺子在抖，你读出来的角度大概率也在抖。LPF 的作用是把尺子按住，但按住的同时也会把尺子往后拽一点——这就是相位延迟的代价。

## 反正切不是终点

到这里你应该明白了：atan2 是一个"够用但不完美"的角度提取工具。

它够简单——一行代码搞定。它够直接——物理意义清晰，e\_alpha/e\_beta 画出来是个圆，atan2 就是圆心角。它够快——没有迭代、没有积分、没有记忆状态，每周期独立计算。

但它的盲区也足够致命：

-   • **低速失明**：信号太弱，角度乱跳，甚至完全失效
    
-   • **噪声敏感**：微小扰动被非线性放大，尤其向量幅值小的低速段
    
-   • **跳变风险**：圆周不连续需要额外保护，否则随时炸
    
-   • **速度提取困难**：差分求速是噪声放大器，工业上不可取
    

VESC 和 ODrive 的代码印证了这个判断。

这对应到工程决策上：**不同项目对 atan2 和 PLL 的分工不同。**

VESC 用 atan2 算控制相位，再用 PLL 的速度输出做相位补偿和速度反馈。ODrive 更直接，控制相位就是 atan2 原始值，PLL 只管速度估计。

但无论哪种接法，**主速度反馈通常不用未处理的 atan2 直接差分**。VESC 保留了一条 `wrap` 保护后差分+低通的路径做快速估计，但闭环速度控制的主流接口仍来自 PLL。 未做任何处理的 atan2 差分噪声太大，单独依赖它闭环是不现实的。

下一篇文章，咱们专门拆 PLL：怎么用"追光"的方式，让角度估计既平滑又准确，还能从同一个反电势信号里把速度也掏出来。

## 代码里的 atan2 长什么样

### VESC 的 fast\_atan2：四个象限一次搞定

`// bldc/util/utils_math.c:utils_fast_atan2()   // DSP Guru 快速近似算法，基于有理多项式      float utils_fast_atan2(float y, float x) {    float abs_y = fabsf(y) + 1e-20;  // 防止 x=y=0 时 0/0    float angle;    if (x >= 0) {        float r = (x - abs_y) / (x + abs_y);        float rsq = r * r;           angle = ((0.1963 * rsq) - 0.9817) * r + (M_PI / 4.0);       } else {        float r = (x + abs_y) / (abs_y - x);        float rsq = r * r;           angle = ((0.1963 * rsq) - 0.9817) * r + (3.0 * M_PI / 4.0);       }    if (y < 0) {        return(-angle);  // 第三、四象限：取负       } else {        return(angle);   // 第一、二象限：保持正       }   }`

这段代码不是标准库 `atan2f`，而是嵌入式工程里的常见优化。**没有标准三角函数调用，主要是分支、除法和多项式乘加**，在 100μs 控制周期里省下的 CPU 周期相当可观。

特别注意：`abs_y + 1e-20` 是防止 `x = y = 0` 时除零的临时解决方案。虽然上一行的幅值保护理论上已经避免了这种情况，但工程上多一层保险永远不嫌多。`x >= 0` 和 `x < 0` 两个分支天然覆盖四个象限，不需要显式查表或条件跳转。

### AN1078 的两级 LPF + arctan 链路

`// 示意用代码，综合 AN1078 工程逻辑编写   // 两级一阶 IIR LPF，截止频率自适应跟踪电频率      #define LPF_K_SLF(Q15_omega)  ((Q15_omega) * 3.1416f / IRP_PERCALC)      // 第一级：从 SMO 切换输出提取等效反电势   static int16_t lpf1_alpha = 0, lpf1_beta = 0;   int16_t k_slf = LPF_K_SLF(eRPS);  // eRPS = 电转速 [rps]，Q15 格式      lpf1_alpha += (k_slf * (z_alpha - lpf1_alpha)) >> 15;   lpf1_beta  += (k_slf * (z_beta  - lpf1_beta))  >> 15;      // 第二级：进一步平滑   static int16_t lpf2_alpha = 0, lpf2_beta = 0;   lpf2_alpha += (k_slf * (lpf1_alpha - lpf2_alpha)) >> 15;   lpf2_beta  += (k_slf * (lpf1_beta  - lpf2_beta))  >> 15;      // 角度提取：CORDIC 定点 atan2   theta = CORDIC_ATAN2(lpf2_beta, lpf2_alpha);      // 相位补偿：补偿两级 LPF 引入的固定相移（约 90°）   theta_compensated = theta + PHASE_COMPENSATION(omega_e);`

注意 AN1078 用的是 **定点 Q15 运算** 和 **CORDIC 定点 atan2 实现** \[AN1078\]，这和 32 位浮点 MCU 的实现差异很大。但核心逻辑——两级 LPF 平滑后做 atan2——是通用的。Q15 格式下 `>> 15` 相当于除以 32768，这是定点小数的标准做法。

CORDIC（坐标旋转数字计算机）是一种迭代算法，用移位和加法代替三角函数。AN1078 在 dsPIC 上采用 CORDIC 实现定点 atan2，省掉了浮点运算开销。32 位浮点 MCU 虽然没有硬件 CORDIC，但 `atan2f` 通常是用多项式逼近或查表法实现的，速度也很快。VESC 的 `utils_fast_atan2` 就是一个嵌入式优化的多项式逼近版本，精度和速度都够工程用。

两级 LPF 的相位延迟合计约 90°（每级约 45°），AN1078 在最终角度上叠加了一个补偿量来抵消这个延迟。补偿量与转速和 LPF 截止频率的比值有关。

### 幅值下限保护（VESC 风格）

`// 示意用：磁链状态防塌陷保护   // 注意：VESC 真实代码操作的是磁链状态 state->x1/x2，   // 此处用 e_alpha/e_beta 做概念示意，变量名已简化。   float mag = sqrtf(e_alpha * e_alpha + e_beta * e_beta);   if (mag < lambda_f * 0.5f) {    // 向量幅值太低，等比例放大防止状态塌陷到原点    float scale = (lambda_f * 0.5f) / (mag + 1e-6f);    if (scale > 1.5f) scale = 1.5f;       e_alpha *= scale;       e_beta  *= scale;   }`

需要特别注意：**等比例放大向量不会改变 atan2 的角度**。这段代码的真实意图是防止观测器内部状态因数值漂移而塌陷到零，导致后续周期的 atan2 进入不稳定区。它不是"改善 atan2 精度"的调参手段。VESC 的 1.1x（放大 10%）是一个比较保守的经验值，具体还得看你的电机参数和应用场景。

## 调试技巧与常见坑

### 示波器看哪里

**第一，看 e\_alpha/e\_beta 的李萨如图形。**

经 DAC 输出或上位机导出后，把 e\_alpha 作为 X 轴数据、e\_beta 作为 Y 轴数据画 XY 图（李萨如图形）。正常情况下应该是一个圆（或椭圆），圆的半径等于向量幅值。

如果圆心偏移，说明有直流偏置——可能是 SMO 的 LPF 有直流泄漏，或者电流采样有零点漂移。偏移量在低速时尤其致命，因为偏移可能和信号幅值同量级，atan2 算出来的角度会系统性地偏向一侧。

如果圆变成了毛球，说明抖振太大，需要检查 SMO 增益 K 和边界层 Φ。毛球的"毛刺长度"大致对应角度抖动的峰峰值。

如果低速时圆缩成了一个点周围的一团噪点，说明信号太弱，atan2 已经在"失明"了。这时候不要调 atan2 的参数，去调启动策略或低速保护逻辑。

**第二，看 atan2 输出的跳变。**

用环形日志或 J-Scope/RTT 实时记录角度序列，事后检查 `delta_theta` 的分布。如果频繁出现接近 ±2π 的跳变值，说明 wrap 保护没做好，或者转速太低信号不稳。注意跳变点附近的 e\_alpha/e\_beta 值——如果向量幅值很小，那就是 SNR 问题；如果幅值正常但单分量过零，那就是象限判断的数值敏感区。

**第三，看速度估计的噪声。**

对比两条曲线：一条是 atan2+差分的速度，一条是编码器实测速度（如果有）。高速时两者应该接近；低速时 atan2 速度会像地震仪一样剧烈摆动。这个对比实验是最有说服力的——拿给客户看，他一眼就知道为什么不能直接差分求速度。

### 常见坑

**坑 1：坐标系符号差一个负号**

症状：电机能转，但负载能力弱，高速时电流环饱和，效率比有感模式低一截。

根因：atan2 算出来的角度和真实角度差了 90° 或 180°，Park 变换后的 d-q 轴完全错乱。d 轴电流本应为零，实际被分配了转矩电流，q 轴电流被迫减小以维持总电流不超限。

解法：用编码器基准对比。同一时刻，编码器角度和 atan2 输出应该要么相等，要么差一个固定偏移（由坐标定义决定）。如果差 90°，检查 e\_alpha/e\_beta 的定义是否和理论一致。最常见的陷阱是 SMO 方程里 `u_switch` 的符号和观测器方程的符号不统一（参见 [第20讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486626&idx=1&sn=090dba2d08fcb7b5e9ae5ffaf1086528&scene=21#wechat_redirect) 的符号链讨论）。

**坑 2：低速切闭环时电流冲击**

症状：开环启动到某个转速后切闭环，电流突然飙升，电机抖动，严重时触发过流。

根因：开环阶段的"编"角度和闭环 atan2 算出来的角度不一致，切换瞬间 Δθ 很大，电流环试图在一个控制周期内补上这个差值。

解法：切换时做角度平滑过渡。不要瞬间从开环角度切到闭环角度，而是用 PLL 或一阶 LPF 把闭环角度慢慢"拉"过来，过渡时间 50~200 ms（经验起点，取决于转速和负载惯性）。VESC 的做法是在 `mcpwm_foc.c` 里用 `m_phase_observer_override` 做软切换，把观测器状态也同步到开环值。

**坑 3：atan2 参数顺序写反了**

症状：电机转起来后，用手逆时针拨动转子，示波器里角度值顺时针增加；或者角度和速度方向相反。

根因：`atan2(y, x)` 的参数顺序是 **y 在前，x 在后**。但有些工程师习惯写成 `atan2(x, y)`，或者把 e\_alpha 当 y、e\_beta 当 x。结果算出来的角度和真实角度关于 45° 线对称，转子的旋转方向完全颠倒。

解法：记住 `atan2(y, x)` 对应的是 `arctan(y/x)`。在咱们的语境里，y = e\_beta，x = e\_alpha。写一行注释在代码旁边：

`// atan2(y, x) = atan2(e_beta, e_alpha)   // 注意：y 在前，x 在后！   theta = atan2f(e_beta, e_alpha);`

**坑 4：差分求速度导致速度环振荡**

症状：速度闭环时电机嗡嗡响，速度波形上有高频毛刺，PID 参数怎么调都调不平。

根因：atan2 角度噪声经过差分后被放大，速度环 PID 把这些高频噪声当成真实速度波动去补偿。Kp 越大，振荡越厉害。

解法：速度别用差分。要么接 PLL（推荐），要么对角度做足够强的 LPF 后再差分，但相位延迟会变大。如果必须用差分，至少先把角度序列通过一个中值滤波器或滑动平均滤波器，把孤立跳变点抹掉。
