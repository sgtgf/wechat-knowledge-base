## 1\. 调试现场的僵局

你终于把扩展卡尔曼滤波器（EKF, Extended Kalman Filter）跑起来了，角度估计能跟着转子转，电流波形也还算干净。但你心里清楚：这组 Q/R 是网上抄的，是 vendor demo 里默认的，是"先这样跑着再说"的。

现在问题来了——低速起步时转子位置跟不上，角度估计明显滞后，你把 Q\[0\]（电流过程噪声）从 0.5 调到 1.0，跟踪倒是快了，可高速空载时角度开始慢悠悠地飘，像喝醉了酒。你把 Q\[0\] 调回 0.5，飘是止住了，低速又跟不上。再一细想，低速稳住以后还会出现角度抖动——那和"跟不上"根本不是一回事，拧同一个旋钮却得出相反的效果。

你咬咬牙，把 R 从 0.5 改成 0.2。这次高速不飘了，但电流波形上突然冒出毛刺，像有人往采样值里撒了沙子。你再改成 0.8，毛刺没了，低速响应又变得黏糊糊的。

你盯着屏幕，彻底懵了。Q 和 R 像两个连体的旋钮，拧一个，另一个的效果就变了。你把 Q\[2\] 从 2e6 改成 1e6，转速阶跃时估计滞后两百毫秒；改到 3e6，低速时转速读数抖得像帕金森。R 也一样，小了噪声穿，大了响应钝。

这不是调参，这是赌博。而且你手里只有两个筹码，却要在**五个维度**（Q\[0\]、Q\[1\]、Q\[2\]、Q\[3\]、R）上押注——虽然 R 标定后冻结，但你还是得先把它测对。

问题的根源不是参数难调，而是**调参没有章法**。你在多维空间里随机游走，没有坐标系，没有方向感，没有判据告诉你"当前这一步走得对不对"。

本文要解决的工程困惑就是：**面对一台具体的电机、一套具体的电流采样板，有没有一套可重复的调参路径，而不是靠运气？**

## 2\. 先回到原点：Q 和 R 到底在分工什么？

在动手拧旋钮之前，必须先澄清一个大多数人模糊带过的问题：Q 和 R 的分工边界在哪里？

### 2.1 R：传感器的"不靠谱程度"

R 是测量噪声协方差。在 phobia 的实现里，它是个标量（`pm->kalman_gain_R = 5.e-1f`，`pm.c:223`），同时管着 iX 和 iY 两个测量通道：

`u = 1.f / (HP[0] + iR);   // iX 通道，S = HPH' + R   u = 1.f / (HP[1] + iR);   // iY 通道，S = HPH' + R`

> 注：源码未标注 `kalman_gain_R` 的单位；按 EKF 测量噪声协方差结构推断，量纲为 A²。

R 的物理含义很直白：你的电流传感器链路（shunt → 运放 → ADC → 零序消除 → 缩放）引入了多少噪声。这不是你能"调"的，它是你**硬件的画像**。换了采样板、改了走线、加了隔离，R 就会变。

R 越大 → EKF 越不信任电流测量 → 更依赖模型预测 → 滤波强但可能滞后。  
R 越小 → EKF 越信任电流测量 → 更紧跟采样值 → 响应快但噪声穿透。

### 2.2 Q：模型的"不靠谱程度"

Q 是过程噪声协方差。phobia 有 4 个分量（`pm.c:219-222`）：

`pm->kalman_gain_Q[0] = 5.e-1f;   // iX/iY 电流模型   pm->kalman_gain_Q[1] = 2.e+0f;   // θ 角度积分   pm->kalman_gain_Q[2] = 2.e+6f;   // ω 角速度   pm->kalman_gain_Q[3] = 2.e-1f;   // bias_Q 慢漂移`

Q 的物理含义是：你的电机模型（电压方程、角度积分、速度假设、bias 演化）与实际电机行为之间有多大偏差。这不是硬件决定的，而是你**控制意图的体现**。你想让滤波器多快响应、多稳滤波，通过 Q 来表达。

Q\[k\] 越大 → 对应状态的模型越不被信任 → EKF 更依赖测量来修正该状态 → 该状态跟踪快但噪声大。  
Q\[k\] 越小 → 对应状态的模型越被信任 → EKF 更依赖模型传播 → 该状态滤波强但可能滞后或发飘。

### 2.3 四个最常见的误解

**误解一："Q 调大 = 更相信模型"**

恰恰相反。Q 调大 = 模型方差膨胀 = 模型可信度下降 = EKF 更相信测量。很多人把 Q 和"模型精度"搞反了，拧了半天发现效果与预期相反。

**误解二："Q 和 R 要同时精细调节"**

理论上 Q 和 R 有耦合（K = P H' / (HPH' + R)，P 又受 Q 影响），但工程实践上，通常先固定 R（由硬件标定），再调 Q（由控制需求决定）。两个一起拧，你永远不知道效果变化是哪个参数引起的。

**误解三："调参就是看波形漂不漂"**

示波器上的电流波形顺不顺眼、角度估计抖不抖，这些是结果，不是判据。真正硬的判据是**残差的统计特性**：均值是否接近零（无偏），方差是否与你预期的 R 匹配（噪声水平一致）。

**误解四："找到一组最优值就万事大吉"**

Q/R 实际上是运行工况的函数。指望一组参数覆盖全工况，是调参痛苦的根源之一。判断该往哪个方向拧，不能只看"低速"或"高速"这个标签，而要看**症状**：是模型跟不上（残差有结构、持续非零），还是噪声穿透（残差抖、方差大）？跟不上就增大对应 Q，让滤波器更开放；抖得厉害就减小对应 Q，让滤波器更保守。同一工况下可能两种症状都有，那就得先分清主次。

## 3\. 汽车避震器的"路况"与"硬度"

想象你在调一辆越野车的避震器。车上有两个因素决定乘坐感受，但只有一个是你能拧的。

**路况（R）**——路面有多颠？碎石路、柏油路、冻土带，这是客观存在的。你不能坐在车里凭空猜"这段路应该很颠"，你得下车走一圈、压几个坑、量一量振幅。如果实际路况是"柏油路偶有裂缝"，你却按"乡村土路"来调避震，车开起来要么太软晃悠，要么太硬颠簸。

**避震硬度（Q）**——这是你能拧的旋钮。注意这里的"软硬"是从"是否跟随输入"定义的：软避震路感清晰，过坑时车身紧密跟随地形起伏；硬避震过滤振动，高速过弯时车身保持稳定。但软和硬没有绝对的好坏：跑烂路时软一点舒服，上高速时硬一点安全。

扩展卡尔曼滤波器（EKF）的 Q/R 调参完全一样：

-   • **R 是你的"路况"**——电流传感器链路实际有多噪？由 ADC 位数、运放温漂、PWM 耦合、板层布局、接插件接触电阻决定。它不是你想调就能调的，你得先**测**。
    
-   • **Q 是你的"避震硬度"**——你对电机模型的信任程度。Q\[k\] 调大 = 对应状态的避震变软，EKF 更相信电流测量，跟踪快但容易被噪声带偏；Q\[k\] 调小 = 对应状态的避震变硬，EKF 更相信模型，滤波强但可能滞后或发飘。
    

很多工程师一上来就把 Q 和 R 两个旋钮一起拧，相当于一边飙车一边调避震，还一边猜路况——不懵才怪。更糟的是，phobia 有 4 个 Q 分量，相当于车上有 4 个独立的避震器（前轮、后轮、左轮、右轮），每个都有自己的硬度旋钮。你没有章法地乱拧，车身姿态不畸形才怪。

> **需要注意的边界差异：**
> 
> 1.  1. **"软/硬"定义与日常汽车术语相反**：日常说"软避震舒服"是指它过滤振动、车身浮动（更像 Q 偏小 / 更信模型）；本文为方便 Q/R 映射，将"软"定义为紧密跟随输入（Q 偏大 / 更信测量）。阅读时务必以本文定义为准，不要凭常识反推。
>     
> 2.  2\. 汽车避震是连续的物理机械系统，有频率响应、阻尼系数、共振峰；EKF 是离散时域递推，不存在"共振频率"或"阻尼比"的概念，只有"信任权重"的分配。但"路况决定下限、硬度调节手感"的直觉是相通的——R 标定了滤波器性能的基准线，Q 在这个基准线上调节跟踪-滤波的平衡。
>     

## 4\. Q/R 调参第一步：R 标定——让"路况"说话

调参的章法只有一句话：**先把 R 接地，再用 Q 调手感。**

R 不是调出来的，是测出来的。你有三条路径可以标定 R，从简到繁：

**为什么这种方法有局限？** 静止时电机没有 PWM 开关噪声耦合（或者耦合模式与实际运行不同），没有反电动势（BEMF, Back-EMF）干扰，没有 shunt 上的共模跳变。你测到的 R 可能比实际运行时偏小。但它给你一个**可信的初始参考**——静止标定通常可作为保守下界，但若运行时的采样同步、滤波窗口或上电零偏与静止状态不同，实际散布未必绝对更大。

### 4.2 堵转标定法（更接近真实）

给电机通一个固定的 d 轴电流（q 轴电流为零），依靠静摩擦力或位置闭环约束让转子保持静止。此时电机有真实的 PWM 开关、真实的 shunt 压降、真实的运放工作点，但机械不转，没有反电动势变化。

采集电流，算方差。堵转状态下的 R 通常比静止标定大（1~3 倍为经验范围，受 PWM 频率、采样拓扑和电流幅值影响，需实测确认），因为 PWM 开关通过寄生电容、地线阻抗耦合到了模拟前端。

**注意**：堵转时间不能太长，否则电机发热、电阻变化，电流环会不断调节以维持给定，引入额外的控制噪声。建议每次堵转不超过 5 秒，冷却后重复 3 次取平均。堵转时给的是 d 轴电流（磁场定向控制 FOC 的标准做法），q 轴电流为零，转子因静摩擦力或位置闭环约束而保持静止。

这种方法的优点是：R 来自真实运行工况，包含了所有实际噪声源。缺点是：它假设你的 Q 已经"大致正确"，否则预测步的偏差会污染残差，导致 R 估计偏高。

> **工程建议**：三种方法结合使用。静止标定给下界，堵转标定给初值，在线反推做微调。不要指望一次标定管永久——换了电源线、改了 PWM 频率、换了电机，R 都可能变。

### 4.4 R 标定后怎么办？

R 定死后，**写在配置文件里，不要动**。它不是调参旋钮，是硬件常数。phobia 的默认 R=0.5 是一个经验值。隔离运放 + 16bit ADC + 独立模拟地的配置下，R 可能显著偏小；低成本 shunt + 单端运放 + 走线贴近桥臂的配置下，R 可能显著偏大。

**R 定错了的后果**：R 偏大 → EKF 过度不信任测量 → 滤波器变得保守 → 响应滞后，负载突变时角度跟不上；R 偏小 → EKF 过度信任测量 → 噪声穿透 → 电流波形毛糙，低速时角度抖动。

## 5\. Q/R 调参第二步：Q 分维度调节——逐个拧旋钮

R 定死后，你只剩四个自由度：Q\[0\]、Q\[1\]、Q\[2\]、Q\[3\]。不要四个一起拧，一次只调一个，观察效果，记录判据。

### 5.1 Q\[0\]：电流模型的"误差预算"

`kalman_gain_Q[0] = 0.5`，加到电流方差 P\[0\] 和 P\[2\] 上，缩放系数是 `lazy_TiLq = dt / Lq`（`pm.c:1169-1170`）。

Q\[0\] 补偿的是电流预测模型的不准确：Rs 温漂、Lq 饱和、未建模交叉耦合。默认值 0.5 说明 phobia 作者认为电流模型相对靠谱——电压方程毕竟是电机学里验证过无数次的基石。

**什么症状该拧它？**

电流波形毛糙、高频噪声明显——多半是 Q\[0\] 偏大，电流方差膨胀，K 的电流分量变大，测量噪声更多地透进状态估计。试试把 Q\[0\] 往小调。

反过来，电机温升后电流估计持续偏差，角度跟着跑偏——这是 Q\[0\] 偏小，模型过度自信，残差没法有效修正电流。试试把 Q\[0\] 往大调。

**拧多大？** 0.1~2.0 之间摸索，作为经验起点。超过这个范围还治不好，问题通常不在 Q\[0\]，而在 R 标定或电机参数辨识。

### 5.2 Q\[1\]：角度积分的"离散化保险"

`kalman_gain_Q[1] = 2.0`，加到角度方差 P\[5\] 上，缩放系数是 `dt`（`pm.c:1171`）。

角度的预测简单到近乎粗暴：。这个公式假设 dt 内速度恒定，但电机正在加速时，平均速度不等于瞬时速度，这就是积分误差。Q\[1\] 就是给这个误差买的保险。

**什么症状该拧它？**

转速突变时角度估计滞后，电流相位对不上，力矩输出明显下降——Q\[1\] 偏小，角度方差被压得过低，滤波器对角度过度自信。往上调一点。

静止或低速时角度抖得厉害，严重时触发堵转——Q\[1\] 偏大，P\[5\] 持续膨胀，角度修正过于敏感。往下压一点。

**拧多大？** Q\[1\] 和 PWM 频率绑得很紧。20 kHz（dt=50μs）时 2.0 够用；PWM 降到 4 kHz（dt=250μs），dt 放大 5 倍，为维持同等响应能力，Q\[1\] 可能需要同比放大，比如从 2.0 调到 10 左右。具体比例取决于电机加速度和离散化误差模型，得结合实际验证。

### 5.3 Q\[2\]：速度估计的"开放性阀门"

`kalman_gain_Q[2] = 2e6`，加到速度方差 P\[9\] 上，缩放系数是 `dt`（`pm.c:1172`）。

这是四个分量里最刺眼的一个。2e6 意味着每 50μs 往 P\[9\] 里注入 100 的方差增量（），而 P\[9\] 的初始化值只有 1.0。第一个周期就把速度方差吹到了 100 以上。

为什么这么大？因为在无感 FOC的 EKF 里，速度没有独立的测量通道，模型又极其简陋（假设恒速，没有显式加速度项）。Q\[2\] 大不是bug，从源码行为看更像一个有意为之的设计——它持续给 P\[9\] 注入足够大的不确定性，迫使 Kalman 增益维持非零，让速度估计始终对电流测量保持响应。

**什么症状该拧它？**

转速阶跃时估计滞后严重，实际转速都爬到目标值了，EKF 还在磨叽——Q\[2\] 偏小，P\[9\] 被更新步压缩得过小，速度修正通道基本关闭。直接以数量级为单位往上加，从 2e6 改到 5e6 甚至 1e7，观察效果。别微调 10%，在这个量级上那点变化淹没在数值噪声里，根本看不出来。

低速时转速读数抖得像筛子，电机啸叫，电流环给定跟着抖——Q\[2\] 偏大，速度噪声一直透过去。往下压，从 2e6 改到 1e6 或 5e5。

> **重要工程判断**：在无感 FOC 里，"跟踪不失"通常比"噪声更低"优先级更高。Q\[2\] 偏大只是噪声问题，Q\[2\] 偏小是跟踪失效问题。从 phobia 的默认值看，工程取向明确偏向保持跟踪能力。

### 5.4 Q\[3\]：bias\_Q 的"慢追机制"

`kalman_gain_Q[3] = 0.2`，加到 bias\_Q 方差 P\[14\] 上，缩放系数是 `dt`（`pm.c:1173`）。

bias\_Q 是一个扩展状态，用来补偿模型里的系统性偏差（如电阻温漂在 q 轴等效电压偏置上的投影）。Q\[3\] 就是这个漂移速率的方差预算。0.2 是个很小的数，说明 bias 的漂移被假设为极慢。

**什么症状该拧它？**

电机长期运行后，电流估计出现持续性偏差，角度慢慢跑偏——Q\[3\] 偏小，bias 估计追不上慢变误差。稍微往上调一点。

bias 估计自己开始抖动，反而引入新的扰动——Q\[3\] 偏大，高频噪声被误当成漂移来追。往下压。

**拧多大？** 0.05~1.0 之间，作为经验起点。但要注意：在 phobia 的实现里，`kalman_bias_Q` 并非全工况持续更新——`pm.c:1329-1335` 显示仅在 `flux_ZONE == PM_ZONE_HIGH` 时才通过残差更新 bias，低速或借速模式下会被清零或钳制。所以如果你发现调 Q\[3\] 长期看不出效果，先确认电机是否运行在对应的速度区间。

## 6\. Q/R 调参第三步：残差诊断——用数据代替"看波形"

调参不能靠"看着顺不顺眼"。EKF 更新步里有个天然的判据，比示波器更硬：**残差**。

### 6.1 残差是什么？

残差 ，即"实际测到的电流"减去"模型预测应该测到的电流"。在 phobia 里，就是这两行（`pm.c:1305-1308`）：

`E[0] = pm->lu_iX - A[0];  // iX 残差   E[1] = pm->lu_iY - A[1];  // iY 残差`

残差是 EKF 的"体检报告"。理想情况下，如果模型准确、R 标定正确、Q 设置合理，残差应该表现为**白噪声**：均值接近零，方差接近 ，且时间上不相关。

### 6.3 一个简单的残差统计代码

在实际工程中，你可以在主循环里加一个轻量的统计窗口：

`#define RESIDUAL_WINDOW 1000      static float residual_sum[2] = {0};   static float residual_sq_sum[2] = {0};   static int residual_cnt = 0;      void log_residual(float eX, float eY) {       residual_sum[0] += eX;       residual_sum[1] += eY;       residual_sq_sum[0] += eX * eX;       residual_sq_sum[1] += eY * eY;       residual_cnt++;        if (residual_cnt >= RESIDUAL_WINDOW) {        float meanX = residual_sum[0] / RESIDUAL_WINDOW;        float meanY = residual_sum[1] / RESIDUAL_WINDOW;        // 简化版有偏估计（N=1000 时与无偏估计差异可忽略）        float varX = residual_sq_sum[0] / RESIDUAL_WINDOW - meanX * meanX;        float varY = residual_sq_sum[1] / RESIDUAL_WINDOW - meanY * meanY;                // 打印或发送到上位机        printf("Residual: mean=(%.4f, %.4f), var=(%.4f, %.4f)\n",                  meanX, meanY, varX, varY);                // 重置窗口           residual_sum[0] = residual_sum[1] = 0;           residual_sq_sum[0] = residual_sq_sum[1] = 0;           residual_cnt = 0;       }   }`

这段代码的示意意义大于直接可用性——实际部署时需要考虑浮点累加误差、窗口溢出、实时性等因素。但它的核心思想是：**把残差从黑盒里掏出来，量化分析。**

### 6.4 残差诊断的实战流程

1.  1. **电机静止，采集残差** → 检验 R 标定。此时模型预测应该接近零，残差主要来自测量噪声。均值应接近零，方差应接近 R。
    
2.  2. **低速恒速运行，采集残差** → 检验 Q\[0\]/Q\[1\]。电流和角度模型在此工况下最准确，残差应该白噪声化。
    
3.  3. **转速阶跃过程中，采集残差** → 检验 Q\[2\]。加速瞬间残差会暂时偏大（模型假设恒速，实际在加速），但如果阶跃结束后残差长期不回零，说明 Q\[2\] 可能偏小，速度估计跟不上。
    
4.  4. **长期运行后，采集残差** → 检验 Q\[3\]。如果残差均值逐渐漂移，说明 bias\_Q 追不上慢变误差，Q\[3\] 可能需要增大（需确认电机运行在 `flux_ZONE == PM_ZONE_HIGH` 或相应 bias 更新分支有效的区间）。
    

## 7\. 典型翻车案例 walkthrough

### 案例一：低速抖动 —— "避震太软"

**现象**：电机在 100 rpm 以下运行时，角度估计抖动明显，电流波形上有 100~200 Hz 的低频调制，电机发出"嗡嗡"声。

**分析**：低速时反电动势小，角度和速度信息在电流残差中的可观测性变差——同样的角度误差产生的电流偏差信号很弱，EKF 从残差里"抠"出角度信息的难度加大。如果这时候 Q\[0\] 还偏大，电流方差膨胀，K 的电流分量变大，测量噪声就更多地透进状态估计。再加上 Q\[1\] 也偏大，角度方差 P\[5\] 跟着膨胀，角度修正过于敏感，静止附近的微小噪声被放大成可见抖动。

**怎么排查？**  
先确认 R 标定——低速时 PWM 耦合在低反电势、低可观测性下更容易显成角度/速度估计抖动。R 没问题的话，先**减小 Q\[0\]**，降低电流状态对测量的敏感度。抖动还在，再**减小 Q\[1\]**，让角度估计稳一点。最后看看有没有触发堵转——phobia 的 `pm_kalman_lockout_guard()` 会根据角速度低通滤波值（`kalman_lpf_wS`）和 `zone_threshold` 做判断，低速时角度抖太狠可能直接触发保护。

**别搞错了**：低速抖动和 PWM 死区补偿不当的症状很像。如果 Q\[0\]/Q\[1\] 都压下去了还是抖，先检查死区补偿，别在 EKF 里死磕。

### 案例二：高速发飘 —— "避震太硬"

**现象**：电机在 3000 rpm 以上空载运行时，角度估计开始慢悠悠地偏离实际位置，像喝醉了酒。电流波形看起来干净，但从控制环视角看，Park 变换用的角度不准，d 轴电流分量逐渐偏离零，q 轴有效转矩电流的效率下降。

**分析**：高速时反电动势大，角度和速度信息在残差中的可观测性改善——同样的角度误差会产生更明显的电流偏差，EKF 更容易从残差里读出角度信息。但如果 Q\[1\] 偏小，角度方差 P\[5\] 被压得过低，滤波器对角度过度自信。而高速时模型误差在累积（dt 内速度变化、参数漂移），过度自信的角度估计无法被及时修正，就会"发飘"。

**怎么排查？**  
先确认 R 标定在高速下还靠不靠谱——高速时共模干扰、di/dt 耦合可能让噪声特性变样。R 没问题的话，**增大 Q\[1\]**，给角度积分多留点误差预算。也别忘了看一眼 Q\[2\]，如果它也偏小，速度估计滞后，角度积分的基准速度不准，同样会发飘。

**别搞错了**：高速发飘也可能是弱磁控制不当、电压饱和、或者电感饱和导致的模型失配。Q\[1\] 调大了还飘，先查电机参数辨识和弱磁策略，别赖 EKF。

### 案例三：负载突变时角度滞后 —— "速度跟不上"

**现象**：电机带载稳定运行时一切正常，但负载突然增加（如机械臂碰到障碍物），转速瞬间下跌，EKF 的速度估计却像粘住了，拖 100~200 毫秒才反应过来。期间电流环因为速度反馈滞后而超调，电机过流。

**分析**：这是 Q\[2\] 偏小的典型症状。负载突变时，实际转速在几十个毫秒内变化，但 EKF 的速度模型假设恒速（协方差预测中没有显式加速度项）。如果 Q\[2\] 不够大，P\[9\] 被更新步迅速压缩，K 的 ω 分量趋近于零，滤波器拒绝用电流测量来修正速度估计。

**怎么排查？**  
直接**增大 Q\[2\]**，以数量级为单位（比如从 2e6 改到 5e6），强制保持速度估计的开放性。还要看看 phobia 的加速度前馈 `pm_lu_accel()`（调用入口 `pm.c:1363-1368`，定义 `pm.c:777-788`）是不是在正常干活——它能部分补偿 Q\[2\] 的不足，但不是 EKF 的一部分，不进协方差传播。如果 Q\[2\] 增大后低速噪声恶化，可以考虑分段参数：低速时 Q\[2\] 压小，中高速时放大。

**别搞错了**：负载突变滞后也可能是电流环带宽不够、速度环 PI 没整好、或者惯量辨识错了。Q\[2\] 已经很大还是滞后，问题八成在控制环，不在 EKF。

## 8\. 工程判断：从"玄学"到"有章法"

Q/R 调参之所以像玄学，是因为大多数人把两个参数混在一起拧，既没有标定 R 的客观步骤，也没有诊断 Q 的量化依据，更没有区分"这是 EKF 的问题还是控制环的问题"。

章法其实很简单，就三步：

**第一步：R 接地。** 静止标定或堵转测试，测出传感器的真实噪声水平。R 是硬件的画像，不是调参旋钮。写在配置里，换板子才重做。

**第二步：Q 逐个调。** 固定 R，一次只调一个 Q 分量，从保守值开始逐步增大。每个 Q\[k\] 对应一个具体的调试现象：Q\[0\] 管电流波形毛糙，Q\[1\] 管角度积分滞后/抖动，Q\[2\] 管速度跟踪能力，Q\[3\] 管长期漂移。现象和参数一一对应，不瞎猜。

**第三步：残差验证。** 用统计量（均值≈0，方差≈S）代替"看波形顺不顺眼"。残差是 EKF 的体检报告，白噪声化是目标。

更进一步，要接受一个现实：**不存在一组 Q/R 覆盖全工况**。空载时模型误差小，Q 整体可保守；重载时负载扰动大，Q\[2\] 通常需要更开放。如果全工况表现冲突，说明你需要分段参数或自适应策略——那是我们后期文章的话题。

最后，永远记住一个排他性检查：**在把问题归咎于 Q/R 之前，先确认电机参数（Rs、Lq、λ）是准的。** 参数辨识错误导致的模型失配，靠拧 Q/R 是救不回来的。你把避震器拧到最软，轮胎气压不对，车还是跑偏。

> **最终工程判断**：R 是硬件的画像，Q 是控制的意图。先画像，再调意图，最后用残差检验——这就是从"瞎拧"到"有章法"的全部秘密。如果画像和意图都对上了，车还是跑偏，先检查轮胎（电机参数），再怀疑路况传感器（R 标定），最后才动避震（Q 调节）。
