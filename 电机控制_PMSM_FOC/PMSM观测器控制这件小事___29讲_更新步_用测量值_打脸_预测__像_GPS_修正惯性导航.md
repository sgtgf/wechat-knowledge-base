各位同仁，你开车的时候有没有注意过导航软件的小心思？

手机放在支架上，导航界面里那个蓝色箭头，一秒刷新好几次。但你如果把手机从支架上拿下来，在车里晃一晃，箭头会抖——明显不是 GPS 的精度，而是加速度计和陀螺仪在"猜"你的运动。

加速度计和陀螺仪每秒更新几百次，反应极快。但它们有个致命毛病——**会漂移**。你站着不动，过一会儿导航也会显示你在缓慢移动。

导航软件每天都在玩一个游戏：**GPS 说你在马路中间，惯性传感器说你在马路左边十厘米。该信谁？**

GPS 直接看卫星，不累积误差。但每秒钟只更新几次，精度也就几米。惯性传感器反应快，可漂移问题无解。

聪明的导航算法不会二选一。

它把两者融合——GPS 定位用来"修正"惯性导航的漂移，惯性导航用来填补 GPS 更新间隙的细节。

这个融合过程，就是卡尔曼滤波的**更新步（Update Step）**。

[第28讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486710&idx=1&sn=d8c07923a9df828adc84be5c99fb87f3&scene=21#wechat_redirect) 中讲述的预测步，相当于惯性导航——根据上一刻的速度和加速度，"推算"下一刻的位置。推算得再勤快，也挡不住漂移。

更新步就是 GPS 发新位置的那一刻。

模型说"你应该在这"，测量值说"不，你在这"。滤波器把两者的差距算出来，决定修正多少。

说白了，更新步就是控制器在说：**"我刚才猜了一手，现在电流传感器的值回来了。让我看看猜得准不准，差多少，该修正多少。"**

## 更新步干三件事：算差距、算权重、打补丁

更新步的数学框架不复杂，核心就四个式子。

**第一步，算残差（Residual）：**

 是传感器实际测到的值（电流采样）。 是"根据预测状态，我应该测到多少"。两者一减，就是**残差**——预测和现实的差距。

残差为零，说明模型猜得准，不用修。残差很大，说明要么模型跑偏了，要么测量有噪声，或者两者都有。

**第二步，算卡尔曼增益（Kalman Gain）：**

K 是个矩阵，每一行对应一个状态（电流、角度、转速、偏置），每一列对应一个测量（X 轴电流、Y 轴电流）。它回答的问题是：**"我测量的电流差了一安培，角度该修正多少？转速该修正多少？"**

**第三步，修正状态：**

把残差按 K 的权重分配到每个状态上。电流差了一安培，K 告诉你角度该拧多少度、转速该加多少 rad/s。

**第四步，修正协方差：**

测量信息进来了，不确定性应该变小。这一步把 P"收紧"，表示"修正之后，我心里更有底了"。

## 第一步：残差——"我猜的电流"和"测到的电流"差多少？

咱们先看 phobia 里的残差是怎么算的。

`// 来源: phobia/src/phobia/pm.c:pm_flux_kalman() (commit 4058e68de0cd)   // 残差计算：测量电流 vs 预测电流      A[0] = pm->flux_F[0] * pm->flux_X[0] - pm->flux_F[1] * pm->flux_X[1];   A[1] = pm->flux_F[1] * pm->flux_X[0] + pm->flux_F[0] * pm->flux_X[1];      E[0] = pm->lu_iX - A[0];   E[1] = pm->lu_iY - A[1];`

这里 `flux_X[0]`、`flux_X[1]` 是 d-q 坐标系下的电流估计，`flux_F[0]`、`flux_F[1]` 是转子角度的 cosθ、sinθ。

`A[0]`、`A[1]` 的计算是把 d-q 电流转回 XY 坐标系：`A[0] = cosθ·i_d - sinθ·i_q`，`A[1] = sinθ·i_d + cosθ·i_q`。这就是"根据当前状态估计，XY 坐标系下的电流应该是多少"。

`lu_iX`、`lu_iY` 是电流传感器实际采样并 Clarke 变换后的 XY 电流。

`E[0]`、`E[1]` 就是残差——**测量值减去估计值**。

用导航的类比来说：惯性导航推算"你在这"，GPS 卫星说"不，你在这"，两者一减，差了几米，这就是残差。

### 残差为零意味着什么？

如果 `E[0]` 和 `E[1]` 都接近零，说明模型预测和传感器测量高度一致。电流该是多少，传感器就报多少。

这时候更新步几乎不做修正——K·y 很小，状态基本保持预测值。滤波器心里明白："我猜得挺准，微调一下就行。"

但残差为零不意味着万事大吉。它可能只是说明你运气好——模型误差和测量噪声恰好抵消了。真正健康的滤波器，残差应该在零附近小幅波动，像心电图一样有规律地起伏。

### 残差很大意味着什么？

残差爆掉，通常有三种原因。

**第一种：模型跑偏了。** 负载突然加上去，转速瞬间下跌，但模型里的机械方程假设负载转矩慢变。预测电流和实际电流差了一大截。

**第二种：测量出问题了。** ADC 采样受干扰，或者电流采样电阻温漂，传感器报了一个离谱的数。

**第三种：两者都有。** 模型有点偏，测量也有点噪，残差就是两者的"叠加态"。

卡尔曼滤波器的聪明之处，在于它**不试图区分具体是哪一种原因**。它只看残差的大小，通过卡尔曼增益 K 来决定"该信模型多一点还是信测量多一点"。

## 第二步：卡尔曼增益——该信模型还是信测量？

卡尔曼增益 K 是整个更新步的灵魂。

它的公式看起来唬人：

但物理意义极其直白：**模型不确定度和测量不确定度的"掰手腕"结果。**

分母里的  有两项。 是"测量值对应的预测不确定度"（把 P 投影到测量空间），R 是"传感器本身的不确定度"。

如果 P 很大（模型心里发虚，预测不靠谱），那  就大，分母大，K 就大。**K 大意味着：残差一出现，我就大幅修正状态——因为我本来就不信模型。**

如果 R 很大（传感器很噪，测量不靠谱），分母也大，但这里的"大"和 P 大的效果不同。R 大时，分子  不变，分母变大，K 反而小。**K 小意味着：残差再大，我也只小幅修正——因为传感器本身就不准，修正可能把噪声也带进来。**

打个比方：

-   • 你的惯性导航已经跑了十分钟没修正过（P 很大，漂移严重），这时 GPS 终于来了信号。哪怕 GPS 精度一般，你也得大信特信——因为惯性导航已经飘到姥姥家了。
    
-   • 你的惯性导航刚修过，状态很准（P 很小），但 GPS 这次信号特别差（R 很大，阴天或多云）。这时候 GPS 说"你偏了十米"，你只会微调——因为你知道 GPS 这次也不靠谱。
    

这就是 K 的物理直觉。

### phobia 里的 K 是怎么算的？

phobia 的 `pm_kalman_update()` 函数负责计算 K 和更新 P。

`// 来源: phobia/src/phobia/pm.c:pm_kalman_update() (commit 4058e68de0cd)   // 卡尔曼增益计算 + 协方差更新      float  *P = pm->kalman_P;   // 5x5 协方差矩阵（15个独立元素）   float  *K = pm->kalman_K;   // 5x2 卡尔曼增益矩阵（10个元素）   float  iR = pm->kalman_gain_R;  // 测量噪声协方差 R 的标量配置值      float  HP[5], u;      /*    * H(1) = [ 1  0  0  0  0 ]    * H(2) = [ 0  1  0  0  0 ]    *    * 状态顺序: [iX, iY, θ, ω, bias]    * */      // 第一次标量更新：处理 X 轴电流测量   HP[0] = P[0];   HP[1] = P[1];   HP[2] = P[3];   HP[3] = P[6];   HP[4] = P[10];      u = 1.f / (HP[0] + iR);      K[0] = HP[0] * u;   // iX 对 iX 测量的增益   K[2] = HP[1] * u;   // iY 对 iX 测量的增益   K[4] = HP[2] * u;   // θ 对 iX 测量的增益   K[6] = HP[3] * u;   // ω 对 iX 测量的增益   K[8] = HP[4] * u;   // bias 对 iX 测量的增益      // 用 K 的第一列更新 P   P[0]  += - K[0] * HP[0];   P[1]  += - K[2] * HP[0];   // ... 共 15 个 P 元素更新 ...      // 第二次标量更新：处理 Y 轴电流测量   HP[0] = P[1];   HP[1] = P[2];   HP[2] = P[4];   HP[3] = P[7];   HP[4] = P[11];      u = 1.f / (HP[1] + iR);      K[1] = HP[0] * u;   // iX 对 iY 测量的增益   K[3] = HP[1] * u;   // iY 对 iY 测量的增益   K[5] = HP[2] * u;   // θ 对 iY 测量的增益   K[7] = HP[3] * u;   // ω 对 iY 测量的增益   K[9] = HP[4] * u;   // bias 对 iY 测量的增益      // 用 K 的第二列更新 P   // ...      // 最后的 K 修正（将顺序标量更新结果转换为联合残差形式）   u = - K[2];   K[0] += K[1] * u;   K[2] += K[3] * u;   K[4] += K[5] * u;   K[6] += K[7] * u;   K[8] += K[9] * u;`

这段代码有几个值得细品的工程技巧。

**技巧一：标量顺序更新。** 标准卡尔曼滤波里，H·P·Hᵀ + R 是一个 2×2 矩阵，需要求逆。但 phobia 选择**分别处理两个测量**：先处理 X 轴电流，更新 P；再处理 Y 轴电流，用更新后的 P 继续算。这样把矩阵求逆变成了两次标量除法，省了大量计算。

数学上，当测量噪声 R 是对角矩阵时（两个电流测量的噪声不相关），顺序标量更新和联合批量更新是等价的。phobia 的 R 是标量 `kalman_gain_R`，说明它假设两个电流通道的测量噪声强度相同。

**技巧二：K 的存储布局。** K 是 5×2 矩阵，但存储成一维数组。索引规律是交错排列：`K[0]` 是 iX 状态对 X 电流测量的增益，`K[1]` 是 iX 状态对 Y 电流测量的增益，`K[2]` 是 iY 状态对 X 电流测量的增益，`K[3]` 是 iY 状态对 Y 电流测量的增益……

用更通用的说法：`K[2·s+0]` 是状态 `s` 对 X 电流残差的增益，`K[2·s+1]` 是状态 `s` 对 Y 电流残差的增益。这种布局方便状态更新时一次性读取某个状态的两个增益。

**技巧三：最后的 K 修正。** 代码末尾有一段看似奇怪的修正：

`u = -K[2];   K[0] += K[1] * u;   K[2] += K[3] * u;   // ...`

这里 `K[2]` 是第一次更新后 iY 状态对 iX 测量的增益。这段修正的数学本质，是把顺序标量更新得到的增益转换成可直接乘原始残差 `E[0]`、`E[1]` 的联合残差形式。没有它，`pm_flux_kalman()` 里按 `K[0]*E[0] + K[1]*E[1]` 这种联合形式使用 K 时，会和顺序更新的数学假设不一致。具体推导涉及协方差矩阵的分块求逆，感兴趣的同仁可以自己用纸笔验算——这里只给一个定性结论：**phobia 用两次标量除法加一行修正，等价于一次 2×2 矩阵求逆，计算量小得多，数值结果一致。**

### R 是什么？传感器的不自信程度

代码里的 `kalman_gain_R` 就是测量噪声协方差 R。

`// phobia/src/phobia/pm.c (commit 4058e68de0cd)   pm->kalman_gain_R = 5.e-1f;   // R = 0.5`

R 小，说明传感器很自信："我测的电流，误差就这么大，你放心用。" 这时候 K 会偏大，滤波器更信测量。

R 大，说明传感器在谦虚："我这 ADC 采样有噪声，温漂也不小，你悠着点。" 这时候 K 偏小，滤波器更信模型。

工程上，R 的选取和电流传感器的分辨率、ADC 位数、采样噪声直接相关。一个 12 位 ADC、量程 ±20A 的霍尔传感器，量化噪声约为 0.01A。但实际 R 还要考虑电磁干扰、布线噪声、温漂——这些因素的贡献通常比量化噪声大。

## 第三步：状态更新——残差怎么分配到各个状态？

K 算好了，残差也知道了，接下来就是"打补丁"。

`// 来源: phobia/src/phobia/pm.c:pm_flux_kalman() (commit 4058e68de0cd)   // 状态更新：用残差和卡尔曼增益修正所有状态   // 注意：以下代码位于 if (likely(pm->vsi_IF == 0)) 分支内      A[0] += K[0] * E[0] + K[1] * E[1];   A[1] += K[2] * E[0] + K[3] * E[1];      dA = K[4] * E[0] + K[5] * E[1];   dA = (dA < -1.f) ? -1.f : (dA > 1.f) ? 1.f : dA;   m_rotatef(pm->flux_F, dA);      pm->flux_X[0] = pm->flux_F[0] * A[0] + pm->flux_F[1] * A[1];   pm->flux_X[1] = pm->flux_F[0] * A[1] - pm->flux_F[1] * A[0];      // 转速更新（仅在 flux_LINKAGE == ENABLED 时）   pm->flux_wS += K[6] * E[0] + K[7] * E[1];   pm->flux_wS = (pm->flux_wS < -pm->m_freq) ? -pm->m_freq       : (pm->flux_wS > pm->m_freq) ? pm->m_freq : pm->flux_wS;      // bias_Q 更新：在 flux_ZONE == PM_ZONE_HIGH 时累积，否则清零   if (pm->flux_ZONE == PM_ZONE_HIGH) {       pm->kalman_bias_Q += K[8] * E[0] + K[9] * E[1];   }   else {       pm->kalman_bias_Q = 0.f;   }`

这段代码的物理含义非常清楚：**残差通过 K 增益"广播"到所有状态。**

电流差了一安培，不只是修正电流——角度、转速、偏置全都要跟着调。因为电机模型里，电流、角度、转速是耦合的。你测到的电流偏差，可能不是电流本身不准，而是角度估偏了，导致坐标变换出错，电流跟着算错。

**K\[4\]、K\[5\] 是角度增益。** 它们回答的问题是："X/Y 轴电流各差了一安培，转子角度该修正多少？" 如果角度误差是导致电流偏差的主因，K\[4\]、K\[5\] 就会比较大。

**K\[6\]、K\[7\] 是转速增益。** 电流差了一安培，转速该修正多少？转速误差会通过反电动势影响电流，所以电流残差也蕴含了转速信息。

**K\[8\]、K\[9\] 是偏置增益。** 电流差了一安培，电压偏置该修正多少？如果电流长期有系统性偏差，可能是电压采样的零点偏置在漂移。

### 角度更新为什么要 clamp？

`dA = K[4] * E[0] + K[5] * E[1];   dA = (dA < -1.f) ? -1.f : (dA > 1.f) ? 1.f : dA;   m_rotatef(pm->flux_F, dA);`

`dA` 是角度修正量，单位是弧度。但这里把它 clamp 在了 \[-1, 1\] 弧度——也就是约 ±57 度。

为什么要限制？

如果某个周期里残差特别大（比如 ADC 采样受干扰爆了一个异常值），K·E 可能算出几百弧度的角度修正。如果不限制，flux\_F 会瞬间旋转一大圈，角度估计彻底崩掉。

57 度的限制听起来很宽，但在常见工况下，单个 50~100 微秒控制周期内的电角度变化通常只有几度到十几度，远小于 1 弧度。所以 ±57 度是一个相当保守的安全边界，正常情况下 dA 远小于 1 弧度。如果电机转速极高、接近该上限，应重新评估采样周期和角速度 clamp 的合理性。

`m_rotatef()` 执行完后再执行 `m_normalizef()`（在 `pm_kalman_solve` 中调用），把 flux\_F 重新归一化为单位向量，防止浮点误差累积。

### 转速更新为什么要 clamp？

`pm->flux_wS += K[6] * E[0] + K[7] * E[1];   pm->flux_wS = (pm->flux_wS < -pm->m_freq) ? -pm->m_freq       : (pm->flux_wS > pm->m_freq) ? pm->m_freq : pm->flux_wS;`

转速被限制在 `[-m_freq, m_freq]`。`flux_wS` 的单位是 rad/s，`m_freq` 是控制频率（单位 s⁻¹，数值上等于 PWM 频率）。如果 m\_freq = 20,000 s⁻¹，那上限就是 ±20,000 rad/s，对应电频率约 3,183 Hz。对于 4 极电机（极对数 p=2），机械转速约 95,500 RPM——这个上限远高于任何实际电机的工作范围。

但它是一道防火墙。万一滤波器发散，转速估计不会飙到无穷大。

### 状态更新的坐标系转换

`pm->flux_X[0] = pm->flux_F[0] * A[0] + pm->flux_F[1] * A[1];   pm->flux_X[1] = pm->flux_F[0] * A[1] - pm->flux_F[1] * A[0];`

这里有一个容易忽略的细节。`A[0]`、`A[1]` 修正前是 XY 坐标系下的电流估计，修正后仍然是在 XY 坐标系下。但 `flux_X[0]`、`flux_X[1]` 是 d-q 坐标系下的电流。

所以更新完 XY 电流后，必须用**新的角度**（已经旋转过的 `flux_F`）把它们转回 d-q，存到 `flux_X` 里。这一步保证了下一周期的预测步（`pm_kalman_solve`）能在 d-q 坐标系下继续积分。

 叫**协方差缩减因子**。它的作用很明确：**测量信息进来了，不确定性应该变小。**

如果 K 很大（说明测量很可信）， 接近单位矩阵， 很小，P 被大幅压缩。滤波器说："这次修正让我信心大增。"

如果 K 很小（说明测量不可靠）， 接近零矩阵，P 几乎不变。滤波器说："这次测量没啥新信息，我心里还是发虚。"

phobia 中 P 的更新在 `pm_kalman_update()` 里和 K 的计算混在一起。代码里每次标量更新后，P 都被立即修改：

`P[0] += -K[0] * HP[0];   // iX 的不确定度被压缩   P[1] += -K[2] * HP[0];   // iX-iY 相关性被调整   // ...`

从数学上看，。对于第一个测量（iX），，所以  就是 P 的第一行，也就是代码里的 `HP[0..4]`。

然后  是一个外积：5×1 向量乘以 1×5 向量，得到 5×5 矩阵。从 P 中减去这个矩阵，就完成了协方差更新。

**P 的对角线元素（方差）在更新后应该减小或不变。** 因为测量带来了新信息，消除了部分不确定性。如果更新后 P 的对角线反而增大了，说明 K 算错了，或者数值溢出了。

### 预测步让 P"呼吸"，更新步让 P"收缩"

如果把整个 EKF 循环画成一张图，P 的时域行为很像呼吸：

-   • **预测步**：P = F·P·Fᵀ + Q。F 拉伸/压缩旧不确定性，Q 叠加模型噪声。整体趋势通常是膨胀。
    
-   • **更新步**：P = P - K·H·P。测量信息注入，P 被压缩。
    

一个健康的滤波器，P 应该**周期性涨落**——预测步涨一点，更新步缩一点，像心跳一样稳定。

如果 P 只涨不缩，说明更新步没起作用。可能的原因：R 过大导致 K 接近 0；P 本身已经很小，再压缩空间有限；更新函数因条件判断未执行；或者 P 矩阵失去正定性，数值溢出。

如果 P 只缩不涨，说明 Q 太小或 F 算错了。滤波器越来越自信，最终"冻住"，再也不接受测量修正。

## 两个函数的分工：预测和更新为什么要拆开？

细心的同仁可能注意到了：phobia 的 EKF 不是"一个函数跑完预测和更新"，而是拆成了 `pm_kalman_update()`（算 K + 更新 P）和 `pm_flux_kalman()`（算残差 + 修正状态）。

为什么要这么拆？

看 `pm.c` 的主循环：

`// 来源: phobia/src/phobia/pm.c (commit 4058e68de0cd)      if (pm->kalman_POSTPONED == PM_ENABLED) {       pm_kalman_forecast(pm);    if (likely(pm->vsi_IF == 0)) {           pm_kalman_update(pm);       }       pm->kalman_POSTPONED = PM_DISABLED;   }`

`kalman_POSTPONED` 是一个标志位。`pm_flux_kalman()` 在修正完状态后把它设为 `PM_ENABLED`。然后**在同一个控制周期内**（PWM 输出后的空闲时段），就会触发 `pm_kalman_forecast()` 和 `pm_kalman_update()`。

但 `pm_flux_kalman()` 本身是在另一个时机调用的——它在电流采样和 Clarke/Park 变换之后执行，计算残差并修正状态。

这么干有两个好处。

**第一，时序解耦。**`pm_kalman_update()` 更新的是 P 和 K，供后续周期使用；`pm_flux_kalman()` 修正的是当前周期的状态。两者在代码层面分开，耦合度大幅降低。

**第二，K 基于最新的 P⁻ 计算。** 标准 EKF 的时序要求：先用预测后的 P⁻ 算 K，再用 K 修正状态。phobia 的分工完全符合这个要求。

## 残差的 debug 意义

残差不只是数学中间量，它是调试 EKF 的**黄金指标**。

在 `pm_flux_kalman()` 的末尾，如果启用了 debug 模式：

`if (PM_CONFIG_DBG(pm) == PM_ENABLED) {       pm->kalman_rsu_D = pm->flux_F[0] * E[0] + pm->flux_F[1] * E[1];       pm->kalman_rsu_Q = pm->flux_F[0] * E[1] - pm->flux_F[1] * E[0];   }`

这里把 XY 坐标系下的残差转回了 d-q 坐标系：`kalman_rsu_D` 是 d 轴残差，`kalman_rsu_Q` 是 q 轴残差。

调试时看这两个值：

-   • 如果 d 轴残差长期不为零，可能是 Ld 参数不准，或者电压偏置估计有问题。
    
-   • 如果 q 轴残差在高速时突然增大，可能是角度估计有滞后（转速变化快，角度没跟上）。
    
-   • 如果两个残差都很大但随机抖动，可能是 ADC 采样受干扰。
    

残差的"长期均值"和"短期方差"是两个独立的信息来源。均值偏离零说明模型有系统性偏差（参数不准或偏置漂移），方差大说明测量噪声大或模型动态没跟上。

## 🔧 调试 Checklist

\[ \] 残差 `E[0]`、`E[1]` 是否在零附近小幅波动（稳态时波动幅度取决于电流采样噪声、PWM 频率、电机参数和负载工况，无统一阈值，需结合实际调试）  
\[ \] 卡尔曼增益 K 的元素数量级是否合理（电流自增益 K\[0\]、K\[3\] 在 0~1 之间；交叉增益如 K\[4\]、K\[5\] 通常远小于 1，具体量级取决于 P 和 R 的相对大小）  
\[ \] 协方差 P 在更新后是否收缩（对角线元素应比更新前小或持平；若增大，检查 R 是否为负或 K 计算溢出）  
\[ \] 角度修正量 `dA` 是否经常触发 clamp（频繁触发说明残差太大，可能是模型参数不准或测量受干扰）  
\[ \] 转速修正后是否触发 clamp（频繁触发说明滤波器在努力追赶，但转速变化超出了滤波器的跟踪能力）

## 调试现场：变量跟踪看哪里

### 看残差

在 `pm_flux_kalman()` 中 `E[0]`、`E[1]` 计算完后打断点。稳态运行时，残差应该在零附近小幅随机波动。如果某个轴残差长期偏向一侧（比如 E\[0\] 一直为正），说明该轴的电流估计有系统性偏差——检查 Rs、Ld、Lq 参数是否标定准确。

### 看卡尔曼增益

在 `pm_kalman_update()` 返回后看 `kalman_K` 数组。K\[0\] 和 K\[3\]（电流自增益）接近 1 说明滤波器几乎完全相信测量；接近 0 说明几乎完全相信模型。K\[4\]、K\[5\]（角度增益）在高速负载突变时通常会暂时增大，帮助角度快速收敛。

### 看协方差对角线

对比 `pm_kalman_update()` 前后的 P 对角线元素。正常情况下，P\[0\]、P\[2\]（电流方差）在更新后应该明显减小。如果不变，优先检查 R 是否过大、P 本身是否已很小、`pm_kalman_update()` 是否实际执行，或 P 是否出现数值/正定性异常。P\[5\]（角度方差）和 P\[9\]（转速方差）的变化更能反映滤波器的"信心度"——收敛后应该稳定在一个较小的范围内。
