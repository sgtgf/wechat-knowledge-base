## 1\. 手动调参的天花板

[上篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)刚把 Q/R 调顺手，你兴冲冲地把参数烧进电机，跑了一组加速-匀速-减速的曲线。波形漂亮，残差平稳，你在群里发了张截图，深藏功与名。

第二天，客户说电机装了减速箱，负载惯量变大了。你重新跑同一段曲线，发现速度估计在加速段出现了一丝滞后——不明显，但肉眼能看出来。你打开 `kalman_gain_Q`，想把 Q\[2\]（速度维）往上提一点，又担心稳态噪声跟着上来。正犹豫着，客户又加了一句："这个工况一天变三四回，你每次都要手动改参数？"

这句话像一根刺。

你突然意识到：[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章教给你的"冻结 R、按症状调 Q"的章法，说白了就是**静态优化**——它假设噪声统计特性在一段时间内不变，然后你作为工程师，根据当前观察到的症状，把参数拧到一个局部最优。这个局部最优只对"当前工况"成立。

而工况都有哪些？至少包括：

-   • **负载惯量**：空载 vs 满载，减速箱传动比变了，机械时间常数跟着变；
    
-   • **温度**：绕组电阻随温度漂移，磁链随温度衰减，模型参数不再是标称值；
    
-   • **转速区间**：低速时反电势弱，电流测量信噪比低；高速时 PWM 占空比饱和，电压重构误差大；
    
-   • **传感器老化**：电流传感器的零漂和增益漂移是慢性毒药，日积月累。
    

这些变化里，有些快（负载突变），有些慢（温度漂移）。[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)提到的手动调参对慢变尚且能应付——你一天改一次参数就行；但对快变，人根本反应不过来。

于是问题变成：**能不能让滤波器自己"长脑子"，根据它实时看到的残差，判断当前 Q/R 是否还合适，并自动修正？**

这就是 Sage-Husa 自适应滤波器的出发点。

## 2\. 与自适应EKF底层原理相同的自动验光机

想象你去配眼镜。传统做法是：验光师让你试戴不同度数的镜片，你凭主观感受说"这个清楚""那个晕"，最后定下一副固定度数的眼镜。这就是[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)讲到的手动调参——效果好，但只对你"当前的眼睛状态"有效。如果你熬夜了、用眼过度了，这副眼镜可能就不再是最优解。

Sage-Husa 的思路完全不同。它像一台**自动验光机**：你盯着视力表看，机器实时收集你眼球的反馈（瞳孔反应、聚焦速度、辨识准确率），自动微调镜片度数，直到找到一个更匹配你当前眼睛状态的配置。

**差异点**：自动验光机是开环的——它调镜片度数，不会反过来改变你的眼睛；但 Sage-Husa 是闭环的——Q/R 的调整会改变卡尔曼增益 K，K 的改变会影响下一时刻的状态估计，下一时刻的残差又会反过来影响 Q/R 的估计。这个闭环耦合，正是 Sage-Husa 可能发散的根源。

## 3\. 新息序列：滤波器的"自我体检报告"

在讲 Sage-Husa 怎么调参数之前，必须先搞清楚它"看"的是什么。它看的不是状态估计值，不是转速曲线，而是**新息**（innovation），也叫残差（residual）。

### 3.1 新息是什么

新息的定义很简单。对一般 EKF，它是测量值与预测测量值之差：

`// pm.c:1307-1308（基于GitHub上 phobia 源码快照）   E[0] = pm->lu_iX - A[0];   E[1] = pm->lu_iY - A[1];`

`A[0]`、`A[1]` 是模型预测的电流，`lu_iX`、`lu_iY` 是实际测到的电流。两者相减，得到的就是"模型以为的电流"和"实际电流"之间的差距。

如果滤波器工作正常，这个差距应该像白噪声一样随机波动，不大不小，没有结构性偏差——既不会持续偏向正（模型系统性地低估了电流），也不会持续偏向负。

新息不是随便大的。EKF 在更新步里，根据当前的预测协方差 P⁻ 和测量噪声 R，算出了一个"理论上的残差应该有多大"：

这个公式的物理意义很直白：

-   • `H·P_{k|k-1}·Hᵀ`：模型预测的不确定性，经过测量矩阵 H 投影到测量空间后的规模；
    
-   • `R`：传感器本身的噪声功率；
    
-   • 两者相加：残差的"天然尺度"——模型不准叠加上传感器撒谎，共同决定了你观测到的电流偏差该有多大。
    

如果实际残差一直远小于 `S_k`，说明滤波器过于保守——它以为自己很没把握，其实模型和传感器都比预期靠谱。反过来，如果残差持续大于 `S_k`，说明滤波器过于自信——它以为残差就该这么点，实际却被更大的噪声或模型误差锤了。

## 4\. 协方差匹配：Sage-Husa 的核心逻辑

有了理论值 `S_k` 和实际值 `Ĉᵥ`，Sage-Husa 的动作就一句话：**让它们匹配**。如果实际残差比理论预期大，说明当前 Q/R 的设定低估了真实的不确定性——可能是模型跟不上（该增大 Q，让滤波器更信测量），也可能是传感器比预想的吵（该增大 R，承认测量噪声更大）；反之亦然。

### 4.1 匹配判据的物理直觉

三种情况的物理意义：

**情况一：Ĉᵥ ≈ Sₖ**

残差大小符合预期。说明当前 Q/R 的设定与真实噪声统计特性基本一致，无需调整。这是理想状态。

**情况二：Ĉᵥ > Sₖ**

实际残差比理论预期大。这意味着：

-   • 要么**模型不准了**——参数漂移、未建模动态、负载突变导致预测误差增大。这时候该增大 Q，让滤波器更信任测量、更少信任模型；
    
-   • 要么**R 定得太小**——你过于信任传感器，把它想象得比实际更准。传感器其实比你想的吵，所以实际残差被 R 低估了。
    

在[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章的语境里，这就是"症状：残差有结构偏差 → 增大 Q"的自动版本。

**情况三：Ĉᵥ < Sₖ**

实际残差比理论预期小。这意味着：

-   • 要么**模型太准了**——当前工况下模型预测极其靠谱，不需要给那么多过程噪声。可以减小 Q；
    
-   • 要么**R 定得太大**——你过于保守，传感器的实际精度比你的设定值更好，残差被 R 高估了。
    

对应于[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章中提到的"症状：噪声穿透/估计抖动 → 减小 Q"。

> **重要提醒**：协方差匹配只能告诉你"不匹配"，但无法唯一确定是 Q 的问题还是 R 的问题。实际残差大，既可能是模型不准（该调 Q），也可能是传感器噪声被低估（该调 R）。Sage-Husa 的简化版本通常同时调整两者，这正是它容易耦合发散的根源之一。

### 4.2 简化 Sage-Husa：比例因子法

原始的 Sage-Husa 算法发表于 1969 年，其完整形式同时估计状态、噪声均值和协方差，公式复杂且计算量大。工程上极少完整使用，常见的做法是退化为**比例因子法**或**遗忘因子法**。

以下是一个简化的比例因子法实现（仅用作演示，非 phobia 源码）：

`// 简化 Sage-Husa：只自适应 Q，冻结 R（演示用）   // 注意：本示意代码只演示 Q 的自适应，R 冻结在[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章中的标定值。   //       同时自适应 Q 和 R 需要额外解耦机制，否则两者互相甩锅导致发散。   void sage_husa_adaptive_Q(    float *Q,           // 当前 Q（标量）    float S_trace,      // 理论新息协方差的迹 trace(S)    float C_nu_trace,   // 实际新息协方差的迹 trace(Ĉᵥ)    float alpha,        // Q 的学习率 [典型值 0.001~0.01]    float b             // 遗忘因子 [典型值 0.01~0.05]   )   {    // 1. 用遗忘因子更新实际协方差估计（指数加权移动平均）    //    注意：首帧直接赋值，避免从 0 开始导致的系统性低估    static float C_nu_trace_filtered = 0.0f;    static int   initialized = 0;    if (!initialized) {           C_nu_trace_filtered = C_nu_trace;           initialized = 1;       }    else {           C_nu_trace_filtered = (1.0f - b) * C_nu_trace_filtered                               + b * C_nu_trace;       }    // 2. 计算匹配误差（归一化，使学习率 alpha 无量纲）    float mismatch_ratio = (C_nu_trace_filtered - S_trace) / S_trace;    // 3. 根据匹配误差调整 Q    //    mismatch_ratio > 0：实际残差大 → 增大 Q（更不信任模型）    //    mismatch_ratio < 0：实际残差小 → 减小 Q（更信任模型）    float Q_scale = 1.0f + alpha * mismatch_ratio;    // 4. 上下界 clamp（工程必备）    //    注意：这里 clamp 的是单步缩放比例 Q_scale，不是 Q 本身。    //    累积多步后 *Q 仍可能跑出范围，所以更新后还要做一次绝对上下界。    const float Q_SCALE_MIN = 0.5f, Q_SCALE_MAX = 2.0f;   // 单步缩放比例限制 [经验值，需仿真标定]    const float Q_ABS_MIN = 0.05f, Q_ABS_MAX = 5.0f;      // Q 绝对范围 [经验值，需仿真标定]    if (Q_scale < Q_SCALE_MIN) Q_scale = Q_SCALE_MIN;    if (Q_scale > Q_SCALE_MAX) Q_scale = Q_SCALE_MAX;          *Q *= Q_scale;    if (*Q < Q_ABS_MIN) *Q = Q_ABS_MIN;    if (*Q > Q_ABS_MAX) *Q = Q_ABS_MAX;   }`

这段代码里有几个需要细说的设计选择：

**为什么用 trace（迹）而不是矩阵？**

因为 phobia 的 R 是标量，Q 被参数化为 4 个标量分量（`kalman_gain_Q[0..3]`）。在这种情况下，用 trace 把矩阵问题降维到标量，是工程上不得不做的简化。代价是丢失了不同状态维度之间的耦合信息——你无法单独判断"是电流维度的 Q 该调，还是速度维度的 Q 该调"。如果你需要维度级的自适应，Q 必须保持矩阵形式，计算量会显著增加。

**学习率 α 怎么选？**

学习率决定了 Q 调整的激进程度。α 太大，Q 会在每个 PWM 周期里剧烈抖动，估计值跟着抖；α 太小，工况变了半天 Q 还无动于衷，丧失了自适应的意义。

工程上没有万能公式。一个务实的做法是在仿真里给阶跃负载，观察 Q 的收敛速度和估计曲线的平滑度，折中选取。典型经验值在 0.001~0.01 之间 (经验值，需仿真标定)。

**遗忘因子 b 的作用**

如果 b 设得极小（接近 0），`C_nu_trace_filtered` 的记忆长度趋近无穷，开机初期的一段异常数据（比如启动过程的电流冲击）会长期拖着统计量往后偏。遗忘因子 b 决定了老残差的衰减速度：`(1-b)^n`。

`b = 0.05` 意味着旧数据按 `(1-b)^k` 指数衰减，约 `1/b = 20` 个采样点后权重降到初始的 `1/e ≈ 37%`。PWM 频率 20kHz 时，20 个采样点仅 1ms——等效记忆太短，容易被瞬时噪声误导。`b = 0.01` 对应约 100 个采样点（5ms），是更常用的选择。

> 注意：这里的 `b` 是 EWMA 中新样本的权重。有些文献把接近 1 的 `λ` 称为 forgetting factor，两者的关系是 `b = 1 - λ`。

## 5\. 验光机也会发疯：发散问题与稳定化

讲到这里，很多读者会兴奋：这不就是自动调参吗？烧进去不就一劳永逸了？

先别急。自动验光机有个致命问题：如果视力表本身印糊了，机器会以为你的眼睛有问题，一直把度数往一个方向调，直到镜片厚得像瓶底。在 EKF 里，这叫做**Sage-Husa 发散**——Q 和 R 的估计误差互相耦合、持续累积，最后协方差矩阵爆炸，滤波器彻底失控。

### 5.1 为什么会发散

Sage-Husa 的核心风险在于：**自适应参数和状态估计形成了一个闭环**。Q 的调整会改变卡尔曼增益 K，K 的改变会影响状态估计，状态估计的改变又会影响下一时刻的残差，残差的统计特性反过来再影响 Q 的调整方向。

假设某一时刻，状态估计出现了偏差（比如负载突变后模型没跟上）。残差开始系统性偏大，Sage-Husa 判断"模型不确定性被低估"，于是增大 Q。Q 增大后，预测协方差 P⁻ 膨胀，卡尔曼增益 K 变大，滤波器更信任测量——这本来是好事。但如果测量本身也有问题（比如传感器在这段时间内引入了额外的零漂），K 变大会把测量误差更快地耦合进状态估计中，导致估计进一步偏离真实值。偏离越大，残差越大，Sage-Husa 继续增大 Q……

这就是**Q 估计与状态估计之间的闭环耦合失控**：一个局部误差通过自适应机制被不断放大，最后 Q 趋向极端值，协方差矩阵失去正定性，滤波器崩溃。

这就是 §5.4 反复强调"只自适应 Q、冻结 R"的原因——减少一个变量，就减少了一层耦合。即使只调 Q，仍然有上述风险，但至少不会出现 Q 和 R 互相"甩锅"的恶性循环。

### 5.2 遗忘因子：让机器"记性不好"

稳定化的第一招，代码里已经有了：**遗忘因子**。

如果不加遗忘因子，Sage-Husa 的协方差估计是一个累积平均。累积平均的问题在于，它对所有历史数据一视同仁——十年前的一个异常点，到今天还有权重。遗忘因子通过指数衰减，让旧数据的权重按指数规律消失，相当于给统计估计加了一个"有限记忆窗口"。

等效记忆长度（指数衰减的半衰期）约为 `1/b` 个采样点。记忆太短，统计量抖动大，容易被噪声误导；记忆太长，对突发异常的遗忘慢，发散风险高。工程上需要在"响应速度"和"稳定性"之间折中。

### 5.3 上下界 clamp：物理常识是底线

第二招更粗暴，也更不可或缺：**上下界 clamp**。

无论 Sage-Husa 算出来的 Q/R 是多少，最后都要 clamp 到工程师预设的合理范围里。这不是可选优化，是工程底线——你可以自动微调，但不能跑出物理常识的边界。

上下界怎么定？可以直接借用[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章中介绍的手动调参时摸索出的经验范围。比如文章里 Q\[0\] 的有效范围大致是 0.1~2.0，那自适应 Q\[0\] 的 clamp 就可以设成 `[0.05, 5.0]`，比手动范围稍宽一点，给自适应留足空间，但绝不至于跑到物理荒谬的区间。

### 5.4 更工程的做法：只自适应一个，冻结另一个

如果你真的担心发散，还有一个更保守的策略：**只自适应 Q，冻结 R**（或反之）。

只自适应 Q 的好处是：R 的标定相对独立——它主要取决于传感器硬件特性，在采样链路已标定且短期稳定的项目里，与工况变化关系相对较小。温度漂移主要影响模型参数（Rs、ψf 等，体现在 Q 里），而电流传感器的本底白噪声功率受温度影响确实较小。但需注意 shunt 阻值温漂和运放失调会引入测量增益/偏置漂移，这不完全由 R 描述，可能需要额外的偏置补偿。所以把 R 冻结在[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章里标定好的值上，只让 Q 随工况漂移，可以大幅降低 Q/R 耦合发散的风险。

代价是自适应能力减半——如果传感器真的老化了、增益漂移了，冻结的 R 无法反映这种变化。但工程本来就是权衡。

## 6\. 适用边界：Sage-Husa 不是万能药

说到这儿，我必须泼一盆冷水：在实际的工程应用中，极难使用完整的 Sage-Husa 自适应 Q/R 实现。原因很现实。

### 6.1 计算代价

标准 EKF 的预测步和更新步已经够忙了。Sage-Husa 还要在线维护：

-   • 残差统计量（滑动窗口或指数加权平均）；
    
-   • 协方差匹配误差的计算；
    
-   • Q/R 的更新和边界检查。
    

这些运算量不算巨大，但在一个 20kHz~50kHz 的 PWM 中断里，每微秒都珍贵。如果你还要同时跑 FOC、SVPWM、速度环、位置环，MCU 的算力预算可能根本容不下一个完整的 Sage-Husa。

### 6.2 它不适合突变场景

电机控制里最头疼的不是"噪声缓慢漂移"，而是"负载突然砸下来""转速指令阶跃"这种突变。Sage-Husa 的滑动窗口有一个固有的响应延迟——它需要积累足够多的残差样本，才能判断"统计特性真的变了"。在窗口积累样本的过程中，系统可能已经失稳了。

换句话说，Sage-Husa 适合**慢性病变**（温度老化、磁链衰减、机械磨损），不适合**急性发作**（负载阶跃、转速突变）。对急性发作，你需要的是另一种武器——**强跟踪滤波器**（Strong Tracking Filter, STF），用渐消因子强制协方差膨胀，让滤波器对突变立即做出反应。那是下一篇的故事。

### 6.3 什么时候该用 Sage-Husa

那么 Sage-Husa 到底什么时候值得引入？几个典型场景：

-   • **长周期运行、环境漂移明显**：比如电动汽车驱动电机，全生命周期温度范围 -40°C~150°C，绕组电阻基于铜温系数（约 0.00393/°C，以 0°C 为基准的工程近似值）可漂移约 75%；
    
-   • **传感器老化不可更换**：工业现场传感器校准一次成本极高，需要在线补偿增益漂移；
    
-   • **多工况切换频繁且慢变**：比如 HVAC 压缩机，负载随季节缓慢变化，但人工频繁调参不现实。
    

在这些场景里，Sage-Husa 的在线修正能力确实能让滤波器"跟得上时间的脚步"。

## 7\. 工程实践建议

如果你读完这篇，决定在项目中引入 Sage-Husa，以下是务实的实施路径，而非"把公式抄进中断就完事"。

### 7.1 先监控，后自适应

不要一上来就把 Q/R 的更新逻辑写进 PWM 中断。先在主循环或诊断线程里跑一个**残差监控器**：

`// 残差监控器（演示用）   typedef struct {    float nu_history[2][RESIDUAL_WINDOW];  // 滑动窗口：[0]=iX 残差, [1]=iY 残差    float C_nu_trace;                   // 实际协方差估计    float S_trace;                      // 理论协方差（从 EKF 获取）    float mismatch_ratio;               // 归一化匹配误差 = (C_ν - S) / S   } residual_monitor_t;`

让它先跑几个工况循环，记录 `mismatch_ratio` 的分布。如果 `mismatch_ratio` 长期在 0 附近小范围波动，说明固定 Q/R 已经足够好，没必要引入自适应。如果 `mismatch_ratio` 在某些工况下持续偏离 0（比如长时间 >1 或 <-0.5）——具体阈值需按实际硬件和工况标定——那才有引入自适应的价值。

### 7.2 从单参数开始

即使决定引入自适应，也不要同时放开 Q 和 R。建议先从**只自适应 Q\[0\]**（电流维的过程噪声）开始，R 冻结在[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章中标定好的值。单参数的自适应不会出现 Q/R 耦合发散，风险可控。跑稳了再考虑扩展到其他 Q 分量。

### 7.3 遗忘因子和窗口长度需要在线验证

遗忘因子 `b` 和窗口长度 `N` 没有理论最优值，必须在目标硬件上实测。测试方法：给一个已知的负载阶跃或参数漂移，观察 Q 的收敛速度和估计曲线的平滑度。如果 Q 抖得像心电图，`b` 太大或 `N` 太短；如果工况变了半天 Q 还不动，`b` 太小或 `N` 太长。

### 7.4 保留手动覆盖的入口

无论自适应做得多漂亮，都要保留一个调试接口，让工程师可以随时手动写 Q/R。自适应不是目的，稳定运行才是。当自适应算法表现异常时，人类工程师必须有能力接管。

## 8\. 结尾：什么时候该信自动，什么时候该信人

Sage-Husa 给了我们一个诱人的前景：滤波器自己看残差、自己调参数，工程师从此告别调参噩梦。但现实是，它增加了一整层在线统计估计的计算量，且有著名的发散风险。工程上常见的归宿是退化为"分段固定"或"比例缩放"的简化方案，而非完整 Sage-Husa。

回到本文开头的困惑：客户说"工况一天变三四回，你每次都要手动改参数？"——读完这篇，你的回答应该更具体了：

-   • 如果工况变化是**缓慢漂移**（温度、老化、磨损），Sage-Husa 的自适应 Q/R 确实能让滤波器跟得上；
    
-   • 如果工况变化是**快速突变**（负载阶跃、转速急变），Sage-Husa 的滑动窗口反应太慢，你需要的是**强跟踪滤波器**；
    
-   • 如果算力预算吃紧，不如做好[上一篇](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486792&idx=1&sn=c2519e9f97c11bb4c04542f2ae259f68&scene=21#wechat_redirect)文章中讲的手动标定，加上 `kalman_bias_Q` 这种极简自适应，ROI 可能更高。
    

自动验光机再智能，最后给你戴镜片的还是验光师。Sage-Husa 再自动，最后拍板的还是工程师的判断。
