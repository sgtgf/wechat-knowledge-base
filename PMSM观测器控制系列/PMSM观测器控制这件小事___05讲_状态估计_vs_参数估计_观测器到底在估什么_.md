你调了一下午观测器。

角度估计还是不准。低速抖，高速偏。你怀疑是增益太大，往小了拧。又怀疑是采样率不够，从中断里抠了几条指令出来。再怀疑是 PLL 带宽不合适，改了一遍又一遍。

你导师过来，扫了一眼参数表，问："你这  是多少？"

"0.35 Ω，LCR 表测的。"

"冷态测的？"

"嗯。"

"电机现在 80 度了，铜电阻比冷态涨了两成左右，你观测器里的模型还是 0.35。它当然跑偏。"

你愣了三秒。

原来问题不在观测器身上。在参数身上。

前面四篇咱们讲了为什么需要观测器、反电动势（BEMF, Back-EMF）从哪来、坐标变换怎么换视角、观测器的预测-校正骨架。但有一个更底层的问题没拆透——观测器猜的是"状态"，模型里填的是"参数"。这两者在物理上、数学上、代码里，到底有什么不同？为什么调观测器的时候，有时候改的是"增益"，有时候改的是"电阻"？

今天咱们就把这条分界线画清楚。看完你会明白：状态估计和参数估计，是两条完全不同的战线。搞混了，就会像开篇描述的情况一样，对着血压计调了一下午，最后发现是体重秤没校准。

## 车速和车重，不是一回事

各位同仁，想象你开着一台车跑长途。

仪表盘上的速度——120 km/h、80 km/h、0 km/h——每一秒都在变。这是**状态**。

车重——1.5 吨——这趟旅程基本不会变。这是**参数**。

速度表只管当前速度，不问车重。地磅只管车重，不问速度。

两个仪器，两个读数，两种用途。你不会因为速度不准去称车重，也不会因为车重变了去修速度表。

回到电机上：

**状态**（State）：随时间变化的量。转子角度 、电角速度 、相电流 、磁链 。它们每一毫秒都可能不一样。

**参数**（Parameter）：描述电机本身属性的量。定子电阻 、直交轴电感 、永磁体磁链 、转动惯量 、极对数 。 和  会随温度漂移，电感会随磁路饱和变化； 和  通常视为固定参数。

观测器估的是速度——当前时刻的角度和速度。辨识器称的是重量——电机本身的电阻和电感。

这个区分听起来简单，但工程上特别容易搞混。因为状态和参数在代码里都是浮点数，在示波器上都是波形，在论文里都是希腊字母。你对着一个变量改了半天，可能根本改错了对象。

通俗来讲，如果你把这台电机换一台同型号的，参数基本一样。但如果你在同一台电机上不同时刻采样，状态完全不同。

观测器在干什么？它根据由采样或重构得到的电压电流 ，去猜此刻的  和 。它的"已知条件"是 ——这些是模型里的常数。

辨识器在干什么？它根据过去一段时间记录下来的电压电流数据，去反推  应该是多少。

说白了，观测器是"解方程求未知数"，未知数是状态。辨识器是"拟合曲线求系数"，系数是参数。

## 测速仪和地磅

咱们把这两套工具拆开来看。

**观测器 = 测速仪**

输入：当前时刻的电压、电流。

输出：当前时刻的角度 、速度 、磁链 。

核心问题："电机现在长什么样？"

它不关心电机的电阻是多少，它只关心——给定这个电阻，给定当前电压和电流，转子应该在哪个位置。电阻只是模型里的一个已知数，不是观测器的输出。

就像测速仪不关心车重多少，它只关心——车轮转多快，此刻速度是多少。

**辨识器 = 地磅**

输入：一段时间内的电压、电流等数据（有些辨识还需要速度或角度信息）。

输出：电机参数 、、。

核心问题："这台电机本身是什么属性？"

它不关心转子此刻在哪，它关心的是——从过去几秒的数据里，能不能反推出这台电机的电阻大概是多少。它需要状态数据作为输入，但输出的是参数。

就像地磅不关心你此刻开多快，它只关心——你站上去，质量是多少。

观测器是"实时直播"——每一毫秒更新一次，告诉你电机现在在哪。辨识器是"事后统计"——需要积累一段数据，算出一个相对稳定的数值。

你可以这样理解：测速仪和地磅是两个独立的仪器。直接测转速的速度表本身不受车重影响。但导航软件估算剩余里程时，车重是它的模型参数——车重变了，估算结果就会偏。电机观测器也一样：它不是直接"看"角度的仪器，而是基于电机模型"算"出来的。模型里的参数不准，算出来的状态就跟着偏。

## 代码里的分界线

工程代码里，这条分界线其实很清楚。

VESC 里有一个专门测电阻的函数（`bldc@c5944554 motor/mcpwm_foc.c:1783-1875`，节选自核心逻辑）：

`// 来源: bldc@c5944554 motor/mcpwm_foc.c:1783-1875   // 节选自 mcpwm_foc_measure_resistance() 核心逻辑      int mcpwm_foc_measure_resistance(float current, int samples,                                 bool stop_after, float *resistance) {    // 锁定转子，施加直流电流       motor->m_phase_override = true;       motor->m_phase_now_override = 0.0;       motor->m_id_set = 0.0;       motor->m_control_mode = CONTROL_MODE_CURRENT;        // ... 电流斜坡上升、等待锁轴、故障检测 ...        // 采样多组电压电流，取平均    const float current_avg = motor->m_samples.avg_current_tot                                 / (float)motor->m_samples.sample_num;    const float voltage_avg = motor->m_samples.avg_voltage_tot                                 / (float)motor->m_samples.sample_num;        // R = V / I       *resistance = voltage_avg / current_avg;        return fault;   }`

这段代码在干什么？锁转子、通直流、测电压、算 。它输出的是一个数——`resistance`。这个数一旦算出来，在后续的运行中就是固定参数。

这是**参数辨识**。它不估计角度，不估计速度，只估计电阻。

注意这个函数的名字：`measure_resistance`。不是 `estimate`，不是 `observe`，是 `measure`。 engineers 的命名习惯已经泄露了秘密——参数是"测"出来的，状态是"估"出来的。

再看观测器。本系列[第4讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486490&idx=1&sn=a9ca650fecf610d6cffb8d896d6752bb&scene=21#wechat_redirect)里咱们看过的 VESC `foc_observer_update()`，每一 PWM 周期运行一次，输入当前电压电流，输出当前磁链。它使用  和  作为模型参数，`R_ia`、`L_ia` 是用当前电流算出的压降和磁链项——不是观测器输出，而是中间计算量。

同一个工程里，既有参数辨识的接口（`mcpwm_foc_measure_resistance`），又有状态估计的观测器（`foc_observer_update`）。两者共存，但职责分明。

## 参数不准，是怎么"毒害"状态估计的？

咱们用一个具体数字来看看，参数漂移对状态估计的影响有多大。

假设你的电机冷态 ，跑半小时后热态涨到约 （铜的温度系数约 0.00386/°C，从 25°C 到 80°C 约涨 20%）。观测器模型里的  还是 0.35。

低速时这个误差尤其致命。因为低速反电动势本身就很弱（， 小的时候  也小），对于小功率电机，0.7 V 的虚假电压可能把真实信号显著淹没。大功率电机由于反电动势基数大，同等参数误差的相对影响会小一些。这就是为什么参数不准时，低速抖得特别厉害。

高速时情况反过来——反电动势基数大，0.7 V 的误差占比变小，相对影响通常下降。但仍可能带来负载相关的相位或幅值偏差，因为电阻误差项  随电流矢量和负载条件变化，不是固定分量。

说白了，参数误差在不同速区的表现不同。低速是"信噪比灾难"——虚假电压把真信号淹了。高速是相对误差变小，但仍可能留下负载相关的相位或幅值偏差。

调试的时候，如果低速抖、高速偏，电阻漂移是常见原因之一。如果低速准、高速偏，电感饱和或磁链标称值不准也值得排查。

这对应到物理直觉上——地磅不准了，你按错误的重量算油耗。测速仪本身没问题，但输入给它的"参考标准"是错的，出来的结果当然不对。

## 一个最要命的坑

### 温度漂移，你以为是增益问题

**症状**：电机跑半小时后，角度估计逐渐偏离，低速抖动加剧。

**误诊**：观测器增益太小，收敛慢。调大 gain，结果抖振更严重。

**根因**：铜电阻随温度升高。冷态 0.35 Ω，热态约 0.42 Ω。观测器模型里的  还是 0.35，预测步的电压降算错了，整个磁链估计都偏了。

**排查思路**：先把电机跑热，再用 LCR 表或 VESC 的 `mcpwm_foc_measure_resistance()` 重新测一次热态电阻。如果热态电阻和冷态差很多，先修正参数，再调观测器增益。

**正解**：先做温度补偿（ 按温度曲线修正），或者做在线电阻辨识。观测器增益本身没问题。

这个坑的共性是：**症状出在状态上，病根在参数上。** 就像你速度表不准了，可能是车重变了（参数变了），也可能是速度表坏了（状态估计坏了）。诊断的时候要先分清是哪种。
