## 一、“看不见的鬼影”与失准的电流

驱动小组正在调试一台使用**下桥臂分流电阻**（Shunt Resistor）进行电流采样的控制器。在低速轻载时，一切正常。但只要电机转速稍微提高，进入中高速区，奇怪的事情就发生了：

1.  **电机开始啸叫**，声音尖锐刺耳。
    
2.  **电流环变得不稳定**，即使PI参数已经调得很保守，还是会出现振荡。
    
3.  算法工程师用示波器抓取软件中计算出的`Id`, `Iq`，发现它们上面叠加了大量的“**毛刺**”和“**噪声**”，就像信号后面跟着一个“鬼影”。
    

团队花了很长时间排查，从EMI到接地，都查了个遍，问题依旧。

最后，一位资深硬件工程师拿出了“杀手锏”：他用示波器同时探了**PWM的门极驱动信号**和**分流电阻上的电压波形**。真相大白了：

在中高速区，为了输出更高的电压，某些相的PWM占空比变得非常小（接近0%）或者非常大（接近100%）。在这些“**极限占空比**”的PWM周期里，对应相的下管导通时间变得**极短**。ADC虽然仍然在固定的时刻去采样，但那个时刻，电流信号可能还在剧烈的开关振铃中，或者干脆下管已经关断，采到了一个无效的“零”。

这个无效的、错误的数据，被软件当成了真实的电流反馈，送进了FOC环路，导致了整个系统的崩溃。这个“鬼影”，就是硬件时序与软件采样“错位”产生的。

**那么，这个问题的解决方案在哪儿？**

答案就在代码A中的`pm.c`文件中的`**pm_clearance()**`和`**pm_voltage()**`这两个函数里。它们是代码A的作者为了解决“采样窗口”这个世纪难题，设计的一套“**软硬协同**”的精妙组合拳。

这两个函数，是FOC算法金矿的**底层基石**，是 FOC 控制里**最考验硬件理解能力**的部分。很多新手写 FOC代码，公式背得滚瓜烂熟，但电机就是转得不顺，或者一到高转速电流就乱跳，问题往往就出在这儿！

这两个函数是一对“欢喜冤家”：

-   `**pm_clearance**`**（安检员）**：负责检查 ADC 采样窗口够不够宽，能不能采到准的电流。
    
-   `**pm_voltage**`**（调度员）**：负责生成 PWM 波形。但它不仅仅是发波，为了让“安检员”高兴，它甚至会**哪怕牺牲一点电压精度，也要硬把采样窗口给挤出来**！
    

这其中藏着的“硬核逻辑”，就是**单/双电阻采样的死区与最小脉宽限制**。今天，我们就来逐行拆解这两个函数，看看它们是如何像天文学家预测日食月食一样，精确地计算出每个PWM周期里，那稍纵即逝的、如月光般宝贵的“**可信采样窗口**”，并如何调整PWM波形来“创造”采样机会的。

## 二、`pm_clearance()` 逐行走读：给数据打上“健康码”

我们先来看“裁判员”——`pm_clearance()`。这个函数不产生控制，它只做一件事：**判定当前周期的电流和电压采样是否可信**。

#### 1\. 定义“安全距离”

```
    xZONE = pm->dc_resolution - pm->ts_clearance;
```

**以上代码段的用意**：

-   `dc_resolution`：PWM 计数器的最大值（代码里该变量被赋值为2940，是由在STM32F4内核的168MHz主频的条件下，除以2倍的PWM频率得到，PWM频率被设置为35us，也就是28571Hz）。
    
-   `ts_clearance`：**最小采样窗口**。电流在采样电阻上流过，需要时间稳定（振铃衰减），ADC 采样保持（Sample & Hold）也需要时间。对应着硬件时间为5us，换算成 PWM 计数值（代码里被定义为419）。也就是所谓的“保护区”。
    
-   `xZONE`：上面两个变量的差值。如果 PWM 占空比超过了这个值，说明上管导通时间太长（或者下管导通时间太短），留给下管采样的时间不够了！
    

#### 2\. 判决：这次采样能信吗？

针对不同的硬件拓扑（`PM_CONFIG_IFB`），判决逻辑不同。咱们重点看最常见的 **下桥臂分流电阻采样（GND 模式）** 和 **相电流采样（Inline 模式）**。

**如果是**`**PM_IFB_AB_INLINE**`**（相电流采样）：**

```
    if (PM_CONFIG_IFB(pm) == PM_IFB_AB_INLINE) {
```

`xTOP`代表PWM计数器的最大值，即PWM周期的顶部边界，在`xTOP`时刻，PWM从最大值跳回0，是切换边界，此时的MOSFET会有很大的电磁干扰，AD采样是不稳定的。

但是注意啊，这个可不是绝对的，尽信书不如无书，要**具体情况具体分析！**在FOC的控制里要避免在MOSFET的切换边界进行AD采样，但在两相120°导通的Sensorless方波控制的BLDC电机的悬空相反电势AD采样的场合，恰恰就是在PWM周期的顶部边界，也就是MOSFET的切换边界进行采样的。

**如果是**`**PM_IFB_AB_GND**`**（下桥臂分流电阻采样，最经典也是最难的）：**

```

#### 3\. 最终裁决：我还有救吗？

```

```

**硬核逻辑**：

-   不管你有几相电流传感器，要重构出完整的相电流 ，最少需要知道**两个**采样数据。
    
-   如果坏了两个采样数据（比如占空比 100% 和 99%，两相下管都不导通或几乎不导通），那这一周期的电流环就**瞎了**！
    
-   `vsi_IF` 就是全局的“失明”标志，代表着整体采样有效性。`vsi_AF`是A相采样有效性；`vsi_BF`是B相采样有效性；`vsi_CF`是C相采样有效性。
    

**这一站的小结:**

`pm_clearance`就像一个兢兢业业的“**数据质检员**”。它不看当前，只看**过去**。它在每个周期的开始，回头检查上一个周期的PWM波形，然后给上个周期采到的数据盖上一个“合格”或“不合格”的章。后面的算法（比如辨识、观测器）就可以凭这个“章”来决定是否采纳这组数据。

以上这段代码的核心目的，就是**为了让电流采样能够正常工作，不惜临时改变 SVPWM 的调制策略。**

我们在学习SVPWM的时候，默认了一个美好的世界：

-   **理想**：SVPWM 的波形又对称又漂亮，电压利用率高。
    
-   **现实**：为了省钱，很多控制器只在某一个桥臂上串了一个采样电阻（比如下桥臂）。
    

**问题来了：**

-   **下桥臂采样**：只有当电流流过下桥臂时，才能采样到电流。
    
-   **采样时机**：ADC 需要时间，而且电流在开关瞬间会有很大的尖峰和振荡，不能采（或者说采集到了数据也不能用）。我们必须等电流**稳定**了才能采。
    

这就意味着，我们必须在 PWM 周期里，留下一个“**干净的、足够长的下管导通时间窗口”**，专门给 ADC 采样用。

标准的 SVPWM（7段式）非常对称，它会用到`000`（三相上桥臂全关）和`111`（三相上桥臂全开）两个零矢量。

**麻烦就出在**`**111**`**上！**

当逆变器处于`111`状态时，三相电流都从上管走，**下桥臂根本没电流**！ADC 采了个寂寞。

更大的麻烦是：在高调制比下（高速重载），为了凑出足够的电压，SVPWM 会让**有效矢量**（比如 100, 110）的时间变得很长，留给**零矢量**的时间就非常非常短。短到什么程度？可能只有几个微秒（µs），ADC 还没反应过来，这个短暂的 `000` 窗口就过去了。

结果就是：**电流采样失败**。FOC 控制失去了眼睛，下一秒电机就会失控。

#### 4.2 `PM_IFB_AB_INLINE` 分支解读（更复杂的情况）

`INLINE`代表**在线采样**（比如采用了隔离的霍尔电流传感器）。这种采样方式更高级，但也有自己的麻烦。它需要 PWM 脉冲既不能太宽（接近100%），也不能太窄（接近0%）。

之所以说它的逻辑更复杂，是因为它不仅涉及“向下看（接地）”，还涉及“向上看（接电源）”，是一套“**双向奔赴”的动态调整策略。**

有同仁可能好奇，用霍尔线圈进行相电流采样，和下桥臂分流电阻相比，不是更高级吗？电流一直都在流，想啥时候采就啥时候采，为啥还要限制占空比？

我来告知如此发问的同仁**3个打脸的现实：**

1.  **开关噪声**：当 IGBT/MOSFET 开关动作的瞬间（0变1，或1变0），电路里会有剧烈的震荡和噪声。
    
2.  **ADC 的恐惧**：如果 PWM 脉冲特别窄（比如只有 1us 的高电平，或者 1us 的低电平），那么开关刚刚打开，噪声还没平息，马上又要关断。这时候 ADC 采样，采到的全是噪声，根本没法用。
    
3.  **死区影响**：极窄脉冲还会受到死区时间的严重扭曲，导致发出的电压和想要的不一致。
    

所以，**代码的目标是：**要么给我一个**足够宽**的脉冲（让噪声平息后再采）；要么干脆**别开关了**（直接钳位到 0% 或 100%），彻底消灭噪声源！

```

很多上桥臂的开关管，如MOSFET、IGBT等，它们的驱动电路是用“自举电容”给上管栅极供电的。这个电容只有在下管导通时才能充电。如果占空比一直是 100%（`xA == dc_resolution`），上管一直开，下管一直关，电容电放光了，上管就驱动不起来了，甚至会进入线性区烧管子。

**代码逻辑是**：如果发现某相一直 100% 占空比的时间太长（超过 `ts_bootstrap`），强制保护停机。

**这段代码是在防谁？**

1.  **防堵转**：电机堵转时，某一相可能长时间输出高电平。
    
2.  **防过调制**：我们前面讲的 `PM_IFB_AB_INLINE` 模式，为了采样，可能会**强制顶部钳位**（让上管长通）。
    

-   **矛盾点**：为了采样，我们希望上管长通；为了硬件不炸，我们不能让上管通太久。
    
-   **平衡点**：这段代码就是那个**“最终裁判”**。你可以钳位，可以长通，但你不能无休止地长通。一旦越过红线，硬件安全高于一切，直接报错停机。
    

这段代码虽然短，但充满了**“硬件亲和力”。**这也是优秀嵌入式代码的特征：**懂算法，且更懂硬件。**

#### 6\. 真实的电压反馈

自举电容亏电保护代码完后，代码又重新算了一次电压：

```
    uA = (xA - xC) * pm->const_fb_U * pm->ts_inverted;
```

有同仁可能会问：“我们刚才不是已经算出`uA, uB, uC`，也生成了`xA, xB, xC`，甚至都`proc_set_DC`输出给硬件了吗？为什么还要反过来再算一遍电压？”

因为经过刚才那一顿“**钳位、限制、死区补偿、自举保护**”的操作，**实际上发给电机的电压，已经和我们最初想要的电压不一样了！**

为了让下一周期的观测器（Observer）能算得准，我们必须**诚实地**告诉它：“**刚才那一波，我实际到底发了多少电压给电机。**”

这个过程总共分为三步：

**第一步：发波。**

```
/* Output DC values to PWM. */
```

这一行很简单，就是把最终裁定好的 `xA, xB, xC`（0 ~ 1000 的整数）写入单片机的定时器寄存器。

**注意**：这时候，电压已经发出去了，木已成舟。

**第二步：重返现场**

现在，我们要把这个`xA, xB, xC`（整数占空比），还原回`vsi_X, vsi_Y`（α，β轴的实际物理电压）。

#### 1\. 为什么要减去共模分量？

```
uDC = 0.33333333f * (xA + xB + xC);
```

-   `xA, xB, xC` 里包含了我们之前注入的**零序分量**（那个 `0.5 - (Max+Min)/2`），甚至还包含了**钳位操作**带来的偏移。
    
-   **物理真理**：电机只认**线电压**（差模电压），不认共模电压。
    
-   所以，我们要算出当前的**平均共模电压** `uDC`，然后把它减掉，还原出电机真正“感觉到”的电压。
    

#### 2\. 还原相电压（标幺值 → 物理值）

```
// (占空比 - 共模) * 母线电压 * 归一化系数
```

-   `xA - uDC`：去除了共模成分的纯净占空比。
    
-   `pm->const_fb_U`：当前的直流母线电压（比如 24V）。
    
-   `pm->ts_inverted`：`1.0 / dc_resolution`（比如 1/1000）。
    
-   **结果**：算出了实际施加在电机绕组上的**物理电压**（比如 12.5V）。
    

#### 3\. Clarke 变换

```
// 三相静止坐标 -> 两相静止坐标
```

这就是经典的 **Clarke 变换**。`0.577...` 是1/sqrt(3) ，`1.154...` 是2/sqrt(3)。目的是把三相电压还原回αβ轴的电压 `vsi_X, vsi_Y`。

有同仁此刻可能会想：“我最开始不就有`uX, uY`吗？直接用那个不行吗？”

**绝对不行！因为：**

-   **输入**：`uX, uY` 是 PI 控制器**想要**发出的电压（理想值）。
    
-   **经过**：过调制处理 → 零序注入 → 采样窗口钳位 → 死区限制 → 自举保护。
    
-   **输出**：`vsi_X, vsi_Y` 是电机**实际**吃到的电压（真实值）。
    

如果我们的无感观测器（Flux Observer）用“理想值”去计算磁链，而电机实际吃的是“阉割版”的电压，观测器就会**产生累积误差**，最后导致估算角度发散，电机失步。

**所以，这段代码是在做“反馈校正”，保证观测器的输入数据是真实可靠的。**

**第三步：再次确认采样窗口**

```
/* Update the clearance flags according to the new DC values. */
```

虽然我们刚才已经在 `INLINE` 或 `GND` 分支里努力调整了占空比，试图留出采样窗口。但是，经过一系列的硬限制和保护，**最终到底留没留出来？** 谁也不敢打包票。所以，这里再次调用 `pm_clearance`，拿着最终的 `xA, xB, xC` 去检查：**“刚才这波操作后，ABC 三相的电流到底能不能采？”**如果检查结果是 **不能**（比如 `vsi_AF = 0`），那么下一周期的电流采样中断里，程序就会**丢弃**这次采样数据，防止脏数据污染控制环路。

这段代码体现了控制系统设计的一个核心原则：**“闭环思维”**。

不要盲目相信你的输出命令，要相信**经过硬件约束后的实际执行结果。**把这个实际结果反馈给下一级的算法（观测器），系统才能在各种极端工况下依然稳如老狗。

## 四、本讲落地：给工程师的行动指南

今天我们一起潜入了PWM周期的微观世界，理解了“采样窗口”和代码为之付出的努力。

### 1\. 对硬件工程师

-   **采样点位置是“核心”**: 你们在设计硬件时，开关管的开关时刻是与算法强相关的关键参数。这个时刻必须和算法工程师达成一致，并写入文档。改变它，就意味着整个`ts_clearance`和钳位逻辑都要重新评审。
    
-   **拓扑选择的权衡**: 今天的文章应该让你们更清楚地看到：选择下桥臂分流电阻采样，就意味着必须在软件层面做更复杂的PWM重构来保证采样；选择相母线电流分流电阻采样，就对运放的共模抑制和ADC的采样精度提出了更高要求；选择霍尔电流传感器，就用成本换来了简单。
    

### 2\. 对算法工程师

-   `**ts_clearance**` **和** `**ts_minimal**` **不再是玄学**: 这两个参数现在对你们来说应该非常具体。它们是需要根据你们的硬件（驱动延时、MOSFET开关时间、采样运放建立时间）来精确标定的。它们是连接软件和硬件的“桥梁”。
    
-   **理解钳位的代价**: `pm_voltage` 里的钳位逻辑，虽然保证了采样的有效性，但它也确实引入了微小的电压失真。在做高精度转矩控制或参数辨识时，你要知道存在这个“代价”。可以考虑在钳位发生时，对辨识数据进行标记或降权。
    

### 3\. 对测试工程师

-   **设计“极限占空比”测试用例**: 在你们的自动化测试脚本中，要专门设计一些能让电机运行在极限占空比区域的工况（比如高转速空载、或高转速满载弱磁）。在这些工况下，重点监控：
    

-   软件是否报出了采样无效的错误码。
    
-   `Id/Iq` 是否出现了大量的毛刺和振荡。
    
-   电机是否出现异常啸叫。 这可以直接验证 `pm_clearance` 和 `pm_voltage` 的钳位逻辑是否有效工作。
