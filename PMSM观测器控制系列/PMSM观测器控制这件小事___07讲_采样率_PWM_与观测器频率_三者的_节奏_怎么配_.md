前向 Euler、改进 Euler、Tustin——该选的方法选好了，该算的载波比也算过了。你信心满满的把代码下到 DSP，电机拉到一万转。

角度估计还是抖。

此时不是离散化方法的锅——假设你的系统 C/F 有 40，Euler 完全够用。电阻电感你也重新测过，增益从 500 调到 5000，再调回 1500，跳变还在。

在参数、增益、死区等因素已经排查后，仍然高速抖动时，下一步要重点检查**采样到执行之间的等效延迟**。

**会发生这种情况大概率是因为你还没意识到一件事：观测器使用的是离散采样得到的电流/电压信息，而控制输出的电压对电机生效存在等效延迟。这个延迟取决于 ADC 触发点、ISR 执行时刻、PWM 寄存器更新方式，可能是半拍、一拍，甚至 1~2 个 PWM 周期。高速时，转子在这段时间里已经转过十几度了。**

这就像你拿着上一秒的照片指导自己开车——照片里路况是对的，但你的车已经开出去了十几米。

说白了，离散化方法选对了只是第一步。你还得搞清楚：**PWM 多久敲一次鼓、ADC 多久听一次、观测器多久算一次——这三个节拍对不上，再好的离散化也白搭。**

## 移动靶：你瞄准的是上一秒的位置

各位同仁不妨先放下示波器，想一个场景。

奥运会双向飞碟比赛。碟靶从掩体里飞出来，运动员举枪射击。

关键是：**他扣下扳机的那一刻，眼睛看到的是碟靶上一瞬间的位置。但子弹从枪口飞到靶位需要时间，碟靶在这几毫秒里又往前飞了一段。** 不打提前量，枪枪脱靶。

电机控制里的 ADC、观测器和 PWM，就是这场射击的三个环节。

**射手眼睛：ADC**

模数转换器（ADC, Analog-to-Digital Converter）是射手的眼睛。它每隔固定周期"看一眼"电流——把电流传感器的模拟信号变成数字量。但就像眼睛看到画面有传输延迟，ADC 采样到的那组电流值，对应的是**采样那一刻**的电机状态；等控制器拿它来计算时，它已经是带时间戳的旧样本了。

为什么常选在 PWM 周期中点采样？因为开关管刚切换完的瞬态噪声最大，等半个周期过去，电流波形基本稳定了，读数最可靠。

**射手大脑：观测器**

观测器接过采样电流，以及由调制量 / 母线电压重构出来的电压信息，像射手的大脑做弹道计算——用模型预测 + 测量校正，算出转子角度和速度。

**子弹飞行：PWM 更新**

脉宽调制（PWM, Pulse Width Modulation）是射出去的子弹。新的占空比算好了，但得等到下一个 PWM 周期开始，才真正打到电机上。这就是子弹从枪口到靶位的飞行时间。

三个环节跑完，一个周期结束。下一个周期，碟靶又飞出去一截。

**但这里有个天大的坑。**

实际链路中的因果顺序是这样的：

1.  1. **PWM / 定时器事件触发 ADC 采样**
    
2.  2. **ISR 读取采样值**（三相电流）
    
3.  3. **观测器 / 控制器计算**（Clarke → Park → 电流环 → 逆 Park + SVPWM）
    
4.  4. **新占空比写入 PWM 寄存器**
    
5.  5. **下一个 PWM 周期开始，新调制量才真正生效**
    

看明白了吗？

**第  拍算出来的控制量，要到第  拍才能影响电机。**

这就是**一拍延迟（One-Step Delay）**。它不是代码写得不够好，不是算法不够快，而是数字控制系统的基本事实——采样、计算、执行之间永远存在等效延迟。真正要核清楚的是：在你的这套系统里，这个延迟到底等效于多少。

就像射手看到的永远是靶子上一瞬间的位置。等他算好提前量、扣下扳机，子弹飞到的时候，靶子早就飞出去一截了。

**12°电角度！** 在磁场定向控制（FOC, Field-Oriented Control）里，Park 变换需要精确的电角度。角度偏差 12°，意味着  轴和  轴的控制量"串味"了——你想控制转矩的电压，有一部分漏到了磁链轴上。

这会导致：

-   • 转矩脉动增大
    
-   • 电流环耦合变严重
    
-   • 高速时效率下降、噪声增加
    

如果观测器更新频率降到 10kHz（一拍 100μs），这个偏差翻倍到 **24°**。对多数 FOC 应用来说，这个偏差已经相当大了。

## VESC 怎么补？代码里找答案

聊了这么多理论，看看真实代码是怎么处理一拍延迟的。

VESC 在运行路径中的做法是：**用当前速度对观测器相位做前推补偿**。

`// 来源: bldc/motor/mcpwm_foc.c:3439   // 节选自 VESC ADC/DMA 采样完成中断路径中的角度补偿   // bldc@c5944554   // dt 为观测器实际更新周期，由 p_dt 决定，不一定等于 PWM 周期      motor_now->m_phase_now_observer += motor_now->m_pll_speed * dt                                       * (0.5 + conf_now->foc_observer_offset);`

这里 `foc_observer_offset` 是用户可配置的补偿参数。源码采用 `0.5 + offset` 作为运行路径中的相位前推系数，实际补偿量由配置决定。默认 `MCCONF_FOC_OBSERVER_OFFSET` 为 -1.0，是否启用补偿以及补偿多少取决于具体固件配置。

为什么是 `0.5 + offset`？

在这条运行路径里，VESC 先给了一个 0.5 个更新周期的基准前推，再把 `foc_observer_offset` 作为可配置修正量叠加进去；真正补偿多少，要看采样时刻、PWM 更新方式和具体配置共同决定。

需要强调的是，这是 VESC 在特定运行路径中的相位前推补偿写法，不是对所有观测器、所有状态下的通用公式。不同厂商 SDK 的采样、计算、PWM 更新时序不一定相同，不能照搬这个补偿写法。

换句话说，这就是**线性外推**："我知道你现在在哪，也知道你跑多快，所以我猜你下一拍会在哪"。

当然，这种预测只在加速度不大的时候准。如果电机在急加速或急减速，线性外推会漏掉加速度项。更高端的做法是用二阶预测（加速度和速度一起外推），但那对算力的要求也更高。

## 同步 vs 异步：两种架构的延迟差异

VESC 采用"多线程异步"架构，不是唯一选择。咱们拿 ST 电机控制软件开发工具包（ST MC SDK）来做个对比。

ST MC SDK 采用**单一主中断**架构 \[UM2374\] 。ADC 采样、Clarke/Park 变换、电流环、观测器更新、占空比写入等模块，通常在同一个中断服务程序（ISR, Interrupt Service Routine）里串行执行。

这种架构下没有线程切换开销，时序相对简单。

VESC 则把不同频率的模块拆到不同线程/中断中：

-   • 高频控制链：ADC/DMA 采样完成中断路径（20~40 kHz），观测器和电流环在这里
    
-   • 中频管理：timer\_thread（约 1 kHz），负责温度补偿、状态机、弱磁等不需要每个 PWM 周期都处理的杂事。速度/位置环的 PID 另有独立控制逻辑，观测器主更新则在采样中断路径中
    
-   • 低速估计：高频注入法（HFI, High-Frequency Injection）独立线程
    

一句话总结：**不同厂商 SDK 的采样、计算、PWM 更新时序不一定相同。ST SDK 的架构相对简单可控；VESC 采用"中断 + 线程"混合架构，复杂性主要来自多速率任务、共享状态和采样/更新时序的协调。**

## 三个坑，坑坑都要避开

**坑 1：在仿真里跑得飞起，下到硬件就抖**

> **症状**：Simulink 里完美运行，代码下到 DSP 后电机一高速就角度抖。
> 
> **根因**：Simulink 的连续模型仿真常使用变步长求解器，效果上相当于使用自适应高精度数值积分。真实硬件里的一拍计算/执行延迟在仿真里不会被自动复现。
> 
> **解法**：做代码一致性验证时，应使用 fixed-step、离散控制器、ZOH 采样保持，并显式加入 Unit Delay / transport delay / PWM 更新延迟模型。线性模型可用 `c2d` 函数辅助离散化。

**坑 2：以为提高 PWM 频率就能消灭延迟**

> **症状**：PWM 从 10kHz 提到 20kHz，观测器更新频率也跟着翻倍，但高速时角度偏差仍然明显。
> 
> **根因**：如果观测器/控制更新频率跟着 PWM 一起提升， 减半，延迟对应的电角度确实会减半。但如果观测器仍降频运行，或者补偿项没有跟着新的时序更新，问题仍可能存在。真正需要做的是**确认补偿项与当前时序匹配**，而不是单纯提频率。
> 
> **解法**：先算清楚你的电机在最高转速、当前观测器更新频率下，一拍转过多少度。如果一拍转过角度较大（如超过 5°~10°，视应用精度要求而定），必须确认代码里有补偿。提 PWM 频率只能缓解，不能根治。

**坑 3：观测器降频"偷懒"**

> **症状**：为了省 CPU，把观测器从每 PWM 周期跑一次改成每两个周期跑一次。
> 
> **根因**：观测器更新频率减半，意味着它拿到的电流信息更旧了。原来是"上一拍"的，现在变成"上上拍"的。等效延迟往往会明显变大，高速时角度偏差也会随之放大，严重时接近翻倍。
> 
> **解法**：观测器更新频率降得越低，信息延迟越大。工程上常见做法是观测器与电流环同频运行，不轻易降频。如果确实算力不够，优先简化观测器算法（比如从扩展卡尔曼滤波器（EKF, Extended Kalman Filter）退到滑模观测器（SMO, Sliding Mode Observer）），而不是降低更新频率。

## 示波器看哪里

一拍延迟问题在示波器上有明确的"症状"。

**症状 1：高速时角度估计系统性超前或滞后**

-   • **看哪里**：把观测器输出的  和编码器实测的  同时上示波器
    
-   • **正常**：两者波形基本重合，误差在几度以内
    
-   • **异常**：高速区出现系统性相位偏移（观测器始终比编码器超前或滞后一个固定角度），且不随增益调整而消失
    
-   • **根因**：一拍延迟补偿不足或补偿过度。补偿少了，观测器滞后；补偿多了，观测器超前
    

**症状 2：同一套参数，低速稳高速抖（与离散化误差的区分）**

-   • **看哪里**：速度环输出或  轴电流给定
    
-   • **正常**：全速域平稳
    
-   • **异常**：低速区一切正常，一过某个转速阈值就开始抖，且抖动幅度随转速线性增大
    
-   • **根因**：一拍延迟导致的偏差角度随转速线性增大（），低速时不明显，高速时致命
    
-   • **与[上一篇文章](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486511&idx=1&sn=06f325c71240480625326415fe7f5c66&scene=21#wechat_redirect)讲到的离散化误差的区别**：离散化误差随 C/F 降低逐渐加重，常在低 C/F 区间明显恶化；一拍延迟误差在固定  下随电角速度线性增加，低速时不明显。
    

## 🔧 调试 Checklist

\[ \] 计算你的电机在最高转速、当前观测器更新频率下，一拍内转过多少度：  
\[ \] 确认代码里有角度补偿项（如 VESC 的 `foc_observer_offset` 或类似的 `speed * dt * 0.5`）  
\[ \] 对比 Simulink 仿真和实际硬件：仿真时是否用了与硬件相同的 fixed-step 和采样时间？  
\[ \] 确认 ADC/PWM 快速中断优先级、最长关中断时间、DMA/ADC 完成延迟和其他高优先级 ISR 是否引入额外抖动  
\[ \] 观测器更新频率是否等于 PWM 频率？如果降频到 1/2，重新核算等效延迟是否增大，以及角度补偿量是否需要相应调整
