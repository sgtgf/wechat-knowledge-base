## 一、调试现场：公式都懂了，代码从哪行开始写？

你读完了 [第41讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486835&idx=1&sn=d4af136833c5b8e10f19d77dbb0f46b4&scene=21#wechat_redirect) 到 [第43讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486846&idx=1&sn=20da599fedfdf713b37f80bcc908d0b2&scene=21#wechat_redirect)，脑子里已经有了完整的 MRAS 图景：电压模型当裁判，电流模型当选手，叉乘类运算  把二维误差压缩成一维转速偏差，PI 自适应律把偏差翻译成转速修正量。你甚至已经在草稿纸上把 Popov 不等式的推导过了一遍，确认 PI 结构在理论上站得住脚。

周一早上，你打开 IDE，新建了一个 `mras.c`，盯着空白屏幕，手指悬在键盘上——

**第一步写什么？**

你当然知道要算两个磁链模型，但你突然意识到一件事：这两个模型不是独立的。电流模型的更新需要当前转速估计值 （通过角度积分隐含），而转速估计值又依赖于两个模型的误差。这就形成了一条**递推依赖链**——上一拍的状态决定当前拍的计算，当前拍的输出又成为下一拍的输入。如果你的更新顺序错了，误差会被"自我欺骗"地缩小，系统越调越偏。

这不是"写得好不好看"的问题，这是**会直接导致电机失步的硬错误**。

更麻烦的是，你翻了翻手头的资料。\[1\] 给了 MATLAB/Simulink 框图，但那是连续域的，没有告诉你中断里每行代码谁先谁后。你找到的开源实现（如果有的话）每家写法都不一样：有的把电压模型和电流模型放在同一个函数里，有的拆成两个；有的先算误差再调转速，有的顺序似乎反了但又能跑——因为那家的模型结构跟你的不一样。

你需要的不是"某一份代码"，而是**理解这条链路上的每一步为什么必须在这个位置**。

这就是本文要解决的困惑。

## 二、先尝后调，还是先调后尝？

想象你学做菜。每轮（每个 PWM 周期）师父端出一盘标准口味的鱼香肉丝（参考模型），你自己也炒了一盘（可调模型）。你的目标是调整下一轮的火候（转速），让自己的菜逐渐接近师父的标准。

正确的做法是什么？

**先尝本轮炒好的两盘菜，对比差距，再决定下一锅的火候。** 你夹一筷子师父的，再夹一筷子自己的，对比咸淡、酸甜、辣度——这就是误差 。然后根据本轮的差距决定下一轮火开大还是关小——这就是自适应律输出的转速估计值 。

你不能用"下一锅调好的火候"回头去修改已经端上桌的菜——那盘菜的味道已经定了，你再怎么调火，改变的是下一盘，不是这一盘。MRAS 的致命错误正是如此：**把本拍新算出的转速"回灌"到本拍已经用过的可调模型里**，等于用"下一锅的火候"去评判"这一锅的菜"，时间戳混用了。

正确的顺序只有八个字：**先裁判、后选手、再算差、最后调。**

下面我们把这八个字翻译成代码，一步一拍地拆开。

## 三、一个 PWM 周期里的八拍

MRAS 的代码链路本质上是一种**保守的显式实现顺序**：每一步的输出是下一步的输入，时间戳必须严格对齐。其他实现（如预测-校正、延迟补偿）在工程上完全可行——VESC、ODrive 等开源项目都有相位预测——但前提是必须证明同一拍内的变量时间戳一致、反馈极性正确。本文先给出最不容易翻车的保守顺序，等你把这条链路跑稳了，再考虑加预测也不迟。

下面是一段演示用示意代码，展示一个 PWM 中断里 MRAS 的完整执行链路。每行注释都标明了"这步的输入从哪里来、输出去哪里"，以及"为什么必须排在这个位置"。

`// 示意用，非特定开源项目源码   // 以下代码假设 alpha/beta 静止坐标系，SPMSM 模型   // 状态变量为全局静态，在定时器中断里按严格顺序更新      static float psi_ref_alpha = 0.0f;   // 参考模型磁链 alpha   static float psi_ref_beta  = 0.0f;   // 参考模型磁链 beta   static float theta_est     = 0.0f;   // 估计电角度   static float omega_est     = 0.0f;   // 估计电角速度   static float integral_A    = 0.0f;   // PI 积分累积器      // 电机参数（标称值，工程上可能在线辨识或查表）   #define Rs   (0.5f)       // 定子电阻，Ω   #define Ls   (0.003f)     // 定子电感，H   #define psi_f (0.15f)     // 永磁体磁链，Wb   #define Ts   (0.00005f)   // 控制周期，20 kHz → 50 μs      void mras_update(float i_alpha, float i_beta,                 float u_alpha, float u_beta)   {    // ============================================================    // Step 1: 输入就绪    // i_alpha/beta: 当前拍采样电流（已由 ADC + Clarke 变换提供）    // u_alpha/beta: 当前拍重构电压（由 Vdc * duty 计算或观测得到）    // ============================================================    // 注意：电压重构的精度直接影响参考模型。死区补偿、    // 逆变器非线性建模、ADC 增益误差都会以偏置形式进入 psi_ref。    // ============================================================    // Step 2: 更新参考模型（电压模型）——"师父的标准菜"    // 输入：上一拍磁链 + 当前电压/电流    // 输出：当前拍磁链估计值    // ============================================================    // 电压模型的本质：psi_ref = integral(u - R*i) dt    // 离散化：前向欧拉，psi += Ts * (u - R*i)    //    // ⚠️ 纯积分会漂移。低速区直流偏置累积会导致 psi_ref 缓慢暴走。    // 工程上需配合 SOGI、准低通或高通反馈抑制漂移（详见 [第42讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486840&idx=1&sn=f3dd1c0b855daf37e51480b45cca0f42&scene=21#wechat_redirect)）。    // 这里为了展示链路完整性，保留纯积分形式，但加了抗漂移注释。          psi_ref_alpha += Ts * (u_alpha - Rs * i_alpha);       psi_ref_beta  += Ts * (u_beta  - Rs * i_beta);    // ============================================================    // Step 3: 更新可调模型（电流模型）——"你自己的菜"    // 输入：当前电流 + 上一拍角度 theta_est    // 输出：当前拍磁链估计值    // ============================================================    // 可调模型的本质：psi_adj = Ls * i + psi_f * e^(j*theta)    // 其中 theta 由 omega_est 积分得到，隐含了待辨识转速。    //    // ⚠️ 关键约束：这里必须用上一拍的角度 theta_est，    // 不能把本拍新算出的转速"回灌"进来更新本拍的可调模型。    // 否则同一拍内出现时间戳混用，误差被人为压缩。    float psi_adj_alpha = Ls * i_alpha + psi_f * cosf(theta_est);    float psi_adj_beta  = Ls * i_beta  + psi_f * sinf(theta_est);    // ============================================================    // Step 4: 计算磁链误差    // 输入：Step 2 和 Step 3 输出的当前拍磁链估计值    // 输出：误差矢量 e_alpha, e_beta    // ============================================================    // 误差定义：参考减可调（与 [第43讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486846&idx=1&sn=20da599fedfdf713b37f80bcc908d0b2&scene=21#wechat_redirect) 约定一致）    // 如果定义反过来，后续 A(e) 的符号也要反，闭环极性必须对应调整。    float e_alpha = psi_ref_alpha - psi_adj_alpha;    float e_beta  = psi_ref_beta  - psi_adj_beta;    // ============================================================    // Step 5: 叉乘类运算 A(e) ——"量错角"    // 输入：误差矢量 e + 可调模型磁链 psi_adj    // 输出：标量转速偏差信号 A_e    // ============================================================    // A(e) 在 alpha/beta 平面上量的是两个磁链矢量之间的有向错角。    // 符号约定与坐标系有关，本文沿用 [第43讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486846&idx=1&sn=20da599fedfdf713b37f80bcc908d0b2&scene=21#wechat_redirect) 的约定。    //    // 如果 psi_adj 滞后于 psi_ref，A_e > 0 → 转速估小了，需要加大；    // 如果 psi_adj 超前于 psi_ref，A_e < 0 → 转速估大了，需要减小。    float A_e = e_beta * psi_adj_alpha - e_alpha * psi_adj_beta;    // ============================================================    // Step 6: PI 自适应律更新转速    // 输入：A_e + 积分历史    // 输出：新转速 omega_new    // ============================================================    // 积分累积（位置式 PI，也可用增量式）       integral_A += A_e * Ts;    // 抗积分饱和：先限幅积分，再计算输出    if (integral_A >  INTEGRAL_MAX) integral_A =  INTEGRAL_MAX;    if (integral_A < -INTEGRAL_MAX) integral_A = -INTEGRAL_MAX;    // 比例 + 积分输出    // K_prop 和 K_int 的量纲/数值选择见 [第43讲](https://mp.weixin.qq.com/s?__biz=MzE5MTYzNjgzOA==&mid=2247486846&idx=1&sn=20da599fedfdf713b37f80bcc908d0b2&scene=21#wechat_redirect)，这里仅展示结构    float omega_new = K_prop * A_e + K_int * integral_A;    // 增益符号必须与 A(e) 的极性共同构成负反馈。    // 如果 K_prop 和 K_int 同号为正，且 A_e 的符号约定如上述，    // 则 omega_new 的变化方向会正确驱动误差收敛。    // 符号反了就是正反馈，系统直接发散。    // ============================================================    // Step 7: 限幅与保护（必须在角度积分之前）    // ============================================================    // 转速限幅：防止估计值暴走导致电流环失控    if (omega_new >  OMEGA_MAX) omega_new =  OMEGA_MAX;    if (omega_new < -OMEGA_MAX) omega_new = -OMEGA_MAX;    // ============================================================    // Step 8: 角度积分    // 输入：限幅后的新转速 omega_new + 上一拍角度 theta_est    // 输出：当前拍新角度（供下一拍使用）    // ============================================================    // 角度由转速积分得到。这里必须用限幅后的 omega_new，    // 否则角度会按照超限值积分，与限幅后的转速状态不一致，    // 高速突变场景下会导致角度和转速脱节。          theta_est += omega_new * Ts;    // wrap to [-pi, pi] 或 [0, 2*pi]，防止浮点溢出    // fmodf 在部分 MCU 上可能较慢，可用条件减法替代       theta_est = fmodf(theta_est, 2.0f * PI);    if (theta_est < 0.0f) theta_est += 2.0f * PI;    // 更新全局状态，供下一拍使用       omega_est = omega_new;   }`

**这八拍的依赖关系是一条严格的有向链**，没有循环。

-   • 参考模型只依赖电压、电流和自身历史；
    
-   • 可调模型依赖电流和**上一拍**的角度（隐含上一拍转速）；
    
-   • 误差依赖两个模型的输出；
    
-   • 自适应律依赖误差和积分历史；
    
-   • 新转速只影响本拍角度积分，以及下一拍的可调模型。

## 四、顺序错了会怎样？

如果你把 Step 3 改成这样——**用本拍新算出的转速"回灌"本拍可调模型**：

`// ════════════════════════════════════════════════════════   // 致命错误示范：本拍回灌——用新转速重写本拍可调模型   // ════════════════════════════════════════════════════════      // Step 6 已经算出了新转速   float omega_new = K_prop * A_e + K_int * integral_A;      // 致命错误：把新转速"回灌"到本拍的可调模型   // 正确的做法：omega_new 只影响下一拍，不能修改本拍已经算过的 psi_adj   float theta_wrong = theta_est + omega_new * Ts;   float psi_adj_alpha = Ls * i_alpha + psi_f * cosf(theta_wrong);   float psi_adj_beta  = Ls * i_beta  + psi_f * sinf(theta_wrong);      // 然后用这个"已经被自我满足"的可调模型算误差   float e_alpha = psi_ref_alpha - psi_adj_alpha;   float e_beta  = psi_ref_beta  - psi_adj_beta;   float A_e = e_beta * psi_adj_alpha - e_alpha * psi_adj_beta;      // 误差被人为压缩，但算法还在继续跑...`

这段代码的逻辑灾难在于**时间戳混用**：同一拍里，可调模型先被新转速"改写"了一遍，然后拿这个"改写后"的版本去跟参考模型比。参考模型用的是"本轮真实样本"，可调模型却用了"本轮修正后的版本"——比较基准被破坏了。

1.  1. **可调模型被"自我满足"了**。它不再是独立的观测基准，而成了自适应律的"回声"。
    
2.  2. **误差被人为压缩**。算出来的  不能反映真实偏差。
    
3.  3. **PI 基于虚假误差继续调整**。在 PI 增益不够保守或初始偏差较大的场景下，系统会进入**结构性发散**——被自己制造的虚假信号骗进正反馈死胡同。
    

> **注意**：很多真实工程代码（如 VESC、ODrive）确实会做一拍相位预测或延迟补偿，但这和"本拍回灌"有本质区别。预测是用**上一拍的状态**推算**下一拍使用**的角度；而致命错误是用**本拍新算出的控制量**去修改**本拍已经用过的**观测基准，导致同一拍内时间戳混用。

另一种常见的变体错误是把限幅和角度积分的顺序反过来：先积分角度，再限幅转速。这会导致角度按照超限值积分，而全局转速状态被限幅——角度和转速脱节，高速突变时 Park 变换的 dq 轴出现一拍偏差，效率下降、电流纹波增大。

## 六、限幅与保护：工程底线

八拍代码里有两处限幅，但很多初学者只写了一处。

### 转速限幅（必须）

`if (omega_new >  OMEGA_MAX) omega_new =  OMEGA_MAX;   if (omega_new < -OMEGA_MAX) omega_new = -OMEGA_MAX;`

这是防止 MRAS 估计值暴走导致电流环失控的最后一道防线。常见工程做法之一是把限幅值设为电机最高运行转速的 1.2~1.5 倍（具体取决于超速保护策略和弱磁深度），既给动态响应留余量，又不让异常值冲击系统。

**没有转速限幅的场景**：假设电机突然堵转，反电动势骤降，电压模型和电流模型的误差急剧放大。如果 PI 增益不够保守， 可能在几毫秒内冲到几千 rpm——电流环按照这个虚假转速做 Park 变换，dq 轴完全错乱，相电流冲击硬件过流保护。

### 积分限幅（必须，常被遗漏）

`if (integral_A >  INTEGRAL_MAX) integral_A =  INTEGRAL_MAX;   if (integral_A < -INTEGRAL_MAX) integral_A = -INTEGRAL_MAX;`

这是**抗积分饱和**。当转速长时间卡在限幅边界（比如电机实际转速很低，但估计值被限幅在 OMEGA\_MAX），PI 的积分项会持续累积。一旦工况突变、真实转速进入正常范围，这个累积的积分会像弹簧一样把转速估计猛推到反向限幅，造成巨大的超调和振荡。

积分限幅值通常设为"在最大稳态误差下，积分项刚好能补偿"的量级。

### 角度 wrap（必须，但实现方式有讲究）

`theta_est = fmodf(theta_est, 2.0f * PI);   if (theta_est < 0.0f) theta_est += 2.0f * PI;`

角度如果不 wrap，浮点数累积几百秒后就会精度劣化。IEEE-754 单精度 float 的尾数 23 位，在  附近（位于 \- 区间）最小步长（ULP）为  rad，角度分辨能力已经开始下降；到  附近（位于 \- 区间）ULP 达到 1 rad，`cosf` 的有效输入已经失真。FOC 里三角函数的输入一旦失真，Park/Clarke 变换直接错乱。

**fmodf 的陷阱**：部分 MCU 的 `fmodf` 不是硬件指令，软件实现可能消耗较多时钟周期。在高频中断里，如果每周期都调，累积起来不可忽视。

工程替代方案：条件减法 wrap。

`while (theta_est >= 2.0f * PI) theta_est -= 2.0f * PI;   while (theta_est <  0.0f)      theta_est += 2.0f * PI;`

正常工况下角度每拍只增加一点点（比如 0.05 rad），while 循环通常只执行一次，比 `fmodf` 快得多。如果追求极致，可以只在角度超过阈值时触发 wrap，而不是每拍都判。

## 七、三个常见误区

### 误区 1："代码顺序无所谓，反正 PI 会自己收敛"

**错。** 顺序错误的本质不是"收敛慢"，而是**时间戳混用**——用本拍新算出的控制量去修改本拍已经用过的观测基准，导致误差被人为压缩。在 PI 增益不够保守或初始偏差较大的场景下，这会演变为结构性发散。这不是收敛速度的问题，是收敛方向的问题。

**验证方法**：在仿真里故意把顺序反过来，观察误差是否指数级缩小但转速估计持续漂移——这就是"自我满足"的典型症状。

### 误区 2："参考模型和可调模型可以并行计算，没有依赖"

**表面看是对的。** 参考模型确实只依赖  和 ，可调模型只依赖  和 ——它们各自独立。但**误差计算和后续步骤有严格的先后顺序**：必须两个模型都算完，才能算误差；必须算出误差，才能更新转速；必须更新转速，才能积分角度。

如果你为了"优化"把参考模型和可调模型并行（比如用 DMA 双缓冲），必须确保两者都完成后，后续链路的执行是原子性的——不能被更高优先级中断打断，否则可能出现"可调模型是新值、参考模型是旧值"的混搭状态。

### 误区 3："角度 wrap 每拍都做太浪费，等溢出再做也行"

**float 溢出不是你想的那样。** 单精度 float 能表示到 ，但精度是有限位的——尾数 23 位，有效精度约 7 位十进制数字。在  附近（位于 \- 区间）最小步长（ULP）为  rad，角度分辨能力已经开始下降；到  附近（位于 \- 区间）ULP 达到 1 rad，`cosf` 的有效输入已经失真。

对于 20 kHz 控制频率、1000 rad/s 电角速度（8 极电机约 2387 rpm）的场景，角度每拍增加  rad。从 0 累积到  rad 需要  个拍，也就是 1000 秒（约 16 分钟）。**16 分钟后，你的 Park 变换精度就开始劣化。** 这不像整数溢出那样"啪"地崩溃，而是缓慢地、无声地让电流环变差。等你发现转矩脉动变大，可能已经排查了半天别的因素，浪费了宝贵的时间和精力。

## 八、本文最重要的工程判断

MRAS 的代码链路不是"把公式翻译成 C 语言"那么简单。在本文的保守显式实现中，每步的输入必须来自上一步的输出，时间戳对齐是底线——其他实现（如预测-校正、延迟补偿）完全可行，但必须先证明同一拍内的时间戳一致和反馈极性正确。

记住这个口诀，比记住任何公式都有用：

> **先裁判、后选手、再算差、最后调。**

具体到八拍：

1.  1. **先算参考模型**——它不依赖转速，是纯客观计算，可以最先执行；
    
2.  2. **再算可调模型**——用上一拍的角度（隐含旧转速），不能用新值；
    
3.  3. **然后算误差**——两个模型都输出后才能算；
    
4.  4. **最后调转速**——PI 输出新转速，先限幅，再积分角度。
    

计算量方面，八拍的核心运算包括若干次浮点乘加、两次三角函数（`sinf`/`cosf`）和可选的 `fmodf`。对带 FPU 的 Cortex-M4 等主流 MCU 来说，MRAS 的运算负担远小于 FOC 电流环，20 kHz 中断里通常不构成瓶颈。

但真正容易翻车的地方不是计算量，而是三件事：**顺序、限幅、积分漂移**。顺序错了发散，限幅漏了暴走，漂移不管低速失明。这三件事都不需要高深的数学，但需要你在写代码时多留一行注释、多判一个条件、多测一种工况。

至于电压模型积分漂移怎么补、离散化方法怎么选、低速区怎么启动——这些是后续文章的话题。本文先把链路跑通，把顺序刻进肌肉记忆。
