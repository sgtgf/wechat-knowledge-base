Simulink 里的波形漂亮得不像话。

你跑了一组 15 000 r/min 的加速工况，观测器输出的角度估计和编码器实测几乎完全重合。误差不超过 1°，稳得像一条直线。你心里踏实了，觉得这版参数可以锁定了。

代码下到 DSP，电机拉到一万转。

示波器上的电流还算正弦，但观测器输出的角度估计开始发抖。不是噪声那种细碎的抖，是每隔几十个毫秒就"跳"一下，像有人从背后推了转子一把。你查参数，电阻测了三遍，电感拿 LCR 表扫了频。增益从 500 调到 5000，再调回 1500，跳变还在。

你怀疑是采样率不够，把 PWM 从 8kHz 提到 16kHz。好了一些，但 MCU 的中断时间负载率飙到 85%，芯片烫手不敢摸。

**发生这种情况的原因，大概率不是观测器算法本身，而是你写在纸上的那个连续域公式，被 MCU "剁碎"成离散步骤的时候，剁歪了。**

## 电影胶片和翻页动画

各位同仁不妨先放下公式，想一个事儿。

你小时候有没有玩过那种翻页动画？一本小册子，每页画一个人物动作，用手指快速翻过，纸上的人就"动"起来了。

翻页动画不是真正的连续运动。它只是把连续动作切成一页一页的静止画面，靠你眼睛的"视觉暂留"骗大脑说"这是流畅的"。

连续域的电机方程，描述的是真实连续运动——时间  可以取任意实数值，电流、电压、磁链的变化是丝滑的曲线，没有"帧"的概念。

离散域的观测器实现，就像翻页动画——MCU 的中断每过一个固定周期 （比如 125μs，对应 8kHz）才"翻一页"。它只看这一帧的画面，算下一帧该长什么样，然后等着时钟滴答再翻下一页。

翻得越快（采样频率越高），动画越流畅。翻得越慢，"卡顿"越明显。

回到那个电压方程：

（这里先按表贴式永磁同步电机（PMSM, Permanent Magnet Synchronous Motor）来讲，。 是电角度， 是电角速度。）

这个式子是连续域的。那个  表示电流在"任意瞬间"的变化率，是连续运动级别的描述。

但 MCU 不懂什么叫"任意瞬间"。它只懂"现在这一拍"和"下一拍"。所以你必须把  换成 ，把微分方程变成差分方程。

这个"换"的过程，就是**离散化**。

换得好，翻页动画流畅得看不出间断。换得不好，人物动作就会抽搐、错位——对应到观测器上，就是角度估计抖动、相位偏移、低速不稳。

换句话说，离散化不是简单的"把公式抄到代码里"。它是一门在"精度"和"计算量"之间走钢丝的手艺。

## 最糙的翻页法：前向 Euler

怎么"换"？先看最省事的一种。

你翻到第  页，看看这一页人物的姿势斜率是多少，然后假设接下来一整页都按这个斜率走。

这就是 **前向欧拉（Forward Euler）** 离散化。几何上看，它用一块矩形去近似曲线下方的面积——矩形的高度是起点处的函数值，宽度是采样周期 。

![](https://mmbiz.qpic.cn/sz_mmbiz_gif/vvmIAIMZsASOt3HwUia6VricjMTx97u3abjBhTeR9plDvt16dGxELzx0WwU2GqHILu8VfgeIibDR9X38B3zUEsly3iclz0ZtDP57ibnlEQaKib26g/640?wx_fmt=gif&from=appmsg)

通俗来讲：你在开车，只看了一眼时速表（当前速度），然后就假设接下来一分钟都以这个速度匀速前进。如果这一分钟里你加速了或减速了，这个假设就会出错。出错的大小，跟你"看表的频率"有关。

来看看真实代码。VESC 的 Ortega 磁链观测器里，核心更新就两行：

`// 来源: bldc/motor/foc_math.c:foc_observer_update()   // 节选自 VESC Ortega 磁链观测器，前向 Euler 离散化   // bldc@c5944554      float x1_dot = v_alpha - R_ia + gamma_half * (state->x1 - L_ia) * err;   float x2_dot = v_beta  - R_ib + gamma_half * (state->x2 - L_ib) * err;      state->x1 += x1_dot * dt;  // x_{k+1} = x_k + T * x_dot   state->x2 += x2_dot * dt;`

`dt` 就是采样周期 ，`x1_dot` 就是当前点的斜率 。两行代码，完事。

前向 Euler 的优点粗暴直接：**算式简单，一步出结果**，每个周期只需要算一次 。

代价也很明显。矩形面积和真实曲线下面积之间的差，叫**截断误差**。前向 Euler 的局部截断误差是 ——采样周期每减半，误差降到四分之一。反过来，**采样周期每放大一倍，误差翻四倍**。

（这里说的是单步局部截断误差；固定时间区间内的全局误差阶次会低一阶。）

当电机转速很高、基波频率接近采样频率的时候，这个  相对电周期已经不算小了。Euler 的"矩形近似"就开始露馅。

有作者做了很直白的仿真验证：在特定观测器结构和参数条件下，采样周期 150μs、电机频率 200Hz 时，Euler 离散化导致观测器发散。\[D-005\]

## 什么时候该升级？先看载波比

前面说了这么多，各位同仁可能有个疑问："我的电机才 3000 转，PWM 16kHz，离散化误差真有那么严重吗？"

不一定。误差严不严重，关键看一个指标——**载波比（Carrier Frequency Ratio）**。

载波比 = 观测器更新频率（或控制采样频率）/ 电机基波频率。

（本文用  表示观测器实际更新频率。只有观测器在每个 PWM 周期都执行一次时，才可以近似把 PWM 频率当作  代入。）

电机转得越快，基波频率越高。3000 r/min 的四极电机，基波频率是 100Hz。假设观测器每 PWM 周期更新，PWM 16kHz，C/F = 160，很高，离散化误差微乎其微，Euler 足够用。

但高速电机呢？两万转，基波频率 667Hz。PWM 8kHz（大功率 IGBT 的常见上限），假设观测器与 PWM 同步，C/F = 12。

**C/F 低于 20，离散化误差通常就需要纳入风险评估。低于 10，它常成为主要风险之一。**

一篇综述汇总了多个研究的结论：部分连续域设计 + Euler 离散化的观测器，在 C/F = 30 时已经出现失稳。而直接在离散域设计的观测器，C/F 低到 10 还能稳定运行。\[D-002\]

D-003 的综述提到，有文献报道精确离散化的全阶状态观测器在载波比低至约 2.5 时仍能稳定运行——采样频率只比电机基波频率高 2.5 倍，观测器还能撑住。换成 Euler，这种工况下早散了架。\[D-003\]

这说明一件事：**离散化方法的选择，在低载波比场景下不是"好一点点"的问题，是"能跑不能跑"的问题。**

换句话说，采样周期和离散化方法是一对跷跷板。一头沉了，另一头就得翘起来补偿。采样率低，通常就需要用更高级的离散化方法来补；方法简单，就必须保证采样率够高。

## 更准一点的翻页法：Tustin 和改进 Euler

矩形近似太糙。如果换成梯形呢？

梯形面积 = 宽度 × (上底 + 下底) / 2。对应到离散化：

这就是**Tustin 方法**，也叫**双线性变换（Bilinear Transform）**或**梯形积分**。它同时用了起点和终点的斜率，用梯形的斜边去贴合曲线，明显比矩形的平顶更贴近真实形状。

![](https://mmbiz.qpic.cn/mmbiz_gif/vvmIAIMZsASbgzuLmLe2BvpDPhcaUyvkfZ7lRWlEts4zMypedeIG0PjRl8VHw4DHSH312WibWYMtTjj3ek1lTZn3zCNA4lHm8qibXdQCnmaog/640?wx_fmt=gif&from=appmsg)

精度也提升了一档：局部截断误差是 。采样周期减半，误差降到八分之一。

但代价同样明显。Tustin 也是隐式方法——等式右边有 ，需要额外处理。工程上通常引入中间变量，把隐式方程拆成递推差分方程和代数方程两步走。\[D-005\]

**在该作者的特定实现中，Tustin 的计算量约为 Euler 的 9 倍。** 作者的原话是："仅在需要在高频率、大采样周期下进行无感控制时，才值得采用 Tustin 法。"\[D-005\]

这解释了为什么 VESC、ODrive 这些开源项目普遍用 Euler——它们的用户跑在从 72MHz STM32F1 到 168MHz F4 的各种 MCU 上，算力预算很紧。9 倍的观测器计算量会显著挤压算力余量；实际能跑到多少，取决于观测器占总中断服务程序（ISR）的比例、MCU 主频、编译器优化和其他并行任务。对很多通用驱动来说，这笔账不划算。

那有没有折中路线？有。**改进 Euler 法**，也叫 **Heun 方法**。

phobia 的 EKF 预测步里就用了这一招：

`// 来源: phobia/src/phobia/pm.c:pm_kalman_solve()   // 节选自 phobia 磁链 EKF，改进 Euler（Heun）离散化   // phobia@4058e68de0cd      pm_kalman_equation(pm, D0);           // 步骤1：算当前斜率      pm->flux_X[0] += D0[0] * pm->m_dT;    // 步骤2：Euler 预测到下一拍   pm->flux_X[1] += D0[1] * pm->m_dT;      m_rotatef(pm->flux_F, pm->flux_wS * pm->m_dT);  // 旋转磁链方向   m_normalizef(pm->flux_F);      pm_kalman_equation(pm, D1);           // 步骤3：在预测点重新算斜率      pm->flux_X[0] += (D1[0] - D0[0]) * pm->m_dT * 0.5f;  // 步骤4：梯形校正   pm->flux_X[1] += (D1[1] - D0[1]) * pm->m_dT * 0.5f;`

核心思想很优雅：先用 Euler 预测一步走到下一拍，在预测点重新算一次斜率，再用"起点斜率 + 预测点斜率"的平均值做校正。

精度 ，跟 Tustin 同级。理论上的计算量约为 Euler 的 2 倍（每周期需要两次方程求值），比 Tustin 的约 9 倍少得多。

phobia 的定位是高性能伺服，对精度要求比通用驱动器高。改进 Euler 是它找到的甜点：**精度明显提升，计算量增加可控**。

**工程决策树：**

-   • 如果你的电机最高转速对应的 C/F > 30，且跑在低成本 MCU（STM32F1/F4 级别）——**前向 Euler 够用**，不用折腾。
    
-   • 如果 C/F 在 15~30 之间，且 MCU 有余量——考虑**改进 Euler**（phobia 的做法），精度提升明显，计算量增加不多。
    
-   • 如果 C/F < 15，或者做高速伺服、航空航天——**通常需要考虑高阶离散化**。预算够就上 RK4 或 ZOH 精确离散化（RK4 在部分低 C/F 实验中的稳定边界优于 Euler/Tustin \[D-004\]），预算紧就考虑在离散域直接设计观测器（而不是连续域设计完再离散化）。
    

## 两个坑，坑坑见血

**坑 1：在仿真里跑得飞起，下到硬件就发散**

> **症状**：Simulink 里完美运行，代码下到 DSP 后电机一高速就飞车或过流。
> 
> **根因**：Simulink 的连续模型仿真常使用变步长求解器（如 ode45），效果上相当于使用自适应高精度数值积分。而你的嵌入式代码用的是固定步长的前向 Euler。两者的精度差距在低速时不明显，高速下天差地别。
> 
> **解法**：做代码一致性验证时，应把 Simulink 仿真改为与目标硬件一致的 fixed-step、采样时间和离散算法。线性模型可用 `c2d` 函数辅助离散化（配 `'zoh'` 或 `'foh'`）。如果仿真用连续模块，至少要加一个 Zero-Order Hold 模块来模拟真实采样。\[D-005\]

**坑 2：以为提高 PWM 频率就能解决一切**

> **症状**：电机高速抖，直接把 PWM 从 8kHz 提到 20kHz，结果抖得更厉害了。
> 
> **根因**：PWM 频率提高不等于观测器更新频率提高。很多系统的观测器只在电流采样中断里跑，PWM 频率变了但 ADC 采样率没变，观测器的  还是原来的值。更糟的是，PWM 频率提高后开关损耗增加，死区占比相对变大，逆变器非线性反而更严重。
> 
> **解法**：先确认观测器的实际更新频率（通常是 ADC 采样频率或控制中断频率）。如果观测器  没变，单纯提 PWM 频率没用。应该考虑的是**提高控制环频率**或者**换离散化方法**。

## 示波器看哪里

离散化搞砸了，示波器上会有很明确的"症状"。

**症状 1：高速时角度估计周期性跳变**

-   • **看哪里**：把观测器输出的  和编码器实测的  同时上示波器（如果有编码器做对比的话）
    
-   • **正常**：两者波形基本重合，误差在几度以内
    
-   • **异常**：高速区（C/F < 20 的转速范围）出现周期性锯齿状跳变，每次跳变幅度随转速升高而增大
    
-   • **根因**：离散化误差导致的相位超前或滞后，Euler 在低 C/F 下尤其明显
    

**症状 2：同一套参数，低速稳高速抖**

-   • **看哪里**：速度环输出或  轴电流给定
    
-   • **正常**：全速域平稳
    
-   • **异常**：低速区（C/F 高）一切正常，一过某个转速阈值就开始抖
    
-   • **根因**：离散化误差的"放大器"效应——C/F 降到临界值以下，误差从"可忽略"变成"致命"
    

## 🔧 调试 Checklist

\[ \] 计算你的系统在最恶劣工况下的载波比 C/F =  / 。如果 C/F < 20，离散化方法需要纳入风险评估  
\[ \] 确认观测器的更新频率等于控制中断频率，而不是 PWM 频率（两者可能不同步）  
\[ \] 对比 Simulink 仿真和实际硬件：仿真时是否用了与硬件相同的固定步长和离散化方法？  
\[ \] 如果高速区出现角度抖动，先用编码器对比实测角度和观测器估计角度，确认是离散化问题还是参数不准  
\[ \] 评估 MCU 的 CPU 余量：如果换改进 Euler，是否能在目标频率下实时完成？  
\[ \] 低速正常但高速抖？离散化误差是优先排查项之一，同时也要排除电感饱和、磁链参数漂移、采样延迟、死区补偿和电压裕量不足等因素。
