# 《PMSM观测器控制这件小事》| 02讲：反电动势到底是什么？

各位同仁，假设你现在刚拿到一个新电机，翻开 datasheet，上面有个参数叫"反电动势常数"，单位是 V/(rad/s)。这里默认指**相电压峰值**对**电角速度**的比值（不同厂家口径可能不同，有的标线电压 RMS，读的时候要注意）。

你盯着它看了三秒，心想：这和磁场定向控制（FOC, Field-Oriented Control）有什么关系？

如果你搞有感控制，答案大概是"关系不大"。编码器直接给角度，若不用前馈补偿、弱磁控制或模型参考，电流闭环本身不强依赖这个参数。电流环的 PI 参数照着手册调，速度环带宽往上顶，电机转得又稳又狠。反电动势（BEMF, Back-EMF）？那是电机学课本里的概念，和调代码有什么关系。

可一旦上了无感控制，这个参数就成了命根子。

观测器靠反电动势推算角度，而这个常数直接决定了反电动势有多大。参数不准，角度就偏。偏偏很多 datasheet 上的值是常温标定的，电机跑热了，永磁体退磁，实际值可能明显下降。你拿着 A 电机的参数去调 B 电机，观测器永远调不顺。

但反电动势到底是什么？电机自己"发"出来的这个电压，从哪来的？为什么转速越高它越大？零速的时候它又为什么消失得无影无踪？

更扎心的是，你翻开 VESC 的 `foc_math.c`，看到 `state->x1 += (v_alpha - R_ia) * dt - L * (i_alpha - state->i_alpha_last)` 这一行。你知道这是在更新观测器状态，但 `v_alpha - R_ia` 是什么意思？`L * di` 又是什么？为什么积分一下就能得到角度？

今天咱们就把这个词拆碎，从水管里的水流开始，一路推到αβ坐标系下的数学表达。不讲观测器怎么用 BEMF，只讲 BEMF 本身是什么、从哪来、长什么样。这是地基。地基不牢，后面滑模观测器（SMO, Sliding Mode Observer）、扩展卡尔曼滤波器（EKF, Extended Kalman Filter）、模型参考自适应系统（MRAS, Model Reference Adaptive System）的算法推导，你看了也是浮在表面上。

看完你会明白：观测器不是凭空"算"出角度的，它只是读出了电机自己发出来的"电报"。

## 水流过水轮机的时候，水压掉了下来

  

各位同仁，咱们先来打个比方。

想象你家的自来水管，接了一台小型水轮机。水龙头一开，水流推动水轮机转起来。水轮机连着一根轴，轴上带个叶轮，叶轮在水管里搅动。

水从水龙头出来，压力大。经过水轮机，推动叶轮转，水的压力掉了下来，最后从出水口流走。

这个"压力差"，就是水流做功的证据。

水轮机转得越快，叶轮搅动得越剧烈，你要维持同样流量，需要的压力差就越大。**转速是因，压力差是果**——转速一上去，水管两端的压力差必然跟着变大。

电机里发生的事，和这个一模一样。

**水管** = 电机的定子绕组  
**水流** = 定子电流  
**水压** = 端电压  
**水轮机** = 转子（永磁体）  
**叶轮** = 转子磁场

当你给电机加电压，电流流进绕组，就像水流进水管。电流产生的磁场和转子永磁体的磁场相互作用，推动转子转起来。转子一转，永磁体在定子绕组周围"扫过"，就像水轮机上的叶轮在水管里搅动。

这个搅动，会在绕组里"感应"出一个电压。

这个电压的方向，按楞次定律反映磁通量的变化。转子永磁体扫过定子绕组，磁通量一直在变，绕组里就被"逼"出一个电压来抵抗这种变化。你加电压推电流，它反过来顶你。这就是"反"电动势——和外加电压"对着干"的那个电压。

说白了，反电动势是电机"反抗"你加电压的证据。转子转得越快，反抗越强烈，反电动势就越大。

回到咱们的电机，这对应的就是：转子永磁磁链扫过定子绕组，使绕组磁链随时间变化，从而感应出 BEMF。

## 法拉第早就告诉过你：磁通一变，电压就来

  

刚才的水管类比，对应的正是法拉第电磁感应定律。

1831年，法拉第发现：穿过闭合回路的磁通量发生变化，回路里就会感应出电动势。

  
负号是楞次定律——感应电动势的方向，总是阻碍磁通量的变化。你推它，它顶你。你拉它，它拽你。像个倔强的弹簧。

说白了，转子永磁体的磁场在转，定子绕组"看"到的磁通量一直在变。变一次，绕组里就被"逼"出一个电压。转子转得越快，磁通量变化越剧烈，这个电压就越大。

这个电压就是反电动势。

电机出厂的时候，永磁体的磁场强度是固定的，用**永磁体磁链** 表示。转子转一圈，定子某相绕组"扫过"的磁通量变化总量也是固定的。所以反电动势的大小，只和一个东西成正比：

**转速**。

转速翻倍，反电动势翻倍。转速为零，反电动势为零。

这就是为什么观测器在零速时不工作——电机静止，没有磁通量变化，反电动势是零。观测器读不到"电报"，自然发不出"定位"。

有些同仁会问：那我用手转动电机，不接电，能测到反电动势吗？

能。你这是在把电机当发电机用。转子在转，永磁体切割定子绕组，感应出电压。你拿万用表量相线之间，能看到电压随转速升高而增大。这个电压就是反电动势。很多电机厂家标称的"反电动势常数"，就是这么测出来的。

电动机状态和发电机状态，本质上是同一个物理过程的两面。当外部电压大于 BEMF，电流正向流动，电机消耗电能产生转矩，这是电动机。当外部电压小于 BEMF（比如减速或外力拖动），电流反向流动，电机把机械能变成电能回馈，这是发电机。在  近似恒定、忽略饱和和退磁的前提下，BEMF 幅值只和电角速度成正比。

##  和  不是"虚拟信号"

  

有些同仁第一次看αβ坐标系，觉得  和  是数学变换造出来的"虚拟量"，没有物理意义。

不对。

它们和  一样真实。只是坐标系不同。

想象你站在A相绕组的轴线上，面朝β方向。 是你前后感受到的电压， 是你左右感受到的电压。

转子磁场在转，你前后左右的"电压感受"也在周期性变化。这个变化就是反电动势的物理实在。

αβ坐标系的好处是：把三相对称问题变成了二维平面问题。两个方程代替三个，计算量减半，几何直觉更清晰。旋转的矢量、反正切求角度、锁相环（PLL, Phase-Locked Loop）跟踪——这些漂亮的数学工具，只有在αβ坐标系里才显得自然。

说白了，三相是三个人的视角，αβ是一个人的视角。信息没丢，只是换了个更舒服的观察位置。

## 从 BEMF 到角度：观测器到底在做什么？

  

前面咱们知道了 BEMF 携带了角度信息，但观测器是怎么"读"出这个角度的？

最直接的路线是反正切。有了  和 ，套公式：

简单粗暴，一个函数调用就出来角度。

但反正切有个致命的毛病——噪声敏感。BEMF 信号里有一点点高频噪声，反正切直接把它放大成角度抖动。更糟糕的是，反正切算出来的是离散的角度值，速度还要再微分一次，噪声又被放大一轮。

所以工程上更常用的是锁相环（PLL）。PLL 不直接算角度，而是"跟踪"角度。它内部有一个振荡器，产生一个猜测的角度，然后对比猜测角度和 BEMF 信号的相位差，用 PI 控制器不断修正猜测。这样得到的角度是连续的，速度是积分出来的，天然平滑。

PLL 就像听导航语音开车。导航不说"你现在在经度 X 纬度 Y"，而是说"前方500米左转"。你根据这个指令不断修正方向，最终平稳到达目的地。反正切像是看地图找方向，每看一眼地图就猛地打一把方向，颠簸得很。

关于 PLL 的详细原理，咱们放到第 9 篇专门讲。今天只需要记住：观测器从 BEMF 里提取角度的路线不止一条，反正切是开路先锋，PLL 才是工程主流。

## 反电动势就是观测器的"信标"

  

现在可以回答开头的问题了：观测器为什么能靠反电动势推算角度？

因为反电动势是电机"主动发出"的信号。

你不需要额外装传感器。转子一转，永磁体就在绕组里感应出电压。这个电压的大小告诉你转多快，相位告诉你朝哪转。电机自己在"广播"自己的状态，观测器只是把这个"广播"截获、解码。

当然，实际工程中不能直接测反电动势。绕组上接的是逆变器，电压是PWM斩波过的方波，电流有纹波。观测器要从噪声中提取信号，还要补偿死区、管压降、采样延迟。这才是难点。

但物理本质不变：

**反电动势是电机内部状态和外部电气量之间的桥梁。**

没有这座桥，观测器就是瞎子。桥搭好了，角度和速度自然显现。

## 几个常见的误解

### "反电动势是逆变器输出的吗？"

不是。

逆变器输出的是端电压 。反电动势是电机内部感应出来的 。

两者的关系是：

端电压要"克服"电阻压降、电感压降，剩下的才"留给"反电动势。高速时反电动势大，你需要更高的端电压才能维持同样的电流。

这也是为什么电机有"最高转速"——反电动势太大，逆变器输出电压不够了，电流推不上去。到了这个点，你再加大占空比也没用，电机"顶回来"的电压和逆变器能给的电压打平了。

这也解释了另一个现象：低速时反电动势小，信噪比差，观测器很难精确提取角度。不是观测器不行，是"电报"信号太弱，淹没在噪声里。

### "反电动势幅值固定不变吗？"

不是。

永磁体磁链  随温度变化。高温下永磁体可能退磁， 可能明显下降。反电动势跟着降。

同一批电机， 也有分散度。这就是为什么无感控制调试时，电机参数必须精确测量，不能抄 datasheet 的额定值。你拿着A电机的参数去调B电机，观测器可能永远调不顺。

### "反正切算出来的角度就是转子位置吗？"

要注意。

从  算出来的就是转子磁链角  本身——公式  已经直接给出转子位置，不需要额外偏移。

但这里有个容易混淆的点：有些观测器不是从 BEMF 出发，而是从磁链出发。ODrive 的磁链观测器先积分得到磁链 ，再用 `fast_atan2(eta[1], eta[0])` 直接出相位。磁链角就是转子位置，没有 90° 偏移。VESC 的 MXLEMMING observer 内部状态 `x1`、`x2` 也是磁链分量，反正切后同样需要确认 atan2 的参数顺序是否匹配你的坐标约定。

### "BEMF 会影响电流环的响应吗？"

会。

电流环的 PI 控制器输出电压，目的是让电流跟踪给定值。但电机高速运转时，BEMF 很大，它"顶"住了你加电压的效果。电流环需要输出更高的电压才能产生同样的电流变化。

这就是为什么高速区的电流环带宽会变窄——不是 PI 参数变了，是 BEMF 占了电压预算的大头。逆变器输出电压有限，BEMF 占掉一部分，留给电流控制的"余量"就少了。

有些高端的驱动器会显式做 BEMF 前馈补偿——在高速时预先加一个和转速成正比的电压项，减轻电流环的负担。ODrive 里有 `bEMF_FF_enable` 开关；VESC 里则是通过 `FOC_CC_DECOUPLING_BEMF` 等解耦选项实现类似功能。

### "BEMF 只和转速有关，和负载没关系？"

对，也不对。

从公式  看，BEMF 确实只和转速有关，和负载转矩无关。但负载变了，转速会变。转速变了，BEMF 跟着变。

所以间接上，BEMF 反映的是转速，而转速是电磁转矩和负载转矩平衡的结果。观测器从 BEMF 里提取的是转速和角度，不是负载。想知道负载，得看电流。

## 代码不会撒谎

  

聊了这么多概念，看看代码层面，BEMF是怎么被"抠"出来的。

VESC 的 `foc_observer_update()` 是核心观测器函数。它用离散化的方式，把电压方程积分更新磁链状态：

`// 来源: 节选自 bldc@c5944554 motor/foc_math.c:82-85,108-121   // MXLEMMING observer 离散实现      // R_ia = R * i_alpha，电阻压降（定义在 foc_math.c:82-85）   const float R_ia = R * i_alpha;   const float R_ib = R * i_beta;      // 积分状态更新：由电压方程更新磁链状态（foc_math.c:108-121）   state->x1 += (v_alpha - R_ia) * dt - L * (i_alpha - state->i_alpha_last);   state->x2 += (v_beta - R_ib) * dt - L * (i_beta - state->i_beta_last);`

`(v_alpha - R_ia)` 是补偿了电阻压降的电压。  
`- L * (i_alpha - state->i_alpha_last)` 是电感压降  在一个采样周期内积分后的  项（量纲为 V·s，与前面的 `* dt` 配合后才是电压积分）。  
两者相减，相当于对 BEMF 做积分，更新的是磁链状态变量 `x1`（即 alpha 轴总磁链），而不是 BEMF 本身。

再看ODrive的 `sensorless_estimator.cpp`。它用的是非线性磁链观测器，但底层逻辑一样——先扣掉电阻和电感的干扰：

`// 来源: 节选自 ODrive@3a2e4dd1 Firmware/MotorControl/sensorless_estimator.cpp:61-84   // 注意：真实源码外层有 for 循环和数组定义，此处省略；后续还有 eta_factor 非线性校正项（sensorless_estimator.cpp:71-84）      // 计算"磁链驱动电压" y = V - R*I   float y = -axis_->motor_.config_.phase_resistance * I_alpha_beta[i]              + V_alpha_beta_memory_[i];      // 积分得到总磁链   flux_state_[i] += y * current_meas_period;      // 减去电感分量，得到永磁体磁链   eta[i] = flux_state_[i]             - axis_->motor_.config_.phase_inductance * I_alpha_beta[i];`

ODrive没有直接输出BEMF，而是把  积分得到总磁链，再减去  得到永磁体磁链 。磁链的角度就是转子位置。

两种实现，殊途同归。都是先把电阻和电感的"干扰"扣掉，分离出转子产生的电磁效应。

VESC 的 MXLEMMING observer 把 BEMF 直接积分进状态变量，再用反正切或 PLL 提取角度。ODrive 的磁链观测器多走一步——先积分得到总磁链，再扣掉电感分量，得到永磁体磁链，磁链的角度直接就是转子位置。

为什么 ODrive 不直接算 BEMF 而要绕到磁链？

因为 BEMF 是磁链的导数，对噪声敏感。磁链是 BEMF 的积分，天然有低通滤波效果，噪声被抑制。代价是积分器有漂移问题，需要非线性校正项（ODrive 里的 `eta_factor`）把磁链幅值钳位在  附近。

两种路线，各有优劣。VESC 直接、轻量，适合资源受限的 MCU。ODrive 鲁棒、平滑，适合高性能场景。

ST 的文档里管这个叫"State Observer"，数学框架与 ODrive 类似（都是磁链观测 + 角度提取），但内部状态方程和离散化方法有差异。只不过 ST 把它封装成了图形化配置界面，你不用写代码，填几个参数就能跑。但填参数之前，你得知道 BEMF 从哪来、怎么算、受什么影响。否则调参就是瞎调。

## 上手之前，先摸清这三个坑

### 示波器看哪里

\[ \] **Check 1（开路反电动势法）**：用外部设备恒速拖动电机（断开逆变器，电机作为发电机），用示波器测线电压基波峰值，反推 。注意：这是**开路**测量，不能和逆变器 PWM 端电压混淆。  
\[ \] **Check 2（逆变器驱动时）**：如果电机已接逆变器运行，端电压是 PWM 方波，不能直接示波器量相电压算 。此时应检查电压重构是否准确（母线电压×占空比−死区补偿），死区补偿不准会直接污染 BEMF 估计。 建议用开路反电动势法或专用参数辨识仪测量，**LCR 表不能直接测 ψ\_f**。  
\[ \] **Check 3**：低速时BEMF幅值小，确认ADC分辨率足够。量化误差对BEMF估计的影响取决于 ADC 满量程、采样电路增益和低速 BEMF 幅值的相对关系，需结合具体硬件评估。

### 常见坑

**坑 1：用额定参数算BEMF，实际差很远**

> **症状**：观测器角度估计偏差大，低速抖动。
> 
> **根因**： 随温度变化。永磁体高温退磁， 可能明显下降。
> 
> **解法**：用 LCR 表测  和 ，用开路反电动势法或专用参数辨识仪测 。批次间参数分散度大，考虑在线参数辨识。

**坑 2：混淆电角度和机械角度**

> **症状**：角度提取结果跳变或偏差固定。
> 
> **根因**：PMSM的BEMF频率是电频率 = 极对数 × 机械频率。公式里所有  和  都是电角度。
> 
> **解法**：确认电机的极对数 。编码器测的是机械角度，乘以  才是电角度。

**坑 3：低速时直接靠BEMF启动**

> **症状**：电机静止时直接切入无感FOC，电机抖动、反转，甚至过流保护。
> 
> **根因**：零速时反电动势为零，没有任何角度信息。
> 
> **解法**：零速启动通常需要辅助手段——高频注入法（HFI, High-Frequency Injection，依赖凸极性）、初始位置检测、对齐+电流/频率开环启动（I/F, current/frequency）等。纯 BEMF 观测器只能在一定转速以上工作。

## 🔧 调试 Checklist

\[ \] 确认电机极对数 ，所有角度计算都用电角度  
\[ \] 精确测量 ：开环拖动法或参数辨识仪  
\[ \] 确认  和  随温度的变化范围  
\[ \] 检查低速时ADC量化误差是否在可接受范围  
\[ \] 规划零速启动策略（HFI / I-F），纯BEMF观测器无法零速工作  
\[ \] 确认逆变器死区时间和管压降补偿是否已启用，电压重构误差会直接传递到BEMF估计
